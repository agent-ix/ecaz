### Fold #1: `descriptor_region_ptrs` combines the two `_ptr` helpers

- **Before:** `coordinator_ptr(state) -> *mut EcParallelCoordinatorState`
  (1 `unsafe { … }` for offset+cast) + `worker_slots_ptr(state) -> *mut EcParallelWorkerSlot`
  (1 `unsafe { … }` for offset+cast). Two separate unsafe blocks
  for offset arithmetic that always happen together in practice
  (both `validate_parallel_scan_state` and `reset_parallel_scan_layout`
  call them in sequence).
- **After:** `descriptor_region_ptrs(state) -> (coord_ptr, slots_ptr)`
  single helper with one `unsafe { … }` block computing both
  pointers under one shared SAFETY anchor. The two thin
  `coordinator_ptr` / `worker_slots_ptr` selectors remain as safe
  projections of the tuple (`.0` / `.1`) for callers that only need
  one — no unsafe operations in those selectors.
- **Net:** **-1 block.** Same number of pointer-arithmetic ops
  executed at runtime; the SAFETY comment moves from being
  duplicated across two helpers to being stated once with both
  derivations together.
- **Metric-gaming guardrail:** the actual `.add()` calls and `.cast()`
  chains still happen — just inside one block instead of two. No
  unsafe operation has been hidden or stripped.

### Fold #2: delete `initialize_parallel_scan_target` thin wrapper

- **Before:** `pub(crate) unsafe fn initialize_parallel_scan_target(target)`
  whose entire body was an `unsafe { initialize_parallel_scan_target_with_worker_slots(target, ec_parallel_scan_worker_slot_capacity()) }`
  delegation to the with-capacity variant. The wrapper had a
  full `/// # Safety` doc (parallel.rs unsafe-fn count was 10/10).
- **After:** Wrapper deleted. Sole caller `ec_aminitparallelscan`
  (the PG `aminitparallelscan` callback) now calls
  `initialize_parallel_scan_target_with_worker_slots(target, ec_parallel_scan_worker_slot_capacity())`
  directly inside its `pg_callback!` body. parallel.rs unsafe-fn
  count drops to 9; `/// # Safety` count drops to 9; parity stays
  9/9.
- **Net:** **-1 block.** The deleted wrapper was pure delegation
  with no PG FFI op or pointer-deref at its layer; deleting it
  removes a syntactic unsafe block without removing any operation.
- **Metric-gaming guardrail:** the seq-02 metric-gaming line forbids
  "stripping explicit `unsafe { … }` wrappers around unsafe-fn
  calls inside `unsafe fn` bodies" when the inner deref / FFI is the
  actual unsafe operation. Here the wrapper is being _deleted_
  entirely along with its safety doc; the underlying unsafe op is
  no longer wrapped at all because the wrapper layer is gone. The
  caller-side `pg_callback!` body invocation matches the pattern
  the file already uses (e.g. for `reset_parallel_scan_state` at
  `ec_amparallelrescan`), so no new pattern is introduced.
