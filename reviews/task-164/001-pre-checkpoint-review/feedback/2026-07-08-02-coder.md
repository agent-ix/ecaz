# Response to pre-checkpoint review 2026-07-08-01

All five findings addressed on `task-164-ec-distann-m2` (fix commit follows the
2c transport commit). Summary:

## P1 — epoch fingerprint now binds the build-time content tier

Added a build-time `content_digest` to the metadata page (format **v2**):
FNV-1a + murmur3 avalanche over, in vec_id-sorted order, each node's
`(vec_id, full-precision source vector, sorted neighbor vec_ids)`. Computed at
flush (`ambuild.rs::compute_content_digest`), persisted, read into
`DistannEpochIdentity`, and folded into `compute_epoch_fingerprint`. Two graphs
with identical shape metadata (node_count/dims/seed/degree/codec) but a
differing vector, vec_id set, or edge now get different fingerprints.

Regression: `test_ec_distann_content_digest_binds_build_content` builds two
same-shape indexes differing by one vector and asserts both the digests and the
epoch fingerprints differ. This binds vec_id set + co-placed vector tier +
adjacency; the head sample and codebook are deterministic functions of these +
seed. If you want them hashed explicitly too, I'll extend the digest — say the
word.

## P2 — typed error classes with distinct SQLSTATEs

New `expand_error::DistannExpandError` { EpochMismatch, Placement,
OwnedRecordMissing, VectorMissing, BadInput, Internal }, each mapped to a
distinct SQLSTATE (epoch mismatch = `40001` serialization-failure, the
retriable class). The `DistannNodeExpander` trait, `LocalNodeExpander`,
`RemoteNodeExpander`, and the orchestration now carry it; the endpoint raises
via `ereport!` with the code (no more generic `error!`), and the transport
classifies remote wire errors by `tokio_postgres::Error::code()` so the
coordinator distinguishes retriable epoch mismatch from non-retriable
placement/structural faults without parsing text. `is_retriable()` gates the
FR-082 restart (the restart loop itself lands in M3). Unit tests assert the
classes are distinct and survive a wire round-trip.

## P2 — endpoint volatility

`ec_distann_expand_nodes` and `ec_distann_epoch_fingerprint` are now
`#[pg_extern(volatile, parallel_restricted)]` (were immutable/parallel_safe) —
they read relations, GUCs, snapshots.

## P2 — grouping carries request positions

`group_by_owning_node` now returns `Vec<Vec<(usize, u64)>>`;
`RemoteNodeExpander` reassembles by original request position (a
`Vec<Option<_>>` filled by index), robust to a repeated vec_id and to
per-node-order concatenation. New tests: interleaved-across-owners ordering,
duplicate-position preservation, wrong-count coverage guard.

## P3 — zero-node roster no longer silently normalized

`owning_node`/`group_by_owning_node` assert `node_count >= 1` (a corrupt
zero-node roster is rejected, not treated as single-node); the single-node
degenerate fallback stays in `current_placement_directory`.
