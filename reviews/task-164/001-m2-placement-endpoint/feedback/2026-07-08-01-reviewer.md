# Task 164 packet 001 review

No signoff. This packet is correctly scoped as slices 1-2b only, but there are still correctness issues that should be fixed before building the transport on top of it.

## Findings

### P1 - Epoch fingerprints do not bind the actual record set or vector tier

FR-082 requires every participant to resolve the same `(manifest, placement, head sample, vector tier)` for the fingerprint and says the fingerprint attests to the build-time record set and vector tier (`spec/functional/index/distann/FR-082-distann-epoch-lifecycle.md:29`, `spec/functional/index/distann/FR-082-distann-epoch-lifecycle.md:54`). The implementation only hashes coarse metadata: epoch, format/hash versions, roster ids, node_count, dimensions, graph_degree, codec kind, and seed (`src/am/ec_distann/epoch.rs:34`, `src/am/ec_distann/epoch.rs:114`; populated from `src/am/ec_distann/roster.rs:185`).

Two different indexes with the same row count, dimensions, degree, codec, seed, epoch, and roster will produce the same fingerprint even if their vec_id set, graph adjacency, head sample, or co-placed vectors differ. That lets a coordinator accept stale or wrong remote epoch contents and continue a scan instead of taking the FR-082 retry path. The fix needs a persisted epoch/content digest that covers the built vec_id set plus graph/head/vector-tier identity, with a regression where same-count but different source vectors/identities produce different fingerprints.

### P2 - The SQL functions are marked immutable and parallel-safe even though they read mutable backend state

Both new SQL surfaces are declared `#[pg_extern(immutable, parallel_safe)]` (`src/am/ec_distann/remote_endpoint.rs:52`, `src/am/ec_distann/remote_endpoint.rs:86`). They read relation metadata, GUC-backed roster/epoch state, the cached index entry, heap tuples, and the active snapshot (`src/am/ec_distann/remote_endpoint.rs:91`, `src/am/ec_distann/remote_endpoint.rs:136`, `src/am/ec_distann/remote_endpoint.rs:173`, `src/am/ec_distann/remote_endpoint.rs:178`, `src/am/ec_distann/remote_endpoint.rs:186`).

That is not immutable, and it is not safe for the planner to fold, cache, or freely parallelize. These should be declared volatile and at least parallel restricted/unsafe until the parallel-safety story is explicit.

### P2 - Retriable and structural endpoint faults are still only string messages

FR-079 and FR-082 distinguish retriable epoch mismatch from non-retriable placement/structural faults (`spec/functional/index/distann/FR-079-distann-remote-expansion-protocol.md:51`, `spec/functional/index/distann/FR-079-distann-remote-expansion-protocol.md:62`). The endpoint still maps every internal error through `pgrx::error!("{e}")` (`src/am/ec_distann/remote_endpoint.rs:77`, `src/am/ec_distann/remote_endpoint.rs:88`), and tests assert substrings only (`src/tests/ec_distann_basic.rs:916`, `src/tests/ec_distann_basic.rs:952`).

The coordinator will need a stable machine-readable class to decide retry/restart vs fail-fast. Add typed error categories and a stable SQLSTATE/detail/hint convention, then make the pgrx tests assert those categories rather than just human text.

### P3 - Zero-node placement is silently normalized to one node

`owning_node` documents `node_count >= 1` but turns zero into one with `node_count.max(1)` (`src/am/ec_distann/placement.rs:63`, `src/am/ec_distann/placement.rs:66`). That masks invalid epoch/roster construction in release builds and can make a bad directory look like a valid single-node placement. Reject zero node_count at the directory boundary or return a `Result`; keep the single-node case explicit through a one-node directory.

### P3 - The packet evidence log does not contain all evidence claimed by the manifest

The request and manifest claim 6 placement tests and clippy clean (`reviews/task-164/001-m2-placement-endpoint/request.md:38`, `reviews/task-164/001-m2-placement-endpoint/artifacts/manifest.md:34`, `reviews/task-164/001-m2-placement-endpoint/artifacts/manifest.md:50`). The durable log only lists epoch, roster, and endpoint pg_tests, with no placement-test lines and no clippy command/output/exit status (`reviews/task-164/001-m2-placement-endpoint/artifacts/test-evidence.log:3`).

Attach full command logs or update the manifest to cite only what is actually present. This is evidence hygiene, but it matters because the review workflow treats packet-local artifacts as the durable source of truth.
