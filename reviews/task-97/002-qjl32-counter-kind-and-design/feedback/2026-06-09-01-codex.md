## Finding 1 (REQUIRED before Phase 2 implementation): strict `to_bits()` anchor must be the forced-scalar reference, not `score_ip_from_parts`

Design §Scalar Pseudocode says "The scalar reference must match the existing
pre-kernel scorer with `f32::to_bits()` equality" and §Tests says "`len < 32`,
`len == 32`, and `len > 32` scalar parity against `score_ip_from_parts`".

`score_ip_from_parts` is production-dispatched: for QJL-active quantizers —
which is precisely Task 97's production scope — `score_ip_from_split_parts`
(`src/quant/prod.rs:501`) selects `..._avx2_checked` / `..._neon_checked`
via `backend()` on every real dev/bench host (`prod.rs:520-531`). Strict
`to_bits()` parity against that dispatched entry point is unachievable by
construction on x86_64/aarch64 hosts. This is the identical Finding 1 the
Task 93 packet 001 review cycle already resolved
(`reviews/task-93/001-rabitq32-design/feedback/2026-06-09-0{1,2}-reviewer.md`),
and the same split-gate contract should be used here:

1. strict `f32::to_bits()` parity vs the forced-scalar reference —
   `ProdQuantizer::score_ip_from_parts_scalar_reference` already exists
   (`prod.rs:248`, `cfg(any(test, feature = "bench"))`) and the design's
   per-lane accumulation order (dim-ascending, MSE and QJL interleaved per
   dim, 8-dim groups) matches `score_ip_from_split_parts_scalar`'s operation
   order, so this anchor is achievable as designed;
2. production-dispatched `score_ip_from_parts` comparisons graded under
   ADR-076 tolerance (`<= 4 ULP` or `1e-6` relative, whichever larger);
3. a one-shot host agreement check between the production per-candidate path
   and any production batch path used as a reference.

Please update §Scalar Pseudocode and §Tests in `design.md` (or carry the
revision into the scalar-kernel packet's request) to name
`score_ip_from_parts_scalar_reference` as the strict anchor. Implementation
that targets the dispatched scorer for `to_bits()` equality will fail its own
gate on both bench hosts.

## Minor (non-blocking): prefer the mode predicate over the `!= 1536` literal

§Shape Validation lists `quantizer.original_dim != 1536` as a validation rule.
The load-bearing production gate is `qjl_enabled(original_dim, bits)` /
`ExactScoreMode::MseLutQjl` (already first in the same list). Hardcoding the
current 1536 exclusion duplicates the rule and will silently drift if
`qjl_enabled` ever changes. Suggest validating only via
`exact_score_mode() == MseLutQjl` and letting `qjl_enabled` own the dimension
rule.
