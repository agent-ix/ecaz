## F1 — Production per-candidate QJL scorer was de-vectorized; needs its own before/after evidence

`b0efa19d9` rewrote `score_ip_from_split_parts_avx2_checked`'s
3-bit arm: the previous 4-accumulator FMA loop with a 32-dim unrolled
section is now an 8-dim loop doing SIMD multiply + store + **16 scalar
adds per 8 dims** (prod.rs diff, -105 lines). This buys scalar-order
accumulation so production dispatch and the qjl32 kernel sit inside
one ADR-076 tolerance gate — a legitimate goal with a real consistency
benefit (per-candidate and batch paths now agree tightly, which
stabilizes top-k tie behavior). But it has two unmeasured costs:

1. **Per-candidate production latency.** The packet's Criterion
   evidence covers qjl32 batch scalar-vs-dispatch only. The rewritten
   per-candidate path — still live for HNSW per-candidate exact
   scoring, scalar tails outside batches, and any non-batched QJL
   caller — lost its FMA accumulators and unroll. Closeout needs an
   old-vs-new Criterion row for `score_ip_from_parts` itself at
   dim 1024, or an explicit statement of why the per-candidate path's
   throughput no longer matters on QJL surfaces after packet 005's
   batch registration.
2. **Score bit-patterns changed on QJL surfaces.** Any existing
   QJL-active deployment's scores shift (within tolerance, but
   shifted). Recall baselines for QJL cells re-anchor at this commit;
   the packet-009-style suite evidence must use post-`b0efa19d9`
   baselines for its batch-off cells, never pre-slice runs.

Also state for the record (one sentence in the next request is fine):
did the old multi-accumulator FMA loop actually FAIL the 4-ULP/1e-6
pair vs scalar at dim 1024? If yes, the rewrite is justified — say so
with the observed ULP figure. If it passed, the rewrite traded
production speed for an alignment the tolerance gate already
permitted, and reverting to the fast loop should be considered.

## F2 — 1.22× local AVX2 micro-speedup is below the task's 1.5× stop-condition floor

The packet reports scalar 35.0µs vs dispatch 28.6µs per 32 candidates
(1.22×). Task 97 AC 4 sets the ladder at ≥2× target / ≥1.8×
acceptable / 1.5–1.8× documented-partial / <1.5× per-ISA Stop
Condition. A Criterion micro-row is not the AC's scoring-share metric,
so this is not yet a stop-condition trigger — but it is a leading
indicator that the AVX2 cell may land in the documented-partial or
stop-condition band. The gamma/sign side-data overhead was always the
known ceiling-reducer (task file "Why"). For the suite packet:

- report scoring-share per the AC definition, not just micro medians;
- if the micro gap persists, the obvious lever is restoring multi-
  accumulator FMA *inside the qjl32 block kernel* where lane order is
  the kernel's own contract (the strict scalar anchor stays bit-exact
  via the forced-scalar reference; the block kernel only needs the
  tolerance pair) — i.e., don't let F1's scalar-order choice in the
  per-candidate path leak into the batch kernel's inner loop.
