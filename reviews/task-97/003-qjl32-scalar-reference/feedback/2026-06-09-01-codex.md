## What is right

- **Strict anchor chosen correctly.** All three parity tests
  (`qjl32_scalar_matches_pre_slice_scorer_bits`,
  `qjl32_batch_with_blocks_and_tail_matches_pre_slice_scorer_bits`,
  `qjl32_block32_matches_pre_slice_scorer_bits`) target
  `score_ip_from_parts_scalar_reference` — the forced-scalar reference — with
  `f32::to_bits()` equality. This independently lands on the same split-gate
  contract the Task 93 packet 001 cycle settled (my packet 002 feedback seq 01
  asked for exactly this; the implementation already satisfies it). Width
  gates `<32` (scalar batch), `==32` (block), and `>32` (block + tail) are all
  covered.
- **Operation-order fidelity.** `scalar::score_scalar_tail` reproduces
  `score_ip_from_split_parts_scalar`'s exact structure: 8-dim aligned
  `decode_eight_3bit_aligned` u32 window, per-byte sign-lane LUT, interleaved
  `mse_sum`/`qjl_sum` accumulation in dim order, unaligned 3-bit tail decode,
  and the final `mse_sum + gamma * qjl_scale * qjl_sum` combine. I compared
  side-by-side with `prod.rs:698-732`; the order matches, which is what makes
  the strict anchor achievable by construction.
- **Counter attribution** follows the established wrapper pattern: validation
  (shape + meta + `MseLutQjl` gate) happens in `..._inner` before any counter
  records; whole blocks record under the backend-returned ISA, scalar batches
  and tails under `(surface, turboquant_qjl, scalar)`; fallback stubs return
  `Isa::Scalar`. The 1536 no-QJL lane is rejected with a mode-named error and
  has a test.
- No new `unsafe`; ISA files are safe stubs, so no `# Safety` surface yet.

## Finding 1 (REQUIRED before the next kernel packet): add the production-dispatch tolerance pair

The packet proves kernel ≡ forced-scalar anchor, but nothing yet bounds the
kernel against what production actually serves: `score_ip_from_parts`
dispatches NEON/AVX2 for QJL-active quantizers on every real host
(`prod.rs:520-531`). The approved split-gate contract (Task 93 packet 001
feedback seq 02, and my packet 002 feedback here) has two more legs:

1. the same fixtures compared against production-dispatched
   `score_ip_from_parts` under ADR-076 tolerance (`<= 4 ULP` or `1e-6`
   relative, whichever is larger); and
2. a one-shot host agreement check between the production per-candidate
   scorer and any production batch reference used later in measurement.

Without leg 1, a kernel could be bit-faithful to the scalar anchor while
drifting from the NEON/AVX2 production scores by more than recall-safe
tolerance, and the bench-level recall byte-equal gate would be the first
place it surfaces — too late and expensive to triage. The rabitq32 test
`production_dispatch_is_within_phase2_tolerance` (Task 93 branch) is a
direct template. This is a small test-only addition; I am not blocking the
scalar reference itself on it, but it must land before the first real ISA
kernel slice or AM registration cites parity.
