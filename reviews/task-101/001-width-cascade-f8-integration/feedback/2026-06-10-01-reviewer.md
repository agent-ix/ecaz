## Findings

### 1. (must-fix for closeout) Flush-width histogram evidence is missing — stale CLI binary

Task 101 scope item 2 explicitly requires using the flush-width histogram
(`record_flush_width`) to record predicted-vs-achieved coverage in the
packet evidence. No artifact in this packet or Task 94 packet 026 contains
`width_lt8/width_8_15/width_16_31/width_ge32` fields.

Root cause is provenance, not code: the histogram plumbing (extension SQL +
CLI emission, commit `fb7083c78`) **is** an ancestor of the measured head,
and the current `crates/ecaz-cli/src/commands/bench/mod.rs:452` prints the
width fields — but the `[block-kernel-counters]` lines in packet 026's
artifacts lack them, which means the `target/debug/ecaz` binary that drove
the suite predates `fb7083c78`. The extension itself was current (the
`scalar_candidates=0` DiskANN rows are only possible with the new dispatch),
so the counter/recall evidence stands, but the CLI was stale.

Action: rebuild the CLI at head, rerun at least one IVF and one DiskANN
latency cell, and cite the width-bucket lines in the next packet. This also
satisfies the "predicted-vs-achieved coverage" wording.

### 2. (cleanup) Dead code left behind by the migration

### 3. (note, scalar-host behavior) Padded-partial helpers do dead-lane work

`score_grouped_pq_partial` and `score_lut_no_qjl_4bit_partial` pad sub-32
tails to a full block and run the block kernel. On SIMD hosts this is the
point of the change. On **scalar-only hosts**, the block path degrades to
`score_block32_scalar`, which scores all 32 lanes — so a 1-candidate tail
now costs 32 scalar scorings where the old gen-1 tail cost 1. The counters
also attribute the dead-lane elapsed time to the live candidates
(candidate count = live lanes, elapsed = full padded block), which skews
per-candidate scalar timing on those hosts. Suggested narrow fix: in the
partial helpers, branch on `current_isa() == Isa::Scalar` and loop the
scalar tail directly. Not blocking — x86/ARM SIMD hosts are the production
targets — but worth landing before G4 evidence so the scalar comparison
rows stay honest.

regression (Task 101 AC5) is unassessable from this run. Not a code
