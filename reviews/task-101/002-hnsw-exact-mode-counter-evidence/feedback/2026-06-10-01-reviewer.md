## Answers to the three review questions

### 1. Is `checked_mse_code_bytes_no_qjl_4bit` the right narrow fix? Yes.

It is stronger than a counter-hygiene fix: the unchecked path called
`quantizer.mse_code_bytes_no_qjl_4bit` → `split_code_bytes`, which slices at
the expected MSE length and **panics on a short code** — inside a
PostgreSQL backend that is an abort path, not just a wrong error message.
Requiring `code.len() == mse_code_len(dim, bits)` exactly (rather than
`>=`) is also the right strictness: a too-long code would previously leave
a non-empty `qjl_packed` remainder guarded only by a `debug_assert`, i.e.
silently accepted in release builds. All three exact-mode helpers now share
one checked helper with a per-family error label; the downstream
`validate_code_shape`/`validate_mse_code_shape` calls remain as
defense-in-depth on the stripped payload. Correct layering.

### 2. Does the test prove the contract without overfitting? Yes.

`turboquant_no_qjl_exact_modes_shape_error_scores_nothing_and_record_no_counters`:

- Malforms candidate 33 — past the first 32-block boundary — so it would
  catch any future driver that interleaves validation with block scoring,
  which is exactly the failure mode the contract forbids.
- Asserts sentinel bit-patterns on every output slot and empty counter
  snapshots, for each of the three helpers independently, with counter
  resets between — no cross-contamination.
- Drives only the public `score_*_batch_for` surfaces; nothing in it
  assumes the width-cascade internals, so it survives driver refactors.

This matches and extends the Task 94 packet 012 pattern as AC3 requires.
With this, the prevalidation contract is now test-proven for all seven
families.
