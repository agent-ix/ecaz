## Accepted — the diagnostic infrastructure

`9de8b4fa2` does what the operator asked for and what feedback 003 on packet 001
specified:

  the series instead of losing it. That was the gap that made run 1 uncitable.
- `--reuse-fixture` is opt-in, rebuild stays the default, build-affecting

  `fixture_decision action=reuse …` in the node log.

  PGDATA with no rebuild.

Reusing the data and re-running the measurement is exactly the intended line.

difference is attributable to the stage-counter setting rather than to build
variance.

## P1 — "no production fix required" is broader than the evidence

The regression decision rests on the production A/B being flat. It is flat. But
per feedback on packet 002, the memory lives in **`TopTransactionContext`**
(8.32 GB of an 8.32 GB dump), which PostgreSQL resets at commit.

The production A/B ran 300 queries in autocommit — **one transaction per query**.
A transaction-lifetime accumulation is invisible under that protocol by
construction. The run does not test the retention; it resets it 300 times.

So the demonstrated claim is narrower than the one recorded:

- **Demonstrated:** the production read path does not retain memory across
  autocommit queries on one backend.
- **Recorded:** no production read-path fix is required.
- **Untested:** a production workload issuing many ANN queries inside **one
  explicit transaction**.

That gap matters because nobody has yet shown the leaking allocation is confined
to coverage-only code. The coverage helper calls into shared machinery —
`PhysicalGenerationScan::open`, `owner_scan_seed_candidates`, the remote
transport. Until the call site is identified (packet 002, P2), "benchmark-only
function" describes the *caller*, not the *allocation*.

Task 200's own framing makes this the live risk: long-lived pooled connections
serving thousands of queries. A batch job or an ETL path holding a transaction
open across many ANN queries is an ordinary production shape, not an exotic one.

## The test that closes it

On the retained fixture, one backend, sampler attached:

```
BEGIN;
  -- 300 ordinary ANN queries through the CustomScan, same as the latency arm
COMMIT;
```

- **Flat** → the closeout is earned, the conclusion holds as written, and the
  packet gains the evidence that actually supports it.
- **Grows** → this is a production defect, priority goes up, and Task 200's
  original premise was right for a reason nobody had identified.

It costs one run on a fixture that already exists, and it is the difference
between a closeout that survives review and one that rests on a protocol
artifact.
