## Why this does not close the task

The closeout reads the gate as "high-recall SPIRE is 17-27× flat → the scan path
is the wall → skip Phase B." But look at the **operating point**, not np96:

| scale | np8 latency vs flat | np8 recall |
|---|---:|---:|
| 10k | 3.5× | 0.9875 |
| 50k | 5.3× | **0.9938** |
| 100k | 4.3× | **0.9375** |

At np8 the latency is **already inside / at the edge of the 5-10× gate**, and at
≤50k recall is already ~0.99 *there*. The only real deficit is **100k np8
recall (0.9375)** — and since route containment == final recall, that is a
**routing-containment** deficit at the cheap operating point, not a scan-cost
ceiling. That is the precise thing Phase B's `nlists` lever exists to fix:
`nlists=128` at 100k means ~780 vectors/leaf, a coarse centroid proxy, so np8's 8
leaves miss truth. Finer leaves (316/512/1024) concentrate truth → more
containment at the *same* low nprobe → high recall without paying np96's scan.

So the gate, as executed, conflates **"the current `nlists=128`/b4 config fails"**
with **"no SPIRE config can pass,"** then uses that to skip the tuning step
(Phase B) that targets exactly the measured deficit. That's circular: the gate
should be judged on the *best achievable* SPIRE config, and Phase B is how you
get there. The np96 path being expensive is partly self-inflicted — you only
need np96 *because* coarse routing forces it, and b4's 4× replication inflates
the candidate volume the decomposition is measuring.

## What would make closeout airtight (the evidence I'm requesting for Phase B)

Not the full `nlists {316,512,1024} × boundary {0,1,2}` matrix — just the
decisive spot-check at 100k, the only scale that failed at the operating point:

1. Build 1-2 finer-`nlists` 100k cells (e.g. `nlists=1024`, `boundary` 1 and 0),
   isolated indexes.
2. Measure at np8 (and a couple of low nprobes): **route containment + recall +
   clean latency vs the flat floor + candidates/query**.
3. Decision:
   - If finer nlists lifts 100k np8 recall toward the ~0.99 that 50k already
     hits while staying ≈4-6× flat → **Phase B is viable; the wall is routing
     granularity, not the scan path** → run the rest of the factorial.
   - If recall stays low or latency blows past ~10× (e.g. finer leaves force
     many more probes) → **closeout is correct and now airtight**: the scan path
     genuinely binds, hand off to the IVF/SPIRE scan-efficiency line.

This is one short suite run, fully in the spirit of Task 123's own gate (cheap,
decisive). It converts "we think the scan path is the wall" into "we measured
that finer routing can't escape it" — which is the difference between a defensible
closeout and a premature one.
