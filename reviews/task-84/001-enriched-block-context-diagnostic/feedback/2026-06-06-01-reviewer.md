# Task 84 packet 001 — enriched block-context diagnostic

## Decision

**Accept.** The enriched diagnostic adds the right four fields
(`cap_block_ip`, `block_ip_margin_to_cap`, `route_rank`, `route_score`)
to attribute *why* a target block missed the cap, not just *by how
much*. Code change is observational only. The new distributions cleanly
shape the next mechanism slice.

## Key new evidence from enriched fields

### Score margin distribution (block_ip − cap_block_ip)

| margin bucket | misses | share | recoverable by what? |
| --- | ---: | ---: | --- |
| (-0.001, 0] | 3 | 3.7% | tiny — calibration noise |
| -0.005..-0.001 | 8 | 9.9% | calibration-recoverable |
| -0.01..-0.005 | 15 | 18.5% | calibration if small bias |
| < -0.01 | 55 | 67.9% | likely needs richer summary signal |

**Cumulative within 0.01 = 26 misses (32%).** This is the calibration-
recoverable share. The remaining 55 misses (68%) sit at score deficits
> 0.01 relative to the cap-threshold block, which is a meaningful gap
in IP-score space and probably needs better-discriminating summaries,
not just calibration.

### Route rank distribution

| route rank | misses | share | density (misses/route) |
| --- | ---: | ---: | ---: |
| top 8 | 28 | 34.6% | 3.5 |
| 9–24 | 24 | 29.6% | 1.5 |
| 25–48 | 19 | 23.5% | 0.79 |
| 49+ (out of 96) | 10 | 12.3% | 0.21 |

There's a strong density bias toward top routes — top-8 routes contain
**16.6× more misses per route** than routes 49+. That's expected: top
routes contain more rows total. But it tells you that **route-aware
signal is real**: routes don't just bulk-filter, they correlate with
where missed-truth-block-containing leaves cluster.

This is the data that re-opens the Task 79 packet 043 "route prior
no help" finding at 1M scale — see packet 002 review for that
follow-up.

## Code review

### Diagnostic-only — no behavior change

The 4 new JSONL fields come from data the diagnostic path already
collects:
- `cap_block_ip`: the IP score of the cap-threshold block (rank 1152).
- `block_ip_margin_to_cap`: arithmetic difference.
- `route_rank` / `route_score`: route-order and score for the loaded leaf.

All come from the existing snapshot machinery; no scan or selector
changes. Confirmed:
- AWS baseline reproduces Task 83 packet 001 numbers exactly (0.9832,
  9,213,846 cands, 84 missed truth rows, 81 selected-leaf, 3 routing).
- `cargo test -p ecaz-cli spire_pipeline` passes 20/20.

### Suite re-registers the snapshot SQL function

> "The suite includes a raw setup step that re-registers
> `ec_spire_index_scan_leaf_target_block_rank_snapshot(...)` with the
> enriched return columns for AWS instances whose SQL wrapper still
> has the older Task 83 shape."

This is the pgrx idempotency gap I flagged in the Task 80 review.
The raw setup step is a sensible workaround; it would be cleaner if
the `ecaz cloud install` path always re-installed extension SQL on
catalog drift. Worth filing as a small ecaz-cli ticket. Not blocking.

### Safety

- No new unsafe.
- No hot-path behavior change.
- Bounded diagnostic still bounded.

## What this packet enables (and what it doesn't)

Enables: the next slice can target either of two recovery mechanisms
with evidence, not guesswork:

1. **Score calibration** for the 26 within-0.01-margin misses.
2. **Route-aware block scoring** for the 28 top-8-route misses (overlap
   with #1 unknown).

Does not enable: a clean answer for the 55 below-0.01-margin misses,
which probably need richer per-block summary geometry. That's still
the ADR-074 territory the Task 81 reviews kept circling.

## Non-blocking notes

1. **The route-rank density bias (3.5 vs 0.21 misses/route)** is the
   strongest single signal in this packet. Worth recording as a
   headline finding — it justifies trying route-prior at 1M density
   even though Task 79 packet 043 rejected it at 100k.
2. **Score-margin and route-rank are likely correlated** — the
   enriched JSONL should enable a cross-tab analysis (route rank ×
   margin bucket). That would tell whether the 28 top-8-route misses
   are mostly the within-0.01-margin ones (in which case calibration
   alone might suffice) or whether they're independently distributed
   (in which case both mechanisms add).

## Verdict

Accept. Clean diagnostic extension that turns Task 83's
"misses are spread across rank deltas" finding into the more
actionable "26 are near-margin, 28 are top-route, 55 are
likely-format-bound". Sets up packet 002 (route-prior sweep) as a
direct test of the route-aware-signal hypothesis. Good baseline
work before any mechanism slice.
