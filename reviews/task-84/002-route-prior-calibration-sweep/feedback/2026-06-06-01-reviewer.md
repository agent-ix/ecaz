# Task 84 packet 002 — route-prior calibration sweep (pre-run review)

## Decision

**Accept the suite shape for AWS execution, with one important caveat
the request should acknowledge before the run lands.**

The hypothesis is sound: packet 001's enriched data showed 28/81
selected-leaf misses cluster in top-8 routes (3.5 misses/route vs 0.21
misses/route at 49+), which is the *kind* of orthogonal route signal
that could let route_prior_weight reorder summary scoring to recover
near-cap misses without changing the candidate budget.

The caveat: **this same axis was tested and rejected at local 100k in
Task 79 packet 043**, with weights 0.02, 0.05, 0.10 producing 0pp
recall improvement at any cap. The packet 002 request doesn't
acknowledge this history. The 1M-scale hypothesis (summary scores are
noisier at 1M leaf density, so route signal becomes additive) is
plausible but should be stated explicitly so the result is
interpretable either way.

## Suite shape is correct

- `global1152`, `nprobe=96`, `rerank_width=25`,
  `summary_radius_weight=0.25` — all match the retained Task 83 baseline.
- Route prior weights `0.02, 0.05, 0.10, 0.20`.
- 4 sweep points, plus implicit `0.0` baseline from packet 001's
  retained surface.

Acceptance criteria as stated:
- Recall > 0.9832 at candidates ≤ 9,213,846, OR
- Clearly better than Task 83 blanket-cap controls if cands rise.

That's a fair pass bar.

## Three predictions to record before the run

So packet 002's interpretation is bounded by what the data shows, not
post-hoc rationalized:

1. **If route prior shows 0pp recall improvement at any weight**:
   matches Task 79 packet 043's finding even at 1M density. The
   route_rank density bias from packet 001 is just an artifact of top
   routes containing more rows total, not orthogonal signal. Close
   the axis cleanly.
2. **If route prior shows +0.2-0.5pp recall at matched cands**: the
   1M density hypothesis is confirmed. This becomes a small operational
   policy with measurable cost; record as recovery option.
3. **If route prior shows recall improvement only at high weight
   (0.20) but distorts the summary score ordering enough to inflate
   cands**: that's the "blanket-cap in disguise" failure mode. Reject
   per the same logic Task 83 packet 002 used.

The 0.20 weight is high — at 20% of the score signal coming from route,
you're materially overlaying route on summary. If the sweet spot exists,
my prior is it's at 0.05-0.10. Including 0.20 is fine as a control to
see when the mechanism distorts.

## What's not being tested (yet)

The packet 001 evidence pointed at two recovery axes:
- Route-aware signal (this packet tests it)
- Score calibration for the 26 within-0.01-margin misses (untested)

Even if route prior succeeds, it likely addresses some subset of the
28 top-8-route misses, not all 81. A follow-up calibration slice will
still be needed for the 55 below-0.01-margin misses. Packet 002 isn't
designed to address those, and that's fine — but the closeout shouldn't
claim "1M recall recovered" if only the route-prior subset moves.

## Non-blocking notes

1. **Add Task 79 packet 043 to the comparator set** in the request /
   manifest. The historical context that route-prior gave 0pp at 100k
   makes the 1M result more interpretable, whether positive or
   negative.
2. **Include a cross-tab of route_rank × score_margin** in the closeout
   if route prior helps. If the recovered misses are predominantly

   useful but suggests pure score calibration would be cleaner.
3. **Don't run additional axes (e.g., new GUCs) inside this packet** —

## Verdict

Accept suite shape. Run it. The hypothesis is well-grounded in
packet 001's route-rank density evidence and the historical Task 79
packet 043 negative is honest to acknowledge. Three clear
interpretation buckets are recorded above for whichever direction
the result goes.

If route prior at 0.05-0.10 weight gets recall to ≥0.9850 at matched
cands, that's a clean partial win. If it stays at 0.9832 across all
weights, the 1M-density hypothesis is closed and Task 84 moves to
score calibration. Either outcome moves the design space forward.
