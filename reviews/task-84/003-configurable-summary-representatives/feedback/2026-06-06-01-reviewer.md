# Task 84 packet 003 — configurable summary representatives (k=1..8)

## Decision

**Accept with notes.** The code is correct and safe. k=2 path is byte-
identical (preserves all retained k=2 evidence), k=1 is trivial mean,
k>2 implements farthest-first seeding + single assignment/mean recompute
as documented. Dual GUC bounds checks present. No new unsafe. No scan-
path change. Test coverage has small gaps worth filling before the AWS
run interprets the k=3 result.

This is the build-time half of the multi-representative recovery path.
Default `representatives=2` keeps existing builds identical; new GUC
controls k for fresh builds only. Existing persisted indexes remain
self-describing through the V4 summary representative count.

## Code review

### k=2 default-preserving (clean)

Old `rabitq_leaf_block_representatives` renamed to
`rabitq_leaf_block_two_representatives` with logic unchanged. The new
`rabitq_leaf_block_k_representatives` wrapper explicitly delegates to
that function when `representative_count == 2`. **Default k=2 builds
are byte-identical** to pre-slice builds.

### k=1 path (clean)

Returns `vec![mean]` directly. Trivially correct.

### k>2 path (correct as documented)

- **Seeding**: farthest-first via `max_by` on minimum distance to
  existing seeds. True farthest-first, not random.
- **Assignment**: each row → closest seed via `min_by` on L2 distance.
- **Recompute**: each rep = mean of its assignments; unused seeds keep
  their seed value.
- **Single pass**: no convergence loop. Matches request's "one
  assignment/mean recompute pass" wording exactly.

The unused-seeds-keep-seed-value behavior (when a representative
captures no rows) is the right defensive choice — it preserves the
geometry instead of collapsing.

### GUC validation (dual-check, clean)

- GUC registration: `min=1, max=EC_SPIRE_MAX_LEAF_BLOCK_SUMMARY_REPRESENTATIVES (=8)`.
- Pre-summary validation: explicit `!(1..=8).contains()` check.
- Build-time validation: redundant but safe.

Three layers of defense. Matches existing GUC validation pattern.

### V4 format compatibility (clean)

No format-version bump. No new V5 struct. The V4 summary representative
count is already self-describing per the ADR-074 work. Scan path
unchanged — it already scores `max payload chunk` per summary.

### Safety (clean)

- No new unsafe blocks.
- `.expect()` calls limited to non-empty preconditions (e.g.,
  `block_vectors` pre-validated by `if rows.is_empty()` guard before
  call site).
- Error paths return `Result<_, String>` and route through
  `pgrx::error!`.

## Test coverage gaps (non-blocking but worth filling)

Tests cover k=2 (existing test updated) and k=3 (new test, 4-row block,
validates payload stride = `3 × encoder_output_len`). Missing:

1. **k=1 test**: trivial path, would catch a regression cheaply.
2. **k=8 test**: largest supported value. Useful to validate stride
   math at boundary.
3. **k > block_row_count edge case** (e.g., k=8 with a 2-row block):
   handled by duplicate-detection fallback that pushes mean clones —
   no panic — but currently untested. Worth a test since the bench
   geometry mixes block sizes near leaf boundaries.

None of these block landing the AWS k=3 experiment in packet 004; they
just close a coverage gap.

## What this enables for packet 004

The build-time GUC is the entry point. Packet 004 will build a fresh
k=3 index (separate from the retained k=2 surface — correct) and
measure recall at matched cap=1152. If the per-block discrimination
improvement from 3 reps vs 2 reps is real at 1M density, recall at
matched candidates should move above 0.9832.

The Task 79 packet 035 evidence at 100k is the relevant prior: k=3
at 100k broke the recall ceiling (0.9925 first hit). The question is
whether the same density argument that made 100k k=3 worthwhile
extends to 1M. Packet 001's enriched-context distribution suggests it
should — most misses are calibration-recoverable or near-margin, which
is the kind of error richer summary geometry directly targets.

## Non-blocking notes

1. **Add the three missing edge-case tests before merging to main**.
   k=1, k=8, k > block_row_count. Each is a few lines. Closes the
   coverage gap before the path goes hot.
2. **Document the unused-seed behavior** in a code comment — the
   "if a representative captures no rows, keep its seed" choice is
   subtle and worth a one-line explanation for future readers.
3. **Build cost at k=3 will be higher** than k=2 (O(k×n) per block
   for seeding + O(n) for assignment). Worth measuring in packet 004
   so a future operator knows the trade.

## Verdict

Accept with notes. Safe code, correct algorithm, no behavior change
on default k=2 path or scan side. The path is ready for the AWS k=3
experiment to test whether richer per-block summary geometry recovers
1M recall at matched cands.
