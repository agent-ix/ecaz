## This follows the repo's benchmark rule exactly

CLAUDE.md is explicit: all matrices run through `ecaz bench suite` with a
checked-in `SuiteConfig`, no packet-local sweepers, and "if `ecaz bench suite` is
missing a step type, profile, or option you need, extend the suite runner in
`ecaz-cli` instead of forking the workflow into a script. **Land that extension
as its own commit before using it in a packet.**"

That is precisely what this is: a standalone harness commit adding typed
`hot_cold_row_tier` and `hot_payload_attnums` to the step schema and to
`ecaz dev distann-multicluster`, ahead of the packet that consumes them. No raw
argument escape hatch. Worth saying plainly because the tempting shortcut here —
a packet-local script for two extra flags — is exactly what the rule exists to
prevent.

The option validation is typed and negative-tested: `hot_cold_row_tier` is
mutually exclusive with `covering_payload_attnums`, `hot_payload_attnums`
requires `hot_cold_row_tier`, and the test removes the flag from a valid JSON
config to prove the second rule fires.

## The fixture-reuse attestation is the important one

Attesting hot/cold reloptions on fixture reuse, so a row-heap control cannot be
silently reused as the candidate or vice versa, is the single highest-value guard
in this slice. Task 229 lost three of its four gates to exactly this class of
error — `materialization_correctness` enabled on cover steps and not on no-cover
steps — and no amount of care at analysis time recovers a contaminated arm. Doing
it as a fail-closed attestation rather than a runbook step is the right call.

Cold heap bytes now flow into per-owner and aggregate generation storage, and
the topology reader rejects incomplete cold-column triples rather than treating a
missing column as zero.

## Must land before the packet-004 matrix runs

Packet-002 closure fixed the TOAST attribution method: capture pre/post
`pg_statio_all_tables` deltas per isolated arm and query shape, covering **heap,
TOAST heap, and TOAST index** reads and hits, with shared-buffer hit ratio
derived from the same deltas.

The only `pg_statio_all_tables` use in the CLI today is
`distann_multicluster.rs:9632-9646`, which reads `heap_blks_read` and
`heap_blks_hit` only, as a `traversal_replica_cache` residency proxy. There is no
`toast_blks_read`/`hit` or `tidx_blks_read`/`hit` anywhere, and no per-arm,
per-query-shape pre/post delta capture.

That is a third of the decided method, for a different purpose. The missing
two-thirds are precisely the columns that attribute the mechanism — control arm
doing TOAST fetches, candidate arm not. Without them packet 004 can report that
hot/cold is faster or slower but cannot say why, which is the difference between
a decision and a number.

This is a harness capability and this is the harness commit, so it belongs in
this lane and under the same rule: land it as its own `ecaz-cli` commit before
the matrix runs. I am not blocking this checkpoint, which delivers what it
claims — but unlike the earlier ledger items, this one cannot be deferred to
"before packet 004 closes." A matrix run without it has to be run again.
