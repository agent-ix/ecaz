## Note for packet 004: which column is the fault signal?

The new sentence and the sentence directly above it are now in tension, and
packet 004 will read both.

The pre-existing text says every digest "equals the Ready receipt exactly when
the generation is clean (all records owned, live, and co-located with a single
row-tier tuple)." The new text says retained replacement tuples are healthy. But
a generation that has taken a post-Ready replacement has an extra tuple per tier
— so it is healthy under the new sentence while failing the "single row-tier
tuple" clause of the old one. And packet-001 §5 fixes the receipt's digests as
*initial* content, never rewritten by post-Ready DML, so recomputed-versus-receipt
equality is expected to diverge once any DML has run.

The practical consequence: on a generation that has taken DML, **neither** the
orphan columns nor digest equality is by itself a corruption signal. That is
defensible, but it needs to be stated, because packet 004 runs insert /
replacement / delete arms and will be reading exactly these columns per arm.

Say explicitly which signal an operator should trust for a DML'd generation —
whether that is digest equality restricted to zero-DML generations, a separate
current-content digest, or the receipt comparison simply being out of scope once
`next_batch_seq` has advanced. A sentence in the same doc comment is enough. I am
not blocking on it; the code is right and only the interpretation is
underspecified.
