## Format versioning

**Receipt V3** appends four fields to the V1 shape — hot and cold initial
content digests plus per-tier heap bytes — giving 303 + 32 + 32 + 8 + 8 = **383**
bytes, matching the declared constant and the extended bootstrap constraint. V1
(303) and Task 229 V2 (351) dispatch exactly and their bytes are untouched.
`validate()` rejects a receipt carrying both a payload sidecar and hot/cold
evidence.

Importantly, V3 extends **V1**, not V2 — which is right, since hot/cold and the
sidecar are mutually exclusive, so there is no shape that needs both.

**The legacy `row_tier_bytes` field stays meaningful.** For a V3 receipt it
becomes hot + cold via `checked_add`, so an existing consumer reading total
physical row storage still gets the true total, while the appended per-tier
fields preserve exact attribution. That is the right call — the alternative,
leaving it as the hot heap alone, would have silently under-reported storage to
every legacy reader.

**Manifest V4 and fingerprint V4** bind the layout-descriptor digest plus
roster-ordered global hot and cold initial content digests, with the existing
global logical row digest left alone as the source/handoff completeness
identity. The `validate()` match is a total five-tuple over
`(cover digest, cover content, layout digest, hot content, cold content)` with
exactly three legal shapes and a catch-all error, and each shape additionally
rejects participant receipts of the wrong kind. Partial state cannot validate.

`graph_record_version` in the manifest is now version-dependent, sourced from
`DISTANN_NODE_HOT_COLD_FORMAT_VERSION` rather than a literal — another instance
of the single-source rule I asked for in seq-03.

## Sealing

The seal path dispatches on a total five-tuple over `(layout, cold relation,
cold slot, cold io, node.cold_tid)`, so a half-configured hot/cold seal cannot
proceed. `fetch_hot_cold_row` takes both TIDs and the `vec_id`, and
`fetch_compact_tier` validates the internal `vec_id` echo per tier with a
tier-named error. Per-tier content digests fold NULL shape and canonical values
in ascending `vec_id` order, and the manifest requires equal graph/hot/cold
counts.

## Note

`DistannEpochManifestV2::version()` returns V4 when **any** of the three
hot/cold fields is set, while `validate()` requires all three or none. The
authoritative order saves it — `encode()` validates first, so a partial manifest
errors rather than emitting a version it cannot fill — but the two predicates
disagree about what "hot/cold" means, and a reader calling `version()` directly
on a partially built value gets an answer the type cannot honour. Make
`version()` use the same all-or-none shape.
