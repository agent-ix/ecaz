## What I checked hardest, and why it holds

**The graph record carries real TIDs, not placeholders.** This was my main
concern: `prepare_hot_cold_entries` builds every node with dummy locators
(`heap_tid` and `cold_tid` both `{block 0, offset 1}`) and calls
`encode_physical_v2` purely as a pre-flight validation whose result is
discarded. If either dummy survived to the real encode, every published record
would point at block 0.

It doesn't. `insert_prepared_entries` sets `entry.node.cold_tid` from the cold
insert's returned TID (`handoff.rs:958-961`) and `entry.node.heap_tid` from the
hot insert's (`handoff.rs:1003-1006`), both **before**
`encode_physical_version` at `handoff.rs:1007`. Both inserts reject an invalid
returned TID first. The discarded pre-flight encode is a legitimate early check —
it catches neighbor-count, padding, and missing-cold-locator faults before any
row is written — and it mirrors the legacy path's use of a placeholder
`heap_tid`.

The PG18 test then proves it end to end rather than by inspection:
`test_distann_hot_cold_handoff_v2_locator` joins graph → hot on
`h.ctid = g.row_tid AND h.vec_id = g.vec_id`, joins cold on `vec_id`, decodes the
graph record at the descriptor's version, and asserts `node.cold_tid` equals the
cold tuple's actual `ctid`. That is the right assertion; a placeholder or a
swapped locator fails it.

**Insert ordering matches the contract.** Cold first, then hot, then graph, all
inside the same owner transaction — packet-001 §3 and §5 exactly.

**The partition walk agrees with the legacy walk it forks from.** Both advance
`non_dropped_position` per live attribute and `value_position` only for non-NULL
values, both reject a NULL identity, and both compare the identity bytes against
`entry.source_identity`. The new one additionally routes by
`placement.physical_ordinal - 1` and fails closed on a missing placement, a zero
ordinal, an out-of-range ordinal, or a compact column with no binary I/O. The
post-loop width check (`non_dropped_position` and `value_position` against the
shape) is retained.

**Compact schema validation is real, not nominal.** `compact_tier_schema_matches`
pins the internal `vec_id` column exactly (attnum 1, name, type, typmod, no
collation, not dropped, not generated, `int8send`/`int8recv`) and then, for every
placement of that tier, pins the physical column's attnum against the frozen
ordinal, its name against `a_{source attnum}`, and its type, typmod, collation,
and send/receive identity against the frozen source attribute. Note the
deliberate asymmetry: the source attribute may be generated, the physical column
may not. The seq-07 test exercises that path — `a_5` carries a generated source
column's materialized value into the cold tier.

**Relation admission extends to the cold tier with the same guard set.** Owner,
persistence, RLS, no indexes, no non-`n` constraints, no user triggers, no
rewrite rules, and matching tablespace, plus, for hot/cold only,
`fillfactor=100`, exactly two `attstorage='p'` attributes, and a
`vec_id`-at-attnum-1 shape with every other column nullable.

The `contype <> 'n'` relaxation is necessary rather than a loosening: PG18
catalogues NOT NULL as `pg_constraint` rows, and `vec_id bigint NOT NULL`
creates one. The legacy path is unaffected because its own branch still rejects
any `attnotnull` column, so a legacy tier carrying a NOT NULL column is still
refused.

**Legacy and Task 229 paths are untouched**, and the packet re-ran
`test_distann_stage_batch_atomic_replay_and_directory` as a regression guard.
Graph encoding is now version-dispatched from the descriptor rather than
hard-coding V1.

## Notes

**A NULL indexed vector is not rejected at handoff.** `prepare_hot_cold_entries`
fails closed on a NULL identity but writes a NULL vector into the hot tuple, and
the compact hot relation permits it by construction — the admission SQL requires
every column past `vec_id` to be nullable. The failure would then surface at
query time as a dimension/finiteness error during expansion rather than at
write time.

This is inherited rather than introduced: `prepare_legacy_entries` has the
identical gap, checking only the identity. Worth closing at the write layer for
both paths, or stating explicitly that the indexed vector cannot be NULL by the
time a row reaches handoff. It matters more for hot/cold than for the legacy
row heap, because the whole point of the hot tier is that a single deform yields
a scoreable vector.

**`pg_test` has again reinstalled a debug `.so`** (`PGRX_BUILD_PROFILE="dev"` in
both seq-07 logs). Third occurrence. Reinstall the release build before any
packet-004 latency measurement.
