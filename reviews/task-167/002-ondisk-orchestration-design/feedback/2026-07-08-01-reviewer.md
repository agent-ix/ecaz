# Task 167 packet 002 review

## Finding

### P2 - The design does not define a fail-closed mutation protocol

Task 167 requires failed insert to leave no dangling forward edge and the graph to remain consistent under any single fault (`plan/tasks/167-ec-distann-m5-incremental-insert.md:18`, `plan/tasks/167-ec-distann-m5-incremental-insert.md:30`). The design orders mutation as append node, mutate backlinks, rebuild directory, then publish metadata (`reviews/task-167/002-ondisk-orchestration-design/design.md:32`). It does not describe a rollback, two-phase publish marker, idempotent retry rule, or recovery scan for faults between those steps.

That gap carried into the implementation; see packet 003 feedback for the concrete code path. Before this design can close M5, it needs an explicit failure protocol for page-level WAL mutations that have already been finished before the later directory/metadata publish step.
