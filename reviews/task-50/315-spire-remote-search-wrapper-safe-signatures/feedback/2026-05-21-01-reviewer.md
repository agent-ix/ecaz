# **BLOCK: same anti-pattern as 311 + introduces the unsound `checked_live_index_relation` helper**

**Block.** Two commits in this packet:

`905f9ba2` lifts nine `pub(crate)` wrappers from `unsafe fn` to safe `fn` while keeping raw `pg_sys::Relation` input. Same regression as 311.

`4dd64664` introduces the helper that enables this entire pattern:

```rust
fn checked_live_index_relation(index_relation: pg_sys::Relation) -> SpireLiveIndexRelation {
    // SAFETY: SQL diagnostic and AM wrapper entry points pass relation guards
    // that keep the SPIRE index relation live for the duration of the call.
    unsafe { live_index_relation(index_relation) }
}
```

This is a **safe `fn` taking raw `pg_sys::Relation` and dereferencing through `unsafe fn live_index_relation`** — identical shape to packet 014's `live_index_relation` (originally flagged anti-pattern A) and packet 236's reversal of round-1 finding #1. The SAFETY comment claim ("entry points pass relation guards") cannot be enforced — any caller in the crate can pass an arbitrary raw pointer.

**This is the third regression of anti-pattern A** in recent work:
1. Packet 236 (planner cost) — caught and reverted by 238
2. Packet 298 (debug_scan_opaque) — caught and reverted by 304
3. This batch (305 + 311-315 + the `checked_live_index_relation` helper)

The fix is the same template every time: pick Option A (`unsafe fn`) or Option B (take a guard reference). Recommend Option B uniformly across these helpers — diagnostic callers already have access to guards via `IndexRelationGuard::access_share`. Pass the guard reference, not the raw pointer.

Asking the coder to revert the `checked_live_index_relation` helper and fix the affected packets (305 + 311-315) by either:
1. Marking each function `unsafe fn` (Option A), OR
2. Threading `&SpireLiveIndexRelation` through call sites (Option B, preferred — matches 306-310's correct pattern in the same surface)

The inconsistency between 306-310 (sound) and 311-315 (unsound) within the same SPIRE diagnostic surface should be resolved in favor of the sound pattern.
