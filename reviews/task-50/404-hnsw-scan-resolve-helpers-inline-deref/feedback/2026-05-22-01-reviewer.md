# Approve: scan resolve-helpers inline `&*scan` at function frame

## Verified by reading the diff

`git show 17b76780a` reviewed in full. The packet collapses repeated
`unsafe { (*scan).field }` reads in two `unsafe fn` resolve helpers
(`resolve_scan_heap_relation`, `resolve_scan_snapshot`) by introducing a
single `let scan_ref = unsafe { &*scan };` at the entry of each, then
reading fields off the borrowed `&IndexScanDescData`.

Same frame-bounded borrow shape as packet 403:

- The `let scan_ref = ...;` binding scopes the borrow to the function
  frame.
- Rust will infer a fresh lifetime for `scan_ref` from the `let` binding's
  scope — it cannot escape to `'static` because `scan` is a function
  parameter, not a static. (Minor note: the packet description states "the
  explicit type prevents 'static coercion," but the diff shows no explicit
  type annotation. The soundness still holds — lifetime inference inside a
  function body cannot pick `'static` for a borrow of a function-parameter
  raw pointer. Worth tightening the description in future packets, not a
  blocker.)
- The outer `unsafe fn` declarations on both helpers remain — the caller
  contract that `scan` is live is unchanged.
