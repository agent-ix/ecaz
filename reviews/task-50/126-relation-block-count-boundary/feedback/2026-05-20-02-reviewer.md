# Re-review finding: relation_tuple_desc returns unbounded raw TupleDesc

Supersedes the soundness "✓" claim in
`feedback/2026-05-20-01-reviewer.md` for this packet (the storage/
relation.rs module touched in this packet series).

On re-reading `src/storage/relation.rs:86`:

```rust
pub(crate) fn relation_tuple_desc(relation: pg_sys::Relation) -> pg_sys::TupleDesc {
    // returns raw pointer borrowed from the relation
}
```

This is a *safe* function that returns a raw borrowed pointer with
no lifetime binding. Callers can stash the result past the relation's
lifetime. The function next to it (`relation_tuple_desc_copy`)
correctly returns `PgTupleDesc<'static>` (owns the copy); the
borrowed variant is the lifetime-leak.

**Fix**: take a `&IndexRelationGuard` / `&HeapRelationGuard` and
return `&'a TupleDesc` so the borrow checker bounds the descriptor
lifetime to the guard's lifetime. Callers that need the
unbounded shape today have a guard in scope; the change is mechanical.

`reviews/task-50/132-helper-soundness-audit/feedback/2026-05-20-01-reviewer.md`.
