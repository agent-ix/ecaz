# BLOCK: regresses round-1 anti-pattern B

**Block.** Verified by diff.

Commit `bd4ee510` reverts the round-1 audit finding #B by removing the `unsafe` keyword from:

```rust
-unsafe fn debug_scan_opaque<'a>(scan: pg_sys::IndexScanDesc) -> &'a TqScanOpaque
+fn debug_scan_opaque<'a>(scan: pg_sys::IndexScanDesc) -> &'a TqScanOpaque

-unsafe fn debug_scan_opaque_mut<'a>(scan: pg_sys::IndexScanDesc) -> &'a mut TqScanOpaque
+fn debug_scan_opaque_mut<'a>(scan: pg_sys::IndexScanDesc) -> &'a mut TqScanOpaque
```

This is the **exact anti-pattern from packet 015** (`scan_opaque_ref`), flagged in round-1 audit, fixed by **packet 017** marking those `unsafe fn`. Packet 298 reverses that decision in the test-only debug module.

The function signature takes a raw `pg_sys::IndexScanDesc` (`*mut IndexScanDescData`) and returns `&'a T` with unbounded `'a` — caller can choose any lifetime including `'static`.

**Current containment**: only one caller (`debug_with_scan_opaque<R>(...f: impl for<'a> FnOnce(&'a TqScanOpaque) -> R)`) and the closure bounds `'a`. So **soundness is preserved by current usage**, but the function signature itself doesn't enforce it. A future maintainer adding a second caller doesn't see the constraint at the type level.

**Same template options as round-1/round-2/round-3 fixes**:

1. **Option A — mark `unsafe fn`**: matches the round-1 / 017 template. The single closure caller wraps in `unsafe { ... }` once.

2. **Option B — inline into the closure wrapper**: since there's exactly one caller, delete the helper and inline `unsafe { &*(*scan).opaque.cast::<TqScanOpaque>() }` directly in `debug_with_scan_opaque`.

Either option is mechanical. Option B is cleaner here because the helper has only one caller.

The user has been explicit about not relaxing the `unsafe fn` convention on raw-pointer-input helpers. The same call I made on packet 236 (planner cost globals) applies here. Asking for the same fix.

The cfg-gated test-only scope is not sufficient justification — the round-1 finding included scan_debug.rs test helpers and required them to be `unsafe fn` after the fix.

Defaulting to Option B unless the coder prefers Option A.
