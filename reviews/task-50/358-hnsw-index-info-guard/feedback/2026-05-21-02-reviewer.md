## Follow-up: `build_parallel.rs:2797` was left behind

`rg 'BuildIndexInfo' src/am/ec_hnsw/` shows a second HNSW site the guard does
not yet cover:

```
src/am/ec_hnsw/build_parallel.rs:2797:
    let index_info = unsafe { pg_sys::BuildIndexInfo(index_relation) };
src/am/ec_hnsw/build_parallel.rs:2799-2801:
    unsafe { (*index_info).ii_Concurrent = (*shared).is_concurrent; }
```

Two differences from the source.rs sites that explain why the guard could not
be dropped in verbatim, and that the next HNSW slice should resolve:

1. The build_parallel worker mutates `ii_Concurrent` on the returned pointer
   before passing it to `table_index_build_scan`. The current guard exposes
   `as_ptr()` but no `as_mut(&mut self) -> &mut pg_sys::IndexInfo` accessor,
   so a verbatim swap would require an extra `unsafe { *guard.as_ptr() = ...
   }`. A small `as_mut` accessor (returning `&mut pg_sys::IndexInfo` derived
   from `NonNull::as_mut`) would remove that block at the call site as well.
2. The build_parallel site never calls `pfree` — the `IndexInfo` rides the
   worker's PG memory context lifetime. The current `IndexInfoGuard::Drop`
   unconditionally pfrees, so reusing it here would double-free at worker
   shutdown if PG already reaped the allocation, **or** prematurely free
   before `table_index_build_scan` finishes if the guard's scope ends earlier
   than the worker context. Neither is acceptable.

Concretely the next HNSW packet (per the redirect feedback on 392/02) should:

- Move `IndexInfoGuard` (or a parallel `BorrowedIndexInfo` newtype) into a
  shared module so build_parallel can consume it without a copy-paste.
- Decide explicitly whether the guard owns `pfree` or borrows the worker
  memory context. The cleanest split is two types: `IndexInfoGuard` (owns
  pfree, used by source.rs) and `IndexInfoView<'a>` (borrows, no Drop, used
  by build_parallel). Both wrap `NonNull<pg_sys::IndexInfo>` and expose the
  same `as_ptr` / `as_mut` accessors.
- Net delta on `build_parallel.rs`: at least the `BuildIndexInfo` and
  `(*index_info).ii_Concurrent` unsafe blocks become safe (-2 minimum).
- This stays HNSW-only — both files are under `src/am/ec_hnsw/`.

The DiskANN equivalent at `src/am/ec_diskann/routine.rs:737-755` is **out of
scope** for the current rotation (HNSW-only directive) and should not be
bundled into the HNSW slice.
