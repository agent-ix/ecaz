## `PgLockedDsmInsertStateCell` migration — soundness

`git show ab09c2a07` diff inspected. The migration:

- Adds `as_atomic_ref(&self) -> PgAtomicU32Ref<'_>` (one
  `unsafe { PgAtomicU32Ref::from_raw(self.0) }`).
- Removes three internal `unsafe` blocks from the three trait impls
  (`load_acquire`, `store_release`, `compare_exchange_acqrel_acquire`).
- Net: -2 unsafe blocks in `build_parallel.rs` (3 removed, 1 added in
  the helper).

Lifetime correctness: `PgAtomicU32Ref<'_>` returned from
`as_atomic_ref(&self)` borrows from `&self`. The wrapper never escapes
the method body (each call site is a single expression like
`self.as_atomic_ref().load_acquire()`), so the borrow is trivially
shorter than the cell, and the cell's lifetime is the production
contract this slice does not change. Sound.

Borrow-pattern note: the helper takes `&self` and returns
`PgAtomicU32Ref<'_>`. The wrapper carries
`PhantomData<&'a pg_atomic_uint32>`, so `'a` ties to the cell's `&self`,
not to the underlying DSM segment. The actual DSM-segment lifetime
invariant is on **`PgLockedDsmInsertStateCell` itself** — the cell
already encodes the "live DSM node array for build duration"
invariant by being constructed via `node_insert_state_cell` in
`build_parallel.rs:282-288`. The new wrapper does not weaken that
invariant; it lifts the ergonomics. Sound.

## `src/am/common/dsm.rs` — soundness pass

Read all 156 lines. Findings:

- `PgAtomicU32Ref::from_raw` (`unsafe fn`, 1 unsafe block in
  constructor) — invariant comment names DSM-segment outlives `'a`
  and segment-owner-initialized. Correct.
- `load_acquire` / `store_release` /
  `compare_exchange_acqrel_acquire` — three `unsafe { pg_sys::... }`
  blocks delegating to PG's atomic primitives. Each method's SAFETY
  comment correctly chains to `from_raw`'s invariant ("see
  `from_raw` — the backing field is live"). Acceptable, though the
  three SAFETY comments are all the same — a single module-level
  comment plus method-level `// SAFETY: see from_raw` would be tighter
  and is the convention elsewhere in `src/storage/`.
- `unsafe impl Send for PgAtomicU32Ref<'_>` /
  `unsafe impl Sync for PgAtomicU32Ref<'_>` — justified: PG atomics
  are explicitly cross-thread-safe through their primitives, and the
  wrapper only exposes those primitives. Send/Sync are sound.
- `SpinLockGuard::acquire` — invariant comment correctly names
  `SpinLockInit` initialization + `'a` borrow lifetime. RAII Drop
  calls `SpinLockRelease`. The acquire/Drop pair is correctly
  symmetric — `acquire` returns `Self`, and the only `Drop` runs
  exactly once because `SpinLockGuard` has no `Copy`. Good.
  - Note: `SpinLockGuard` is **not** `Send`. That is correct for a
    PG spinlock — spinlocks are not designed to be released by a
    different worker than the acquirer. No explicit `!Send` needed
    because `*mut slock_t` is `!Send` by default; the wrapper
    inherits that. Sound.
- `ConditionVariableRef::from_raw` / `signal()` — same pattern as
  `PgAtomicU32Ref`. `unsafe impl Send + Sync` are correct: PG
  condvar signal is thread-safe by PG contract.
- `spinlock_init` / `condition_variable_init` (`unsafe fn`) — each
  with a single `unsafe { pg_sys::... }` block. Invariants name
  exclusive ownership of uninitialized memory. Standard "PG primitive
  in-place init" pattern. Sound.

**No unsoundness found.** The module is a clean P8 opening.

## Count-metric integrity check

The closeout records the +9 unsafe blocks in `dsm.rs` as a
"category shift" per plan §P8 — DSM atomics moved into a typed
wrapper module rather than open-coded at HNSW call sites. This is
the intended disposition; it is **not** a counting game because:

1. Each of the 9 dsm.rs blocks wraps a single PG primitive
   (`pg_atomic_*`, `SpinLock*`, `ConditionVariable*`,
   `PageInit` is not in this module). One primitive ≈ one block.
   No multi-line compound unsafe was preserved by being moved into
   the wrapper.
2. Each wrapper is reusable. The plan §P8 anticipates SPIRE / IVF
   parallel-build consuming the same `PgAtomicU32Ref` /
   `SpinLockGuard`. Even if those reuses don't happen on this
   branch (per the next-rotation scope lock), the 9 blocks
   amortize across HNSW alone: every existing or future
   `pg_atomic_*` call site in HNSW now flows through the wrapper.

Caveat: I would still surface a **`src/` total** snapshot, not just
the HNSW subsystem subtotal, in the next closeout. The +9 dsm.rs
blocks are legitimate today; in the next P8 slice they will
multiply (typed shared-header views, ShmToc wrappers, etc.).
Without a `src/` total dashboard line, the agent can't see if
`common/` accretion outpaces HNSW reduction. The HNSW-only metric
remains the primary §Exit gate, but a parallel `src/` total line
would catch metric drift early.

## SAFETY comment style

Minor nit, non-blocking: three of the four operations on
`PgAtomicU32Ref` carry separate SAFETY comments. They all say the
same thing. The pattern most of the codebase uses (see
`src/storage/locked_buffer.rs`) is **one module-level invariant
comment** plus terse `// SAFETY: see from_raw` per-call. Tightening
the dsm.rs comments to that style is a 3-line cleanup the next P8
slice can absorb.
