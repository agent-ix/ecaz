# Block: 4th regression of anti-pattern B (unbounded lifetime from raw pointer)

## Decision

Block. The packet's intent is good and the call-site cleanup is correct,
but the new helper `shared_header_ref` reintroduces the **exact anti-
pattern** that has been blocked three times before this work-day:

```rust
fn shared_header_ref<'a>(
    shared: *mut EcHnswParallelBuildSharedHeader,
) -> &'a EcHnswParallelBuildSharedHeader {
    let header = ptr::NonNull::new(shared)
        .unwrap_or_else(|| pgrx::error!("..."));
    // SAFETY: see function-level contract above; ...
    unsafe { header.as_ref() }
}
```

This is a **safe `fn` taking a raw pointer that returns `&'a T` with
unbounded `'a`** — the caller can choose any lifetime including
`'static`. The Rust nomicon's "unbounded lifetimes" rule applies. The
NonNull null-check catches null but not use-after-free, not wrong
pointer, not stale state.

## Why this is still anti-pattern B even with NonNull

The `NonNull::new(...).unwrap_or_else(...)` step *does* eliminate the
null-pointer failure mode. That's a real improvement over a bare
raw-pointer cast. But it doesn't fix the unbounded-lifetime problem:

- A future caller can write `let h: &'static EcHnswParallelBuildSharedHeader = shared_header_ref(ptr);`
- Compiler accepts it (since `'a` is free)
- Helper has no input borrow to bound `'a` to
- Header gets freed by the leader; caller still has a `'static` reference → use-after-free

Current callers (`parallel_build_worker_main` /
`parallel_graph_build_worker_main`) don't trigger this because they
use the returned reference inside the same function frame. But the
**signature** doesn't enforce that. A future maintainer or a refactor
that moves the helper output into a struct can hit UAF without any
compile-time signal.

## Fix template (same as the prior three regressions)

Two options:

**Option A — `unsafe fn`** (matches packet 017 / 304's first-choice):

```rust
unsafe fn shared_header_ref<'a>(
    shared: *mut EcHnswParallelBuildSharedHeader,
) -> &'a EcHnswParallelBuildSharedHeader {
    let header = ptr::NonNull::new(shared)
        .unwrap_or_else(|| pgrx::error!("..."));
    // SAFETY: caller asserts the shared header outlives 'a.
    unsafe { header.as_ref() }
}
```

Two callers wrap each invocation in `unsafe { shared_header_ref(shared) }`
with a context-specific SAFETY comment (e.g., "leader keeps the
header live until all workers finish"). Block count cost: +2 at
call sites; the helper remains.

**Option B — inline into the two call sites** (matches packet 304's
final fix — preferred when caller count is ≤2):

```rust
// In parallel_build_worker_main and parallel_graph_build_worker_main:
let header = unsafe {
    // SAFETY: leader keeps the header live until all workers finish.
    ptr::NonNull::new(shared)
        .unwrap_or_else(|| pgrx::error!("..."))
        .as_ref()
};
let is_concurrent = header.is_concurrent;
// ... rest of the function uses `header` ...
```

The helper goes away; each worker function has its own one-line
acknowledgment. Block count cost: +2 in build_parallel.rs (one per
worker entry), but each is bounded to the function frame
syntactically. Net `-3` instead of `-5`.

**Recommended: Option B.** With exactly two callers in the same file,
inlining the unsafe acknowledgment is cleaner than maintaining a
helper that has the wrong contract shape. Packet 304 took this path
and it worked.

## Approve only the unaffected parts

The five caller-side `(*shared).field` deletions in
`parallel_build_worker_main` and `parallel_graph_build_worker_main` are
correct in concept — `header.field` reads after a sound borrow are
exactly the right shape. The only thing that needs fixing is **how**
`header` is obtained.

After Option B is applied, the −5 reduction in `build_parallel.rs` is
preserved (the call sites' deletions stand; the helper just goes away
and is replaced by two `let header = unsafe { ... };` statements at
the function entries).

## What's not blocking

Approve the diagnostic clarity in the request.md (which correctly
identifies which residual unsafes are irreducible PG-API boundaries).
Approve the call-site rewrite from `(*shared).field` to `header.field`
in concept. Approve the `participant_count` hoist removing the
downstream unnecessary unsafe wrapper.

Block only the helper's signature. Coder fix should be one small
follow-on packet that either marks `unsafe fn` or inlines the two
acknowledgments.
