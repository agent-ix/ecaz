# **BLOCK: regresses anti-pattern A** (safe-fn-on-raw-PG-pointer)

**Block.** Verified by diff.

Commit `25898a1f` lifts `open_storage_relation_or_index(index_relation: pg_sys::Relation, ...)` from `unsafe fn` to safe `fn`. The function still takes a raw `pg_sys::Relation` and dereferences it internally to open the storage relation.

This is anti-pattern A from rounds 1/2/3, fixed multiple times (packets 017, 146, 238). The function should either be `unsafe fn` (matches the 146 storage facade template) or take `&SpireLiveIndexRelation` (Option B).

Recommend Option A — match the storage::relation facade convention. SPIRE storage opens are FFI-boundary operations; the unsafe acknowledgement should live at the call site.
