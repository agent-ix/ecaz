# Re-review finding: scan_output safe fns dereference raw IndexScanDesc

Supersedes the soundness "✓" claim in
`feedback/2026-05-20-01-reviewer.md` for this packet.

On re-reading `src/am/common/scan_output.rs`:

```rust
pub(crate) fn set_scan_heap_tid(scan: pg_sys::IndexScanDesc, heap_tid: ItemPointer)
pub(crate) fn set_scan_orderby_score(scan: pg_sys::IndexScanDesc, score: f64)
pub(crate) fn clear_scan_orderby_output(scan: pg_sys::IndexScanDesc)
```

`pg_sys::IndexScanDesc` is a raw pointer. These three are *safe*
functions that dereference it. Same anti-pattern packet 017 was
created to fix: safe-fn-on-raw-pointer-input, where the SAFETY
contract lives in the comment but the borrow checker doesn't carry
it.

The null check guards against null but not use-after-free or wrong
pointer.

**Fix**: either accept `&IndexScanGuard` (or a fresh
`IndexScanDescView<'a>` with `unsafe fn new`) so the input lifetime
carries the contract, or mark all three `unsafe fn` so callers
acknowledge it.
