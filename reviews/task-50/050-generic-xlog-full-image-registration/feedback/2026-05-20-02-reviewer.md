# Re-review finding: GenericXLogRegisterBuffer return value ignored

Lower-severity follow-up to `feedback/2026-05-20-01-reviewer.md`.

On re-reading `src/storage/wal.rs`:

```rust
pg_sys::GenericXLogRegisterBuffer(...);  // return value not checked
```

PG documents `GenericXLogRegisterBuffer` as returning the registered
page-image pointer for callers to mutate. With the
`GENERIC_XLOG_FULL_IMAGE` flag the failure case is rare, but if PG
ever returns NULL the downstream mutation operates on a stale page.

**Fix**: check the return value, error on NULL, or add a SAFETY note
citing the PG docs explaining why ignoring is sound for this flag.

Not a blocker; just an honesty fix so future readers don't assume
the ignored return is intentional.
