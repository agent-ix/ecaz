## The one remaining partial fix

Round-1 findings #4 and #5 had two halves:

1. **constructor `unsafe fn`** — closed by commit `7920c133`. ✓
2. **struct `<'rel,'snap>` / `<'rel>` PhantomData lifetimes** — not
   yet added. The structs still look like:

   ```rust
   pub(crate) struct IndexScanGuard {
       scan: pg_sys::IndexScanDesc,
       // no PhantomData<&'rel HeapRelationGuard> etc.
   }
   pub(crate) struct TupleTableSlotGuard {
       slot: *mut pg_sys::TupleTableSlot,
       // no PhantomData<&'rel RelationGuard>
   }
   ```

   Today every caller holds all three guards in the same stack
   frame, so the partial fix is sound in practice. The architectural
   risk is that the lifetime parameters are what makes the claim
   defensible by *construction* — without them, the claim relies on
   caller discipline at every future call site.
