# Approve: `shm_toc_lookup_required<T>` typed FFI helper

## Verified by reading the diff

`git show be3089a17` reviewed in full. The packet adds one module-private
helper and converts 8 worker-side TOC lookups to it.

```rust
fn shm_toc_lookup_required<T>(toc: *mut pg_sys::shm_toc, key: u64) -> *mut T {
    // SAFETY: see function-level contract; the TOC entry exists, PG ereports
    // if missing, and the DSM segment outlives the returned pointer's use.
    unsafe { pg_sys::shm_toc_lookup(toc, key, false) }.cast::<T>()
}
```

## Why this is NOT anti-pattern B

The recurring anti-pattern B is "safe `fn` taking `*mut T` and returning
`&'a T` with unbounded `'a`." This helper returns `*mut T`, **not** a
borrowed reference. The caller still gets a raw pointer and must deref under
their own `unsafe`. The helper just consolidates:

1. The FFI call to `shm_toc_lookup(toc, key, false)`.
2. The `.cast::<T>()` from `*mut c_void` to the typed pointer.

Both of those are already safe Rust operations *except* for the FFI call
itself. No lifetime laundering, no spurious `&` materialization. This is
the right shape for a typed FFI wrapper. ✓

## Soundness check

- `noerror=false` argument: PG ereports (longjmps) if the key is missing,
  so the returned pointer is non-null on successful return. The helper's
  doc comment is explicit about this. ✓
- Caller-chosen `T`: the helper has no way to verify `T` matches what the
  leader installed. This is the same trust model as the prior
  `pg_sys::shm_toc_lookup(...).cast::<T>()` pattern at each call site —
  unchanged. The leader/worker pair must agree on the type via the
  `PARALLEL_KEY_*` constants, which is already a hand-coded protocol. ✓
- Generic over `T`: nothing in `T` is constrained, so the helper
  compiles into 8 monomorphized copies (one per concrete type at the
  call sites). Each is a single instruction after inlining — no
  performance concern. ✓
