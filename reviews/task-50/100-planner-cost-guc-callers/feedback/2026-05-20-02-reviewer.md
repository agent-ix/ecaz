# Re-review finding: planner cost / cpu-cost readers exposed as safe fn

Supersedes the soundness "✓" claim in
`feedback/2026-05-20-01-reviewer.md` for this packet.

On re-reading `src/am/common/cost.rs`:

```rust
pub(crate) fn current_planner_cost_constants() -> PlannerCostConstants {
    // reads pg_sys::random_page_cost, pg_sys::seq_page_cost,
    // pg_sys::cpu_tuple_cost, etc.
}

pub(crate) fn current_cpu_tuple_cost() -> f64 {
    // reads pg_sys::cpu_tuple_cost
}
```

Both are *safe* functions that read backend-local PG globals. Those
globals are only well-defined during planner-callback execution. A
safe caller outside that context — a background maintenance thread,
a unit test, a future module that reuses these helpers — gets stale
or garbage data and bypasses what the SAFETY comment claims.

**Fix options**:
1. Mark `unsafe fn` and require callers to wrap and acknowledge.
2. Take a `&PlannerCallbackContext` token whose constructor is
   `unsafe fn new` and is only called from inside the AM callback
   wrapper.

See the consolidated audit at
`reviews/task-50/132-helper-soundness-audit/feedback/2026-05-20-01-reviewer.md`.
