## Slice A — `train_spherical_kmeans` parallelism

**Implementation choice (NOTE, not BLOCK):** the parallel implementation
parallelises (a) per-sample `normalize_vector` and (b) the per-iteration
nearest-centroid scan, but keeps the sums/counts accumulation **sequential
in source order** (`training.rs:200-211` in the new code). The coder's note
calls this out explicitly: byte-equality vs the scalar baseline is preserved
by avoiding a partial-sum reduction across threads.

This is a defensible tradeoff. Assignment is `O(samples * nlists *
dimensions)` and accumulation is `O(samples * dimensions)`; at the shapes
SPIRE recursion and IVF actually hit, assignment dominates by orders of
magnitude, so parallelising assignment alone should capture most of the
win. The task plan's recommendation to use chunked `.reduce_with` was an
allowed alternative for keeping determinism while parallelising
accumulation — it would have produced a different deterministic baseline.
The coder picked the strictly-byte-equal path against the existing scalar
reference, which is the safer choice for slice A.

**Required for Slice D follow-up:** if the Slice D measurement packet
shows the accumulation step on the wall-time profile at SPIRE's recursion
shapes (e.g. high `nlists`, modest sample count per level), the team
should land a follow-up that switches to chunked reduction with a fresh
deterministic baseline. Until then, the current shape is fine.

**Tests:** `spherical_kmeans_parallel_matches_scalar_byte_for_byte` covers
the required 16 combinations (4 seeds × 4 shapes including `(17,3,2,4)`,
`(31,5,4,6)`, `(40,8,7,5)`, `(24,13,9,7)`). Byte-equality is asserted via
`PartialEq` on `SphericalKMeansModel`, which compares centroid `Vec<f32>`
contents — that is the right granularity.

## Slice C — `assign_vectors_to_centroids` fan-out

`training.rs:252-261`:

```rust
let assignments = sources
    .par_iter()
    .map(|source| assign_vector_to_centroid(error_label, source, model))
    .collect::<Vec<_>>();
assignments.into_iter().collect()
```

Determinism: `par_iter().collect::<Vec<_>>()` preserves source order in
the materialised `Vec<Result<_, _>>`, then `into_iter().collect()` via
`Result::FromIterator` returns the first `Err` in iteration order —
which is the lowest source index. `batch_assignment_returns_lowest_error_index`
verifies this with a `[valid, too_short, non_finite]` arrangement,
asserting the `too_short` (index 1) error wins over `non_finite` (index 2).
Correct.

Minor: every source is still evaluated by the parallel map before
short-circuiting. Not a correctness issue (no panic, no UB), and the
spec doesn't require early cancellation. Fine as-is.
