## Correctness — verified, PASS

1. **int16 LUT (Task 125).** `build_prepared_query_lut_i16` (prod.rs) quantizes
   the f32 LUT with `scale = max_abs / i16::MAX`, `round().clamp(i16::MIN,i16::MAX)`,
   zero-guard when `max_abs <= EPSILON`. Scoring accumulates `i16 as i32`
   (max |sum| ≈ 1536·32767 ≈ 50M ≪ i32::MAX — no overflow at realistic dims) and
   applies `lut_scale` once. NEON widens `i16→i32` via `vmovl_s16` before
   `vaddq_s32`, matching scalar. The exactness test was **honestly** relaxed
   (`explicit_lut_..._matches` → `..._tracks_..._with_int16_lut`, 1e-6 → 5e-5) —
   the int16 path is an approximation of the f32 dot product, recall-neutral by
   measurement (see below), not bit-exact. Good.

2. **Exact suffix-bound pruning (Task 127).** `build_lut_suffix_max_i16` builds a
   reverse cumulative max of per-dim max nibble values; the cutoff
   `partial + suffix_max[d+1] < min_ip_to_keep` is a valid upper bound, so
   pruning is exact and cannot drop a true top-k candidate. **Exactness w.r.t.
   the ranked score is confirmed:** `centroid_ip_by_list` is populated only
   `if quantizer.rabitq_residual()` (scan.rs:1502); TQ no-QJL is non-residual →
   `centroid_ip == 0` → the ranked score `-(score + 0)` is pure ip-space, so the
   ip-space cutoff is exact. The bounded scorer is gated to exactly this lane
   (`TurboQuantNoQjl4BitLut` + `TurboQuant` profile + `current_isa()==Neon`).
   Bit-identical recall at every scale (below) is the empirical backstop.
   - **Recommend (locks the invariant):** add a `debug_assert!`/guard that the
     bounded path is only taken when `centroid_ip == 0` (non-residual). Today the
     safety rests on an implicit gate; if a residual TQ variant ever reuses this
     dispatch, ip-space pruning would silently over-prune. (Raised by the
     integration audit; resolved-but-fragile.)

3. **Gamma (Tasks 128/129).** Gamma dropped **only** on the no-QJL path
   (`CandidateMeta::None`, quantizer.rs:775/962); QJL still parses+applies gamma
   (`CandidateMeta::Gamma`, :824/1020) and the validation now additionally
   requires `gammas.len()==out_scores.len()` (:792/979). Scalar min-bound arm
   (:499) matches only `TurboQuantNoQjl4BitLut`; QJL falls through to the
   gamma-applying scorer. No path scores a QJL payload without gamma; a "QJL +
   no gamma" combination fails **closed** (error), not silent. PASS.

4. **Buffer reuse / aliasing (Task 128).** Vec wrappers clear+resize both
   `out_scores` and `out_kept`; the `_negated_into` slice variants validate
   length and the width-cascade scorer overwrites every element, so in-place
   negate touches only fresh scores. `process_dense_posting_block` guards
   `keep_count != 0 && keep_count != block.len()`, so indexing `kept`/`scores`
   cannot OOB and pruned slots (sentinel `0.0`) are never read. No aliasing/OOB.

5. **Unsafe.** No new `unsafe fn`. Two new `unsafe {}` blocks (scan.rs:2146,2166)
   deref a **pre-existing** raw `*mut IvfDensePostingBlockScratch` — not
   anti-pattern B (no `fn(ptr)->&'a T` fabrication), no missing `# Safety`.
   NIT: add a one-line `// SAFETY:` at the two new derefs.

6. **Scope constraint honored.** No new `StorageFormat`, reloption, payload tag,
   or rerank mode. int16 LUT + `lut_scale` are in-memory query-prep only; on-disk
   `mse_packed` unchanged; `uses_score_bound_pruning` is a scan-time flag. Meets
   the "optimize the EXISTING 4-bit no-QJL scorer only" hard constraint of all
   five specs.

## Attribution — the headline finding

The packet's own four A/B suites (good — this follows the "A/B per change" rule)
show that **only Task 125 moved the bar**:

| suite | kernel (10k/50k/100k, ms) | latency mean (10k/50k/100k) | recall |
|---|---|---|---|
| baseline | 45.45 / 75.37 / 75.17 | 1.26 / 2.55 / 3.91 | 0.9734 / 0.9521 / 0.8969 |
| candidate-final (BLOCK_WIDTH 64 + T128/129) | 45.27 / 75.74 / 74.26 | 1.20 / 2.55 / 3.85 | identical |
| candidate-t127-sparse (+ bound pruning) | 46.24 / 76.96 / 74.88 | 1.22 / 2.58 / 3.86 | identical |
| **candidate-int16-lut (Task 125)** | **23.92 / 41.57 / 38.90** | **0.88 / 1.88 / 2.73** | identical |

- **Task 125 (int16 LUT): ~2× kernel speedup, ~30% latency, recall-neutral,
  storage-neutral.** This directly confirms Task 125's premise (LUT L2 traffic is
  the bottleneck; halving LUT bytes ≈ halves kernel time). Genuine win.
- **Tasks 126 (BLOCK_WIDTH 64), 127 (bound pruning), 128, 129: measurably
  neutral** (127 is slightly *negative* on kernel at 10k). They preserve recall
  but do not deliver the ns/candidate improvement their specs gate on.
- **Ask:** state this plainly in the packet. `request.md`'s headline compares
  "int16 vs prior sparse t127," which obscures that 126–129 were inert. The
  honest closeout is "125 shipped a 2× kernel win; 126–129 recall-safe but
  no measurable speedup on IVF/DBPedia/nprobe32." Task 127 in particular added a
  whole NEON bounded-scorer + 2 unsafe derefs for **zero** measured benefit —
  justify keeping it in tree or drop it. (128/129 are defensible as
  allocation/parse hygiene even if unmeasurable; say so if that's the intent.)

## Cross-AM evidence gap — must close before broad closeout

int16 LUT, `BLOCK_WIDTH=64`, and bound pruning are changes to the **shared**
`PreparedLutNoQjl4BitQuery` / `lut32` kernel, which IVF, SPIRE, HNSW, and DiskANN
all use. Two in-diff tests are direct evidence of cross-AM impact:

- **SPIRE:** `ec_spire/quantizer/tests.rs` tolerance relaxed `1e-6 → 1e-3` and
  `observed` re-pointed to `expected_lut` — the int16 LUT shifts SPIRE assignment
  scores by up to ~1e-3. Unmeasured recall effect on SPIRE.
- **DiskANN:** `ec_diskann/quantizer.rs` test flipped `32 kernel / 7 scalar` →
  `0 kernel / 39 scalar`. With `BLOCK_WIDTH=64`, **any batch < 64 candidates
  never hits the wide block kernel** — that is the common case for graph-AM
  neighbor scoring (DiskANN/HNSW), so the block-width lever is inert-or-harmful
  there and is unmeasured.

Per the repo closeout rule (A/B at 10/50/100k for the relevant quant/index), a
shared-quantizer change needs at least a recall spot-check on SPIRE/HNSW/DiskANN,
or the change must be explicitly scoped so only IVF consumes int16/bound (it is
not today — the kernel is shared). This does not block landing the IVF win, but
it blocks calling the scorer change validated across the TurboQuant family.
