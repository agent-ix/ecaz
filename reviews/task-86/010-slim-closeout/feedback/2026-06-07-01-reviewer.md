## Architectural read

The shipped change is a **cross-AM consistency fix**, not a
new feature. SPIRE was previously the only one of {HNSW, IVF,
SPIRE} that didn't route its TurboQuant scoring through the
shared LUT kernel — now it does. The result is:

- Mathematical equivalence to the prior scorer on the
  `no_qjl_4bit` lane (proven via packet 009's parity test
  with `gamma > 0`)
- Measured latency improvement at every benchmark cell
- No on-disk format change
- No new reloption surface
- No new `unsafe` blocks
- No anti-pattern B introductions

This is the kind of small, low-risk, recall-neutral change
that's safe to ship without further deliberation. The bigger
architectural commitment (TQ+ as a new format tag) correctly
went to Task 89 where it can be validated across the surfaces
that matter before any operator-visible API lands.
