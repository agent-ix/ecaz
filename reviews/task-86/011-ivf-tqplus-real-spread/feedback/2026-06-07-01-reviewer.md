  `prepare_ip_query_tqplus_no_qjl_4bit`,
  `score_tqplus_no_qjl_4bit_from_parts` (`src/quant/prod.rs`).
  Quantile cache (`OnceLock<Mutex<HashMap<usize,...>>>`) added to avoid
  recomputing 20001-point beta quantiles per build.
- IVF wiring: build trains calibration from
  `training_sample_vectors` (deterministic seed-derived indices) and
  re-encodes postings; insert.rs `reencode_tuple_for_storage` loads the
  persisted model and re-encodes incoming tuples; scan.rs caches the
  model in the scan opaque and folds shift/scale into the prepared LUT.
- Plain `prepare_ip_query` / `encode_source` reject TQ+ profile with
  "requires a persisted TQ+ calibration model", so model-less dispatch
  cannot silently fall back to baseline TurboQuant. Cross-profile
  prepared-query / quantizer pairings explicitly error.
- Calibration validation (added in `c7e85e8ac`): rejects non-finite
  shifts, non-finite scales, and `abs(scale) <= 1e-8`.

## 3. Safety / Determinism / Backwards-Compat

- **Unsafe surface:** task §Exit Criteria says "No new unsafe blocks";
  packet adds `pub(super) unsafe fn load_tqplus_model` and
  `unsafe fn tqplus_model_for_scan<'a>(opaque: &'a mut ..., ...) ->
  Result<&'a IvfTqPlusModel, String>`. The post-packet commit
  `d58ff8716` stripped redundant call-site `unsafe { }` blocks but the
  `unsafe fn` signatures remain. These mirror the pre-existing
  `load_pq_fastscan_model` / `pq_fastscan_model_for_scan` shape (legit
  precedent extension, not net-new pattern). **Not anti-pattern B**:
  the returned `&'a` is bound to `&'a mut EcIvfScanOpaque` (owned
  storage), not a raw `*mut T`, and has a `# Safety` block. Acceptable
  as a measurement profile; should be flagged as a literal-text
  deviation from "no new unsafe blocks".
- **Determinism:** TQ+ calibration is fit from
  `training_sample_vectors()` which uses
  `training::deterministic_sample_indices(..., self.options.seed)`. Fit
  for a given seed + sample is deterministic. Good.
- **Backwards compat:** decode_storage_format accepts tags 0..3
  unchanged; tag 4 is rejected by pre-TQ+ binaries as "invalid ec_ivf
  storage format code" (not silently misinterpreted). Old indexes load
  unchanged. TQ+ is opt-in via reloption.

### Flags (non-blocking; track before broader promotion)

1. **Exit-criterion literal-text deviation (medium):** Task 86
   `§Exit Criteria` says "No new unsafe blocks". Packet adds
   `unsafe fn load_tqplus_model` and `unsafe fn tqplus_model_for_scan`,
   mirroring pre-existing PQ-fastscan shapes. Pattern is acceptable
   (the existing precedent already lives in the same file), but the
   coder should either (a) restate this as "no new anti-pattern-B
   unsafe", (b) un-`unsafe`-ify the loader by passing a checked
   `&Relation` wrapper, or (c) call this out explicitly in the
   closeout audit so the exit-criterion bullet is not silently
   relaxed.
2. **Calibration tuple reuse (low):** Using `IvfPqCodebookTuple` for
   shift/scale is acknowledged in `tqplus-format-plan.md` as a
   measurement-profile expedient. Promotion requirement #1 in the
   format plan already gates this — make sure it's actually done
   before TQ+ ships to SPIRE/HNSW/DiskANN.
3. **Negative metadata fixtures (low):** Format plan promotion
   requirement #3 (corruption fixtures for missing-head /
   wrong-group-order / trailing-tuple / non-finite shift / zero-scale)
   is documented but only the in-binary `validate_tqplus_model`
   rejects today. Add a metadata-corruption regression test before
   broader production promotion.
4. **Quantile cache poison handling (very low):** `OnceLock<Mutex<...>>`
   uses `.expect("TQ+ quantile cache poisoned")`. Cheap unwind on
   poisoning is fine since it's a pure-compute cache, but worth a
   `# Safety`-style note.
5. **No nightly upgrade test (low):** Format plan §Compatibility
   asserts a pre-TQ+ binary rejects tag `4`. No regression test
   exercises this; rely on the unit test
   `metadata_decode_accepts_known_format_codes_and_rejects_unknown_codes`
   covering the inverse direction. Add a tag-4-on-old-binary fixture
   in the promotion follow-up.

Recall + latency + storage evidence is sufficient to ship TQ+ as the
IVF measurement profile on this branch and to advance the task. The
flags above are explicit pre-conditions for cross-AM promotion, not
blockers for the current packet.
