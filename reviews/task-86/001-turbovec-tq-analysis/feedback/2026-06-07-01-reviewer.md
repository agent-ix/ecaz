# Packet 001 — TurboVec TQ Analysis — APPROVE

## Verdict

**APPROVE** with four minor follow-ups for the coder to
address in subsequent slices.

## Coverage of plan-required questions

All 5 questions from the task plan's "first report and design
packet must answer" list are answered with substantive,
source-grounded responses:

1. ✓ "Query in same space" — answered: asymmetric, query is
   rotated + inverse-calibrated (not packed); cited
   `search.rs:1466-1530`, `:1419-1455`.
2. ✓ Encoding/transform/calibration/scorer — four distinct
   levers identified (per-coord TQ+ shift/scale, dense
   rotation, per-vector renorm scalar, u8 nibble LUT), each
   anchored to source.
3. ✓ Per-vector bytes — clean side-by-side (TurboVec
   `dim*bits/8 + 4` + index-level `4 + 8*dim`; ours `4 +
   mse_code_len + qjl_code_len_for_bits`).
4. ✓ SIMD/block kernel — four structural deltas named
   (32-vector blocked slabs, u8 nibble LUTs, block-level
   filter skip, fused top-k, 4-query fused scoring).
5. ✓ Index type + transferability — TurboVec called as flat
   positional compressed-vector index, no graph/IVF/disk
   routing; transferability scoped honestly to kernel ideas
   rather than end-to-end claims.

## Transferability matrix is well-ranked

The packet's recommended first prototype (TQ+ calibration)
and second priority (u8 nibble LUT) match the natural risk
gradient. Per-coord calibration is high-impact across all 4
AMs; 32-vector blocked slabs degrade outside flat scanners
(graph traversal disrupts contiguity).

## Follow-ups (non-blocking, fold into slice 002)

1. **Measurement methodology pre-commit.** The plan's
   §Required Evidence lists specific fields (`p50/p95/p99`,
   scorer timing, query-prep timing, payload bytes, kernel
   variant). The packet does not pre-declare an
   `ecaz bench suite` SuiteConfig shape or which lane (IVF
   microbench vs quantizer microbench) will be used. Without
   this, subsequent prototype packets have no shared
   baseline reference. Add to the slice-002 request.md.

2. **Line range mis-citation in `prod.rs`.** The packet cites
   `prod.rs:1466-1497` for QJL/mse-bits definitions — that
   range is actually NEON kernel code. The named functions
   (`qjl_enabled`, `mse_bits`, `mse_code_len`,
   `qjl_code_len_for_bits`) do exist; the line range
   targeting them is wrong. Substantive claim about
   `4 + mse_code_len + qjl_code_len_for_bits` is correct.

3. **Byte comparison is narrative-only.** Only
   `dim=1536` is walked through. Add a 3-row (dim, bits)
   table covering `768/1536/3072` at `2/4 bits` so prototype
   packets can cite numeric ground truth.

4. **Renormalization derivation missing.** Report states our
   `gamma` is residual-magnitude for QJL while TurboVec's is
   `norm/dot(rot_unit, recon_centroid)` and that these "are
   not the same estimator-bias correction" — but does not
   show why TurboVec's form is an unbiased IP estimator.
   Slice 003 (renormalization) will need this derivation.

5. **Bound what is NOT learnable.** Nothing acknowledges that
   flat-scanner LUT economics may not survive page-bounded
   scans, that calibration fit on a single first batch may
   degrade under streaming inserts, or that dense rotation
   cannot be A/B'd against SRHT without a separate rotation-
   quality probe. Add a "Not learnable from analysis alone"
   section.

## Closeout posture

This packet is the design foundation for slices 002-007. None
of the follow-ups block slice 002 from starting (the TQ+
calibration prototype is the recommended next step and is
already in flight per packet 002). Items 1 and 5 should land
before slice 003+ to keep methodology consistent.
