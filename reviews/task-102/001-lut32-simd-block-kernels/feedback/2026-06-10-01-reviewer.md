## Code review

- **AVX2 transpose/repack shape:** accepted. `transpose_8x16` produces byte
  columns in the order the scoring loop expects, and the score loop consumes
  each packed byte as low nibble then high nibble, matching the scalar
  per-dim accumulation order. The 16-entry f32 LUT select via two 8-lane
  permutes plus the high-bit blend is correct because AVX2 permute indexes
  use the low three bits while the blend selects the high half for indexes
  8..15.
- **Bit-exactness:** accepted. The implementation accumulates one dim at a
  time per lane, so it does not change floating-point associativity relative
  to the scalar reference. The focused tests cover full blocks, odd dims, and
  partial widths.
- **Partial dispatch and counters:** accepted. `score_lut_no_qjl_4bit_partial`
  keeps scalar hosts and single-lane tails on the scalar path, uses AVX2
  octets when available, and otherwise falls back to the existing padded
  block path for NEON/SVE. `score_width_cascade(..., true, ...)` records the
  returned ISA as kernel work and the single-lane tails as scalar work, which
  matches the current HNSW counter rows.
- **NEON/SVE readiness:** no local blocker found from static review. NEON's
  `vqtbl4q_u8` byte-index construction maps nibble `n` to byte indexes
  `4n..4n+3` for each f32 lane, and SVE gathers `lut[dim*16 + nibble]` under
  the active predicate. Both preserve dim order. They still need the deferred
  G4 compile/run evidence before Task 102 can be called fully closed.
