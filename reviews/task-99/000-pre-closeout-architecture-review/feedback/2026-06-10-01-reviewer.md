# Architectural review — Tasks 91–98 QuantCodec + block-kernel consolidation

Reviewer-initiated pre-closeout review of the consolidated branch state
(all kernel-family lanes merged; head at review time `062f88b95`).
Evaluated against the initiative's two stated goals: (1) unified
architecture — consistent patterns, code reuse, maintainability;
(2) latency improvement via optimization. This document is direct
input to Task 99; findings are numbered for the closeout matrix and
ADR-077.

## A. What was built

- **One trait** (`QuantCodec`, ADR-071): prepare/encode/score with
  `score_ip_batch` defaulting to per-candidate and
  `try_score_ip_candidate` for cutoff-capable codecs. 8 registration
  sites across IVF / SPIRE / HNSW / DiskANN; AMs never touch ISA
  modules directly (verified: zero direct calls from `src/am/**`).
- **Seven kernel families**, uniform module layout
  `src/quant/<family>/{mod,scalar,neon,sve,avx2}.rs`: lut32,
  grouped_pq_block, qjl32, rabitq32, hamming32, int8_approx32,
  tiled_lut32 (scalar-only by measured decision). All runtime-ISA
  gated via the shared `Isa` dispatcher (`sve2` before `sve`,
  Apple-aarch64 asm gating where SVE asm exists).
- **One observability surface**: `(surface × quant_kind × isa)` counter
  matrix (5×5×5), direct `[block-kernel-counters]` + Task 87 compat
  lines, flush-width histogram (`record_flush_width`), suite-runner
  parsing into `results.jsonl` (`metric=block_kernel_counters`),
  `kernel_status` markers for absent cells.
- **Process artifacts**: ADR-076 pattern doc,
  `docs/block-kernel-development.md`, per-task Graviton 4 runbooks,
  and three evidence-driven scope decisions (Task 96 stop, Task 95
  SVE scope-down, Task 98 SVE skip-by-rule).

## B. Goal 1 — Unified architecture: ACHIEVED, with convergence debts

The consolidation is real: seven families share one trait, one module
shape, one counter surface, one bench harness, and one review/evidence
discipline. The extension pattern was exercised twice mid-flight
(Diskann surface, TurboQuantQjl kind) without breaking compat — the
architecture absorbs growth as designed. Cross-lane semantics
converged where it mattered (kernel-row = ISA-dispatch attribution,
adopted independently by Tasks 93 and 97 and ratified consistently).

The debts are convergence gaps between generations of the pattern,
not design flaws:

### F1 — Sub-width dispatch: four generations coexist (HIGHEST-VALUE ITEM)

| Generation | Families | Tail handling | Coverage |
|---|---|---|---|
| 1 | lut32, grouped_pq_block | 32-blocks only; tails scalar | worst |
| 2 | qjl32 | 32-blocks + 8-octets; <8 scalar | good |
| 3 | rabitq32 | partial SIMD 1..=31 | full |
| 4 | tiled_lut32, int8_approx32 | arbitrary-width runs | full |

Generations 3/4 subsume 1/2. The cost of generation 1 is measured,
not hypothetical: Task 94's DiskANN grouped-PQ counters show ~6.5k
kernel vs 145k–273k scalar-tail candidates (~3% SIMD coverage), and
Task 97's pre-octet SPIRE numbers showed the same structure before
generation 2 fixed it. **Recommendation: a single follow-up task
(post-G4) backports partial/run dispatch to lut32 and
grouped_pq_block.** Expected effects: DiskANN grouped-PQ moves from
no-claim to a measurable win; SPIRE/HNSW lut32 tails shrink; the
flush-width histogram already in place can size the win in advance.

### F2 — Task 98 modes share `QuantCodecKind::TurboQuant`

tiled_lut32 and int8_approx32 record under the same kind as lut32, so
on HNSW three kernel families share one counter key. Unlike the QJL
case (which got its own kind), these modes are mutually exclusive per
session GUC, and suite steps pin one mode each — so per-run
attribution survives via step config rather than the counter key.
Acceptable, but ADR-077 must state it: the matrix's FullLut/TiledLut/
Int8Approx columns are disambiguated by step metadata, not by
counters, and mixed-mode sessions cannot be decomposed post hoc.

### F3 — Prevalidation contract not backported

The no-partial-score-write contract (validate every candidate before
any output mutation; Task 94 packet 012) holds for grouped_pq, qjl32,
hamming32, tiled_lut32, int8_approx32 — but the original
no-QJL/lut32 inner (`score_turboquant_no_qjl_4bit_batch_inner`) still
validates inside its scoring loops. Counters stay clean (Ok-gated),
but the failure contract is weaker on the flagship lane than on every
newer one. One-function fix; fold into the F1 follow-up.

### F4 — Three enablement models across AMs

Always-on (SPIRE, HNSW), GUC default-on
(`ec_diskann.candidate_batch_scoring`), GUC default-off
(`ec_ivf.scratch_soa_batch_decode`). Each is individually justified
(IVF has the suffix-max pruning trade; DiskANN measured parity), but
jointly there is no stated policy. Task 99 owes one paragraph: which
AMs default to kernels and why, including the IVF default decision
informed by the complete profile (carried from Task 93/004 and
Task 94/024-F2 feedback).

### F5 — Three anchor/tolerance regimes

(a) bit-exact scalar-order (lut32, grouped_pq; tiled/int8 are
integer-exact across backends — the strongest property); (b)
forced-scalar bit-exact anchor + 4-ULP/1e-6 dispatch pair (qjl32);
(c) bit-equal-to-production-same-order + 1e-5 envelope + recall-
binding (rabitq32). All sound; all reviewed; but a new kernel author
today has three precedents and no rule. ADR-077 must codify the menu
and when each applies (carried from Task 93/003 feedback). The
Task 97 packet 015 diagnostic (5920 ULP from cancellation under
reordering) is the cautionary citation for why (b)/(c) exist.

### F6 — Scaffolding duplication in candidate_batch.rs (1,951 lines)

Seven `score_*_batch_for` functions repeat the same
timing/counter/validation scaffolding around family-specific inner
loops. Mechanical, well-tested duplication — but it is now the
single largest consistency-risk surface (F3 exists precisely because
a fix landed in some copies and not others). A generic batch driver
parameterized by (validator, block scorer, partial scorer, kind)
would halve the file. Separately, the LUT-core parameterization
tripwire set in Task 97 packet 001 seq 03 ("a fourth LUT family
triggers extraction") is now technically hit (lut32, grouped_pq,
qjl32-MSE-stage, tiled_lut32). **Recommendation: neither
consolidation blocks closeout; schedule both as one post-Task-99
hygiene task, sized after the F1 backport (which touches the same
code and should land first).**

### F7 — Housekeeping

Task 94 bucket still has the duplicate `029-*` ordinal (H1, open).
SAFETY-comment convention splits by lane: `// SAFETY:` call-site
comments (grouped_pq, qjl32) vs `/// # Safety` doc sections
(rabitq32, hamming32, int8_approx32) — both legitimate; pick one in
the development doc.

## C. Goal 2 — Latency: ACHIEVED WHERE HEADROOM EXISTED, honestly bounded elsewhere

| Family | Best measured result (local) | State |
|---|---|---|
| rabitq32 (93) | NEON scoring-share 2.69–3.55×; e2e real100k p50 3.57→3.82 ms (~7%); full SIMD coverage on HNSW/DiskANN via partial-width | **win** |
| qjl32 (97) | SPIRE direct 2.48–2.97× (target band); IVF e2e up to 1.71×; recall byte-equal 14/14 | **win** |
| grouped_pq (94) | Recall exact; IVF e2e parity-to-small-wins (suffix-max pruning trade, documented); DiskANN tail-bound (→F1) | parity + documented trade |
| lut32 (87/92) | Pre-initiative flagship; tails on graph AMs → F1 upside | shipped |
| hamming32 (95) | NEON 1.17×/1.10× — popcount-bound; scoped down per stop-condition rule | honest bound |
| tiled/int8 (98) | Width histogram resolved the open question; integer-exact; SVE skip by rule | honest bound |

Two structural lessons the initiative produced (worth one ADR-077
paragraph each): batch SIMD trades against per-candidate pruning
(suffix-max, Task 94) and against batch-formation width (every graph
AM) — both are now measurable via the counter surface rather than
assumed, which is the lasting value of the observability investment.

**Remaining identified upside**, in expected-value order: (1) F1
backport (DiskANN grouped-PQ, SPIRE/HNSW lut32 tails); (2) Graviton 4
lane for 94/97 (approval-gated, runbooks approved) and the deferred
93/95/98 ARM/Intel cells Task 99 absorbs; (3) IVF GUC default
decision after the complete profile.

## D. Verdict

The consolidation achieved its architectural goal: one trait, one
kernel pattern, one evidence surface, and a demonstrated ability to
extend all three without breakage. It achieved its latency goal where
SIMD had genuine headroom, and — equally important — produced
measured, documented boundaries where it did not, instead of
unsubstantiated kernels. The remaining work is convergence (F1–F6),
not construction, plus the gated ARM evidence. Task 99 should treat
F1 as its highest-value implementation follow-up and F2/F4/F5 as
ADR-077 content.
