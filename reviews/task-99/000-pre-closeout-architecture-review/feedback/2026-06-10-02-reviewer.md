# Addendum — F1 win revision + new finding F8 (grouped-PQ kernel is gather-bound)

Follow-up analysis on the seq 01 F1 finding, from Task 94 packet 025's
own counter rows.

## F8 — The grouped-PQ AVX2 kernel rate is ~1.1× scalar, not ~4×

Per-candidate rates derived from the DiskANN 50k/ls=128 cell:
AVX2 kernel rows 6,592 candidates / 0.649 ms ≈ **98 ns/cand**; scalar
rows 240,260 / 26.46 ms ≈ **110 ns/cand**. The f32-gather
(`_mm256_i32gather_ps`) first-landing kernel is gather-bound. Compare
qjl32 post-transpose: ~253 vs ~1,100 ns/cand (4.4×).

The Task 94 Phase 1 design explicitly deferred byte/shuffle LUT
repacking "unless measurements require it." These measurements require
it. The deferred design is the original task-file scope: FAISS
PQ4-FastScan-style `_mm256_shuffle_epi8` with the 16-entry LUT held in
registers (typical 3–8× over scalar for this shape). Parity contract:
the scalar f32-LUT reference remains the strict anchor (designed to
survive exactly this repack); the repacked kernel grades under the
ADR-076 tolerance pair or, preferably, bit-exact if accumulation order
is preserved per candidate.

## Revised expected wins

- **DiskANN grouped-PQ needs F1 AND F8 together**: coverage alone
  saves ~10% of the scoring pool (converted candidates only run ~1.1×
  faster); repack alone touches only ~3% of candidates. Together the
  16–32 ms/cell scoring pool plausibly drops to ~4–8 ms, bounded by
  scoring's share of DiskANN query time — read the per-cell share off
  the counters before sizing the claim.
- **IVF grouped-PQ is the primary F8 beneficiary**: full block
  coverage already (pools up to 50M candidates/sweep at 100k/np64), so
  the kernel-rate multiplier applies directly — and it shifts the
  suffix-max pruning-trade calculus that made Task 94's IVF end-to-end
  "mixed". Re-run the packet 025 matrix after F8 before deciding the
  `ec_ivf.scratch_soa_batch_decode` default (F4).
- Cross-expansion batching is NOT a lever for DiskANN width: greedy
  descent consumes this expansion's scores to choose the next node, so
  expansion-bound widths are structural; partial dispatch (F1) is the
  complete coverage answer.
