# Feedback: Task 111a Packet 003 — Aligned LE Typed Dense Layout

## Verdict

LGTM for the typed-view building block. This is a faithful, correct
implementation of the aligned LE typed-view design: the accessors are
memory-safe, the new aligned layout is backward-compatible and gated default-off,
and — most importantly — the scan wiring puts the zero-copy win exactly where it
belongs without breaking the coalescing width fix. Not blocking. One real process
gap (the page-spanning B core is unreviewed) and two coverage notes below.

## Verified correct

- **Typed accessors are sound.** `native_le_{f32,u16,u32}_slice` guard on
  `cfg!(target_endian = "little")` + `len % size == 0` + the real
  `ptr.cast::<T>().is_aligned()` (not the illustrative `is_aligned_to::<T>()`),
  with SAFETY comments. `f32`/`u16`/`u32` have no invalid bit patterns and the
  bytes are a validated subslice of the pinned page, so on LE + aligned the
  reinterpret is sound; the returned slice lifetime is correctly tied to the
  input. Falls back to byte decode otherwise.
- **Backward compatible.** New aligned tag `0x28` is decoded alongside the
  original `0x25`; the decoder branches array offsets on `is_aligned_layout`, so
  existing `0x25` blocks still read. Aligned layout is written only under the new
  `dense_posting_typed_layout` reloption (default off).
- **The roundtrip test is the right guard.** `dense_posting_aligned_block_round
  trip_exposes_native_views` asserts the `0x28` layout returns `Some` from all
  three native accessors with correct values, and that legacy `0x25` returns
  `None` — i.e. it proves the fast path actually engages and doesn't silently
  always fall back.
- **Scan wiring preserves the coalescing width fix (the load-bearing point).**
  In `append_dense_posting_block_to_coalesced_scratch` the typed gamma view is
  used only to read the gamma value cheaply; postings still accumulate into the
  coalescing scratch and flush at `IVF_POSTING_SCRATCH_SOA_BATCH_POSTINGS`. So
  TurboQuant stays wide — the typed view makes the *gather* cheaper, it does not
  reintroduce per-block flushes.
- **Per-block path gets true zero-copy.** In `process_dense_posting_block`, when
  a typed view is available it is passed straight to the batch scorer
  (`gammas = typed_gammas`, no `load_gammas` copy). This is exactly where the
  zero-copy win should land — the RaBitQ per-block case — and is the cleaner
  recovery of the RB1 regression-vs-`dense-old` than the width-aware heuristic I
  had earlier suggested.
- **Diagnostic toggle.** `ec_ivf.dense_posting_typed_views` GUC disables runtime
  typed reads while leaving the durable layout intact — good A/B knob for the
  upcoming benchmark, mirroring the coalescing GUC.
