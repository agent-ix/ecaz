## Minor / non-blocking

1. **`Isa::Scalar` label for a SIMD estimator.** The width counter is recorded
   under `Isa::Scalar`, but the rb4/8 arithmetic estimator is SIMD
   (NeonBits4/8 / Avx2Bits4/8), not scalar. A bench reader could misread rb4/8
   as having run a scalar path. Consider a distinct ISA/label (or a one-line note
   in the bench-counter docs) so the width-only rows aren't confused with scalar
   scoring. Cosmetic — the comment in code is clear, but the emitted label is
   what bench consumers see.
2. **Provenance:** this width counter is added *after* the 007 run, so 007's
   rb4/8 cells did not have it. The closeout decision does not depend on rb4/8
   flush-width (it rests on latency/storage/copy, which 007 has), so this is not
   a gap — just note that any future rb4/8 *width* claim needs a re-run to
   populate the new counter.
3. `cargo fmt --check` drift is pre-existing and outside this slice; correct not
   to do a repo-wide format pass here.
