### P1-D — the test module does not compile; the tests that close P3-O were never run

`src/am/ec_distann/traversal_replica.rs:2644`:

```rust
TRAVERSAL_REPLICA_SUPPRESSION.with(|suppressed| suppressed.borrow_mut().clear());
```

`TRAVERSAL_REPLICA_SUPPRESSION` does not exist. The thread-local is
`SUPPRESSED_READY_REPLICAS` (declared at line 52; used at 62, 118, 126, and by
the sibling test at 2643). A repo-wide grep finds exactly one occurrence of
`TRAVERSAL_REPLICA_SUPPRESSION` — this line. That is `error[E0425]: cannot
find value ... in this scope` under `cfg(test)`.

The release extension build is unaffected (the module is `cfg(test)`), so the
release matrix at `2a4a70b23` is untouched by this — it predates the commit.
But `cargo test` and `cargo clippy --all-targets` are red at HEAD, and
`862b0a2ed` is the commit that closes P3-O.

Compounding it: **no `cargo test` or `cargo clippy` artifact accompanies any of
these three commits.** `git diff --name-only 637388d9b..9ac7ba677` contains no
test or lint log. So the finding-closing tests were written, committed, and
cited without being executed once — which is precisely the failure mode the
tests were requested to prevent.

Ask: rename to `SUPPRESSED_READY_REPLICAS`, run
`cargo test --no-default-features --features pg18` (or the narrower focused
target) and `cargo clippy --all-targets --no-default-features --features pg18
-- -D warnings`, and commit both logs to the packet. Then P3-O is closed.

|---|---|---|
| `run/normal-release-ab-10k` | 18.30 (p50 18.10, p95 21.70) | **16.00** (p50 15.40, p95 19.70) |
| `run-10k/normal-release-ab-10k` | 18.30 (p50 18.20, p95 21.70) | **15.30** (p50 14.80, p95 19.00) |

The table cites **16.00** — the *old* run — while "Result rows" now points at

**50k** — same fields:

| run | owner | replica |
|---|---|---|
| `run/normal-release-ab-50k` | **19.40** | 16.40 |
| `run-50k-final/normal-release-ab-50k` | **20.40** | 16.40 |

The table cites **20.40** — the *new* run — but the sentence "The packet-local
`distann-multinode-summary.log` files are the cited raw result artifacts" and
the hash table both list `run/normal-release-ab-50k/distann-multinode-summary.log`,
which says 19.40.

So 10k takes the old number with new provenance, and 50k takes the new number
with old provenance. To be explicit about what I am *not* alleging: every
number in the table exists in a committed log at the right SHA, and the 10k
mismatch is in the conservative direction (the cited 16.00 understates the
newer 15.30). This is not fabrication. It is that a reader cannot determine

determination has to be mechanical.

Ask: choose one run per scale as *the* release run, cite and hash that run's

## P2 findings

### P2-O — run-to-run dispersion is now measurable, and it is not small next to the claimed effect

The reruns give us something the packet did not have before: a second
observation per scale, same binary, same measurement parameters.

| quantity | run A | run B | spread |
|---|---:|---:|---:|
| 10k replica warm mean | 16.00 | 15.30 | 4.4% |
| 50k owner warm mean | 19.40 | 20.40 | 5.2% |
| 50k replica **bulk** mean (2,000 trials) | 17.97 | 20.34 | 13.2% |

The claimed benefit is 12–20%. A 4–5% run-to-run spread on the warm means is
not disqualifying, but it should be visible in a promotion packet, and right
now it is not: `physical_benchmark_recall` carries `distinct_recall_ci95_low/high`
while `physical_benchmark_latency` reports no dispersion at all beyond p50/p95
within a single run.

This also bears on P2-H, which I am closing as disclosed but whose *explanation*
does not yet hold up. The manifest says:

> The 2,000-trial recall mean includes setup/cold effects; the 50-sample
> latency step is warm-cache steady state.

If that were the whole story the bulk-mean gain would be systematically smaller
at larger scales but stable across runs of the same scale. Instead the 50k
bulk-mean gain moved from −15.3% (run A) to −6.5% (run B) between two runs of
the same binary. That looks like variance in the bulk step, not a clean
cold-cache term, which means the 100k bulk result (21.43 → 21.50, +0.3%) is
also within plausible noise rather than evidence of "no benefit at 100k".

The narrowed promotion claim — warm steady-state benefit, stated explicitly —
survives either reading, and that narrowing is the right call. Ask: report both
runs per scale (or mean ± spread) in the table, and either substantiate the
cold-effects explanation or replace it with "the bulk-mean step is noisier than
the warm step; promotion claims only the warm steady-state figure."
