## How to read

- Sweep points per family: IVF/SPIRE `nprobe=16|64`, HNSW
  `ef_search=80|160`, DiskANN `list_size=64|128`. Latency cells show
  `on/off p50 ms (delta)` per point.
- **on/off semantics**: for HNSW/SPIRE/DiskANN the off arm sets
  `ec_<am>.candidate_batch_scoring=off` — a true kernel A/B. For IVF the
  config's off arm merely omits `--ivf-scratch-soa-batch-decode`, which
  after the ADR-077 §4 default flip leaves batch decode ON in both arms:
  **the IVF on/off pairs shown at 10k/50k/1M are same-config noise-floor
  pairs**, not an A/B (they read 0 ± 4% at every scale, which doubles as
  a measurement stability check). The IVF kernel differential evidence
  is Task 99's explicit pre-flip A/B at 100k (−44% G4, −70.3/−68.9%
  Intel on IVF TQ) — see the 100k note below. (Packet 002's config
  off-arm defect and its relabel are tracked in that packet's feedback.)
- **100k column — delegated to Task 99 by Phase 2 design, not
  republished here.** Phase 2 reused the existing Task 99 100k fixtures
  rather than re-replicating them, so the only 100k data Task 105 itself
  collected is the **G4 dispatch-confirm gate** (kernel-on only, 32
  steps, `isa=neon`) — the post-flip confirmation AC3 specifies. The
  **full 100k on/off A/B for both lanes lives in Task 99**:
  `reviews/task-99/008-g4-lane/artifacts/profile-run` (G4) and
  `reviews/task-99/009-intel-lane/artifacts/profile-run` (Intel), each
  run under its own config (an extra `ef_search=32` / `nprobe=8` low
  point) and dispatch era. **G4 caveat**: the Task 99 G4 *default*
  profile-run predates the Phase 1 NEON-first flip and dispatches
  SVE-eligible families through `sve2`, so it is **not lane-equivalent
  to post-flip code** and is deliberately *not* imported into this
  matrix; the Task 99 **NEON-capped** subset (kernel-on) is what matches
  post-flip dispatch, and the G4 confirm gate reproduces it exactly
  (AC3, finding 5). Intel dispatch is unchanged by the flip, so Task 99
  packet 009 is post-flip-equivalent for Intel, but to avoid
  cross-config cell duplication (the extra low sweep point) it is read
  from packet 009 rather than restated here. The `—` cells in the 100k
  columns below are therefore **intentional delegations, not missing
  evidence**. QJL-1024 fixtures exist only at 100k by design.
- Recall cells show kernel-on recall@10 per sweep point. Every on/off
  recall pair at every shown scale on both lanes is **equal** (the
  generator marks mismatches; none exist). `*` = on-only cell (no off
  step in the config: `hnsw-tq-tiled_lut`, `ivf-rabitq4`, the G4 100k
  confirm column).

1. **SPIRE × TurboQuant is the headline kernel win at every scale on
   both lanes**: G4 −30/−35% (10k) → −23/−28% (1M); Intel −49/−57%
   (10k) → −37/−48% (1M). The win narrows but holds at 1M because the
   kernel is still 34–48% (G4) of query time there.
2. **DiskANN × TurboQuant wins consistently**: −11..−15% G4 across all
   scales; −21..−37% Intel at 10k/50k, −5/−11% at 1M.
3. **HNSW × TQ int8_approx wins steadily** (−8..−18% both lanes);
   `full_lut` is neutral-to-slightly-negative on G4 (+3..+17%, kernel-on
   slower at small scales) and neutral on Intel — see honest markers.
4. **IVF cells are flat by construction** (see "How to read"): the
   batch-decode optimization is the production default in both arms.
   The kernel runs 35–71% of 1M query time with `isa=neon`/`avx2`
   attribution — engagement is real; only the differential lives in
   Task 99's explicit A/B.
5. **Dispatch is fully proven**: zero `sve`/foreign-lane attribution
   anywhere in the Task 105 cells; G4 kernel cells are `neon` (+`scalar`
   for the documented scalar-mode arms), Intel `avx2`/`scalar`. The G4
   100k confirm-gate recall values match the Task 99 NEON-capped run
   **exactly** (e.g. QJL cells 0.1800/0.3480, 0.1790/0.3050,
   0.1800/0.3110 — identical to `reviews/task-99/008-g4-lane`
   neoncap-run), satisfying AC3 at the result level; kernel rates were
   verified within 0.7% in the gate packet. (The Task 99 G4 *default*
   profile-run shows `sve2` for SVE-eligible families because it
   predates the Phase 1 flip — that is exactly the pre-flip behaviour
   the flip replaced, and is why that run is not imported into this
   matrix.)
6. **Recall parity is absolute**: every kernel on/off recall pair at
   every shown scale, sweep point, and lane is equal (the generator
   flags mismatches; none).
7. **Storage is lane-identical and scale-linear** per family;
   per-row bytes are flat across scales (e.g. diskann-tq 1024 B/row at
   every scale; ivf-pqfs improves with scale as PQ amortizes:
   273→189 B/row).

## Honest markers (cells that must not be over-read)

- **100k on/off cells are delegated, not measured here.** The only
  Task-105-collected 100k data is the G4 NEON confirm column
  (kernel-on; `isa=neon`). Intel 100k and both lanes' 100k off-arms are
  Task 99 008/009 (different config — extra `ef_search=32`/`nprobe=8`
  point — and dispatch era); the G4 pre-flip profile-run is `sve2` for
  SVE-eligible families and is deliberately excluded. Read the `—` 100k
  cells as delegations, not gaps. (See "How to read" and AC2 below.)
- **IVF on/off pairs (10k/50k/1M)**: same-config noise-floor pairs
  post-ADR-077 §4 default flip; not a kernel A/B (config off-arm omitted
  the flag instead of forcing the GUC off). Differential evidence =
  Task 99's pre-flip 100k A/B. A follow-up explicit-off rerun is
  possible from the snapshots if a reviewer wants fresh IVF
  differentials at non-100k scales. Packet 002's config defect and its
  relabel are tracked there.
- **`spire-rabitq`**: no kernel counter rows at any scale on any host —
  the batch toggle is inert on this lane (legacy estimator path).
  Documented as ADR-077 §9 gap 1; Task 106 slice 1. Deltas on this
  family (±3%) are noise, not kernel effect.
- **`hnsw-tq-default` / `hnsw-tq-exact`**: no counter rows — these
  modes score via the binary-prefilter / non-kernel exact paths; their
  on/off deltas are noise pairs. (`full_lut`/`int8_approx` are the
  kernel-engaged HNSW TQ modes.)
- **`hnsw-tq-tiled_lut`**: `isa=scalar` only with 0% kernel share —
  tiled mode has no block kernel; on-only diagnostic column.
- **`ivf-rabitq4`**: on-only, no counters (bits=4 RaBitQ kernel
  out of scope per the Task 93 decision).
- **`diskann-pqfs-binary` on Intel**: `isa=scalar` (no AVX2
  binary-sidecar kernel in the menu — known coverage shape); its
  on/off deltas there are prefilter-path noise. The @64 1M point
  (+26%) is a single noisy cell (stddev ≈ 1.4 ms on ~4 ms p50);
  @128 is −7%.
- **Intel 1M HNSW cells show high variance** (mixed-direction deltas
  ef=80 vs ef=160, e.g. tq-default +35%/−25%): graph traversal at 1M
  on this host is cache-sensitive; read the family trend, not single
  points. The G4 lane (which ran warm) does not show this.
- **Intel 50k ivf-rabitq1** (−16/−23%): same-config pair (see IVF
  marker) showing an environmental gap; flat at 10k/1M and on G4.
- **QJL-1024 cells**: 100k-only dispatch-correctness columns at a
  dimension-reduced operating point (recall 0.18–0.35 matches Task 99
  exactly; not a regression, not a production-recall claim).
- **`diskann-pqfs-grouped-pq` at 1M** (~324/308 ms p50): the grouped-PQ
  prefilter at 1M is dominated by non-kernel costs (kernel share 0.1%);
  the cell is green but this config is not production-competitive at 1M.
