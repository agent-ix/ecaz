# 115/002 — Benchmark: residual gives no recall-per-probe win under exact rerank (net-negative)

Evidence: `benchmarks/ivf-111g-115-attribution/` (FINDINGS.md, `head-residual-ab`),
fixed `.so` 67e1534c, plain vs `rabitq_residual=1`, 10/50/100k, sweep
`[8,16,32,64,128,200]`, rerank=heap_f32.

## Measured (100k; 10k/50k same pattern)

| | recall np64 / np200 | p50 np200 | index size |
|---|---|---|---|
| plain    | 0.9655 / 0.9990 | 43.3 ms | 90.4 MiB |
| residual | 0.9655 / 0.9990 | 47.3 ms | 90.4 MiB |

- **No recall-per-probe gain** (identical at every nprobe, every scale).
- **~9% slower** (the per-list `⟨q,c⟩` add), **same index size** (zero-metadata
  confirmed). → **net-negative under exact `heap_f32` rerank.**

## Why + verdict

Residual lowers the *coarse* quantization error, but exact `heap_f32` rerank
already fixes the final ranking from the coarse top-`rerank_width`, so the gain is
**masked**. This is the same mechanism as the quant_bits result (1-bit recall ==
4-bit). Residual's benefit can only appear where the coarse score *is* the final
ranking — i.e. `rerank=off` (or a quant-only path). The 115 implementation is
correct and recall-safe (codex's structural review + the prune-off-in-residual
guard hold), but **promotion is not warranted** on this evidence:

- **Keep residual opt-in and off by default** (correct current state).
- **Follow-up to actually test the thesis:** re-bench plain vs residual with
  `rerank=off` (coarse-only ranking) — that is the only regime where residual's
  lower quant error can move recall-per-probe. The heap_f32 regime benched here
  shows no win.
