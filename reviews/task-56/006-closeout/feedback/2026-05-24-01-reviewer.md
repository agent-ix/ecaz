## HARD BLOCK 1 — scope drift to `src/storage/wal.rs` AT WRONG LAYER

`git diff main --name-only -- src/` includes `src/storage/wal.rs`.
Task 56 spec scope-locks to `src/am/ec_spire/` per the directive
packet. **Touching storage/wal.rs is out-of-scope.**

The diff adds a `GenericXLogTxn::start_handle(handle: RelationHandle)`
safe wrapper at `wal.rs:89`:

```rust
+    pub fn start_handle(handle: RelationHandle) -> Self {
+        // SAFETY: `RelationHandle` is a non-null pointer whose construction
+        // contract requires a live opened PostgreSQL relation; that contract
+        // satisfies `GenericXLogStart`'s precondition.
+        unsafe { Self::start(handle.as_ptr()) }
+    }
```

This is **wrong layer in two ways**:

1. **A safe `start_handle` ALREADY exists on `WalTxnScope`** at
   `wal.rs:314`:
   ```
   $ grep -n "fn start_handle" src/storage/wal.rs
   89:    pub fn start_handle(handle: RelationHandle) -> Self {        ← NEW (SPIRE)
   314:    pub(crate) fn start_handle(handle: RelationHandle) -> Self { ← Task 54 P3 wrapper
   ```
   `WalTxnScope::start_handle` is the **typed RAII wrapper** Task 54
   established as the safe consumer API. The new
   `GenericXLogTxn::start_handle` is **redundant**.

2. **Adding the safe wrapper to `GenericXLogTxn` (the primitive)
   bypasses RAII.** `WalTxnScope` exists precisely so consumers
   can't accidentally call `start` without going through the typed
   scope. Adding `GenericXLogTxn::start_handle` lets future callers
   skip the RAII guard. This is an anti-pattern: **the wrong layer
   safe boundary degrades the safety architecture**.

Per [[feedback_dont_defer_safety_fixes]] (HARD RULE 2026-05-24):

> If a review finding is "this could be properly safe but isn't" —
> BLOCK. If a review finding is "this signature ... where a typed
> handle exists" — BLOCK.

**Required fix**:

1. **Revert the `GenericXLogTxn::start_handle` addition** at
   `wal.rs:79-93`.
2. **Migrate SPIRE callers to `WalTxnScope::start_handle`** instead
   (the existing Task 54 P3 wrapper).
3. **Remove the `src/storage/wal.rs` line** from the Task 56 diff
   entirely — branch should touch only `src/am/ec_spire/*`.

If the migration uncovers a need that `WalTxnScope` doesn't cover,
that's a Task 54 follow-up packet, not a slip into storage/wal.rs
on a SPIRE branch. Open a separate Task 54/007 packet for that.
