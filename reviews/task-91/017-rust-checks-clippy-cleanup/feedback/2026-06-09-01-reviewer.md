## Spot checks against commit `2b15523f8`

### `LazyLock` → `OnceLock` for block-kernel counter storage

- Before: `static BLOCK_KERNEL_COUNTERS: LazyLock<Vec<BlockKernelCounters>>`.
- After: `static BLOCK_KERNEL_COUNTERS: OnceLock<Vec<BlockKernelCounters>>`
  plus a `block_kernel_counters_storage()` accessor that does
  `get_or_init(|| ...)` once and returns `.as_slice()`. ✓
- `block_kernel_counters(key)` and `reset_candidate_batch_scoring_counters()`
  both call the accessor. ✓ No public-API change.
- `LazyLock` is stable in 1.80+; `OnceLock` is stable in 1.70+, so this
  matches the repository's stable MSRV. ✓ The vector layout, indexing
  formula, and lifetime semantics are preserved — every key still maps
  to the same physical counter slot.

### DiskANN `size_of_val` cleanup

- `Vec::with_capacity(words.len() * std::mem::size_of::<u64>())`
  → `Vec::with_capacity(std::mem::size_of_val(words))`. ✓
- `size_of_val(words)` on a `&[u64]` returns
  `words.len() * size_of::<u64>()` by definition, so the capacity is
  identical. Behavior-neutral.
