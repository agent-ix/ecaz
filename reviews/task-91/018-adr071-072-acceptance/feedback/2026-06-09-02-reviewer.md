## Trait surface

```rust
pub(crate) trait QuantCodec {
    type PreparedQuery;
    fn codec_kind(&self) -> QuantCodecKind;
    fn search_codec_tag(&self) -> QuantSearchCodecTag;
    fn payload_len(&self) -> usize;
    fn encode_source(&self, source: &[f32]) -> Result<EncodedQuantPayload, String>;
    fn prepare_ip_query(&self, query: &[f32]) -> Result<Self::PreparedQuery, String>;
    fn score_ip_candidate(...) -> Result<f32, String>;
    fn try_score_ip_candidate(..., min_ip_to_keep: Option<f32>) -> Result<Option<f32>, String> { /* default */ }
    fn score_ip_batch<Id>(...) -> Result<(), String> { /* default */ }
}
```

Five required methods, two defaulted. Associated `PreparedQuery` keeps the
hot path off `dyn`. `QuantSearchCodecTag::GroupedPq` carrying `group_size`
finally unifies IVF/HNSW/DiskANN. `EncodedQuantPayload { dimensions, gamma,
code }` is the right minimal carrier.

Ten implementors across four AMs:

```

IvfQuantizer / IvfQuantCodec<'a>                (IVF, with model binding)
HnswTurboQuantScanCodec / HnswGroupedPqScanCodec / HnswRaBitQScanCodec

```

Load-bearing invariant: AM scan loops never call ISA-specific kernel
functions directly. They pass `CandidateBatch` through the trait and let
`score_ip_batch` handle width gating, kernel dispatch, and counter
attribution. That is exactly the boundary Tasks 93–98 need.

## ISA + counter surface

`src/quant/isa.rs` ships `Isa { Scalar, Neon, Sve, Sve2, Avx2 }` with
runtime `is_aarch64_feature_detected!("sve2"|"sve"|"neon")` and
`is_x86_feature_detected!("avx2")`. Block-kernel modules return the
backend-dispatched ISA from `score_block32_<isa>(...) -> Isa`, which
threads into `BatchScoringTiming.kernel_isa` and lands in
`BlockKernelCounterKey { surface, quant_kind, isa }`. Scalar tails
always go to the `isa=Scalar` row via a separate API.

Counter invariants now structurally enforced:

- `flushes/candidates/elapsed_nanos` are row totals.
- `kernel_*` and `scalar_*` lanes split additively.
- Scalar tails after a kernel block land in the `isa=Scalar` row, not in
  `scalar_*` fields under the selected ISA — enforced by API split.
- Task 87 compat surface preserved by aggregating from new rows.

## Strengths

1. **Polarity discipline is consistent.** Every migration preserves the
   score-polarity contract at the AM/prefilter layer, never inside the
   codec. HNSW negates outside `score_ip_candidate`. DiskANN prefilter
   negates at `DiskannPreparedPrefilter::score`. Easy to audit.
2. **Bit-exact gate everywhere.** Every AM migration shipped a
   `f32::to_bits()` parity test against the pre-slice scorer. No
   approximate-equality tests masking drift.
3. **Model binding in the right place.** `IvfQuantCodec::with_pq_model`
   keeps grouped-PQ codebooks in the prepared-query state, not in
   `CandidateBatch` metadata. HNSW and DiskANN follow.
4. **Width gating + ISA selection are encapsulated.** Tasks 93–98 add a
   real `score_block32_sve` returning `Isa::Sve2` and the entire counter
   pipeline picks it up with zero changes elsewhere.
5. **Off-path counter is structurally honest.** Recording API physically
   prevents mixed rows; locked F2 rule is enforced by call shape, not
   convention.

## Rough edges (non-blocking, worth tracking)

1. **`[block-kernel-counters]` not emitted by the suite latency path.**
   The off-path calibration run (T92 packet 014) shows only
   `[task87-counters]` lines. Underlying counters work — the compat row
   aggregates from new rows — but the new line shape isn't emitted via
   the suite latency emitter. Task 99 matrix will want it visible
   directly. Flag for the T92 closeout packet or first T93+ slice.
2. **Three HNSW codecs colocated in `scan.rs`.** Defensible, but if a
   Task 93+ HNSW slice grows the file, a
   `src/am/ec_hnsw/quant_codec.rs` split would mirror IVF's shape.
3. **`SpireAssignmentQuantCodec` constructed per-call** in selected-row
   scoring. `Copy` data so no perf impact; could elide later with a
   `quant_codec_borrowed()` if profiling shows it.
4. **`select_highest_isa` hybrid-features test is synthetic.** Worth a
   one-line comment so a future reader doesn't read it as a real
   precedence claim. Cosmetic.
5. **Duplicate `ADR-075` numbering** is pre-existing repo defect; not
   introduced by this branch but now more visible. Separate cleanup
   commit at some point.
6. **`encode_source` returns `String` errors.** Fine for now. If a
   caller needs structured handling later, an enum upgrade is local.
