## What's actually new vs Task 79 / packet 002

This packet is different from packets 002 and 003 in two important ways:

1. **New isolated surface** (`task81_nprobe_100k_idx`) built with
   `top_graph_search_list_size=256` instead of the Task 79 / packet 002
   shared `task79_surface_100k_idx` which had tg96. The first attempt
   failed because the reused tg96 index can't satisfy nprobe>96 — that
   guard worked as intended. Failed run retained as provenance.
2. **Wider routing breadth** at nprobe=128: 25,600 routes vs 19,200 at
   nprobe=96. That's the lever being tested.

The +0.20pp recall lift at matched candidates is real: with more leaves
routed, the global cap=1152 selection has access to a slightly larger
pool of high-scoring summaries, so the selected 1152 blocks are subtly
better. The +22 candidates over 200q is rounding/edge-of-block noise —
not a meaningful surface change.

## Clamp at nprobe>128 is informative

Requested nprobe 160/192 both clamp to `effective_nprobe=128`. The
manifest correctly attributes this to `max_routing_expansions=128`
binding. That tells us:

- tg256 doesn't actually give you 256 leaves at this geometry — the
  routing budget caps at 128.
- The local recall ceiling at this surface/cap combo is 0.9965 — beyond
  that needs a different lever (richer summaries, different cap, or
  format change).

## Cross-cutting note for AWS

The packet correctly proposes `nprobe=128` as the next AWS 1M candidate.
However, the packet 003 evidence (cap=1152 produces byte-identical
9,213,846 cands as old tg96 baseline at 1M) suggests that **the cap
mechanism's selection at 1M is dominated by leaf row content, not by
routing breadth**. So my hypothesis is that nprobe=128 at AWS 1M will
produce the same 9.2M candidates, same 0.9832 recall, but more summary
scoring CPU (more leaves to summary-score) → worse latency.

That's still worth measuring — it would tighten the diagnosis that the
1M problem is summary geometry, not routing breadth. Packet 005 will
either falsify my prediction (good — the recall transfers) or confirm
it (also useful — narrows the format-change scope).

## Non-blocking notes

1. **Recall ceiling at local 100k is now 0.9965** with tg256 / cap1152.
   Worth recording this as the local "best possible" reference point
   for future Task 81 packets — any mechanism change should be measured
   against this ceiling, not against the older 0.9940 Task 79 044 row.
2. **The +22 candidate delta at nprobe=128 vs nprobe=96** (3,672,641
   vs 3,672,619) is deterministic edge behavior, not noise. The
   selector is taking exactly 1152 blocks both times; the row count
   difference comes from blocks at end-of-leaf having ≤16 rows.
3. **nprobe>=160 entries** could be omitted from the comparison table
   in future packets since they clamp — keeping them is fine for audit
   provenance but they don't add information.
