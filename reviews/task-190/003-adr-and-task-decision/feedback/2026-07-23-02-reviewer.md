## New contract text: reviewed and sound

The incorporation upgraded the mutation story from "invalidate before
visible" to a concrete fail-fast protocol: the first mutation attempt against
a Ready replica durably transitions it to Stale and returns a stable
retryable error *before* dispatching owner writes; the retry observes Stale
and uses the owner path. This is the right shape — it needs no distributed
commit, and a crash after invalidation only costs performance. Two
observations for Task 198 packet 001, not defects in the decision:

1. **R1 (P3, implementation gotcha to pin in the contract).** The Ready→Stale
   transition must be durable *independently of the failing statement's
   transaction* — if the catalog flip rides the same transaction that then
   errors, it rolls back and every retry fails forever (livelock). The word
   "durably" implies this, but Task 198 packet `001-contract-and-format`
   should state the mechanism (committed side-transaction or equivalent)
   explicitly, and the Phase 2 drill should assert that exactly one mutation
   attempt fails before the retry succeeds.
2. The error-on-first-DML is a user-visible behavior change whenever a
   replica is Ready. Acceptable for this research system and correctly
   scoped, but Phase 4's promotion packet should say so out loud when it
   proposes any production default.
