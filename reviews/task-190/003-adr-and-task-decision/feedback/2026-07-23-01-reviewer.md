# Task 190 packet 003 review — ACCEPT ADR-086 and Task 198; contract findings for Phase 1

## Verdict

**ACCEPT.** ADR-086 records a properly bounded decision: the replica is a
rebuildable derived artifact, never a source of truth; owner generations stay
authoritative; lazy10 payloads stay owner-side; fallback is the unchanged
owner traversal path with no partial-result success; rollback is
invalidate/drop and serve remotely. Task 198 is a genuinely separate,
separately numbered, bounded implementation task — phased, feature-gated,
single-candidate, with promotion pushed to yet another reviewed decision —
not a bundled rewrite smuggled through the gate. Commit `20179d68f` touches
documentation only; Task 190 implements no production behavior, as required.

Findings F1/F2 are contract gaps that Task 198 Phase 1/2 must close before
implementation locks in; they do not invalidate the decision, because the
decision does not depend on how they are resolved.

## F1 (P2): specify where replica staleness authority lives and how scans observe it

ADR-086 requires that any traversal-visible mutation "marks the replica stale
before the mutation can become visible." The ordering direction is correct
and fail-safe (a crash between stale-mark and commit leaves a needlessly
stale replica, which only costs performance). But the mechanism is
unspecified, and it is load-bearing:

- The replica lives at the coordinator; mutations commit at owners. A
  coordinator-local staleness flag cannot be updated "before the mutation
  becomes visible" without a distributed commit protocol — which the ADR
  rightly does not want.
- The workable shape is owner/shared-metadata authority: the stale mark
  lives in the same metadata the scan already reads when it "pins and
  revalidates the active epoch," so observation costs zero additional round
  trips. If that is the intent, say so; if the intent is anything else, the
  per-scan observation cost and the multi-coordinator fan-out ordering must
  be designed explicitly.
- With N coordinators, define whether one stale mark invalidates all
  replicas of that fingerprint at once (single authority — simpler, and the
  right default) or per-coordinator (requires fan-out before visibility —
  avoid).

Task 198 packet `001-contract-and-format` should pin this down; AC 2 cannot
be tested until the observation point is defined.

## F2 (P2): in-flight replica scans versus concurrent invalidating mutation

AC 2 ("no scan can *select* a replica for a mutation-stale fingerprint") and
the Phase 2 drills all fence at selection time. A scan that selected a Ready
replica and is mid-traversal when the invalidating mutation commits is not
covered. The two coherent options: (a) the in-flight scan completes on the
replica — equivalent to a slightly stale-but-consistent snapshot of the
graph; or (b) it aborts/restarts on the owner path. Note the owner path
itself reads committed graph state as it goes, so a mid-scan mutation can be
partially visible there; option (a) is arguably *more* consistent, not less.
Whichever is chosen, it must be stated in the contract, covered by AC 1's
identity/parity definition (define what "same result" means when a mutation
races the scan), and exercised by a Phase 2 drill: mutate while a replica
scan is in flight, verify no partial prefix, no crash, and the documented
semantics. Without this drill the "mutation invalidation" story is only
tested in its quiescent form.

## F3 (P3): faithful copy versus "no projected payload columns" — resolve the tension

ADR-086 states the replica "does not contain projected payload columns," yet
the faithful first implementation "may faithfully copy the current graph and
exact vector tier" with a 1.0×-generation upper envelope (2,496,626,688
bytes). Those two statements only coexist if the exact vectors can be
extracted from the frozen row tier without its payload columns — in which
case the honest expectation is far below 1.0× (graph 826,925,056 + vectors
~614 MB + directory ≈ the 1.445 GB envelope plus real layout overhead) — or
if the prototype is permitted to copy the full row tier, payload bytes
included as dead weight, in which case the no-payload-columns sentence needs
a qualifier ("not served/queried," rather than "not present"). Task 198
Phase 1 step 2 ("do not copy arbitrary payload columns") inherits the same
ambiguity. Decide which is permitted for the prototype before format work
starts; the upper envelope stands either way, but implementers should not
have to guess which sentence wins.

## F4 (P3): mid-scan replica failure semantics

"A replica error cannot return a partial prefix" is the right invariant.
State the recovery explicitly: a replica failure mid-traversal restarts the
scan from the beginning on the owner path (no reuse of partial replica
frontier state), so result identity is preserved by construction. Add it to
the Phase 2 drill list alongside the build/activation/retirement races.
