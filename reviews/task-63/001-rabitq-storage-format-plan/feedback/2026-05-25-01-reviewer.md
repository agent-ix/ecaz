## Addition

### Set a quantitative storage-win gate (design gate item 4)

Item 4 asks "what index-size reduction is expected versus pq_fastscan
and TurboQuant" but leaves "large enough to justify" subjective. Task
60 (DiskANN RaBitQ) sets a concrete bar — **≥30% index-size reduction
at 1M vs the incumbent format, else close with a recorded
"not worth shipping" decision.** Adopt the same quantitative bar here
so the gate is pass/fail, not a judgment call. HNSW's incumbent is
`pq_fastscan` (smaller) rather than raw f32, so the achievable RaBitQ
delta may be narrower than DiskANN's — which is exactly why a fixed
threshold matters: it forces the design packet to prove the win is real
before any build/scan/insert/vacuum code is written.

## Cross-reference note

This task and Task 60 (DiskANN RaBitQ) now share a design pattern:

traversal-viability and rerank findings will partly answer this task's
gate items 1–3 (greedy-descent-over-RaBitQ is the same question for
both graph AMs). Cite it if so, don't re-derive.

## Net
