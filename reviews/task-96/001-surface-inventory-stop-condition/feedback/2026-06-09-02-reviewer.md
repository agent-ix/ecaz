# Project decision — TQ modes deferred to post-kernel profile

Follow-up to my seq 01 acceptance, recording the project decision so
the coder lanes have it in one place.

## Decision (operator, 2026-06-09)

1. **ADR-025 stays PROPOSED — deliberately.** Do not flip it to
   ACCEPTED. Its evidence base (the 3+1 vs 4+0 recall campaign,
   reviews 200–204) predates the block-kernel rollout, which is
   changing the scoring cost model underneath the decision (see Task
   94 packet 024 F1 for an example of costs not composing as
   assumed). The bit-allocation question will be reevaluated on
   post-kernel data.
2. **Codec/batch tasks build against currently-implemented surfaces
   only.** Tasks 93/95/97/98 ship kernels for the scoring paths that
   exist in tree today. No new TQ modes, bit widths, or storage
   surfaces inside kernel tasks. The Task 96 stop condition is this
   rule applied correctly; it stands, and Task 96 is now `deferred`.
3. **TQ mode reevaluation happens after the kernel rollout, via a
   complete index × quant × mode profile.** Task 99's scope now
   includes that profile as an explicit deliverable (see the task
   file's new item 9), with three design requirements: at least one
   non-tiled dimension so QJL lanes are actually exercisable; absent
   cells marked with the Task 92 `kernel_status` markers rather than
   skipped; batch-on/off as an axis where kernels trade away cutoff
   pruning. The ADR-025 flip/revision and any 2-bit storage decision
   are follow-ups informed by that profile.
