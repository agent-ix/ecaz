# Review: Task 144 Packet 001 — Geometry Diagnostics (single-assignment surface)

## Verdict

**Approved as Phase 0 substrate — sound foundation, proceed.** This is the
right single-assignment measurement surface for the "is a 1–4 probe (≤5%
scanned) operating point geometrically possible" question the task asks. No
blocking findings. The heavier methodology assessment lives in the packet 002
and 003 feedback (the closure simulation and the real-index run); this file
just clears the single-assignment half.

## What this establishes (and how I verified it)

- `spire_geometry_leaf_size_summary` (leaf-size variance) and
  `spire_geometry_true_neighbor_concentration` (per-query count of leaf lists
  holding the exact top-k) are the two Phase 0 numbers the task scope asks for.
- Both are measured from **real SQL-visible index snapshots**
  (`ec_spire_index_leaf_snapshot`,
  `ec_spire_index_leaf_target_assignment_snapshot`,
  `ec_spire_index_routing_centroid_snapshot`) — I confirmed these functions
  exist and are exercised across `src/tests/*`. This is NOT a hand-rolled
  re-derivation of assignment; the single-assignment concentration is read from
  the index's own assignment, so it faithfully reflects real build behavior.
  That is the key thing that keeps this out of the ADR-0004 "benchmark cited a
  nonexistent surface" failure mode.
- `--geometry-output` correctly requires `--include-recall` so it reuses the
  existing exact-truth path rather than inventing a second truth source.
- Suite plumbing (`geometry_output` on `spire-pipeline` steps, `${artifact_dir}`
  rewrite, expected-artifact tracking) keeps future evidence inside
  `ecaz bench suite` per the workflow rule — good, no bespoke sweeper.

## Notes / non-blocking

1. **Ranking-independence is a feature here.** Concentration and leaf-size are
   properties of the index *assignment* + exact truth, not of the scan's
   ranking. So running this diagnostic before Task 143's ranking fix lands is
   methodologically legitimate *for these two numbers*. (The recall figure that
   rides along in `results.jsonl` is a different, ranking-dependent quantity —
   see the 003 feedback; do not treat it as a closure baseline.)
2. This packet's own `cargo test` log is unit-level only (`30 passed`) — it
   validates the record math, not any real-index number. The real-index
   instantiation is packet 003, reviewed separately.

Foundation is clean. Verdict stands: approved.
