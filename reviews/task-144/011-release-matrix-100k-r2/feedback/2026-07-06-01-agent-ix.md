```

```

- At 50k, plain `fixed_b2` was the least-bad 0.99 point (35.68%). **At 100k,
  `fixed_b2` no longer reaches 0.99 at all** — it tops out at 0.9775
  (`fixed_b2-adaptive @ np96`, 33.1731% candidate, verified). The only family
  that clears 0.99 is `closure_e050`, and it pays **79% candidate scan** to do
  it. So closure-ε *is* doing something (lifting recall over a line fixed can't
  reach) — but at catastrophic scan and storage cost, not a usable operating
  point.
- Best recall per family @ 100k (all cross-checked): single-adaptive 0.9240 @
  10.93%; closure_e010-adaptive 0.9680 @ 26.44%; fixed_b2-adaptive 0.9775 @
  33.17%; closure_e025-adaptive 0.9835 @ 54.91%; closure_e050-adaptive 0.9925 @
  79.50%. Recall climbs with ε only by scanning drastically more of the corpus.

This is a **major finding**, stated plainly: the AC that held at 10k fails at
50k and fails *harder* at 100k. The trend is monotone-bad — scan% at the 0.99
frontier is drifting up with corpus size (2.96% → 35.68% → 78.66%), the opposite
of the "1–4-probe / 1–5% scanned" SPANN goal in the spec.

## Ratio pruning is INERT at 100k (same disposition as 10k/50k) — retire it

```

fixed_b2          0.9245    0.9750    0.9750    0.9750     0.9750  0.9775

```

At np96, **ratio ≥2.0 gives recall bit-identical to `fixed`** (r2.0 = r4.0 =
r8.0 = fixed across every row) — i.e. at these ratios the distance filter never
bites; it is "no pruning." Only r1.25 changes the candidate set, and it does so
by **collapsing recall** (closure_e050 0.9925 → 0.9645; single 0.9215 → 0.8125).
There is no ratio that both prunes and holds ≥0.99. This exactly reproduces the
10k and 50k conclusion. **Retire ratio pruning as a headline lever** on the full
cross-scale evidence — it never earns an operating point at any scale.

## Cross-scale disposition (reviewer's read): iterate / escalate / shelve — NOT promote

the spec pre-registers for escalation.
