# Review: Task 144 Packet 004 — Probe Distance-Ratio Pruning GUC

## Verdict

**Code APPROVE (mechanism lands correctly, gated, default-off). The prior
closure-surrogate ADR ask is RESOLVED by ADR-084.** But this is the critical
lever of Task 144, and the first real-index run (packet 007) *falsifies the

## The surrogate-consistency ask (my 002/003 F1): RESOLVED

ADR-084 pins `d_route(score)=max(0,1-score)` for closure assignment, query-time
pruning, and the Phase 0 diagnostic; explicitly carries forward my 002 caveat
("not norm-robust; ratio bands collapse when best distance floors to zero");
labels it a Known Limitation; and defers normalized cosine to a future ADR with
the reason (the scan pruning point only has the final routed leaf score, not raw
query/centroid vectors). This is the right disposition — the three knobs are now
the same knob and it is documented.

## Finding F1 (the crux) — the mechanism does not hold recall as built/configured

From packet 007's real 10k release index (I recomputed from
`results-10k-r4-pipelines.jsonl`, candidate_sum/200/10000):

| cell | np96 recall | np96 row-instances scanned |
|---|---:|---:|
| single **fixed** | 0.9935 | 10.37% |
| single **ratio125** | **0.7635** | **0.26%** |
| fixed_b2 ratio125 | 0.9150 | 0.58% |
| closure_e010_b8 ratio125 | 0.7680 | 0.27% |

Two things this proves:

1. Ratio pruning **does** collapse scan (10.4% → 0.26%), so the plumbing works.
2. It **does not** hold recall — and, damningly, recall under ratio125 is
   *flat across the whole nprobe sweep* (single: 0.7585→0.7635 from np8→np96;
   closure: 0.7630→0.7680). Increasing nprobe 12× barely moves recall because the
   ratio band, not nprobe, is doing the cutting and it saturates at a hard low
   ceiling. That flatness is the signature of the ADR-084 surrogate collapse
   (`best_distance→0` for high-norm vectors → `threshold=0` → keep ~1 route),
   *not* a genuine geometric (1+ε) band. Corroborating smell: closure *under*
   ratio pruning is **worse** than fixed_b2 (0.768 vs 0.915), the opposite of
   the SPANN thesis — another symptom that the surrogate, not geometry, is
   governing.

So at ratio 1.25 the crux mechanism is falsified. This is not a code defect —
it is exactly the risk the ADR flags. To make ratio pruning evaluable you need
**either** the norm-robust surrogate (normalize before the ratio) **or** a
ratio sweep to find the recall/scan knee (1.25 catastrophically overprunes;
2.0/4.0/8.0 are untested). Packet 006 only carries the single 1.25 point, so the
matrix cannot currently characterize this knob (see 006 feedback).
