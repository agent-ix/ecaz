## One substantive change vs. the working-tree state seq-01 inspected

While running the smoke I noticed an off-by-one in the worker key
walk: `pick_shared = local_ops % 2 == 0`, so shared accesses land on
`local_ops ∈ {0, 2, 4, ...}`, and `key_index = local_ops % shared_keys`
only walks half the slots when `shared_keys` is even. Fixed by
dividing first: `key_index = (local_ops / 2) % shared_keys`. The
post-fix smoke at `artifacts/soak-quant-cache-5s-smoke.log` shows
`distinct_shared_keys_observed` walking 1 → 3 → 4 across iterations
(matches configured `shared_keys: 4`) and mean throughput up from
1483 → 2709 ops/sec because workers stop relocking the same two
keys.
