topology are decision-grade at 10k/50k/100k and can close; the LATENCY
arm cannot — it was measured at the pre-fix SHA with five named hot-path

recall+storage+topology, keep latency + Task 172 open) is defensible in

required arm, so AC-13 stays open on that axis. No fabricated numbers;

## Per-arm ruling

- **RECALL — CLOSEABLE.** Physical == single at every scale (delta
  0.0000), exact by construction (disjoint owners, exact truth cache).
  Commit-INSENSITIVE: none of the deferred fixes change which neighbors
  are returned. Caveat: 10 queries is thin (10k recall CI95 ≈
  [0.963, 1.000]); acceptable only because the A/B *delta* is exactly
  zero — flag the sample size, don't rest a standalone recall claim on it.
- **STORAGE — CLOSEABLE as a measurement; NFR-018 promotion correctly
  withheld.** On-disk-format bytes, commit-INSENSITIVE. ~4.06× raw-vector
  amplification at 100k is plausible for the physical layout (RaBitQ codes
  + frozen full-precision rows + Vamana graph + directory ≈ several
  copy-scale terms). The coder is right that 50k/100k exceeding 4.0×
  blocks an NFR-018 promotion claim.
- **TOPOLOGY — CLOSEABLE.** Exact global coverage (owner records sum to
  10k/50k/100k), zero non-owned, zero orphans, genuinely disjoint shards
  (NOT the old replicated fixture), 2 remote owners materialized at every
  scale, instances=3 on distinct ports. Commit-INSENSITIVE, decision-grade
  at all three scales.
- **LATENCY — NOT CLOSEABLE.** Three independent disqualifiers: (1)
  commit-SENSITIVE — every one of the five open findings at 77e09a511
  (scan-token leak, per-scan Vamana head-graph rebuild, per-scan candidate
  digest recompute, serial remote fan-out, unprepared per-hop SPI) inflates
  exactly this arm, so p50 of 12-21s measures un-optimized overhead, not
  the design; (2) the fix commit changed physical_ms to include
  build_epoch, so this packet's timer basis is already superseded; (3)
  methodology — the single arm is a cold-outlier-contaminated sample
  mislabeled "warm" (5 iters, p50 ~2.7ms but stddev 4116ms > mean 2061ms,
  max 10.3s), and the headline overhead ratios (11.68/10.56/9.36×) are
  computed from recall mean_ms, NOT the latency table beside them. n=5 /
  10 queries is below decision-grade for any latency claim regardless.

## Findings

- **P1 — AC-13 latency requirement not met.** AC-13 (task 179 ~line 547)
  names "recall, latency, and storage." The latency arm here is pre-fix,
  superseded-timer, contaminated-baseline, n=5. It is a valid OPEN Task 172
  performance finding but does not satisfy AC-13's latency axis. AC-13
  cannot be marked fully complete on this packet; re-run latency at a
  post-822949d6d SHA with real warmup and a larger sample.
- **P2-1 — the 0.296% balance figure is untraceable and appears wrong.**
  No logged value yields 0.296%; owner record counts give max-dev-from-mean
  = 0.415% (bytes 0.409%). Topology is still excellent (0.415% is tight) —
  this is a citation-accuracy defect, not a balance problem. Correct the
  verdict before any signoff.
- **P2-2 — "warm" mislabel.** The single-arm latency artifact asserts
  cache_state=warm but is cold+warm mixed; the verdict acknowledges the
  outlier but the artifact table still says warm. Any future latency close
  must add real warmup.
- **P3-1 — overhead-ratio provenance.** 11.68/10.56/9.36× is derived from
  recall mean_ms, not the latency arm, and is presented adjacent to the
  latency table without stating the source. Label the denominator.
- **P3-2 — amplification denominator implicit.** 3.95/4.05/4.06× =
  gen_bytes / (rows × 1536 × 4); correct and reproducible but the raw
  baseline is a computed constant, not a logged field. State it in the
  manifest.
- **P3-3 — stale log banner** (10k header reads rows=2000 dim=16, a
  fixture default; the real load is ec_real_10k dim=1536/10000 rows per the
  topology rows) and **top_k=32 in the recall/latency tables vs top_k=10 in
  config** (likely rerank_k vs return_k) — cosmetic, but note both so they
  aren't read as drift.

## Disposition

Mark AC-13's recall + storage + topology satisfied by this packet (with
the P2/P3 citation corrections). Keep AC-13's latency axis OPEN; it must
be re-measured after the read-path optimizations land (head-graph
caching, prepared-plan reuse, parallel fan-out — packets 020/029/031
findings), with real warmup and a decision-grade sample. This is not a
Task 179 closeout, and the coder correctly does not claim one.
