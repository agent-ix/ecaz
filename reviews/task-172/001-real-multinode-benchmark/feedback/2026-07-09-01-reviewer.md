# Task 172 pre-checkpoint review and prior-finding verification

The real-corpus fixture is worthwhile progress, but this is still development
preflight, not Task 172 gate evidence. Do not promote the current artifacts.

## Current result

The direct real-10k run shows a useful signal: 200/200 single-vs-multinode top-k
identity and `single=0.9990`, `multi=0.9990`. The full fixture's saved summary
also reports `concurrency_scan_insert_epochswap pass=false` and
`ac5_frozen_vector_after_vacuum_reuse pass=false`. The in-progress dimension
fixes make those drills executable on 1536 dimensions, but do not change the
underlying distributed-DML or frozen-epoch semantics.

## Findings

### P0 - The proposed suite config does not implement the Task 172 benchmark gate

The config contains three `distann-local-multinode` fixture steps. That step
produces result identity, one hard-coded recall point (`top_k` sweep 32), a qual
smoke, and an epoch smoke. It has no distributed latency sweep, throughput /
concurrency curve, per-node or cluster storage, load/build timing, remote-path
engagement audit, benchmark/full-metrics modes, instrumentation-overhead audit,
telemetry attribution, or 1m/10m capacity model. These are explicit Task 172
acceptance requirements, not optional follow-ups.

The current direct runs use `target/debug/ecaz` and the shared debug-installed
extension. Final evidence must be a clean release-verified suite run on every
participant.

### P1 - Current provenance labels are false and the artifact directory is contaminated

The real 10k summary reports `rows=2000` and `dim=16`, even though the disjoint
row counts sum to 10,000 and the loaded vectors are 1536-dimensional. The
summary prints synthetic argument defaults instead of measured real-corpus
metadata. It also omits corpus/query SHA, staged manifest identity, exact head,
and build profile.

`direct-10k-full/node*-postgres.log` has been reused across several attempts and
contains earlier epoch mismatches, invalid-port injections, a graph-degree-40
page-overflow failure, and dimension failures. `run_dir` is cleared, but
`artifact_dir` is not, and PostgreSQL appends to existing log files. Use a fresh
immutable artifact directory per attempt and promote only a clean successful
suite run.

### P1 - The 10k full-fixture passes do not close the prior lifecycle/DML findings

The full fixture still counts the aborted-but-persistent tombstone as a passing
fault arm. It still mutates only the coordinator in the insert concurrency
worker, and `active_epoch` still relabels one graph rather than swapping complete
Building/Published record, head, placement, and frozen-vector generations.
Making insert vectors dimension-correct can turn a smoke from red to green; it
does not prove FR-082-AC-1/4/5 or distributed DML routing.

### P1 - The lane remains replicated index storage

Every node builds the complete graph. The final “disjoint” drill deletes heap
rows and tombstones non-owned records; vacuum cleanup does not physically
reclaim the directory or graph records. Label and measure this as a
replicated-index/partitioned-heap control. It cannot supply NFR-018's disjoint
cluster-storage result.

### P2 - Real-corpus COPY paths are interpolated without SQL-literal escaping

`real_setup_sql` inserts canonicalized file paths directly inside single-quoted
`COPY ... FROM` literals. A valid path containing `'` breaks the SQL and can
change its meaning. Quote the path through a PostgreSQL literal helper or pass it
through a parameterized/operator-controlled surface.
