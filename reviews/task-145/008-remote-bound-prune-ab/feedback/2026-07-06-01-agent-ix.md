## 1. Does bound pruning ENGAGE on the remote path? NO — proven inert

The decisive counter is `leaf_candidate_sum` (`visible_leaf_candidate`,
`scan/types.rs:750`, `candidates.rs:3369`/`3179`). It is incremented **only for a
row that PASSES the bound-prune check** — the prune branch `continue`s at
`candidates.rs:3356`/`3166` **before** `visible_leaf_candidate`. So if the prune
fired N times, the `on` arm's `leaf_candidate_sum` must be `off − N`.

Summed over the three remote nodes, **`leaf_candidate_sum` is byte-identical
off vs on in all 15 cells** (3 scales × 5 nprobe):

| scale | np96 leaf_candidate off | on | np64 off | on |
| --- | ---: | ---: | ---: | ---: |
| 10k n128   | 1,502,699 | 1,502,699 | 1,001,156 | 1,001,156 |
| 50k n1024  | 986,258   | 986,258   | 656,529   | 656,529 |
| 100k n1024 | 1,874,885 | 1,874,885 | 1,242,261 | 1,242,261 |

`truncated_candidate_sum` is likewise identical everywhere (100k np96
1,868,885 = 1,868,885). **N = 0. The prune skipped zero rows.**

- Remote path IS engaged (`local_heap_candidate_sum=0`, `remote_heap=30000`,
  `compact=30000` both arms) — so this is the remote coordinator scan, not the
  local path. The mechanism is present on this path (rabitq → quantized-v2 column
  scorer, prune branch at `candidates.rs:3350`). It simply never took the branch.
- The only fields that differ off→on at 100k np96 are **timing** —
  `leaf_row_score_nanos_sum`/`candidate_score_nanos_sum` +1.13% on the `on`
  arm (i.e. slightly *slower*), and a `heap_started_before_all_candidates_done`
  concurrency artifact. Every structural counter is identical. That is the
  signature of the two arms running **identical code paths** — consistent with
  `pre_materialization_prune_enabled()` returning false on the worker in both arms.
- Note `sound_bound_available_sum = 0` / `sound_bound_missing_sum = 38400` (np96
  100k) in **both** arms — the sound bound is always missing. Whether or not that
  gates the skip, the behavioral proof (`leaf_candidate_sum` unchanged) is
  sufficient: **nothing was pruned.**

**Why "candidates identical" is not enough on its own (and why the packet's
framing is wrong):** even if the prune HAD fired, `truncated_candidate_sum` would
have stayed conserved (a pre-materialization skip and an append-overflow drop both
call `observer.truncated_candidate` → same counter). So `truncated`/`candidate`
identity cannot distinguish "fired losslessly" from "never fired." Only
`leaf_candidate_sum` (post-prune, materialized-only) can — and it says **never
fired.** The packet leans on the conserved counters and concludes "recall-safe but
no work saved," which reads as *engaged-but-unhelpful*. The stronger, correct
reading is **not engaged at all.** There is no dedicated pre-materialization-prune
counter, so this A/B has **no clean 0→nonzero engagement proof** — exactly the gap
that made 006's leaf-block A/B inert. AC1/AC2 rigor (and my 007 steer) require that
proof; it is absent.
