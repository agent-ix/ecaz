# Task 162 full `ec_distann` review

## Findings

1. **P1 - Current-head pg_test validation is stale and should fail.**
   Packet 001 reports `cargo pgrx test pg18 ec_distann` as 42/42 green at
   head `6e8e58572` (`reviews/task-162/001-m0-scaffold-build-scan/request.md:3`,
   `:82-98`), but later commit `1fd015935` changed the hop-round default to
   100 (`src/am/ec_distann/mod.rs:62-66`) and the current pg_test still asserts
   `SHOW ec_distann.hop_rounds = '8'`
   (`src/tests/ec_distann_basic.rs:551-561`). This violates the task
   acceptance criterion that TC-037 pg_tests are green at the reviewed head
   (`plan/tasks/162-ec-distann-m0-single-node-parity.md:55-60`). Update the
   expectation or default, then rerun and packet-local-log current-head PG18
   validation before declaring the phase reviewed.

2. **P2 - The measured D7 codec decision is not reflected in the default.**
   Packet 002 says the codec data contradicts the GroupedPq default and
   recommends flipping `neighbor_code_format` to `rabitq`
   (`reviews/task-162/002-m0-bench-cells/request.md:21-25`), with raw summary
   showing 50k rbq at 0.9950 recall while gpq tops out at 0.9245
   (`reviews/task-162/002-m0-bench-cells/artifacts/manifest.md:67-72`). The
   code still has `NeighborCodeFormat::DEFAULT = GroupedPq`
   (`src/am/ec_distann/options.rs:52-64`) and the pg_test names grouped_pq as
   the default path (`src/tests/ec_distann_basic.rs:436-444`). That leaves the
   out-of-box AM on the measured non-parity path. Either flip the default to
   rabitq and update tests/spec text, or record an explicit operator decision
   that M0 accepts a lower-recall default despite the packet recommendation.

3. **P2 - M0 single-node parity is not closed at the stated acceptance bar.**
   The task requires release A/B against `ec_diskann` at 10k/50k with latency
   `<= 1.3x` and recall within 0.002
   (`plan/tasks/162-ec-distann-m0-single-node-parity.md:44-49`). Packet 002
   passes the lower/mid recall range but records a 50k high-recall miss:
   0.9950 recall costs 13.7 ms for distann vs 6.67 ms for diskann, a 2.05x
   ratio (`reviews/task-162/002-m0-bench-cells/request.md:13-20`,
   `reviews/task-162/002-m0-bench-cells/artifacts/manifest.md:60-65`). Packet
   003 is a valid architecture kill-check GO for the distributed shape, but it
   does not satisfy the M0 single-node parity exit criterion. Keep the task
   open for the proposed levers (wider beam, batched neighbor scoring, heap
   prefetch) or explicitly rescope the parity requirement.

4. **P2 - Query correctness depends on callers manually matching
   `ec_distann.top_k` to SQL `LIMIT`.** The scan callback reads `top_k` only
   from the session GUC (`src/am/ec_distann/routine.rs:246-307`), and the
   early-exit proves convergence only for that `top_k`
   (`src/am/ec_distann/scan.rs:139-147`). The GUC help text warns users to set
   `k >= LIMIT` (`src/am/ec_distann/options.rs:165-174`), but the AM cannot
   see or enforce the SQL LIMIT and `amgettuple` will keep returning whatever
   eager result buffer was produced (`src/am/ec_distann/routine.rs:329-355`).
   A query with `LIMIT 20` under the default `top_k=10` can stop after proving
   the top 10 only, leaving rows 11-20 incomplete or misordered. Before this
   becomes a production surface, derive the requested k from planner/executor
   state if possible, conservatively disable early-exit when the requested
   limit is unknown, or add a hard guard/documented SQL wrapper plus regression
   coverage for `LIMIT > ec_distann.top_k`.

## Architecture review

The core M0 architecture is strong. The code follows ADR-085's single global
graph shape, keeps full vectors out of graph records, and makes the local
expansion seam look like the future FR-079 remote function rather than baking
single-node assumptions into the orchestrator. Good choices include the 72-byte
metadata page, fixed-length lean records with pooled decode, stable D6 vec_id
derivation with collision checks, seed-deterministic build/head sample, sorted
directory lookup, and metadata-fingerprint cache invalidation while DML is
frozen. The response-order and cardinality checks in the expansion seam are
also the right kind of defensive contract for the future remote path.

The main architecture gaps are product-surface gaps rather than format flaws:
the default codec contradicts the measured M0 decision, `top_k` is a user-set
session knob for a query property, and the per-backend head graph is rebuilt
from persisted vectors rather than persisted/shared as an adjacency tier.
Those are acceptable M0 discoveries, but not things to leave implicit.

## Efficiency review

The benchmark packets support the big conclusions: storage is comfortably under
NFR-018 for rbq/gpq, the G0 wide-beam/few-round shape is viable, and the high
recall single-node tail is expensive. The packet's proposed levers are the
right ones. In the current hot path each expanded node does a record read, a
scalar score over each embedded neighbor code, and a heap exact-distance read
(`src/am/ec_distann/expand.rs:72-141`; scalar scoring in
`src/am/ec_distann/quantizer.rs:238-250`). Batched code scoring and heap
prefetch should be treated as the next performance slice before re-running the
parity gate.

Two lower-priority scaling notes: `scan.rs` sorts the full beam every hop
round (`src/am/ec_distann/scan.rs:117-147`), which is fine for the current
caps but will become unnecessary frontier churn at larger beams/rounds; and
the per-backend cache map is keyed only by oid and fingerprint with no pruning
(`src/am/ec_distann/head_cache.rs:75-105`), so a long-lived backend touching
many rebuilt indexes can retain stale entries. Neither blocks M0, but both
should stay on the M2/M3 efficiency list.

## Testing and evidence

The targeted coverage is good for a first AM milestone: tuple/layout round
trips, metadata validation, deterministic identity/head sample, planner-driven
ordered scans, loop invariants, tombstone traversal, and DML posture are all
represented in packet 001. Packet 002/003 are also useful measurement packets:
they use `ecaz bench suite`, release install precheck, one table/index per arm,
and packet-local result artifacts.

It is not yet well-tested at closeout head because of the stale GUC pg_test
finding above, and the packet evidence does not include current-head clippy or
PG18 test logs after the `top_k`/H semantics change. Missing tests I would add
before merge: `LIMIT > ec_distann.top_k`, default codec expectation after the
D7 decision, current-head rabitq default planner scan if the default flips,
cache invalidation across REINDEX with repeated scans in one backend, and a
small regression that the high-level scan does not silently return a partial
page of rows when early-exit fires.

## Overall

This is a successful architecture spike and a credible M0 implementation
foundation, but not a clean M0 closeout yet. Packet 003 earns a GO for the
program's distributed-shape kill-check; packet 002 and current code still leave
single-node parity/default/validation work before the task should be marked
done.
