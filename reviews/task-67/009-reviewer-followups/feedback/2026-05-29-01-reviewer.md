(only `_mm512_loadu_ps` / `_mm512_fmadd_ps`), but was gated on
`avx512f,avx512vpopcntdq`. This commit relaxes:

- `sum_query_dequant_avx512_bits1` `target_feature` and SAFETY doc
  (`src/quant/rabitq.rs:2714-2715`).

  (`src/quant/rabitq.rs:2874-2875`).

  (`src/quant/simd.rs:156-158`).
- Dispatch SAFETY comments at `src/quant/rabitq.rs:1670-1675` and
  `:4108-4114` updated to drop the VPOPCNTDQ claim.

  single `is_x86_feature_detected!("avx512f")` check.

  `no_vpopcnt` case now asserts `has_avx512_bits1()` is **true** (regression
  inverter for the prior incorrect contract). Verified.

Skylake-X / Cascade Lake hosts now correctly take the AVX-512 bits=1 path.

### F2 (packet 001 nit) — `backend_name()` drops bf16 for partial-feature hosts — **Resolved**

Match table replaced with an exhaustive 8-arm table (one arm per
`(vpopcntdq, bw, bf16)` combination) via a new
`SimdBackend::static_name()` (`src/quant/simd.rs:21-78`). All previously
collapsed combinations now produce distinct labels:

- `avx512f+vpopcntdq+bf16`
- `avx512f+bw+bf16`
- `avx512f+bf16`

A new test `backend_name_preserves_avx512_feature_parts`
(`src/quant/simd.rs:353-401`) locks five representative combinations,
including the three that were previously lossy.

### F3 (packet 001 nit) — `ECAZ_SIMD=avx512` hardcoded `bf16: false` — **Resolved**

New `forced_backend_from_env` arm
(`src/quant/simd.rs:198-202`) accepts `avx512_bf16`, `avx512+bf16`,
`avx512f+bf16` and yields a fully-featured AVX-512 backend
(`vpopcntdq: true, bw: true, bf16: true`). Bench operators on bf16-capable
hosts can now force the bf16 lane. Covered by a new `with_simd_env` arm in
`forced_backend_from_env_recognises_known_aliases`
(`src/quant/simd.rs:272-282`).

### F4 (packets 003 + 005 gap) — odd batch-tail uncovered by tests — **Resolved**

`bits8_batch_estimator_matches_scalar_order` and
`bits4_batch_estimator_matches_scalar_order` flipped from `0..6` to `0..5`
candidates (`src/quant/rabitq.rs:4615` and `:4652`). With 5 candidates,
`chunks_exact_mut(2)` yields 2 pairs + a `.into_remainder()` of length 1,
which now exercises the single-candidate fallback inside both the AVX-512
and AVX2 batch wrappers (lines `:3814` for bits=1 single fallback model;
identical patterns at the bits=4 / bits=8 batch wrappers). Note the
flip removes coverage of the even-count branch from these particular tests;
the even branch is exercised indirectly by other batch tests in the module
and by the `_pair` differential tests at `:6212+`, so coverage of the
typical even slab is not lost.
