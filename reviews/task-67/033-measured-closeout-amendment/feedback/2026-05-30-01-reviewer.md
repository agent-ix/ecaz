# Verdict: APPROVE

The amendment is honest about the original gate misses and records the
measured outcomes without redefining a miss as a pass.

## What the amendment does well

- **Honest about misses.** Line 37-38 explicitly says:
  "The original 4x bits=8 and all-nprobe 3x bits=1 SQL thresholds
  are no longer closeout blockers" — i.e. the originals are recorded
  as *not met*, not redefined to match the measurement.
- **bits=1 scope tightened, not redefined.** Lines 18-20 + AC bullet 3
  call out that 3x is reached only at `nprobe=64` and explicitly
  document `nprobe=16/32` as below 3x. This matches packet 022.
- **bits=8 architectural finding captured.** Lines 21-25 record the
  1.09x SQL top-out and attribute it to sidecar scoring being ~1% of
  total wall time. This matches my packet 027 audit (kernel-layer
  6.04-6.69x → SQL 1.09x because scorer is 0.025ms of 3ms total).
  The amendment correctly states "further scorer work cannot
  materially move those SQL metrics."
- **bf16 decision recorded.** Line 26-27 + bullet 5 align with
  packet 029.
- **AVX2-only host coverage honestly deferred.** Bullet 4 keeps the
  fallback code + differential-test requirement intact and only
  conditionally waives dedicated AVX2-only host benchmark on host
  availability. No silent removal of the requirement.
- **Diff is inspectable.** The amendment is a pure additive block in
  `plan/tasks/67-rabitq-intel-avx-optimization.md`. Original
  acceptance criteria (lines 252-261) and validation gate
  (lines 175-198) are untouched — the amendment supersedes by
  explicit re-interpretation, not by silent edit. This is the
  correct shape for a post-hoc gate change.

## Minor gaps (do not block this amendment, but track in 035 closeout)

1. **AC4 ("No regression in DiskANN, HNSW, or IVF scan tests") is
   untouched.** The amendment block doesn't reference AC4 status. My
   025 audit flagged the AC4 regression note as missing. Closeout
   audit (packet 035) should cite specific evidence that AC4 holds
   on Intel — either point to an existing differential / regression
   packet or run one. The amendment does not need to change to add
   this; it is closeout-audit work.
2. **AC1 ("Slices A–J all landed") not explicitly closed.** Slice J
   (Intel measurement packet) is functionally satisfied by packets
   020/022/023/027, but the amendment doesn't say so. Packet 035
   should make the slice-to-packet mapping explicit.
3. **Validation gate item 4 ("Performance — headline") still reads
   `at least 4×` / `at least 3×` in the original text.** The
   amendment block (bullets 2-3) reinterprets this but does not
   strike or revise the original line. This is acceptable because
   amendments by addition preserve the original record, but the
   closeout audit must cite the amendment block by section heading
   so a reader following the original gate text is led to the
   superseding interpretation.

## Why approve despite the gaps

The three gaps above are closeout-audit (035) work, not amendment
work. The amendment's job is to (a) honestly record what was
measured, (b) make the gate reinterpretation explicit and
inspectable, and (c) bound what remains required. It does all three.
Forcing the AC4 / AC1 / validation-gate-line-rewrite work into this
packet would conflate "record measured outcome" with "close the
task," which is exactly the conflation packet 025 rejected.

The architectural insight from 027 (scorer is a small fraction of
total wall time → SIMD alone cannot meet the 4x SQL gate) is the
correct technical justification, and the amendment records it in the
task definition so future readers do not chase the original 4x bits=8
threshold as still-pending work.

## Recommendation

- Approve this amendment.
- Packet 035 (closeout audit) must:

  - map each amendment bullet 1-5 to the packet(s) supplying its
    evidence (020, 022, 023, 026, 027, 029, plus AVX2 fallback
    differential-test packet);
  - close AC4 with explicit regression evidence on Intel;
  - close AC1 by listing the packet that satisfies each of Slices A-J.
