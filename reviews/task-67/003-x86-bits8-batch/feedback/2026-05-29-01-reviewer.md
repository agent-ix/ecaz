## Findings

### Confirmed correct

- **API shape parity with NEON Slice D.** `estimate_ip_batch_avx512_bits8`
  (`src/quant/rabitq.rs:3936`) and `estimate_ip_batch_avx2_bits8` (`:3966`)
  match `estimate_ip_batch_neon_bits8` (`:3750`) signature-for-signature
  (`query_scale, query_offset, dimensions, codes, code_len, out_scores`).
  Same `chunks_exact / chunks_exact_mut(2)` outer loop, same
  `finish_scalar_only_estimate(dimensions, 8, sum, code)` call.

- **Slot registration.** `Avx512Bits8` and `Avx2Bits8` arms added to
  `estimate_ip_batch_impl` (`:4173`, `:4188`) before the existing aarch64
  arms. `select_query_dequant_kernel` is reused — no edits to
  `select_x86_query_dequant_kernel_with_bits8` or
  `sum_query_dequant_with_bf16`. Dispatch constraint (task 67, lines
  158–174) honored.

- **Lane tail (dim not a multiple of 16).** Both pair kernels fall
  through to the scalar `while dim_index < dimensions` loop using the same
  `code[i] as f32 * scale + offset` formula (`:3679-3686`, `:3724-3730`).
  Matches packet 002's single-candidate formula exactly.

- **Batch tail (odd `out_scores.len()`).** `chunks_exact_mut(2).into_remainder()`
  yields the trailing single slot, which is filled by the already-reviewed
  single-candidate kernel (`sum_query_dequant_avx512_bits8` at `:3953`,
  `sum_query_dequant_avx2_bits8` at `:3986`). Correct fan-back.

- **Aliasing safety.** `out_pair` is a unique `&mut [f32]` of length 2 from
  `chunks_exact_mut(2)`; writes to `out_pair[0]` and `out_pair[1]` are
  disjoint. `code_chunks` borrows immutably and pairs cleanly with the
  mutable output iterator. No aliased writes.

- **target_feature hygiene.** Pair kernels declare
  `#[target_feature(enable = "avx512f")]` and
  `#[target_feature(enable = "avx2,fma")]`. All intrinsics used
  (`_mm512_cvtepu8_epi32`, `_mm512_cvtepi32_ps`, `_mm512_fmadd_ps`,
  `_mm256_cvtepu8_epi32`, `_mm_srli_si128`, `_mm_loadu_si128`) are covered
  by those gates (no AVX-512BW / VL intrinsic snuck in). `unsafe` is
  contained inside the `target_feature` bodies; outer dispatch uses
  `// SAFETY:` comments anchored to runtime detection — same pattern as
  the bits=1 batched arms at `:4107` and `:4126`.

- **Arithmetic equivalence (AVX2 split halves).** `bytes_lo` uses
  `s0/o0` (lanes 0..8) and `bytes_hi` uses `s1/o1` (lanes 8..16), each
  reused for both code0 and code1. The two-accumulator (`a0+a1`, `b0+b1`)
  reduction is associative-equivalent under f32 within the documented
  1e-5 tolerance, and the differential test asserts that bound.
