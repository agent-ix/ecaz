## Findings

### F1 — No SIMD-backend telemetry in any log (minor)

The four `rabitq8*` variants are run under `--simd-mode auto` and
`--simd-mode scalar`, but none of the `sidecar-*.log`, `suite-run.log`,
or `cloud-bench-*.log` files emit which backend the runtime actually
selected (e.g. `avx512`, `avx2`, `scalar`). With `sidecar_score_p50`
identical to within 0.001 ms between scalar and auto rows (0.022-0.026
ms vs 0.024-0.026 ms), the SQL evidence alone does not prove AVX-512
was engaged. Packet 023's kernel microbench is the actual evidence
that the AVX path is live; packet 027 inherits that.

Suggested follow-up (not blocking this packet's acceptance, but
relevant before any future gate claim): land a small telemetry line in
`bench sidecar-rerank` that prints the selected scoring backend per
variant, and rerun.

### F2 — Within-lane candidate_sql is identical, cross-lane is noisy (informational)

Within the scalar lane, `candidate_sql_p50` is 2.207 / 2.647 /
3.706 ms at nprobe=16/32/64 for **every** variant. Within the auto
lane, 2.419 / 2.912 / 3.406 ms. The within-lane identity is expected
(the four variants share the IVF base index; candidate retrieval is
the same SQL plan and the harness likely uses cached/warm results
across variants). The cross-lane comparison shows scalar **faster**
at nprobe=16 (2.207 vs 2.419 ms) but **slower** at nprobe=64
(3.706 vs 3.406 ms). Inconsistent direction with a ~10% swing on
200-query samples suggests run-to-run jitter, not a real signal. Fine
for evidence framing; do not cite candidate-side SIMD wins/losses
from this run.

### F3 — `bits 4` in load + sidecar with `quant_bits=1` index (informational, not a bug)

The auto suite step logs `--bits 4` on both `corpus load` and
`bench sidecar-rerank` while the IVF base index uses
`quant_bits=1` and the four sidecar variants are `rabitq8*` (8-bit
sidecar quantization). This is the documented sidecar-rerank harness
shape (index bits independent of sidecar score bits). The packet
would be slightly clearer with a one-line note in `manifest.md` that
the `--bits 4` flag is the harness training/probe parameter and not
the sidecar quantization bits.

### F4 — Honest framing in `request.md` (positive)

Lines 11-13 and 53-59 explicitly state "this fills the missing SQL
evidence, but it does not close the 4× headline gate" and explain
the engineering implication: bits=8 kernel work cannot move this
metric. That framing is exactly what the 025 audit asked for. No
overclaim.
