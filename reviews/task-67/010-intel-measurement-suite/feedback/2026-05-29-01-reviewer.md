# Task 67 Packet 010 — Intel Measurement Suite (prep)

## Verdict

Approve as a measurement-prep packet. Suite shape, isolation, and provenance
match the CLAUDE.md "Benchmark Runner: ecaz bench suite Only" rule and
NFR-007. The final Slice J packet must execute this suite on the Intel host
without `--dry-run` and publish the actual throughput / recall artifacts.

of running on Intel is left to a subsequent packet.

## Compliance checks

## Minor concerns / nits

1. `defaults.bits = 4` (`task67-intel-suite.json:11`) propagates as
   `--bits 4` to every `corpus load` / `bench recall` / `bench latency` /
   `bench sidecar-rerank` invocation (visible in `validation.log:13-21`),
   while the lane is named `rabitq1` and the on-disk storage is
   `quant_bits=1` (reloptions). This is internally consistent — `--bits 4`
   is the query-projection width historically used for RaBitQ bits=1
   storage in this repo — but the lane naming combined with `bits: 4`
   defaults is confusing to a reviewer skimming the JSON. Consider either
   a top-of-file comment in `manifest.md` clarifying that `--bits 4` is
   query-side projection (not storage), or making the per-step `bits`
   explicit so the connection between `quant_bits=1` reloption and
   `--bits 4` CLI flag is documented in one place. Non-blocking.

2. `sweep` for both `recall` and `latency` is `[32, 64, 96, 128]` while
   the load uses `nprobe=128` reloption (`task67-intel-suite.json:49`).
   Bench commands override at query time via `--sweep`, so this is fine
   — flagging only because the `defaults.nprobe`-style alignment was not
   centralized. Non-blocking.

3. `truth_cache_file` (`task67-intel-suite.json:68, 156`) is shared
   between scalar and auto-SIMD lanes
   (`truth-ec-real-100k-q200-k10.json`). Correct — ground truth is
   SIMD-independent — but worth a one-line note in the final measurement
   packet's manifest confirming the cache hash is the same across both
   lanes when the suite runs live.

4. `allow_manifest_mismatch: true` (`task67-intel-suite.json:46, 134`)
   should be justified in `manifest.md` for the live-run packet. Prep
   packet is fine.
