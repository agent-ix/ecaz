# Task 67 Packet 013 Reviewer Feedback: Local Runtime Validation Attempt

## Verdict

**Accept as evidence packet.** This is not a code-review request; it is an
evidence-only packet recording (a) why the focused Task 67 differential
scaffold test cannot start locally and (b) why the local CPU cannot satisfy
the AVX-512 acceptance gate. The packet correctly disclaims itself in
`request.md:25-27` and `artifacts/manifest.md:31-35` as a non-validation
packet. No `src/**` changes are included in commit `3fc7e0d65`
(`.../artifacts/cpu-features.log`, `.../artifacts/manifest.md`,
`.../artifacts/runtime-attempt.log`, `.../request.md`), which is correct
for an evidence packet.

## Findings

### Strengths

- Manifest follows NFR-007 shape: head SHA, task bucket, packet path,
  timestamp, lane, fixture, and per-artifact command + key lines
  (`artifacts/manifest.md:1-29`).
- `request.md` cites both packet-local artifact files
  (`request.md:17-18`) rather than `tmp/` or scrollback.
- Runtime log captures the full failure mode including binary path, exit
  code 127, and the cargo "Caused by" chain
  (`artifacts/runtime-attempt.log:11-19`), so the dynamic-loader failure is
  reproducible from the recorded command.
- CPU inventory enumerates the actual `Flags:` line
  (`artifacts/cpu-features.log:13`), making the "no AVX-512" claim auditable
  rather than asserted — reviewers can grep for `avx512*` and confirm absence.
- Interpretation sections in both logs are conservative: they state what the
  evidence does and does not prove, and do not claim AVX2 runtime acceptance
  was achieved (`artifacts/cpu-features.log:15-18`).

### Observations (non-blocking)

1. **Symbol differs from prior context.** Parent context flagged the prior
   blocker as `LockBuffer`; this attempt fails on `pg_re_throw`
   (`artifacts/runtime-attempt.log:14`). Both are unresolved PostgreSQL
   symbols in the unit-test binary, so the class of failure is the same
   (pgrx-linked unit test cannot satisfy backend symbols at load time), but
   the specific symbol moved. Worth noting in a follow-up packet if a
   pgrx-test variant is later attempted — `cargo pgrx test pg18` resolves
   backend symbols via the running postmaster and is the canonical surface
   for tests touching pgrx-flagged code. The packet does not claim
   `cargo pgrx test pg18` was tried; `manifest.md:17` only records
   `cargo test -p ecaz ...`. If the scaffold test was intentionally written
   to be runnable under bare `cargo test`, that intent should be captured;
   otherwise the next attempt should switch surfaces.

2. **Kernels unverified at runtime are not enumerated.** Review focus asked
   for "which kernels remain unverified at runtime." The packet states
   runtime acceptance is unproven for AVX-512 / AVX-512 BF16
   (`artifacts/cpu-features.log:17-18`, `artifacts/manifest.md:33-35`) but
   does not enumerate the specific Task 67 kernel symbols (e.g. bits1 batch,
   bits4 batch, BF16 paths) whose runtime correctness remains unproven on
   this host even for AVX2. Non-blocking because the packet's stated scope
   is "evidence of local limitations," but an enumeration would help the
   Intel validation lane scope its work.

3. **AVX2+FMA runtime not exercised either.** The host *could* in principle
   prove AVX2/FMA runtime acceptance, but the same `pg_re_throw` failure
   blocks that too. The packet correctly says so
   (`artifacts/cpu-features.log:16-18`). No action; just confirming the
   reviewer read it that way.

### Compliance

- NFR-007 (benchmark provenance / manifest): satisfied for an evidence
  packet (`manifest.md:1-29`).
- "No src/** in evidence packets": satisfied — `git show --stat 3fc7e0d65`
  shows only `request.md` and three files under `artifacts/`.
- Packet ordinal `013-` and slug placement under `reviews/task-67/`:
  conforms to packet ordering rules.

## Outcome

Evidence packet is accepted as a faithful record that:

1. Local PG18-linked unit-test surface cannot start the Task 67 scaffold
   test (`pg_re_throw` undefined at dynamic load).
2. Local CPU (i9-10900K) cannot satisfy AVX-512 or AVX-512 BF16 runtime
   gates regardless of (1).

Full Task 67 runtime acceptance still requires an Intel validation lane
with (a) a pgrx-test or otherwise PG-symbol-resolving runner and (b)
AVX-512 + AVX-512 BF16 capable silicon. Recommend the next runtime packet
either switch to `cargo pgrx test pg18` locally for the AVX2 paths, or
move directly to the Intel lane and skip local runtime.
