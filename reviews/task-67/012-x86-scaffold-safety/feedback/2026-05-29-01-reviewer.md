### Wrappers cannot be reached from a feature-deficient host

The dispatch site is the differential test at
`src/quant/rabitq.rs:4829-4848`. It iterates the
`SUM_QUERY_DEQUANT_KERNELS_FOR_TEST` registry
(`src/quant/rabitq.rs:4472-4540`) and calls
`task67_kernel_features_available(kernel.required_features)`
(`src/quant/rabitq.rs:4755-4770`), which evaluates
`std::arch::is_x86_feature_detected!` for each named feature and `continue`s
when any feature is missing. The `required_features` strings in the registry
match the wrapper's `target_feature` attribute exactly for every entry:

- `avx512_bits1` → `["avx512f"]`
- `avx2_bits1` → `["avx2","fma"]`
- `avx512_bits4` → `["avx512f","avx512bw"]`
- `avx2_bits4` → `["avx2","fma"]`
- `avx512_bits8` → `["avx512f"]`
- `avx2_bits8` → `["avx2","fma"]`
- `avx512_bf16_bits4` → `["avx512f","avx512bf16"]`

The scalar wrappers have `required_features: &[]` and use no
`#[target_feature]`, which is consistent with the new docstring listing only
fixture shape (no CPU precondition). The fixture-shape preconditions named
in each wrapper's docstring are satisfied by the harness at
`src/quant/rabitq.rs:4796-4827` (packed code sized `packed_bytes +
RABITQ_SCALAR_LEN`, `query` length `dim`, bits8 scale/offset precomputed
when `bits == 8`, bf16 mirrors `None` when the bf16 feature is off — and
the bf16 wrapper short-circuits via `fixture.query_bf16?` and
`fixture.dequant_lut_bf16?`).

`bench_api` is `#[cfg(test)] pub(crate)`, so it is unreachable from any
production caller; the only invocation path is the differential test in
the same module's `tests` submodule.
