# Feedback: Cloud install clean target option

## Verdict

Approve. The change is narrow, opt-in, well-tested, and addresses the
packet 029 bf16 disk-full failure without changing the default install path.

## Review scope

- Commit `25f2b4754` "Allow cloud install to clean remote cargo target"
- Touched: `crates/ecaz-cloud/src/commands/install.rs` only
- Noted follow-up: `650fb11c8` "Clean cloud cargo target before git reset"
  (not under explicit review here but reinforces the same intent)

## Findings

### Pass: opt-in default
`#[arg(long)] pub clean_cargo_target: bool` defaults to false. The new
script branch only emits `cargo clean` when the flag is set; the existing
install path is byte-for-byte unchanged when the flag is absent. Verified
the three pre-existing unit tests still pass the same flag value (`false`).

### Pass: no user input reaches the new shell fragment
The new fragment is a hard-coded literal `"  cargo clean\n"`. No
templated user input flows through it, so `shell_escape` is not required
for this path. Existing escaping for `url`, `r`, `origin_ref`,
`extension_features_arg` is untouched.

### Pass: wipe is scoped to the cargo target
`cargo clean` runs after `cd /var/lib/pgsql/build/ecaz`, so it only
removes that crate's `target/` directory. It does not touch `$HOME`,
sibling checkouts, the postgres data dir, or other workspace paths.

### Pass: idempotent
`cargo clean` on a tree with no `target/` exits 0, so a fresh host
running with `--clean-cargo-target` does not fail. In commit
`25f2b4754` the clean is placed after `git reset --hard {r}`, which
guarantees `Cargo.toml` is present. The follow-up `650fb11c8` moves it
earlier (after `cd` but before `git reset`); this still requires a
checked-out `Cargo.toml`, which is guaranteed by the preceding
`git clone` branch.

### Pass: test coverage
`install_script_can_clean_cargo_target_before_build` asserts the
fragment is present and ordered before `cargo pgrx install`. The
follow-up commit extends it with an ordering check against
`git reset --hard`, which strengthens the contract.

### Pass: no drift
Only `install.rs` is touched. CLI surface gains one opt-in flag.
No GUC, planner, or storage-format changes.

## Minor notes (non-blocking)

- Under `set -eux`, any non-zero exit from `cargo clean` (e.g. a
  permission-damaged subtree) will abort the whole install. That is
  acceptable for an opt-in recovery flag, but worth keeping in mind if a
  future caller wants "best effort" cleaning; a `cargo clean || true`
  would be the obvious knob if that ever comes up. No change requested.
- The placement chosen in the follow-up (`650fb11c8`, before
  `git reset --hard` / `git clean -fd`) is the better position: it
  reclaims disk before subsequent steps that may themselves need space.
  No further action needed in this packet.

## Recommendation

Land as-is. Continue with the packet 029 bf16 on/off SQL measurement
that this support checkpoint unblocks.
