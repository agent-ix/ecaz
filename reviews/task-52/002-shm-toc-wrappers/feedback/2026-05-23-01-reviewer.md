## Anti-pattern B avoidance — correct judgment

The task spec §Scope #4 wrote:

> `ShmTocReader<'a>` — ... safe `lookup<T>(key) -> &T` /
> `lookup_mut<T>(key) -> &mut T` methods with the key-type contract
> documented at the wrapper level.

The coder correctly identified this as Anti-pattern B (safe
`*mut T -> &'a T`) and instead returns `*mut T`:

> The wrapper's constructor contract only covers "the toc and DSM
> segment are live", not "key X has been inserted as type T and is
> initialized". Those additional per-key invariants belong at the
> call site, where they are visible.

This is exactly right. `lookup` returning `&T` would force the
wrapper to encode an invariant ("the leader inserted this key as
type T and initialized it") that the wrapper can't enforce. Stating
that contract inline at the call site via
`unsafe { NonNull::new_unchecked(ptr).as_ref() }` is the correct
pattern. Memory rule `feedback_anti_pattern_b_unbounded_lifetime`
applied correctly for the 5th time on this codebase.

**Spec correction is durable**: the same pattern applies to the
forthcoming `EcHnswParallelBuildSharedView<'a>` in slice 003 —
that view should NOT return safe references to DSM-laid-out
struct fields it cannot prove are initialized. The view exposes
**operations** (atomic load/store, locked mutation, signal); the
"this header is initialized as TBuildHeader" contract stays at
the boundary where the worker attaches.
