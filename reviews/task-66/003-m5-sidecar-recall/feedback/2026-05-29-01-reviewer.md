## Methodology check

The comparison method is the right one:

1. Build an isolated index with `rerank=off` (so the sidecar
   rerank kernel is the *only* code path that differs between
   runs). Fixture prefix
   `task66_m5_10k_ivf_rabitq1_n64_sidecar_off` is unique to this
   packet — no shared-surface contamination.
2. Run the bench suite with NEON dispatch (default) → recall@10
   per variant.
3. Force scalar with `ECAZ_SIMD=scalar` via the existing env
   override at `src/quant/simd.rs:50` → recall@10 per variant.
4. Subtract.

The runtime backend override is the correct mechanism for this
comparison — it gates the whole `select_query_dequant_kernel`
dispatch through `SimdBackend::Scalar`, so every scoring call
funnels into the same scalar fallback path the differential
unit tests use. The recall delta is therefore the *runtime
scoring kernel* delta, not contaminated by build-time
differences.

Both `free` and `tid-sorted` read modes are tested. Tid-sorted
is the one reported in the manifest; the `free` numbers should
be in `results.jsonl` if needed for cross-mode comparison.

Fixture details (10k corpus, 200 query rows, `nlists=64`,
`nprobe=32`, `candidate_k=50`, `k=10`, queries_limit=100) are
all recorded.
