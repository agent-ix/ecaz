## Findings

### The change does what the packet claims

Before:

```rust
/// # Safety
/// ...
#[cfg(target_arch = "aarch64")]
#[inline]
unsafe fn prefetch_read_l1(ptr: *const u8) {
    core::arch::asm!("prfm pldl1keep, ...");
}
```

With call sites wrapped in `unsafe { prefetch_read_l1(...) }`
each carrying their own SAFETY comment.

After:

```rust
#[cfg(target_arch = "aarch64")]
#[inline]
fn prefetch_read_l1(ptr: *const u8) {
    // SAFETY: `prfm pldl1keep` is a non-faulting cache hint and
    // does not architecturally dereference `ptr`; ...
    unsafe {
        core::arch::asm!("prfm pldl1keep, ...");
    }
}
```

Call sites collapse to plain `prefetch_read_l1(code.as_ptr()
.add(byte_base + 64))` — no `unsafe` block at the call site.

This is the textbook pattern for inline asm that's
architecturally non-faulting: encapsulate the `unsafe` in the
function body with the rationale, expose a safe fn to callers.
The SAFETY justification is correct — `prfm pldl1keep` is a
non-faulting hint per AArch64 architecture reference, and the
pointer-arithmetic safety is the caller's responsibility but the
**dereference** safety is unconditional.

### Net effect on unsafe surface

- **Removes one `unsafe fn`** from `rabitq.rs` (`prefetch_read_l1`).
- **Removes two `unsafe { }` blocks** at the call sites in
  `sum_query_dequant_neon_bits1` and `sum_query_dequant_neon_bits8`
  (the calls are now inside `unsafe fn` bodies but no longer
  need their own `unsafe` wrapper since the callee is safe).
- **Adds one `unsafe { }` block** inside `prefetch_read_l1`.

Net: one fewer `unsafe fn` and one fewer `unsafe` block in the
file. Cleaner safety topology.
