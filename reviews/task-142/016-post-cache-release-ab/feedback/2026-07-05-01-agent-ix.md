## Epoch-cache invalidation correctness (spec #1 risk): SOUND

Read the cache mechanism directly. Every cache keys strictly on
`(index_relid, active_epoch)`:

- `SpireRoutingHierarchyCacheKey` (`scan/types.rs:72`), built per query from
  `index.relid()` + `root_control.active_epoch`
  (`coordinator/remote_candidates/scan_output.rs:130-133`) — both read fresh from
  the authoritative root control each query.
- `load_cached_coordinator_routing_hierarchy` (`scan/routing.rs:167-187`) holds a
  single-slot `Option<(key, hierarchy)>` thread-local, serves only on
  `*cached_key == cache_key`, and overwrites the slot on a miss. A mid-flight
  epoch publish bumps `active_epoch` → key mismatch → forced reload + eviction of
  the stale entry. No stale-serve path exists.
- Same pattern replicated in `SpireCoordinatorFanoutManifestCacheKey`
  (`hierarchy_snapshots.rs:311-369`) and `SpireActiveEpochAnchorCacheKey`
  (`coordinator/snapshots.rs`).

Pool reuse (packet 012): confirmed at runtime — `socket_open_sum=0`,
`connection_pool_miss_sum=0`; the "3 fresh sockets per query" regression is gone.
Prepared statements (packet 009): confirmed — cached `Option<Statement>` slots
with a get-or-prepare helper (`dispatch.rs:474-478, 608-613`).

## Findings

1. **[medium] `nlists=2048` A/B cell missing.** Phase 3 explicitly requires
   nlists {128, 1024, **2048**} at 50k/100k. Packet 016 covers only {128,1024}.
   The staircase-flattening claim is only demonstrated over two nlists points.
   Run the 2048 cells (50k + 100k) before Task-142 closeout; the packet stands as
   an anchor without them, but the task does not close.

2. **[low] No explicit epoch-change invalidation regression test.** The reuse
   test (`scan/tests/routed_rows.rs:376-387`, load_count 1 then 0) covers the
   *hit* path only. There is no test that warms the cache at epoch N, calls again
   with a *different* `active_epoch` key, and asserts a reload (load_count back to
   1) + stale eviction. The logic is correct by inspection, but this is the spec's
   #1 correctness risk and deserves a guarding test.

3. **[low] Aggregate-only A/B in 016.** The closeout rule warns against benching
   only the aggregate. 016 is the aggregate anchor; per-change attribution rests
   on packets 002–015, which I did not re-verify in this review. Acceptable given
   those packets exist, but the final closeout summary should tie the aggregate
   delta back to the per-layer packets.

4. **[nit] Result-ID identity asserted via recall, not a raw ID diff.** Consider
   emitting/committing a result-set digest so the "identical result IDs pre/post"
   evidence line is directly satisfiable rather than inferred.
