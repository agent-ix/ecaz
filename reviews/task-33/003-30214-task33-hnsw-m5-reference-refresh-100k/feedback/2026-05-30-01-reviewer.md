## Worker curve at real100K

| workers | wall s | speedup vs `w1` |
| ---: | ---: | ---: |
| 1 | 98.05 | 1.00× |
| 2 | 24.84 | 3.95× |
| 4 | 18.47 | 5.31× |
| 8 | 21.85 | 4.49× (regression vs `w4`) |

The shape repeats the real50K result: gains through `w4`, regression
at `w8`. At 100K the 1→2 gain is much larger (3.95× vs 1.36× at 50K)
because the single-worker baseline is slower in absolute terms,
which makes the parallel overhead amortise better. The `w4 → w8`
regression is the load-bearing observation, and it matches Task 26.

Index size: `136,544,256 B` at every worker count (1365.4 B/row) —
graph topology byte-equivalent across worker counts, same as at 50K.

Recall on the workers=4 index:

| ef_search | recall@10 | mean q-time |
| ---: | ---: | ---: |
| 64 | 0.8350 | 1.71 ms |
| 128 | 0.9205 | 2.14 ms |
| 200 | 0.9575 | 2.88 ms |
| 400 | 0.9775 | 4.81 ms |

Recall is lower at every ef than at 50K (as expected — more rows,
same `m=16/ef_construction=128`). The 400-ef value (0.9775) is
within 0.5 pp of the 50K 400-ef value (0.9800), so the recall floor
is preserved relative to the smaller corpus. The lower ef points
(64, 128) show a steeper degradation at 100K — that's expected for
HNSW scaling, not a regression.

## Phase 2 decision strength

Two packet measurements (50K + 100K) now converge on the same
conclusion:

- The current ADR-048 ConcurrentDsm path scales useful-but-modestly
  through `w4` and regresses at `w8` on the M5 host.
- Building a 100K HNSW index in 18.5 seconds with 4 workers is
  acceptable for the M5 reference role, but not where HNSW will win
  on bulk builds at larger scale.
- The shape **does not** suggest that more worker-threshold tuning
  will pay off — it suggests the architectural constant is the
  graph-construction work inside PostgreSQL, not the worker count.

That's the correct evidence to base the Phase 2 lane choice on. The
packet's recommendation ("offline/staged bulk build ADR as next
checkpoint, direct DSM ingestion only if a focused profile proves
queue/drain is still dominant") is right and matches the Task 33
plan §Phase 2's three options.
