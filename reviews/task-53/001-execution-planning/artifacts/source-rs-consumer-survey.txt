New wrappers per task spec
--------------------------
1. **`DetoastedVarlena<'a>`** — already lifted; promote `&[u8]` /
   `&[T]` view methods to typed-slice accessors, add `'a` lifetime
   that ties to the wrapper's borrow scope (currently `'static`-ish
   via Drop owning the pointer).

2. **`FlatFloat4Source<'a>`** — single typed wrapper that absorbs both
   `FlatFloat4ArrayRef` and `FlatFloat4VarlenaRef` (currently split as
   `FlatFloat4SourceRef` enum). The split-by-input is fine; what's new
   is moving them to `src/am/common/datum.rs`. The internal unsafe
   blocks (header read, dims, data offset, from_raw_parts) become
   wrapper-side; consumer-side gets a single safe `as_slice() -> &[f32]`
   call.

3. **`EcVectorDatum<'a>`** — typed Datum -> EcVector extraction. Source.rs
   uses `IndexedVectorAttribute::kind` to dispatch through
   `FromDatum<EcVector>` or `FromDatum<...>` paths. The wrapper bundles
   this dispatch into one safe method `view(datum, kind, label) ->
   EcVectorView<'a>`.

4. **`AttnumLookup`** — `pg_sys::get_attnum(rel.rd_id, attname.as_ptr())`
   safe wrapper. 1 consumer site at line 269.

Estimated consumer-side reduction
---------------------------------
- AttnumLookup migration: -1 (line 269 single-op).
- Lifts of DetoastedFloat4Datum + FlatFloat4ArrayRef + FlatFloat4VarlenaRef
  + FlatFloat4SourceRef from source.rs to common/datum.rs: removes the
  internal-impl unsafe blocks from source.rs (they move to common; common's
  total wrapper-side cost grows). Estimated -12 to -15 source.rs blocks.
- Consumer call sites (`unsafe { Wrapper::from_datum(...) }`) become safe
  through the new `from_datum` returning `Option<Self>` + the contract
  encoded in the wrapper's lifetime: -3 to -5 consumer-side.

Total estimated source.rs reduction: -16 to -21. Target: 29 -> ≤14
(-15 minimum). Margin is thin but tractable.

10 SIMD blocks (lines 84, 93, 115, 125, 157, 178, 195, 215, 237, 252)

Open questions for slice time
-----------------------------
- `EcVectorDatum<'a>` — task spec mentions this but source.rs
  currently dispatches per `IndexedVectorAttribute::kind` via
  `FlatFloat4SourceRef`. The IndexedVectorKind enum has multiple
  variants; the wrapper may need an enum-shaped Source type. Worth
  inspecting at slice 002 design time.
- `DetoastedVarlena<'a>` lifetime addition — currently the struct
  owns the detoasted varlena via Drop. Adding `'a` requires deciding
  whether borrowed vs owned variants both flow through one type or
  split.
