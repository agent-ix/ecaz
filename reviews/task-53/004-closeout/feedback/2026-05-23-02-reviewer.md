## Code review

Read all four touched files end-to-end.

**`src/am/common/datum.rs`** — sound:
- `FlatFloat4Source::from_datum` is the only unsafe surface; the
  per-kind extractors (`extract_array`, `extract_varlena`) are private
  `unsafe fn` so the unsafe burden is concentrated.
- All inner `unsafe { ... }` blocks have correct SAFETY comments tied
  to `detoasted`'s ownership of the backing storage.
- `as_slice(&self) -> &[f32]` ties the borrow lifetime to `&self`; the
  detoasted varlena is dropped only when `self` is dropped, so the
  invariant is enforced by Rust's borrow checker — no escape risk.
- `AttnumLookup::lookup` correctly null-guards `rel` before the
  `(*rel).rd_id` deref and CString-encodes `attname` (returning `None`
  on NUL-bearing names rather than `pgrx::error!`-ing — a behavior
  change the slice 003 review already accepted).
- `EcVectorDatum`/`EcVectorView` shim is honestly documented as a
  stand-in for a future first-class `EcVector` type, with a
  `TODO(slice-003)` marker.

**`src/am/common/detoast.rs`** — `as_typed_slice<T: Copy>` rejects
non-aligned prefix/suffix and non-multiple lengths cleanly. The
`Copy` bound is the right floor for transmuting packed bytes.

**`src/am/ec_hnsw/source.rs`** — the consumer migration replaces
`DetoastedFloat4Datum` / `FlatFloat4ArrayRef` / `FlatFloat4VarlenaRef` /
`FlatFloat4SourceRef` plus their helpers with the common wrappers via
`with_flat_float4_source_from_datum` and
`with_indexed_ecvector_from_slot_reader`. Closure-CPS preserved
(`feedback_anti_pattern_b_unbounded_lifetime` honored — no `*mut T ->
&'a T` escape paths).

## One non-blocking nit — doc/types drift after phantom-`'a` cleanup

Commit `f86e26d4f` dropped the phantom `'a` from `FlatFloat4Source`
and `EcVectorDatum` (correctly — they own their detoasted backing and
the `&self`-tied `as_slice` borrow is what protects callers). However
the docs and handoff list still spell the old names:

- `datum.rs:39-40` says "ties its slice lifetime to `'a` so the borrowed
  view cannot escape" — the struct now has no `'a` parameter.
- `datum.rs:57-58` SAFETY says "backing varlena outlives `'a`" — no `'a`.
- `datum.rs:222-223` `EcVectorDatum::from_datum` doc says "outlives `'a`" — no `'a`.
- `handoff-list.md:17,20` types are spelled `FlatFloat4Source<'a>` /
  `EcVectorDatum<'a>` / `EcVectorView<'a>` — only the third still has
  a lifetime parameter.

**Fix**: one-shot pass that strikes `'a` from the docs and the handoff
list and reframes the contract as "borrow lifetime tied to `&self` via
the owned `DetoastedVarlena` backing" (which is what the code actually
guarantees and is arguably stronger than a free-standing `'a`). Not
blocking close — the contract is correct in code; only the prose is
stale. Land as a slice-005 doc-drift micro-commit on this branch
before opening Task 54, or fold into Task 54's planning packet.
