## Anti-pattern B audit — looked twice, passes

`grep -nE "pub.*fn.*-> *&" src/am/common/datum.rs` returns two
hits worth examining:

1. **`FlatFloat4Source::as_slice(&self) -> &[f32]`** (line 164)
2. **`EcVectorView::as_slice(&self) -> &'a [f32]`** (line 207)

Both LOOK like anti-pattern B candidates. Audit determined neither
is, for distinct reasons:

**FlatFloat4Source::as_slice**: the wrapper struct has `_detoasted:
DetoastedVarlena` as an OWNED field (line 42). The detoasted
backing storage lives inside the wrapper; the returned `&[f32]`
borrows from `&self` and cannot outlive the wrapper by Rust's
borrow rules. The internal `unsafe { from_raw_parts(data_ptr, len) }`
is justified by the construction-time validation (line 100-138:
array header read, FLOAT4OID check, ArrayGetNItems, alignment
check on data_ptr). Sound.

**EcVectorView::as_slice**: returns the inner `data: &'a [f32]`
field. The `'a` is set at `EcVectorDatum::view(&self) -> EcVectorView<'_>`
where the lifetime correctly elides to `&self`'s lifetime. So
the slice is bound by the parent's borrow. Sound.

Neither is anti-pattern B's prohibited pattern (safe `*mut T -> &'a T`
with unbounded `'a`). Both are owning-wrapper safe-accessor patterns
that match the slice-447 `DetoastedVarlena::as_bytes() -> &[u8]`
precedent.

## Phantom `'a` lifetime — style nit, not unsoundness

`FlatFloat4Source<'a>` has `PhantomData<&'a [f32]>` but no field
actually borrows from `'a`. The `_detoasted` is owned; `data_ptr`
is a raw pointer; the `'a` parameter is decorative. The struct
could be `FlatFloat4Source` (no lifetime) and behavior would be
identical.

Not blocking — phantom lifetimes are a common Rust pattern when
the author wants to *suggest* a lifetime contract that the
compiler can't enforce. The actual lifetime safety holds via
ownership of `_detoasted`. Slice 003 or a future cleanup pass
could drop the unused `'a` for clarity; not required.
