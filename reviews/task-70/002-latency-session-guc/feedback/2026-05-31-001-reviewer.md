# Review: Task 70 / Packet 002 — Latency Session GUC Support — ACCEPT with note

Reviewed the source diff in `19c4a2126ea4dacd39ba38e6a833545ccaa11ba1`
(`crates/ecaz-cli/src/commands/bench/{latency,suite}.rs`) plus the manifest.

## What this packet does

Wires `--session-guc name=value` (repeatable) into `ecaz bench latency`
and adds a `session_gucs: [...]` field to suite `LatencyStep` configs, so
benchmark workers can opt into `ec_diskann.scan_profile_notice=on` (and
similar) without per-suite shell wrappers.

## What I verified against the source

- **Worker connection wiring is correct.** Each per-worker connection
  runs `SET {name} = {value}` after sweep/rerank GUCs but before
  adaptive/IVF options and queries — that ordering means scan profile
  notices are emitted on the first relevant query, not lost during
  warmup setup.
- **Name validation prevents most injection.** `validate_guc_name` splits
  on `.` and validates every part with `profiles::validate_ident`, so a
  malicious name like `foo; DROP TABLE x` is rejected.
- **Empty value rejection.** `parse_session_gucs` errors on empty value
  (the `;DROP` style attack via value would need a syntactically valid
  segment; the runner is operator-only so the threat is "typo causes
  surprise" not "untrusted input attacks DB").
- **No new unsafe.** Confirmed.
- **Tests cover happy path + three malformed shapes**: missing `=`,
  empty value, hyphen in name. Suite test asserts the value flows into
  expanded args. Good coverage for plumbing-only code.

## Note (non-blocking)

**`value` is interpolated raw into `SET {name} = {value}`.** Names are
identifier-validated; values are not. For internal operator tooling
this is acceptable — anyone running `ecaz bench` already has full DB
access — but a careless value like
`--session-guc 'work_mem=64MB; DROP TABLE x'` would execute the
trailing statement. Two cheap mitigations if you want defense in depth:

1. Quote the value: `SET {name} = '{escape_single_quotes(value)}'`.
   Works for any GUC that accepts a string; the GUC framework
   handles type coercion.
2. Or use `pg_catalog.set_config($1, $2, false)` with bound
   parameters — fully injection-safe but requires changing every
   benchmark-side GUC set, not just this one.

Neither is required for Phase 1 measurement work; flag for a later
hygiene pass if this surface grows.
