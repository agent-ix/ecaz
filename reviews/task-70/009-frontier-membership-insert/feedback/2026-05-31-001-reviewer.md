# Review: Task 70 / Packet 009 — Frontier Membership Insert — ACCEPT

Reviewed `31de2206a6eda1578d48d90e70661eaf24108fda`
(`src/am/ec_diskann/scan.rs` line 458, 522, 543, 562 changes),

membership-insert summary.

## What this packet does

Collapses the two-step "contains then insert" pattern in the
neighbor loop into a single `HashSet::insert(nbr)` whose `bool`
return value drives the skip:

```rust
// old: 2 hash ops per first-seen neighbor
if scratch.in_frontier.contains(&nbr) { continue; }
... push_frontier_entry(.., scratch, ..)  // inserts inside

// new: 1 hash op per first-seen neighbor
if !scratch.in_frontier.insert(nbr) { continue; }
... push_frontier_entry(.., ..)  // no longer touches scratch
```

`push_frontier_entry` is also simplified — it no longer takes
`&mut VisitedState`. Entry-point membership is inserted explicitly
before the initial push.

## What I verified against the source

- **`HashSet::insert(value)` semantics are correct.** Returns `true`
  on new insertion, `false` if already present. `if !insert(nbr)`
  is the exact semantic equivalent of the old
  `if contains(&nbr)` skip path. Confirmed against std docs and the
  diff context.
- **Entry-point handling preserved.** Explicit
  `scratch.in_frontier.insert(entry.tid)` before the entry push
  replaces the in-helper insert. Same net effect.
- **`INVALID` neighbor skip still happens before the membership
  insert** — INVALID slots do not pollute the visited set. Verified
  against diff line 514-520 context (neighbor_started/INVALID
  handling preserved upstream of the change).
- **Tombstone-retention behavior preserved.** The
  `if picked.emittable` gate from packet 007 is unchanged; sc_018
  test still passes (cargo-test reports 19 passing).
- **`push_frontier_entry` simplification is mechanical.** Removing
  the `scratch` param makes the helper do exactly what its name
  says.
- **No new `unsafe`. No anti-pattern-B issues.** Confirmed.

## Important inference from this slice

The packet 008 sub-timers showed `frontier_candidate_heap_us` +
`frontier_visited_set_us` combined were only ~12 us at L200. But
this slice — which moves work between exactly those two buckets and
removes one hash op per first-seen neighbor — recovers **77 us** of
frontier_us at L200. That confirms the packet 008 sub-timers
significantly *under-account* the actual cost of these inner ops:
the per-op `Instant::now()` wrapping is too coarse for individual
hash-table operations, but the cumulative wall time is real and
recoverable.

**Operational lesson**: trust the operation counts (which showed
~5256 visited_set_ops at L200) and the *cumulative* wall-time
deltas across slices, more than the per-op micro-timers. Future
slices that remove or batch redundant per-visit work in the
unaccounted residual likely have similar 5–10 % gains available.
