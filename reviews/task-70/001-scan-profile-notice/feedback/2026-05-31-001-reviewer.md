# Review: Task 70 / Packet 001 — Scan Profile Notice — ACCEPT

Reviewed the actual source diff in `a93e464024818b64bd18b0b438d2652dc0964d8f`
(`src/am/ec_diskann/options.rs`, `src/am/ec_diskann/routine.rs`) plus the
packet manifest.

## What this packet does

Adds an opt-in `ec_diskann.scan_profile_notice` USERSET bool GUC (default
`false`) that, when enabled, routes `amrescan` through a `_profiled` variant
emitting one NOTICE per query with per-phase microsecond timings and event
counts (graph reads, prefilter scores, reranks, results).

## What I verified against the source

- **Default-off contract holds.** `register_gucs` wires the GUC at
  `USERSET` with default `false`; `current_session_list_size` style accessor
  pattern is reused; unit test `scan_profile_notice_guc_defaults_to_off`
  asserts the default. The unprofiled `execute_diskann_scan` path is the
  default and pays zero `Instant`/`RefCell` overhead.
- **No new `unsafe` blocks.** Confirmed by reading the full diff. The
  profiled path uses `RefCell` + closures inside the existing PG callback
  boundary, which is the right shape per
  `feedback_anti_pattern_b_unbounded_lifetime`.
- **`frontier_us` derivation is honest.** Computed as `vamana_scan_with`
  wall time minus the four sub-phases that were measured inside the
  closures (`graph_read_decode_us` + `prefilter_score_us` +
  `heap_prefetch_us` + `exact_rerank_us`), using `saturating_sub` to
  avoid underflow if measurement jitter inverts the relation. This is
  the residual orchestration cost — a sensible Phase 1 split.
- **`setup_us` derivation.** Calculated as
  `total_started.elapsed() - entry_resolution_us` at the moment entry
  resolution completes. That equals "all time before entry resolution
  started" — i.e., true pre-resolution setup. Labeling is accurate.
- **NOTICE format covers the columns the request promises.** All 17
  fields in the request text appear verbatim in `emit_scan_profile_notice`.

## Concerns (non-blocking)

1. **Code duplication.** `execute_diskann_scan_profiled` is a near-clone
   of `execute_diskann_scan` with closure wrappers. That is the right
   tradeoff for keeping the default path free of per-call profiling
   overhead, but it creates two scan paths to keep in sync. Acceptable
   for a developer measurement aid; flag for a later refactor once Phase
   1 ranks the P0 slices and the profile path's shape stabilises.
2. **No smoke test for the profiled path.** The only unit test is the
   GUC default check. The profiled execution path is sizable and has
   never run under tests. A small integration smoke (set GUC, run a
   tiny synthetic scan, assert NOTICE emitted, no panic) would be cheap
   insurance. Not blocking Phase 1 measurement work, but worth adding
   before the GUC graduates beyond "developer switch."
3. **`setup_us` definition is implicit.** A one-line comment near the
   `setup_us = total_started.saturating_sub(entry_resolution_us)`
   computation would make future readers understand that it is
   pre-entry-resolution time, not post-setup-pre-scan time. Cheap
   clarity win.

## Verdict

Accept. This unblocks Phase 1 — capture NOTICE output on M5 real10K and
real100K fixtures at the recall points Task 70's plan calls out, combine
with `EXPLAIN (ANALYZE, BUFFERS)` and external profiler evidence, and
rank P0 slices off that data.

The Follow-Up section of `request.md` already tracks that next step.
