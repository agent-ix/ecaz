## What this packet does

Adds the unit test I flagged as missing in my packet 008 feedback —
direct coverage of `vamana_scan_with_frontier_profile`. Pure
test-only change, no production code touched.

The test asserts four things:

1. Profile path returns the same results as `vamana_scan` (default
   path) on the same input.
2. The prefetch hook is invoked with `rerank_budget` TIDs.
3. All four frontier counters (`candidate_heap_ops`,
   `visited_set_ops`, `neighbor_slots`, `retained_inserts`) are
   positive.
4. `retained_inserts >= rerank_budget` — sanity floor for the
   bounded retained set.

## What I verified against the source

- **Result-parity assertion is the strong one.** `assert_eq!(got,
  expected, ...)` against the default-path output catches any
  observable behavior divergence between profile-on and
  profile-off code paths. Strongest possible assurance that the
  profile wrapping doesn't change semantics.
- **Counter-only assertions, not timer-based.** Honors my packet 008
  observation that per-op `Instant` timers quantize to zero on
  small/fast fixtures. The test author preempts that footgun.
- **Prefetch verification.** Captures `prefetched: Vec<ItemPointer>`
  via a closure, then asserts `prefetched.len() ==
  params.rerank_budget`. Confirms the prefetch hook is still
  wired up correctly under profile mode.
- **`retained_inserts >= rerank_budget` floor is correct.** With
  the packet 007 emittable gate, the retained set holds only
  emittable candidates. To have `rerank_budget` items going into
  rerank, the retained set must have had at least that many
  inserts. The inequality (≥, not ==) correctly accounts for
  retained inserts that exceeded rerank_budget before
  filtering/truncation.
- **No new `unsafe`. No production code touched.** Confirmed.
- **Test fixture (`chain_graph(12, 4)`)** exercises multi-hop
  traversal, which is what triggers heap push/pop and visited-set
  ops. Adequate for smoke purposes.
- **Tests pass.** 19 → 20.

## Minor notes

1. **Single topology (chain).** Reasonable for a smoke test. If the
   profile path ever grows more complex (e.g. branching control
   flow per topology), additional topology coverage would be
   warranted. Not required now.

2. **Timer subfields (`candidate_heap_us`, etc.) are not asserted.**
   Correct decision — they may legitimately be zero on this
   fixture. The op-count assertions are the right signal.

3. **`prefetched.len() == rerank_budget`** is an exact equality;
   the prefetch path could theoretically dedupe to fewer in edge
   cases (e.g. if some retained candidates were dropped after
   filter). Worth a comment if the equality ever becomes a `>=`,
   but not a blocker.
