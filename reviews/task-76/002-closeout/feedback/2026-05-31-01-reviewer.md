# Task 76 packet 002 — closeout

## Decision

**Accept with one substantive note.** The "keep current SPIRE defaults
unchanged" decision is defensible if the user-perspective is "pick the
best AM available" (IVF dominates at matched recall). But the closeout

Task 76 can close on this round if the quality-preset shelve is
explicitly justified (or revisited).

## Finding — Phase 2 option 2 (quality-preset reloption) not addressed

The Task 76 spec explicitly listed three Phase 2 shapes:

1. Change `top_graph_search_list_size` and `nprobe` defaults
2. **Add a quality-preset reloption** (`spire_quality=balanced|fast|high`)
   that maps to vetted `(tg, nprobe)` pairs, keeping the current
   default unchanged
3. Adaptive default keyed on corpus size

The closeout's "keep current defaults" decision rules out option 1 and
option 3, but option 2 was specifically designed to ship the Pareto
points to users without touching the default. The Task 76 data
supports it directly:

- `spire_quality=fast` → `tg16 nprobe=16` (current default,
  recall 0.8525, p50 26 ms)
- `spire_quality=balanced` → `tg32 nprobe=32`
  (recall 0.9310, p50 48 ms — +7.85pp recall for 1.8x latency)
- `spire_quality=high` → `tg96 nprobe=96`
  (recall 0.9975, p50 147 ms — quality ceiling)

For a SPIRE-bound user (e.g. needing distribution properties IVF
doesn't have), option 2 is a clear win and the Task 76 evidence is
sufficient to ship it. The closeout doesn't explain why it was
shelved.

Two acceptable responses:

- **Justify the shelve in the closeout:** e.g. "preset reloption is
  shelved because [no SPIRE-bound user need yet / wiring cost / scope
  outside one task]". Then the close is clean.
- **Reopen Phase 2 for the preset:** add the reloption as a narrow
  slice and ship the three preset points. Defaults stay the same.

Either is fine. Silently shelving an explicitly-listed Phase 2 option
is what I'm flagging.
