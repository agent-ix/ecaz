## New highest-standards review of `f4caf3c23` + `e827d8ee7`

### Soundness pass

All three structural fixes verified:

- **`mem::replace` + scoped `Box::from_raw`**: atomically nulls the
  field, then drops the box on the swapped-out raw pointer. Drop-safe
  (panic between replace and drop still leaves the field null and
  the box leaked once, but never double-freed). Correct pattern.
- **`Option<Box<T>>` for `heap_rerank_state` + `pq_fastscan_model`**:
  proper Rust ownership; `None` is the empty state, `Some(Box::new(...))`
  stores, `take()` or `= None` drops. No unsafe needed.
- **`RelationHandle` for `visit_ivf_posting_refs_for_block_sequence`**:
  typed boundary at function signature; call site validates via
  `NonNull::new(...).unwrap_or_else(error!)`. Anti-pattern A removed.

No new UB. No aliasing hazards. No lifetime erosion.

### Honest accounting of the deferral

The commit message explains why `prepared_query`/`candidate_dedup`/
`posting_scratch_soa` stayed as `*mut`: "borrow-checker constraints
in `materialize_probe_candidates`". The visitor closure needs
multiple borrows of the scratch buffer that `Option<Box<T>>` would
forbid via single-owner semantics; `*mut` lets the closure borrow
without moving the box.

This is a legitimate design constraint, not a metric-gaming
shortcut. The `mem::replace` + scoped inner unsafe pattern is the
correct fallback when `Option<Box<T>>` isn't available. **Approve.**
