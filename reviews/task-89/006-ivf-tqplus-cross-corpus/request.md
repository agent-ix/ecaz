# Task 89 Review Request: IVF TQ+ Cross-Corpus Synthetic

## Summary

This packet adds the Task 89 cross-corpus gate using a deterministic synthetic
unit-sphere corpus generated by `ecaz corpus generate`.

The suite shape is:

- Generate 10,000 corpus vectors and 200 query vectors at 1536 dimensions.
- Load baseline IVF TurboQuant and IVF TQ+ under
  `turboquant_calibration=tqplus_experimental`.
- Measure recall@10, latency, and storage at `nprobe=16,32,48,64`.

The generated TSV files are suite outputs under `artifacts/generated/` and are
not committed.

## Result

This gate does not support promotion. On this non-DBPedia distribution, TQ+
regresses recall at every measured `nprobe`, with the high-coverage probes
showing systematic loss:

| nprobe | TQ recall@10 | TQ+ recall@10 | Delta |
| ---: | ---: | ---: | ---: |
| 16 | 0.3800 | 0.3755 | -0.45 pp |
| 32 | 0.6075 | 0.5780 | -2.95 pp |
| 48 | 0.7675 | 0.7175 | -5.00 pp |
| 64 | 0.8610 | 0.7880 | -7.30 pp |

Latency also regresses on this corpus, but per reviewer feedback in packet 001
this is **not** used as a promotion/defer reason because current TQ+ scoring is
scalar-only while baseline TurboQuant can use tiled/SIMD scoring:

| nprobe | TQ p50 | TQ+ p50 | TQ p95 | TQ+ p95 |
| ---: | ---: | ---: | ---: | ---: |
| 16 | 1.72 ms | 4.07 ms | 2.27 ms | 4.43 ms |
| 32 | 3.99 ms | 5.76 ms | 4.57 ms | 6.04 ms |
| 48 | 3.99 ms | 8.38 ms | 4.60 ms | 8.73 ms |
| 64 | 4.24 ms | 10.9 ms | 4.66 ms | 11.2 ms |

Storage is effectively neutral at the table level but TQ+ adds a small IVF
index overhead: baseline IVF TQ is 989.6 B/index row; TQ+ is 991.2 B/index row.

Given the cross-corpus recall loss plus the existing DBPedia/QJL recall and
storage evidence from earlier packets, the next public-shape gate should treat
TQ+ as not ready for a production option or separate public format. Latency
remains an implementation-comparability gap until a tiled/SIMD TQ+ scorer lands.
