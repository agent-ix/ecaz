## Status of the code

`010a0accc` moves the `RegisteredSnapshotGuard` into a
`retry_snapshot: Option<RegisteredSnapshotGuard>` field on
`GenerationExpander`, so the guard lives as long as the `self.snapshot`
pointer that references it. Four construction sites get `retry_snapshot:
None`. That is the right fix and the right size — the guard is returned by
`lookup_graph_nodes_with_reopened_intent_retry` as its fourth tuple element
precisely so the caller holds it, and the previous code dropped it at the end
of the method while keeping the pointer.

Reviewed and accepted as written. No change requested to the fix.

## Required before this can be called done

### 1. A regression test — this is the item that stops it recurring

`ec_distann.debug_force_frontier_retry` (`options.rs:722`, consumed at
`generation_read.rs:398`) already forces the retry path exactly once under
`pg_test`, and **no test in the repository sets it**. That is why a
use-after-free introduced on 2026-08-15 reached `main` and sat there for nine
days.

The test must drive an expansion through the forced retry **and then keep
traversing**, so the dangling snapshot is actually dereferenced. Pin it to
fail on `origin/main` and pass with the fix; state both outcomes in the
packet.

### 2. Land it on `main` on its own

It currently exists on exactly one remote branch,
`origin/plan/distann-materialization-followups`, which is 17 commits ahead of
main and gated on a Task 222 benchmark that has not run. There is no PR.
`generation_read.rs` on this branch differs from main by exactly this commit,
so the cherry-pick is conflict-free:

    git checkout -b fix/distann-retry-snapshot-uaf origin/main
    git cherry-pick 010a0accc
    gh pr create

### 3. State the blast radius, including the non-crash case

The retry path is entered only when the initial lookup returns
`OwnedRecordMissing` — a read racing a concurrent owner write or build. Two
things must be written down rather than assumed:

- **Benchmark exposure.** Static build-then-query shapes almost certainly
  never enter the path, so prior distann numbers are probably unaffected —
  but say so explicitly rather than leaving it implied.
- **Wrong answers, not only crashes.** A freed snapshot whose memory still
  holds plausible bytes yields incorrect visibility decisions instead of a
  SIGSEGV. Whether any result-correctness exposure exists is a question the
  packet has to answer.
