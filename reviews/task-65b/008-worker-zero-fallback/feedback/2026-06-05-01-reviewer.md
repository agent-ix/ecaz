## Methodology — what "byte-equal" means here

It doesn't. The packet ships three digests per index (live TID,
adjacency, first-256-node) computed by a NEW `ecaz bench
diskann-graph` surface, then plants them as forward-looking
baselines. The manifest is explicit:

> "This packet establishes digestable worker-zero fallback outputs
> at corpus scale. It does not prove byte equality against Task 65
> head because the digest surface did not exist in the earlier
> Task 65 baseline packet."

That's honest framing but it leaves Acceptance #6 / gate #5 open.
Adjacency digest + first-256-node digest are good granularity for
a future comparison; full-file page-hash would be stronger but the
adjacency-set digest is what the gate's algorithmic invariant
actually needs.

   the Task 65 close commit (or the immediate pre-65b parent) for

   that, gate #5's "byte-equal" half is asserted, not proven.
2. **real-10k build time not actually measured this run.** Load
   log line: `task65b_w0_real10k_r32_l100_pq_fastscan_idx already

   (task-65b 28250dd4), not Task 65 head. Slice A *is* Task 65b's
   measurement floor on its own branch, so this is internally

   plan-language "vs. Task 65 head."

   That's a real `ecaz bench suite` gap and should be tracked as
