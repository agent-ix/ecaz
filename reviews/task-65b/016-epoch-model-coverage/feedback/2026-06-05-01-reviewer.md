## How this closes 006 / 005 B-3

**006 — "pre-sorted commit, no actual interleaving"**
(packet 006 seq 01 finding): the prior test sorted proposals
by `ordinal` before passing into the reducer, which asserted
`sort()` is idempotent rather than schedule-invariance. The
permutation sweep here passes the **unsorted** permutations
directly — each of the 6 orderings goes through the model
helper and the reducer's own ordinal sort. All 6 producing
byte-identical adjacency is exactly the property packet 003
specified ("repeated schedules → fixed output").

**005 B-3 — "cross-epoch boundary unchecked"**: the new test
constructs epoch-0 proposals that read a pre-commit snapshot
and epoch-1 proposals that observe epoch-0 commits. Verifies
the monotonic-epoch invariant directly. This was the third
piece of packet 003's spec ("no proposal from epoch N can
observe commits from epoch N").

## Note on test scope

The 3-proposal epoch with 6 permutations is enough to prove
the property (sort-invariance + idempotence are universally
quantified by ordering). Larger N is not needed unless a
future refactor changes the reducer's sort key.

The cross-epoch test uses 2 epochs which is sufficient for
the boundary invariant — repeating the pattern at N epochs
doesn't add coverage because each epoch boundary is
independently exercised by the 2-epoch case.
