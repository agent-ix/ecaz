## Blocking gaps

1. **Reference-host topology is implicit.** Task plan gate #2
   says "≤ 3 s on a 4-core host" for real-10k. The packet
   records only `max_parallel_maintenance_workers=2` and an
   Apple M5 (10/16 cores depending on model). Either state the
   reference host topology explicitly (CPU model, physical /
   logical core count, the gate's 4-core mapping) or re-run
   the floor on the 4-core target. Without that, gate #2
   cannot be evaluated. Per `feedback_dont_overclaim_done`.

2. **6.72 s SQL build vs. 62.045 s probe `build_seconds` =
   ~9× divergence with no explanation.** The probe is
   documented as "the durable phase / counter detail" — but if
   it diverges this much from SQL wall time, the counters
   Slice B/C/D will tune against are not anchored. Possible
   causes worth ruling out: different build path (probe ≠
   ambuild?), cold-cache effects, debug-vs-release,
   instrumentation overhead, separate medoid phases. Need a
   reconciliation note: what does the probe measure that the
   SQL build doesn't, and why is the difference so large?

3. **No synth-10k fixture.** Gate #1 requires synth-10k held
   within the Task 65 envelope. Task 65 packet 002 only got
   synth within gate by raising L=200, so the regression
   surface is real and load-bearing. The "if a fixture is
   restored" framing is exactly the deferral
   `feedback_no_setup_deferral` blocks: re-stage or regenerate
   the synth-10k corpus and run it in this packet.

## Substantive concerns (non-blocking but worth flagging early)

4. **No worker-count axis in `suite.json`.** Slice plan H
   needs a per-worker scaling curve. Reserve the worker-count
   matrix dimension in this packet's suite as a no-op at w=0
   so Slice D/G/H reuse one harness rather than re-cutting it.

5. **Fallback baseline has no checksum / page-shape snapshot.**
   Acceptance #6 wants byte-equal output vs. Task 65 head. Pin
   a canonical index-page hash + adjacency-list digest now so
   later w=0 runs have something to diff against. The recall
   numbers alone don't prove byte equality.

6. **real-100k at 243 s vs. gate of 30 s** is an 8× gap.
   Informational, not a blocker, but the packet should frame
   the gap explicitly rather than leave it inferred from the
   results table.

## What this packet should add before Slice C/D land

- One paragraph in `request.md` documenting the reference host
  topology (CPU model, core count) and how it maps to the
  "4-core gate" framing in the task plan.
- One paragraph reconciling the 6.72 s SQL vs. 62.045 s probe
  divergence. Either: probe is single-pass with extra accounting
  (state which fields), or rerun the probe to match the SQL
  path, or de-scope the probe counters from being the Slice B
  tuning oracle.
- Synth-10k re-stage + a run, with recall envelope cited from
  Task 65.
- Suite-level worker-count axis stub (single w=0 today) so
  Slices D/G/H inherit it.
- Packet-local checksum / first-N-page hash of the real-10k
  index as the Acceptance #6 baseline.
