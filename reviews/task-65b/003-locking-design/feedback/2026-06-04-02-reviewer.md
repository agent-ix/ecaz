# Slice C — Locking Design — APPROVE (REQUEST-CHANGES lifted)

## Verdict

**APPROVE.** Three seq 01 REQUEST-CHANGES items are addressed
in commit e979a7d80 + the new ADR-075 (commit a816c2ccf). The
design is now load-bearing for Slice D/E.

## Items closed

### 1. Concurrency-test surface — specified

> Slice E should use a hand-rolled deterministic interleaving
> model for the ordered reducer rather than loom over rayon
> internals.

Concrete model surface listed:
- immutable snapshot once per epoch,
- workers only produce proposal records,
- reducer is the only writer to `BuilderNeighborCache`,
- reducer commits sorted by `(pass, epoch, pivot_ordinal)`,
- monotonic epoch numbers; no proposal from epoch N observes
  commits from epoch N.

Tests run without PostgreSQL, assert single-writer cache
ownership + snapshot immutability + fixed output for repeated
schedules. This is the right shape — names a small invariant
set Slice E can implement against rather than punting to "loom
TBD".

### 2. Reducer Amdahl floor — computed

> If ordered commit costs more than 1500 ms on real10k, the
> Task 65b ≤ 3 s gate is likely unreachable with this design
> and Slice F should open the sharded live-commit path
> instead of tuning only batch size.

Floor anchored to Slice A data: 142,105 backlink additions +
61,593 reprunes; `backlink_ms = 12,362` from packet 002 as
conservative upper bound. The 1500 ms threshold + explicit
"sharded live-commit instead of tuning batch size" gives
Slice E a binary go/no-go signal rather than open-ended
optimization.

### 3. Validation gate #6 disposition — stated via ADR-075

> Task 65b validation gate #6 applies only to a production
> `ParallelContext` coordinator. It is not claimed by the
> rayon stepping stone.

Migration trigger conditions named: ordered leader commit
becomes the measured Amdahl bottleneck after Slice E/F, OR
Task 65b acceptance requires PostgreSQL worker accounting/
visibility. Either condition forces the
`ParallelContext`/DSM path. Honest.

## Additional improvements I didn't ask for

- **Stale-read recall gate now explicit**: "Any larger batch
  size must report `stale_read_fraction` and fails review if
  real10k Recall@10 moves more than 0.5 percentage points
  below the packet 001/002 baseline." Concrete recall-floor
  enforcement in code, not just narrative.
- **Slice E starts with `parallel_batch_size = 1` for
  byte-equivalence** — locks in the determinism oracle at
  the cheapest possible test point.

## Cross-reference

ADR-075 (`spec/adr/ADR-075-diskann-graph-build-worker-stepping-stone.md`)
is the long-form rationale. Combined with this packet, the
Slice E implementation has:

- An explicit coordinator choice (rayon stepping stone) with
  migration triggers.
- An explicit determinism model (single-writer reducer,
  ordered commit).
- An explicit concurrency-test surface (epoch state machine).
- An explicit Amdahl ceiling (1500 ms reducer wall time).
- An explicit recall gate (0.5 pp at batch > 1).

Slice E can proceed against this design.
