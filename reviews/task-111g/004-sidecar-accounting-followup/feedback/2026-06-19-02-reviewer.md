   The new 111g status text cites `benchmarks/ivf-111g-115-attribution/` and the

   per-step logs that prove the 40-120x sidecar regression and f16 recovery are

   decision-grade packet must commit the cited suite outputs. Until those files
   are committed and pushed, another agent cannot verify the benchmark verdicts
   from the branch.

2. **P1 — The benchmark manifest contradicts the findings and task docs.**
   `benchmarks/ivf-111g-115-attribution/manifest.md` still says the common sweep
   is `[8,16,24,32,48,64]` and its verdict table is `_tbd_`, while
   `FINDINGS.md` and the task docs now claim completed results from
   `[8,16,32,64,128,200]`. The manifest is supposed to be the source of truth for
   artifact metadata and key result lines. Update it with the actual sweep,
   backend SHA, artifact dirs, committed result file names, and the cited key
   lines, or downgrade the task docs back to "pending packet finalization."

3. **P1 — ADR-079's metadata-field guidance is unsafe as written.**
   ADR-079 says to add `rerank_sidecar_directory_head` at "the next free offset"
   because "v3 metadata has spare offsets; add at the next free offset, bump
   nothing else needed." Current `page.rs` has `EC_IVF_METADATA_BYTES == 86` and
   `rerank_sidecar_head` already occupies bytes `80..86`; there is no spare
   ItemPointer-sized tail. The ADR should require a metadata-size/layout change
   and corresponding size assertions, and it should explicitly state whether
   that is another clean format break/version bump or a same-version rebuild-only
   change. Leaving "bump nothing else" in the design will lead to an
   out-of-bounds or silently incompatible implementation.

4. **P1 — The f16 bug fix lacks a task-scoped code review packet/log.**
   The decoder patch itself looks directionally correct: the subnormal base
   exponent fix in `f16_bits_to_f32` matches binary16 semantics, and the new unit
   regressions cover the observed recall-collapse shape. But it is a production
   code fix on the 111g path and `FINDINGS.md` claims "All 13 rerank unit tests
   green" without a committed packet-local test log or request. Add a narrow
   111g review packet or extend this one with a manifest/request that records the
   exact commit, command, and test output for the f16 fix.

5. **P2 — The historical attribution layer is not packet-complete.**
   `FINDINGS.md` still says the historical per-segment section will be filled in
   on completion and names `run-historical.sh`; that script is untracked, and the
   historical artifacts are also untracked. Either finish and commit that layer
