# Reviewer Feedback: Exp 5 Final Investigation and Close-Out

Follow-up to `2026-05-23-01-reviewer.md` on packet 014. This note
authorizes one final investigation pass on Exp 5 (Adaptive nprobe /
adaptive rerank_width), after which the experiment closes out
either way.

## Why this is the last pass

The current µs-gap signal is conclusively not the right knob:
- Aggressive (gap=1000): only setting that moves p50, drops
  `recall_p10` 0.89 → 0.80.
- Conservative (gap=10000, 100000): never fires enough to matter.

There is no middle setting that preserves recall and moves latency
on this signal. The Amended Strategy cost decomposition independently
caps what any adaptive nprobe policy can achieve: p50 is dominated
by heap fetch + toast detoast (~18 ms of ~33 ms at 1m nprobe=128),
and adaptive nprobe can only avoid the cheap centroid/posting work —
not the heap path. The realistic ceiling for Exp 5 is single-digit
p50 improvement at matched tail recall.

Continuing to cycle on this experiment past one more honest pass is
not a productive use of round time.

## Final pass — required steps

1. **Land worst-query recall in the recall runner.** The harness
   already computes per-query recall; surface the minimum as a
   reported metric alongside `recall_p10/p50/p90`. Without this,
   Exp 5 cannot close per plan §5 acceptance criteria.
2. **Try one score-based adaptive signal**, not time-based. Pick
   one (your call which) from plan §5's named candidates:
   - centroid score margin ratio (top-1 vs top-N margin)
   - candidate score margin
   - observed bound progress (how quickly the candidate frontier
     stops improving)
   Run it on the same 990k local fixture with the same isolated
   prefix used by 014. Two or three threshold values is enough —
   this is screen, not a sweep.
3. **Report worst-query recall + p50/p95/p99 for the new signal.**
   Same metric set as 014 plus the worst-query column.

## Close-out criteria

After the final pass, write a single round-level finding (could be
its own packet under `reviews/task-51/`, or a closing note on the
014 / 015 / next packet — your call) that records the outcome:

**Path A — promote.** Score-based signal finds a threshold where:
- p50 improves materially (concretely: ≥10% over static on the
  same fixture), AND
- recall@10 is unchanged within CI95, AND
- `recall_p10` does not regress, AND
- worst-query recall does not regress.

If all four hold, the next step is an AWS Graviton 1m cell to
confirm. Only then is Exp 5 a Task 51 win.

**Path B — close as unproductive.** Any of the four criteria fail.
Record the finding: "Exp 5 (adaptive nprobe) does not produce a
recall-preserving p50 improvement on this corpus/access method.
The µs-gap signal collapses recall whenever it moves latency;
[chosen score-based signal] behaves the same way. Closed as
unproductive in this round; not a candidate for AWS."

Either path is a successful close. The thing the round cannot tolerate
is the experiment remaining open and consuming review/bench time
without a resolution.

## What does NOT need to happen

- **No AWS run for Exp 5 before Path A criteria are met locally.**
  Spending Graviton time on a policy that hasn't passed local tail
  recall is cost without yield.
- **No further µs-gap experimentation.** That signal is settled.
- **No "third signal" pass.** One score-based signal is the final
  experiment. If it doesn't work, the experiment is closed — do not
  cycle through margin ratio, then bound progress, then candidate
  margin sequentially. Pick one, run it, record the outcome.
- **No adaptive `rerank_width` experiment** as part of this
  close-out. The plan listed it as a sibling to adaptive nprobe,
  but the same heap-fetch ceiling applies to it. If Exp 5 closes
  Path B, adaptive rerank_width closes with it implicitly. If Exp 5
  closes Path A, adaptive rerank_width becomes a follow-up task,
  not part of this round.
