## Honest read of the numbers

Headline reproduces the prior `94c02c682` baseline almost exactly:

| nprobe | recall@10 | p50 | prior baseline p50 |
| ---: | ---: | ---: | ---: |
| 64  | 0.9716 | 18.7 ms | n/a |

| 256 | 0.9936 | 66.2 ms | ~67 ms |

**This gate confirms the current `ec_ivf` shape on Graviton; it does not
yet show a Task 51 optimization win.** The pre-Task-51 byte-LUT and
prefetch-dedup work (packets 002, 003, 004) is already in this binary,
and what we're reading is its steady state. None of the *new* in-flight
work — adaptive nprobe (012/014), scratch SoA (015), real-I/O sidecar
(016) — is exercised by this run.

That is the right thing for a baseline gate, but it should be framed
that way in `request.md` and `manifest.md`. The current packet language
("final gate") risks reading as "Task 51 round result," which it is not.

## Asks

1. **Rename or reframe in `request.md`/`manifest.md`** so this packet
   reads as the *baseline-confirmation gate* for the current code,
   not the round's final result. Something like "AWS baseline gate
   (pre-Exp-3/5/7-product)."
2. **State explicitly** which optimization GUCs/flags were not enabled
   during this run (adaptive nprobe = off, scratch SoA GUC = off,
   sidecar real-I/O paths = harness-only). Future reviewers
   reading this packet should not have to infer absence.
3. **No new run needed** until at least one of (a) adaptive nprobe
   passes its local gate including worst-query recall, (b) scratch
   SoA shows a real win on the chunked path (not the current 2%
   scalar-reuse result), or (c) a real-I/O sidecar variant lands as
   product code. Re-running this exact configuration would burn
   Graviton time for no new information.
4. **Pair the next AWS run with the snapshot policy.** Snapshot before
   destroy, restore via `ecaz cloud up --from-snapshot`, verify
   `describe-snapshots` first. The preserved snapshot pattern is
   already working for this packet; keep it for the next gate.

## Recommendation

Acceptable as a baseline confirmation gate. **Do not promote as a

what was actually measured, and reserve the next AWS run for a
