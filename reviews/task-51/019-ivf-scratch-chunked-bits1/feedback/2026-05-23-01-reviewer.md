## The local result is uninformative — that's the point

Headline: candidates/sec 226740 → 222337 (-1.9%); p50 549.1 → 653.4 ms
(-19% regression). Fails the 20% candidates/sec local gate.

But **WSL2 is x86 and the bits=1 byte-LUT optimization is NEON-specific**
(packet 003 work targets ARM Neoverse). On x86 the existing scoring
path uses the scalar fallback. The chunked path tested here runs
through *the same scalar fallback* with added scratch-buffer overhead,
so a small regression is the expected result. This local measurement
does not answer the Exp 3 question; it confirms the experiment cannot
be answered on x86.

The plan's promotion gate already reflects this — it's "20% candidates/sec
locally **OR** 10% AWS p50 at high nprobe," with the OR present
precisely so kernel work that's NEON-specific isn't blocked by an
x86 screen.

## Decision needed: run one Graviton cell or close Exp 3

Per my earlier note in conversation: the Graviton 1m microbench is
the only honest way to answer the Exp 3 question. Two options:

**Option A — one AWS Graviton cell.** Single nprobe (e.g., 128),
q=200 latency, scratch SoA GUC enabled, on the preserved snapshot.
Same isolated table as packet 011 if possible. Measure
candidates/sec + p50 vs the GUC-off baseline. Cost: small (one
profile, one cell, existing snapshot). Yield: definitive answer.

**Option B — close Exp 3 with evidence.** Cite the NEON kernel
work in packets 002/003 already shipped in the AWS binary; argue
that the chunked path can only improve on what's already there if
the existing kernel has substantial scratch-buffer slack to exploit;

shape almost exactly, implying the existing kernel is already
close to floor. Close as "WSL2 result inconclusive; AWS evidence
from packet 011 shows kernel is at floor for this corpus shape;
chunked scratch does not unlock additional headroom."

**Recommended:** Option A. The cost is genuinely small (one cell
on an existing snapshot), and a definitive negative result is
much stronger than a structural argument for an experiment plan
that named chunked bits=1 as a load-bearing branch. If Option A
shows ≥10% AWS p50 win at high nprobe, this becomes a Task 51
promotion; if it shows <10% or a regression, Exp 3 closes
cleanly and Posting Layout v2 is rejected with evidence (which is
itself a plan exit-criterion item).
