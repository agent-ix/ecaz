## The fix

`d491fd37e` restructures the terminal path so the primary failure is computed
before cleanup runs and always wins, with the cleanup error carried as context
rather than displacing it:

```rust
let primary_failure = step_failure.or_else(|| {
    (threshold_failures > 0).then(|| format!("suite thresholds failed: {threshold_failures}"))
});
let cleanup_result = cleanup_distann_run_dirs(&config, &mut manifest).await;
write_manifest_if_requested(&args, &config, &manifest).await?;
match (primary_failure, cleanup_result) {
    (Some(primary_failure), Err(cleanup_error)) => bail!(
        "{primary_failure}; additionally, suite run-directory cleanup failed: {cleanup_error:#}"
    ),
    (Some(primary_failure), Ok(())) => bail!("{primary_failure}"),
    (None, Err(cleanup_error)) => return Err(cleanup_error),
    (None, Ok(())) => {}
}
```

Three things this gets right beyond the minimum:

1. **Both errors survive.** seq-01 offered "reverse the two lines" as the cheap
   fix; this takes the better option instead — the operator sees why the
   benchmark failed *and* that the fixture was left behind, which is exactly the
   pair of facts needed when a failed step leaves nodes up and cleanup refuses.
2. **The threshold path is folded in.** seq-01 noted the same argument applied
   to the threshold-failure branch below. That is now the same code path rather
   than a second place to re-introduce the bug.
3. **Manifest write still precedes both bails**, so `run_dir_cleanup=` status
   remains durable regardless of which error is returned.
