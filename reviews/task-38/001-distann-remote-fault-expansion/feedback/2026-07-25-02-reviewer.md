### Flag 2 — Unix-peer degradation → **CLOSED**

`peer_target_matches` now rejects both failure modes before they can produce a
matchable key:

    if (address_len <= offsetof(struct sockaddr_un, sun_path) ||
        unix_address->sun_path[0] == '\0') { ... return 0; }

That covers the unnamed accepted peer (short `address_len`) and the abstract
namespace (leading NUL), which is the pair I was worried about — I only named
the first. Docs and `--peer-match` help now say "absolute named `unix:/path`"
and state that unnamed and abstract peers never match, so the TCP-only caveat
is recorded rather than implied.

### Flag 3 — interposed syscall set → **CLOSED**

Added `readv`, `writev`, `recvfrom`, `sendto`, `recvmsg`, `sendmsg`, all
following the existing `recv`/`send` shape. That is the full set I named plus
the datagram pair, and it makes the question moot rather than deferring it to a
trace — a better answer than the `strace` I suggested, since it does not depend
on the transport's current implementation staying put.

The file-mode short-circuit still holds for the new entry points:
`should_fault_socket` checks `enabled()` and `mode_is()` before `getpeername`,
so EIO/ENOSPC/slow-disk lanes do not pay the socket path.

### Flag 4 — invalid state representable → **CLOSED**

`FaultFixture` is now an enum with `DistAnn(DistannCodec)`, the
`(FaultAm, Option<DistannCodec>)` constructor is gone, and both `_ => "invalid"`
arms are deleted. `FaultFixture::DistAnn` without a codec is no longer
constructible. Exactly the refactor I suggested, done at the type level rather
than by adding a validation check.

### Flag 5 — errno hygiene → **CLOSED, more thoroughly than asked**

I called this harmless-as-written and suggested a comment. The coder saved and
restored `errno` on *every* return path from `peer_target_matches`, including
the success path, and documented why:

    /*
     * getpeername(2) on a regular file sets errno. Preserve the caller's errno
     * when this descriptor is not the configured TCP peer so merely enabling a
     * socket mode cannot perturb unrelated file I/O.
     */

That is the correct fix and the comment states the actual hazard.

## Residual 1 (LOW) — `-Wall -Wextra` without `-Werror` still cannot fail the build

`build.rs` now passes `-Wall -Wextra`, which was half the suggestion. Without
`-Werror` the compile gate's behavior is unchanged: a new warning prints into a
CI log nobody reads and the job stays green. The flags help a human who is
already looking, not the gate.

My seq-01 note asked for `-Werror` conditional on the file being clean under
the new flags. It now demonstrably is — 0 non-deprecated warnings under
`clang -Wall -Wextra` on this host, and the Linux job compiled clean enough to
succeed. So the risk of adding `-Werror` has dropped to roughly nil, and it
converts the compile gate from advisory to enforcing for exactly the code this
PR added: `snprintf` into fixed buffers, `getpeername` results, and six new
interposers with hand-written function-pointer types where a signature typo is
a warning before it is a crash.

Caveat in fairness: my check is clang on macOS with four pre-existing
Linux-only type errors present, and CI builds with gcc on Linux. gcc's `-Wextra`
is not clang's. If `-Werror` is added, expect one iteration to clear gcc-only
warnings, and do it in a commit of its own so a red build is unambiguous.
