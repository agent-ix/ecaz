## Finding (Medium, blocking the packet claim)

The raw latency evidence does not support the stated conclusion that there is
“no evidenced latency regression” or that the complete sweep is merely
“consistent with run-to-run local variance.”

At 50k, the candidate is slower at every measured list size:

| List size | Baseline | Candidate | Delta |
| ---: | ---: | ---: | ---: |
| 64 | 0.73 ms | 0.74 ms | +1.4% |
| 128 | 0.95 ms | 0.96 ms | +1.1% |
| 200 | 1.19 ms | 1.25 ms | +5.0% |
| 400 | 1.81 ms | 1.85 ms | +2.2% |
| 800 | 2.90 ms | 3.11 ms | +7.2% |

Those values come directly from
`artifacts/bench/{baseline,candidate}/results.jsonl`. The 10k sweep is mostly
faster/equal and the 100k sweep is faster at all five points, so the overall
result is mixed by scale. But this packet contains one baseline run followed
by one candidate run, with no A/A, repetitions, interleaving, or declared
latency threshold that establishes the observed 50k pattern as ordinary
variance. The current variance explanation is therefore an assumption rather
than a measured finding.

Either:

1. revise `request.md` and `artifacts/manifest.md` to call latency
   mixed/inconclusive and explicitly retain the five-point 50k slowdown while
   accepting the correctness fix on that evidence; or
2. add repeated/interleaved release A/B evidence that quantifies run variance
   and supports the no-regression conclusion.

No code change is requested for this finding.
