## Verdict

## Finding 1 (HIGH) — recovery can pass with no ECAZ index at all

The worker prepares only the table with `workload_table_sql`
(`fault.rs:721-724`). It then executes an infinite `DROP INDEX` / `CREATE
INDEX` loop inside one `DO` statement (`:726-744`), hence inside one
transaction. A group kill aborts that transaction; there was no committed
index before it began.

The recovery probe checks:

- `SELECT 1`;
- zero rows in `pg_index` where `indisvalid = false`;
- only that the fixture table contains more than zero rows
  (`fault.rs:837-860`).

An empty set of indexes therefore satisfies `invalid_indexes=0`, and no ECAZ
scan is executed after restart. The lane can report `recovery=pass` while the
AM is entirely absent.

Create and commit an initial fixture index before the fault transaction, then
after restart require the expected index to exist, be valid/ready, and execute
the fixture's forced AM scan (or rebuild and then scan if the intended
postcondition is rebuildability). Also run the shared leak/lock cleanup
postconditions required by Task 38.

## Finding 2 (MEDIUM) — "preserved fixture rows" means only nonempty

The parent knows the requested `--rows`, but `cgroup-recover` does not receive
it. Recovery accepts `recovered_rows > 0` at `fault.rs:853-860`, so partial row
loss would be reported as preserved.

Pass the expected row count to the recovery worker and require equality. The
retained recovery line should include both expected and observed values.

## Finding 3 (HIGH) — artifact and runtime roots are not required to be disjoint

The CLI accepts arbitrary `--artifact-dir` and `--runtime-dir`, canonicalizes
both, and never checks overlap (`fault.rs:422-445`). With equal roots, their
identical run/case suffixes make `case_dir == case_runtime_dir`; the successful
cleanup at `:602-607` deletes `scope.log`, `recovery.log`, and `postgres.log`
along with the data directory. If runtime is placed below a review packet, the
uncommittable PostgreSQL cluster also lands inside review evidence.

Reject equal or ancestor/descendant artifact/runtime roots, and reject runtime
paths under `reviews/` or `benchmarks/`. This is required for the packet's
claim that transient PG data cannot enter review packets and that evidence
survives cleanup.
