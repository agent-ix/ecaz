# Review: SPIRE Phase 13e Local AWS Harness — the gate working as intended

This is the most valuable packet in the AWS series, and it's the right model:
run the **actual AWS workflow scripts** (`load.sh` / `register.sh` / `smoke.sh`)
against **4 local PostgreSQL instances**, so AWS-path bugs surface locally
instead of on rented hardware. It's also properly committed (tracked, with
`request.md` + `manifest.md`) — unlike 985/988/990/991.

## What it proved

- **Reproduced the AWS failure locally.** `escalated-skip-install-run/
  smoke-customscan-read.log`: `ERROR: ec_spire production executor cannot merge
  remote heap candidates while node_id 2 is in state CandidateReceiveFailed
  with status remote_candidate_receive_failed`.
- **Found root cause + fixed it.** Remote `conninfo_secret_name` values weren't
  visible to the coordinator PostgreSQL backend; the fix exports conninfo before
  coordinator start (local) and writes a systemd `EnvironmentFile` + restarts PG
  before register/read (AWS install path).
- **Read passes after the fix.** `conninfo-before-start-run/
  smoke-customscan-read.log`: `Custom Scan (EcSpireDistributedScan)`,
  `remote_fanout: 3`, `rows=10`, `remote_heap_failed_dispatch_count 0`.

## Why this matters

This conninfo bug is a **deployment-path** failure (multi-process / systemd
backend environment) that the 987 in-process `ecaz bench suite` proof did **not**
catch. So 987 (production read logic green) and 989 (production deployment path
green) are complementary, and *both* were needed. 989 validates exactly why the
local-AWS-harness approach is the correct gate: it caught on local PG what
otherwise would have cost another AWS provision/install/load cycle to discover.

## Findings

- `phase13e-aws-harness-local.log` ends with `Error:` amid nightly
  `hnsw_recall_export_debug` macro warnings. Confirm this is a benign
  build-phase warning in the harness and not a real failure — the
  `conninfo-before-start-run` smoke read clearly succeeds, but the top-level log
  tail reads as an error. Please make the harness's overall pass/fail line
  unambiguous (a final `HARNESS PASSED`/`FAILED`).
- Good that this packet is committed with a manifest. Keep this as the standard:
  AWS-path changes get a local-harness gate run + committed evidence before any
  AWS spend.

No blocking findings. This is the right gate and it's green. Deferring formal
accept to an outside reviewer.
