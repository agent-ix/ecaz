# Review: SPIRE Phase 13e Suite Read Matrix

Review target: commit `b3a86fbe9...` (`bench/suite.rs` +115,
`scripts/spire-aws/bench.sh` +5/-2, `suite-{correctness,representative,stress}.json`).

## Assessment — clean adherence to the bench-suite workflow rule

This is the right way to close the 13e.3 "drive all read matrices through
`ecaz bench suite`" item:

- `scripts/spire-aws/bench.sh` is a **thin wrapper** — its only change is to
  inject the operator-supplied `artifact_dir` into the tier config via `jq` and
  call `ecaz bench suite run --config`. No per-tier shell sweeping, no ad hoc
  `ecaz corpus load` / `ecaz bench recall|latency` glue. Exactly the FR-038
  expectation.
- The three tier matrices are **checked-in JSON SuiteConfigs**
  (`suite-correctness/representative/stress.json`), so the matrices are
  reviewable and reproducible rather than living in shell.
- `suite.rs` gains packet-local default `--log-output` derivation from
  `artifact_dir` for recall/latency/spire-pipeline/sidecar-rerank steps —
  sensible, keeps evidence packet-local by default.
- Dry-run + audit logs for all three tiers are packet-local and pass.

## Index isolation — checked, OK

The representative config runs recall, latency, and spire-pipeline steps all
against a single `ec_spire_aws_repr_1m` prefix. That is correct: these are all
the same access method (`ec_spire`) sweeping nprobe (8/16/24/32), k, and
concurrency, plus the remote tuple-transport sweep
(`auto`/`json_tuple_payload_v1`/`pg_binary_attr_v1`) which is a read-path
setting, not an index variant. The per-variant one-table-per-index rule applies
to comparisons *across access methods*, which this matrix does not do, so
sharing the index here is appropriate. `require_remote_placements: true` on the
spire-pipeline steps correctly wires in the packet-959 smoke gate.

## Notes (deferred AWS execution)

- These are dry-run + audit only; no AWS tier has been executed. When the real
  AWS correctness/representative runs happen, the standing AWS rules apply:
  reuse the existing corpus/index (do not recreate), snapshot before any
  destroy/terminate, and capture results packet-local. The suite-runner approach
  here makes those runs reproducible, which is the point.
- `include_recall: true` on the representative spire-pipeline steps is good — it
  lets the representative tier capture recall alongside p50/p95/p99 latency as
  13e.3 requires. Confirm the stress tier's profile step is not expected to gate
  on recall thresholds (stress is throughput-oriented).

No blocking findings. Deferring formal accept to an outside reviewer.
