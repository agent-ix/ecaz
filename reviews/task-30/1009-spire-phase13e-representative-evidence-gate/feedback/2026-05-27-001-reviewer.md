# Consolidated review: representative-tier scaffolding (packets 1000–1035) — the actual run is still missing

This is a cross-cutting finding for the representative-tier work, filed here on
the evidence-gate packet rather than as 36 separate files (that would add to the
problem described below).

## Headline: no real AWS representative run exists yet

I checked all 36 packets (1000–1035) for an actual representative-tier
measurement. **There is none.** Every "result" I found is sample/synthetic:

- 1001/1010/1013 cite `sample-input` / `sample-summary-input`
  `suite-results-representative-pooling.jsonl`.
- 1004/1019 cite `sample-output/representative-latency-recall-summary.tsv`.
- **1009 (this packet)** states its own fixture is *"packet-local TSV summaries
  copied from packet 1004 sample output, plus a negative pooling-latency delta
  fixture."*
- The rest are dry-run manifests, `tfvars` fixtures, preflight/confirmation
  logs, and gate/notes.

No packet contains real instance IDs, real provision/install/load logs, a real
SSM tunnel, real-network p50/p95/p99, or recall over the 1M representative
corpus. No AWS instances are running. So the **main remaining 13e gate — the
representative tier over the real network — has not been executed.**

## The pattern: scaffolding has outrun measurement

36 packets landed for the representative tier and **21 of them are
note/marker/status/confirmation/preflight/gate/selfcheck** packets
(`representative-gate-note`, `watchdog-status-note`, `order-status-note`,
`suite-gate-note`, `representative-start-marker`, `provision-confirmation`,
`autostop-preflight`, `graviton-lane-preflight`, `current-aws-preflight`,
`representative-preflight-rerun`, …). The verifier/summary/gate tooling itself
is reasonable and its dry-runs pass — but building 36 packets of gating and
process around a measurement that hasn't been taken is exactly the churn this
review has flagged before, just in a new form: process artifacts instead of
evidence.

## What I am NOT saying

The tooling isn't worthless — a representative summary tool (1001), a
recall-floor verifier (1021), and a pooling-latency-delta gate (1013) are
legitimate and will make the real run's evidence cleaner. The problem is purely
that they are validating **sample data**, and the real run keeps being deferred
behind more preflights.

## Recommendation

1. **Run the representative tier once, for real.** The tooling is demonstrably
   ready (dry-runs green, preflights pass). Provision the quota-fit Graviton
   representative topology, run it through `ecaz bench suite`, and capture in
   ONE packet: real-network p50/p95/p99, recall vs the floor, and the
   pooled-vs-unpooled connect/latency delta. That single packet is worth more
   than all 36 scaffolding packets combined.
2. **Stop opening note/marker/status micro-packets.** Fold status into the run
   packet's `request.md`. Each note-packet is overhead with no evidence.
3. The bucket has crossed 999; the widened `1000-`+ ordinals are fine per
   CLAUDE.md, but the proliferation rate is the signal to watch.

No blocking finding on the gate *tooling* itself; the blocking gap is that the
representative **measurement** is still absent. Until a real AWS representative
run lands, 13e is not done — and this is the one thing left that actually needs
AWS. Leaving open.
