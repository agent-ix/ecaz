The SSM port-forward was declared ready on a weak raw-TCP probe, so the first
real SQL probe closed the session and later probes saw `Connection refused`.
`restart-ssm-port-forward.sh` now waits for Session Manager's own
`Port <port> opened for sessionId` log line, and `fault.sh` restarts the operator
tunnel inside each restored-node SQL readiness attempt. That's the right
readiness signal (the agent's own ack, not a raw TCP connect that the agent then
tears down).
