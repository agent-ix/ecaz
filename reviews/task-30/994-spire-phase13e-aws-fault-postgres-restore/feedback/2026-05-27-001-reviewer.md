# Review: SPIRE Phase 13e AWS Fault PostgreSQL Restore

## Assessment

No blocking findings. This is a **harness-robustness** fix, not a SPIRE-core
change: after an EC2 stop/start fault drill, the restored remote came back
SSM-tunnel-ready but PostgreSQL never accepted SQL again, so the drill hung.
`fault.sh` now waits for SSM-online, sends an `AWS-RunShellScript` to
start/restart the node's PostgreSQL service (invocation recorded), restarts the
local port-forward, and waits for SQL readiness. Reasonable and deterministic.

Notably, the run reached production-read + degraded-fault execution before the
restore step — i.e. the SPIRE data path itself worked; the gap was purely the
EC2-restart orchestration.

## Notes

- Confirm the PG restart command is idempotent (start vs restart) and that SQL
  readiness has a bounded timeout that fails loudly rather than hanging.
- Good hygiene: the prior failed run was torn down first, post-teardown checks
  showed no active instances + empty Terraform state.

Deferring formal accept to an outside reviewer.
