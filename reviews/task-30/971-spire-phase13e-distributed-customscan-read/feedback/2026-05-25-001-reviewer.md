(`src/lib.rs` +221, `materialization.rs`, `debug.rs`, `scan_output.rs`, fixture).

## Assessment — this is the 13e.2 acceptance proof and it holds up

The fixture demonstrates each 13e.2 acceptance bullet against a real PG18 run:

- `EXPLAIN` shows `Custom Scan (EcSpireDistributedScan)` with `remote_fanout: 3`
  — the production distributed scan is the read path.
- `read_rows` equals `exact_rows` (`1,5,9,2,6,10`) — top-k matches the
  deterministic baseline and includes remote-owned rows.
- **Strict** remote failure: `strict_remote_failure_exit_code=3` with an ERROR
  and no partial rows — fails closed, correct.
- **Degraded** remote failure: returns `4,8,12,3,7,11` from the surviving nodes
  with `degraded_skipped_dispatch_count=1` and status `degraded_ready` — partial
  rows plus skip diagnostics, correct.

The new `publish_static_remote_placement_nodes_with_mode` /
materialization-with-mode operator variants validate the consistency mode and
reject anything other than `strict`/`degraded` with a clear error. Routing
degraded pre-dispatch skips through the same executor diagnostics as the
existing degraded path (rather than a parallel code path) is the right call.

## Findings (non-blocking)

### N1 — New validators/operator variants still lack isolated tests (recurring)

As with 964/968, the new mode-parsing and the strict/degraded operator variants
are exercised only by the happy/failure paths the PG18 fixture drives. There are
no `#[test]`/`#[pg_test]` functions in this commit. The mode-parse rejection
(`got '{other}'`) and the degraded-skip accounting are exactly the kind of logic
that wants a focused test so a regression is caught without a full fixture run.
Please add coverage for: invalid consistency mode string, degraded with >1
blocked remote (skip count > 1), and strict with a blocked remote returning zero
rows.

### N2 — Confirm degraded republish doesn't strand a strict epoch

Degraded mode "republishes the surviving remote indexes and coordinator epoch as
degraded." Confirm that after a degraded run the index is not left advertising a
degraded epoch that a subsequent strict read would then treat as authoritative
(i.e., that consistency mode is a per-query GUC, not sticky index state). The
fixture runs strict before degraded; a degraded→strict ordering test would
close this. If the epoch/mode are already decoupled by design, a one-line note
suffices.
