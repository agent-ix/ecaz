# Review: SPIRE Descriptor Registration Plan

Review target: commit `e02f0ce310b7dd3d8e205882e9f9f40e9b6b751d`
(`distributed_remote_identity_query_sql` and the registration template in
`crates/ecaz-cli/src/commands/corpus/load.rs`).

## Findings

### P1 — Identity query emits `active_epoch`, which the downstream renderer rejects

`distributed_remote_identity_query_sql` (`load.rs:994`) builds the JSON the
renderer in packet 962 consumes. It includes an `active_epoch` key in addition
to `last_served_epoch`/`min_retained_epoch`:

```
'active_epoch', a.active_epoch,
'last_served_epoch', a.active_epoch,
'min_retained_epoch', a.active_epoch,
```

`render_spire_registrations.rs`'s `RemoteEndpointIdentity` is
`#[serde(deny_unknown_fields)]` and has no `active_epoch` field, so the live
payload fails to deserialize. Either drop `active_epoch` here (the three epoch
fields all read `a.active_epoch` anyway, so it carries no extra information) or
add it to the consumer struct. Tracked as the primary finding in packet 962.

### Observation — all three epochs collapse to `active_epoch`

`last_served_epoch` and `min_retained_epoch` are both populated from
`a.active_epoch`. Confirm that is intentional for the static-placement phase. If
`ec_spire_index_active_snapshot_diagnostics` exposes distinct served/retained
epochs, using the real values would make the registered descriptor's retention
window accurate rather than a single-point collapse. Acceptable for 13e.1 if
documented as a known simplification.

## What looks good

- Replacing the prior `node_id`-derived fake identity with the remote's real
  `profile_fingerprint` as `remote_index_identity` is the correct direction and
  removes the fake-identity registration pattern the task called out.
- The template gates on live endpoint identity and snapshot diagnostics rather
  than operator-supplied constants.
- SQL literal escaping tests on the generated fragments are appropriate.

Holding open; the `active_epoch` mismatch must be resolved with packet 962.
