(`ec_spire_publish_static_remote_placement_nodes`, `src/lib.rs`,

## Assessment

This is the right shape for the task's core acceptance item — a *production*
placement publication surface that replaces `tests.ec_spire_test_rewrite_
placement_node`. Validation is layered correctly:

- **SQL boundary (`src/lib.rs`):** length mismatch between `pids`/`node_ids`
  rejected; negative `pid` (`u64::try_from`) and negative `node_id`
  (`u32::try_from`) rejected; `validate_ec_spire_index` gate. Good — these are
  the boundary checks the request claims, enforced before the typed core runs.
- **Core (`debug.rs`):** empty rewrites, `pid == 0`, local-node assignment,
  duplicate pid, and missing pid all rejected with clear messages.
- Correctly de-gates `spire_manifest_bundle_for_placement_publish` from
  `#[cfg(test/pg_test)]` to production and routes the existing test-only
  rewrite helpers through the same helper — no logic fork.

## Findings (non-blocking)

### N1 — Validation rejection branches have no isolated test coverage

`validate_static_remote_placement_rewrites` and the SQL-boundary guards are
pure functions over plain slices/vecs, but the only behavioral exercise of this
function is packet 969's happy-path PG18 fixture, which never trips a rejection.
A regression that weakens (e.g.) the duplicate-pid or local-node check would
pass CI silently. These validators don't need a live index — please add unit
tests for the rejection branches (empty, pid 0, local node_id, duplicate,
missing pid, length mismatch, negative). Cheap, and it's where the safety value
of this function actually lives.

### N2 — Confirm epoch reuse is intentional

`publish_static_remote_placement_nodes` republishes the manifest bundle with
`root_control.active_epoch` unchanged (in-place placement rewrite, no epoch
bump). That mirrors the test-only rewrite path, so it's likely intended, but
please confirm readers that cache manifests by epoch handle a same-epoch
manifest replacement correctly — otherwise a stale reader could keep the
pre-rewrite placement directory. If the existing rewrite path already proved
this safe, a one-line note in the packet is enough.

## Evidence note

proof for this function comes from packet 969's fixture. Acceptable given 969
exists, but see N1 — the validation branches 969 doesn't cover still want a
test.

Script ordering (coordinator build → distributed plan → remote shard load →
