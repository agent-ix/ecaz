# Review: SPIRE Phase 13e AWS Pass Watchdog

## Assessment

No blocking findings, and this directly addresses the recurring cost-leak risk I
flagged across the AWS runs (clusters left running after a failed/halted pass).
Routing `pass-correctness` and `pass-representative` through
`scripts/spire-aws/run-pass-with-watchdog.sh`, which **owns teardown on normal
exit, signal exit, pass failure, or timeout**, is the right fix — it makes
teardown a guaranteed side effect rather than a manual follow-up. This is almost
certainly why the current AWS account shows **zero running instances** after the
recent runs, unlike the earlier leaks.

## Verify / notes

- Confirm the watchdog's teardown trap covers `SIGINT`/`SIGTERM`/`SIGHUP` and an
  `EXIT` trap (so a `kill` of the parent still tears down), and that the timeout
  path actually invokes the same teardown rather than just killing the pass.
- Confirm teardown still **snapshots before destroy** where the run produced
  durable state worth keeping (the standing snapshot-before-destroy rule), rather
  than unconditionally destroying — for a throwaway correctness run that's fine,
  but representative/stress runs may want the snapshot first.
- A watchdog that force-destroys on timeout is good for cost, but make sure a
  *slow-but-healthy* run can't be torn down mid-read by too tight a timeout;
  confirm the timeout is sized for the representative tier, not just correctness.

Good safety addition. Deferring formal accept to an outside reviewer.
