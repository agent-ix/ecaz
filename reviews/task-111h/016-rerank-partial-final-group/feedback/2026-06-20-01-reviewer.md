## What I verified (the two I was most skeptical of)

### Chain relink is genuinely atomic (012 / `db6b63977`)
`update_metadata_page_prepending_rerank_group` (`page.rs:4621-4695`) acquires
**both** the metadata buffer and the new group's header buffer
`BUFFER_LOCK_EXCLUSIVE` *before* `start_wal()`, then read-head
(`previous_head = metadata.rerank_sidecar_head`), header rewrite
(`group_header.next_group_tid = previous_head`), and head publish
(`metadata.rerank_sidecar_head = group_tid`) all execute inside one `wal_txn`
committed by a single `GenericXLogFinish`. That is one critical section / one WAL
record — the TOCTOU window from finding P2-1 is genuinely closed, not narrowed.
First-ever insert handled (head reads INVALID → new group's `next_group_tid`
stays INVALID). The durable posting already carries `rerank_tid` to the
unpublished group, so the hot path is reachable even pre-splice; error paths
abort the xlog and release both locks. Lock order (metadata-then-group) is
consistent, no deadlock.

### Coverage gaps are real end-to-end pg_tests (010, 016)
- `test_ec_ivf_index_placement_partial_final_group` (016): `rerank_width=8`, 3
  rows / 1 list → a real on-disk group with `valid_count=3 < scorer_width=8`;
  asserts exactly 3 outputs (no padded slots emitted) and
  `payload_bytes_scored == 3*4`. Genuinely exercises the partial-group scan path
  on disk, not the in-memory unit branch.
- `test_ec_ivf_index_placement_mixed_fallback_chain` (010): forces a survivor's
  `rerank_tid = INVALID` via a `#[cfg(pg_test)]` hook, driving
  `use_direct_tids=false` → `load_rerank_groups_full_chain` over the real
  persisted chain; asserts `rerank_full_chain_loads == 1` and bit-identical
  output vs the direct path. The INVALID trigger is injected (acceptable
  deterministic trigger), but the fallback loader + guarded chain walk run
  end-to-end over real groups.
