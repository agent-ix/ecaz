## Constructive notes (owed by the matrix run, not blockers)

1. **Pin the HNSW anchor, not just IVF.** Spec AC2 requires "comparison to
   IVF/HNSW release baselines," and the task76 bucket has the HNSW control, but
   the decision criteria name only the IVF 100k anchor as the comparison source.
   The frontier table must report the release **HNSW** anchor alongside IVF, and
   the matrix packet should state which one(s) SPIRE is being judged against.

2. **142 epoch cache must show as engaged, not assumed-on.** The packet asserts
   142 is closeable and reload-floor-removed, but epoch cache is not listed in
   the common settings and no epoch-cache hit/reuse counter is required in the
   manifest. By your own null-evidence rule, "the floor is gone" needs a live
   counter (or an explicit statement that it is baked into the Task 141 release
   substrate and which manifest field proves it). Add the epoch-cache-engaged
   evidence to the required per-node profile so 142's win is demonstrably active
   under these runs.

3. **The primary gate is a viability band, not Pareto-dominance — say so.** Pass
   = recall 0.999 + scan ≤15% + p50 within **4x** IVF. 4x of 37.7 ms is ~150 ms,
   which is roughly the ~140 ms transport floor Task 145 documented; a multinode
   shape can therefore "pass" while single-node IVF (0.998 @ 37.7 ms) still
   latency-dominates it. Your interpretation rules already lean this way, but the
   matrix packet should make explicit that a gate-pass is a *viability* verdict,
   and the frontier table must surface whether IVF/HNSW Pareto-dominate at every
   operating point so "promote" is never misread as a dominance claim.

4. **Report matched-scale anchors at 10k/50k, not only the 100k anchor.** The p50
   criterion is pinned to the 100k IVF anchor. For an honest full Pareto the
   10k/50k IVF (and HNSW) anchors should also appear in the frontier table, even
   though the gate arithmetic keys off 100k/1M.

5. **Minor: justify 15% over 10%.** The spec gate is "≤10–15%"; the packet pins
   the looser 15%. Within spec, but pre-registration should state why the
   permissive end was chosen so it doesn't read as picking the easier bar.
