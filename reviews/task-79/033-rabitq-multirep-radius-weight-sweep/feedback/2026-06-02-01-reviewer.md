# Task 79 packet 033 — multi-rep radius-weight sweep

## Decision

**Accept as cheap-axis closure.** The radius-weight sweep at k=2
confirms 0.25 is already the optimum. Recall curve is extremely
shallow (only 0.6pp total span across w=0.0 to w=0.5), peaks
exactly at 0.25 with 0.9870 recall. Radius-weight tuning is now
closed as the recovery path.

This was the cheapest fix to try; correctly ruled out before
heavier work.

## Curve shape tells a story

| weight | recall | delta from peak |
| ---: | ---: | ---: |
| 0.00 | 0.9840 | -0.30pp |
| 0.10 | 0.9850 | -0.20pp |
| 0.20 | 0.9865 | -0.05pp |
| **0.25** | **0.9870** | **peak** |
| 0.30 | 0.9865 | -0.05pp |
| 0.40 | 0.9840 | -0.30pp |
| 0.50 | 0.9810 | -0.60pp |

Symmetric around 0.25, total span 0.6pp. That tells us:

- The Cauchy-Schwarz radius bound is *informative* — going from
  pure mean (w=0.0) to w=0.25 lifts recall by 0.3pp
- But it's also *bounded in usefulness* — pushing to w=0.5
  starts losing 0.6pp because the bound becomes too loose
- The current 0.25 setting is genuinely optimal, not a lucky
  default

The cheap "maybe the weight was wrong" hypothesis is now closed.
The 11 missed targets at cap640 need recovery from a different
mechanism.

## What's now ruled out for cheap recovery

After packets 031 (sampling), 032 (endpoint reps), and 033
(radius weight) on multi-rep:

- **Sampling** → doesn't recover any of the 11 misses
- **Endpoint representatives** → -7pp recall vs cluster means
- **Radius weight tuning** → 0.25 is already optimal

Remaining viable paths to recover the 11:

1. **Per-leaf score calibration** — learn at build time how to
   normalize summaries across leaves of different size/density.
   Cheap (build-only), addresses cross-leaf score comparability.
2. **Per-leaf quota in global selector** — guarantee each routed
   leaf contributes a minimum number of blocks to the final cap.
   Coder is testing this in packet 034 (in flight). Doesn't add
   information; redistributes the existing budget.
3. **k=3 representatives** — more discrimination, +1.3ms p50
   cost (puts us at ~46ms, marginal viability).
4. **Richer cluster-mean (e.g. weighted by distance to centroid
   in the block)** — packet 032 tried raw endpoints; a more
   controlled variant might help.

(2) is being tested now in packet 034. If quota works, it's the
cheapest win (no format change, no extra CPU). If not, (1) is
next.

## Verdict

Radius weight axis closed. Packet 034 (per-leaf quota) is the
right next experiment. The 11-target recovery question is
unresolved but the remaining viable paths are narrow.
