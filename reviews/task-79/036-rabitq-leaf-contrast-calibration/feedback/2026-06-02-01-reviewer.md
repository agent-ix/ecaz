# Task 79 packet 036 — leaf-contrast calibration (Path A simple variant)

## Decision

**Accept as negative-evidence axis closure.** Per-leaf contrast
calibration in the simple "deviation from leaf mean" form
*degrades* recall instead of improving it. As contrast weight
increases (0.0 → 4.0), recall drops from 0.9870 to 0.9540.

This rules out the cheapest form of Path A from my packet 035
feedback. The k=3 packet 035 result remains the closest to Task
79 closure.

## What the contrast sweep tells us

| weight | recall | delta |
| ---: | ---: | ---: |
| 0.00 | 0.9870 | baseline |
| 0.25 | 0.9860 | -0.10pp |
| 0.50 | 0.9860 | -0.10pp |
| 1.00 | 0.9800 | -0.70pp |
| 2.00 | 0.9705 | -1.65pp |
| 4.00 | 0.9540 | -3.30pp |

The signal is strong and monotone-negative: contrast amplification
*systematically removes* the right blocks. That means the
deviation-from-leaf-mean signal is *anti-correlated* with block
winnership, not just uncorrelated.

Mechanism: in a high-recall block, the cluster centroid is
representative of the leaf's geometric center. So "deviation from
leaf mean" highlights *outlier* blocks (geometrically far from
the leaf's centroid), which by construction are *less likely* to
contain top-IP rows for a typical query. Contrast amplifies the
worst signal.

This is a useful insight: the leaf mean is not a useful baseline
for score normalization.

## What remains viable

After 036, the remaining candidate paths are:

1. **Different calibration baseline** — instead of per-leaf mean,
   normalize by per-leaf score *variance* or *quantile*. Could
   work; could fail for similar reasons.
2. **Two-stage scoring (Path B from 035)** — k=2 cheap shortlist
   + k=3 expensive final. Estimated overhead: ~1.5ms cheaper than
   pure k=3, possibly enough to clear p50 gate.
3. **Optimized k=3 implementation** — k=3 currently adds ~4.4ms
   p50. SIMD/cache-aware multi-rep scoring might reduce this to
   ~2-3ms, possibly enough to clear the gate.
4. **Accept the slight p50 miss** — k=3 at 49.25ms vs 45ms gate.
   9% over. If Task 79 is reframed as "operationally close enough,"
   this might be shippable as-is.

(3) is the most technically interesting — the k=3 cost shouldn't
*need* to be 3×k=2 in well-tuned code. (2) is more conservative.
(4) is a product call.

## Verdict

Per-leaf contrast calibration in simple form is closed. The
recall-passing recipe remains k=3 at cap768. Next packet should
either pursue Path B (two-stage scoring), an SIMD/cache
optimization of k=3 scoring, or signal a pause-and-decide moment
for the user on whether 49.25ms p50 is operationally acceptable.

The breakthrough from packet 035 still stands — Task 79 is now a
narrow latency optimization problem, not a recall ceiling problem.
The remaining 4.25ms is small enough that several paths might
deliver it.
