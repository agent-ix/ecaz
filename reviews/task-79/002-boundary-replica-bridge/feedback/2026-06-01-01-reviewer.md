# Task 79 packet 002 — boundary replica bridge

## Decision

**Accept.** The packet correctly closes packet 001's F1 (missing `nlists=256`
row) and adds a clean answer on whether boundary replicas can bridge the
recall gap on smaller leaves. The conclusion ("boundary replicas are not
the answer on this fixture") is correctly drawn from the data. The
proposed direction (row-budgeted routing or leaf-local subpartition
pruning) is the right next move per the task spec's Phase 3/4.

## What's solid

- **F1 addressed directly.** The `nlists=256` row is now measured at both
  nprobe=96 and nprobe=128.
- **Boundary-replica behavior is honest.** At `nlists=512`, going from
  b=0 (Phase 1 row: 4M cands / 0.9420 recall) to b=1 (8M / 0.9750) to
  b=2 (12M / 0.9845) shows diminishing returns: each replica step
  roughly doubles candidates for ~3pp recall recovery. That's a clean
  "boundary replicas trade candidates for recall, badly" signal.
- **Pareto frontier shape is now bounded from both sides.** Combined
  with packet 001's n2048 row, no geometry+replica combo tested clears
  both gates: closest to recall gate is n256/nprobe=128 (0.9910, but
  10M cands); closest to candidate gate is n1024/b=1 (4.3M ✓, but
  0.9635 recall, -3.4pp). The "geometry alone fails" verdict is now
  airtight.
- **Methodology is consistent with packet 001.** Same suite shape,
  same database, isolated index per build. Funnel JSONL per-query
  fields healthy.

## Single most interesting Pareto data point

**n256/f16/b=0/nprobe=128** — 10.07M cands, recall 0.9910, p50 46.1 ms.
That's:

- 1.5x reduction in candidates vs baseline (15.5M → 10M)
- 24% p50 improvement (61.2 ms → 46.1 ms)
- 0.65pp short of recall gate

If a tuning task ever revisits SPIRE defaults outside the Task 79
scope, this row deserves a flag as the best geometry-only point under
the high-recall band. Not enough to land as a Task 79 win, but
informative for the defaults follow-on.

## Findings

### F1 — Per-leaf density skew is real and supports Phase 3 direction (non-blocking)

Packet 001's F2 (surface per-config leaf-density percentiles) still
isn't reflected in the summary table, but the funnel JSONL contains it.
Spot-checked n256/nprobe=96: `cand_mean=377`, `cand_p95=789`,
`cand_max=990` per leaf — a ~2.6x skew between mean and max.

That skew is direct evidence supporting Phase 3 (row-budgeted routing):
if a per-query row budget caps the long tail, the savings come from
the p95/p99 leaves not from the median ones. A row-budget of, say,
`96 × mean = 36k` rows per query would cut the candidate surface
significantly at n256 while preserving most leaf coverage.

Please surface this distribution explicitly in the Phase 3 baseline
comparison so the row-budget slice has a clean target. The funnel data
is already collected — just promote it to the summary.

### F2 — Boundary-replica build cost not quantified

The packet correctly observes that boundary replicas "[increase] build
cost" but doesn't quantify it. The Task 73/74 data showed b=1 / b=2
roughly tripled SPIRE build time on M5 (`22041 ms` / `22688 ms` vs
`2671 ms` for b=0 at tg128). If a future packet needs to argue
boundary-replica policy, the build-time cost should be cited alongside
the candidate/recall data. Not blocking here — the recall/candidate
data alone is enough to shelve replicas on this fixture.

## Forward-looking note

The proposed Phase 3/Phase 4 direction is sound. Two specific
suggestions:

1. **Lead with Phase 3 (row-budgeted routing) over Phase 4 (subleaf
   storage).** Phase 3 needs only `source_count` propagation or a
   lightweight estimate path — likely a non-format change. Phase 4 is
   a storage-format/ADR-shaped task and should only be opened if
   Phase 3 measurement shows row-budgeting cannot reach the gate.
2. **Pick a starting `nlists` for the Phase 3 packet.** Based on
   packets 001+002, `nlists=256` and `nlists=512` are the relevant
   bracket: 256 has the right recall floor without budgeting,
   512 has the right candidate count but loses recall. A row-budgeted
   route over n=256-512 has the cleanest headroom against the gates.

## Verdict

Phase 1 geometry/replica exploration is closed. Packet accepted as a
shelve-with-evidence for the boundary-replica direction. The next slice
should be Phase 3 row-budgeted routing, scoped against the n=256-512
range with leaf-density percentiles surfaced in the baseline.
