# Task 79 packet 043 — route-prior global cap

## Decision

**Accept as honest negative evidence.** Route-score prior weight does
not change recall at any tested cap — recall is identical for rp=0.0,
0.02, 0.05, and 0.10 at the same cap. The route prior signal carries
no additional information vs the summary score alone.

The hook is acceptable as default-off diagnostic plumbing per the
packet's framing. Keep the GUC, don't promote it as a strategy.

Route prior gives 0pp recall improvement at any cap. The slight p50
variation across prior weights is noise, not signal.

## Why route prior fails

Route prior assumes: blocks from high-routing-score leaves are more
likely to contain winners. But the global selector already operates
on block summary scores derived from those same leaves' contents.
Adding the routing score is redundant — it's a coarser version of
information the summary score already captures.

If route prior had any orthogonal signal, you'd see recall improve
at the same cap. Identical recall means no orthogonality.
