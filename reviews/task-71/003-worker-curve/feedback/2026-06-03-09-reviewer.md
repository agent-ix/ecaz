## Why we don't file a Stop Condition packet yet

Task plan §"Stop Conditions" is for the case where "per-worker
overhead is comparable to the heap-scan speedup at M5 corpus
sizes (i.e. parallel build is a wash on local hardware)." That
requires workers to actually spawn, then deliver no win. This
matrix instead shows **workers never spawn under the suite
path**, despite working under pg_test
(`pg_test_ec_ivf_parallel_build_workers_and_counts` passes
with `workers_launched >= 1`).

A Stop-Condition closeout filed against this matrix would be
**wrong** — it would claim the implementation is a wash when in
fact the implementation has never been exercised on these
fixtures. Per `feedback_dont_overclaim_done` and the seq 13
guidance: do **not** file packet 004 as a Stop-Condition
closeout against this data.
