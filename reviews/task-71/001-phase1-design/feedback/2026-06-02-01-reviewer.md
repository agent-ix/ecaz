# Phase 1 Design Review — BLOCK

## Verdict

**BLOCK — request revision.** Phase 1 does not meet the task plan's
Phase 1 gating criteria.

## What the packet picks

Option A: per-worker `shm_mq` heap-tuple collection; leader sorts by
heap TID, then runs the existing leader-side `train_model` /
`train_pq_fastscan_model` / `assign_vectors_to_centroids` /
`stage_build_plan` / `flush_build_plan`. Justified mainly as the
smallest engineering surface that mirrors HNSW's pre-DSM coordinator.

## Gating dimensions vs. task plan §"Phase 1 — Design Decision"

| Dimension | Coverage |
|---|---|
| Rough Amdahl bound on heap-scan share | **NOT COVERED.** Zero numbers, no profile. |
| Engineering cost | Qualitative only, no LOC/risk comparison vs. B/C. |
| HNSW alignment | Covered. Correctly identifies the pre-DSM coordinator analog. |
| Determinism / fallback contract | **Asserted, not proven.** See §Blocking issues. |

## Blocking issues

1. **No Amdahl bound.** Task plan §"Phase 1" explicitly requires
   "rough Amdahl bound on heap-scan share." The packet substitutes
   "Task 69 made the rest of the pipeline rayon-parallel" for an
   actual phase-share number. Rayon-parallel inside the leader is
   not free and competes with whatever else runs in the leader; the
   ceiling for Option A is not estimated. Without this, Task §"Stop
   Conditions" — "stop if per-worker overhead is comparable to the
   heap-scan speedup at M5 corpus sizes" — cannot be evaluated.

2. **Posting flush dominance unanalyzed.** ADR-048's lesson was
   that, post-heap-ingestion, graph assembly dominated HNSW build
   wall-clock and motivated ConcurrentDsm. The IVF analog is
   `flush_build_plan` (leader-only page write in centroid order)
   plus PQ-FastScan training. The packet rejects Option C
   ("revisit only if Phase 3 shows posting flush dominates") — a
   wait-and-see deferral that the Phase 1 packet was supposed to
   resolve. With Phase 3 evidence now in (packet 003 shows **no
   speedup** at any worker count on real10k/25k), this design's
   premise is empirically invalidated.

3. **Determinism claim is unjustified.** The packet asserts
   structural equality of "deterministic sample indices, k-means
   seed, centroid assignment, posting-list layout, directory
   entries, metadata." Sorting merged tuples by `(block, offset)`
   only matches the serial baseline **if the serial baseline also
   walks heap in `(block, offset)` order**. `table_index_build_scan`
   does deliver TIDs in physical heap order on a clean table, but
   that order is not stable under HOT pruning / vacuum
   reorganization. Per Task §"Stop Conditions", recall drift > 0.5
   pp is a hard stop — and a sample-set change is the textbook
   driver. The packet needs either (a) a load-bearing argument that
   the sample set is invariant under parallel scan reordering, or
   (b) an explicit change-to-the-sampling-contract note acknowledging
   the new behavior.

## Substantive concerns

- `pq_fastscan` training is also leader-only post-merge. Mentioned
  in passing; no rationale why moving it out of band is not worth
  Option B-style consideration.
- No worker-overhead estimate at small corpora — the very thing the
  Stop Conditions ask about for M5.
- The packet should have run a 5-minute profile on real10k/25k to
  produce the Amdahl numbers. The "no tests run for this design-
  only packet" stance is exactly wrong when the design hinges on
  a phase-share assumption.

## Inconsistency vs. HNSW reference

The packet says Option A "mirrors the proven HNSW parallel
heap-ingestion coordinator." HNSW's coordinator today is a
**two-layered** design — shm_mq heap ingestion **plus**
ConcurrentDsm graph assembly (ADR-048). Option A only takes the
first layer. The packet claims IVF "has no analogous concurrent
graph mutation" — true for the graph itself, but the IVF analog
serial-leader bottleneck (centroid assignment + posting flush)
**does** exist; HNSW measured that it dominated and added the
second layer. IVF skips that measurement and assumes the
bottleneck won't materialize.

## Required to unblock

1. Profile current `ec_ivf` build on real10k and real25k; record
   phase shares (heap scan / train / fastscan-train / assign /
   stage / flush) as `artifacts/phase-profile-real10k.txt` etc.
2. Compute and state the Amdahl ceiling for Option A at workers
   2/4/8 from those numbers.
3. Address sample-set invariance explicitly: either prove the
   serial baseline's sample indices are identical to the
   post-TID-sort indices, or document the sampling-contract change
   and the recall risk.
4. Reconcile with packet 003 evidence: if Option A gives no
   measured speedup at the current corpora (which it does not),
   the Phase 1 packet must either (a) re-pick Option B/C, or
   (b) invoke Task §"Stop Conditions" — defer to Graviton/cloud
   fixtures.
