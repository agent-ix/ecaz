## Still open

3. **`IndexInfoView` / `build_index_info_inner` duplication**
   between IVF and HNSW — both engines now carry near-identical
   typed views. Lift to `src/am/common/index_info.rs` (or extend
   the existing HNSW module) so future safety tightenings only
   need to happen once. Not blocking but invited to land while
   the call-site surface is shallow.

4. **2× heap-row memory peak / no HWM gate**
   (`src/am/ec_ivf/build_parallel.rs:169-180`). Leader still
   holds `worker_tuples: Vec<BuildTuple>` for the full heap
   alongside the populated `state.heap_tuples`. Either
   stream-consume the worker_tuples Vec or capture peak Vec
   capacity into `BuildTimingSnapshot` so the Phase 3 manifest
   stops emitting `not_measured`.

5. **Unused `nparticipantsdone` / `scanned_heap_tuples`
   spinlock-protected counters**
   (`src/am/ec_ivf/build_parallel.rs:127-131, 581-586`). Either
   consume them as a leader-side cross-check
   (`assert nparticipantsdone == launched && scanned ==
   state.scanned_tuples`) or delete the struct entirely. Dead
   synchronization surface hides bugs later.

6. **Missing parallel-vs-serial page-equivalence pg_test.** The
   pg_test that landed
   (`test_ec_ivf_parallel_build_workers_and_counts`) validates
   `workers_launched >= 1` and directory liveness, but does NOT
   compare a `parallel_workers=4` build's posting / centroid /
   directory pages against a `parallel_workers=0` build at fixed
   seed. Task plan §"Phase 2 Exit Criteria" explicitly requires
   this. The escalated cargo-pgrx-test path is now known to work
   (per packet 003 seq 08), so adding a second pg_test is the
   right shape.

## Verdict
