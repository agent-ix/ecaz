# Phase 2 Parallel Heap Ingest Review — REQUEST-CHANGES

## Verdict

**REQUEST-CHANGES.** The slice implements Phase 1 Option A
faithfully and mirrors HNSW patterns, but the Task 71 exit
criterion "structurally-equivalent posting/centroid pages as
single-process build" is not validated by the included tests, and
several `# Safety` and reuse items must land before merge.

## Shape implemented

Workers run `table_index_build_scan` on a parallel heap scan,
encode `BuildTuple` (heap TID, dims, gamma, payload, source-vector
bits) over `shm_mq`, the leader sorts merged tuples by
`(block_number, offset_number)`, then feeds the existing serial
training / staging / flush path. `amcanbuildparallel = true` is
flipped. New ~931-line module
`src/am/ec_ivf/build_parallel.rs` plus ~70 lines of
timing/dispatch in `build.rs`.

## Blocking findings

None at the safety-burndown floor (no anti-pattern B regression,
no new unsafe outside the IVF callback boundary). The items below
must land before this packet closes, but no immediate revert is
needed.

## Substantive concerns (file:line)

1. **`# Safety` docs missing on unsafe fn surface.** Per the user's
   HARD RULE every `unsafe fn` needs a `# Safety` block on the
   item, not a body comment.
   - `src/am/ec_ivf/build_parallel.rs:485`
     (`ec_ivf_parallel_build_main`)
   - `src/am/ec_ivf/build_parallel.rs:494`
     (`parallel_build_worker_main`)
   - `src/am/ec_ivf/build_parallel.rs:787`
     (`estimate_chunk`)
   - `src/am/ec_ivf/build_parallel.rs:798`
     (`estimate_keys`)

2. **`IndexInfoView::as_mut` returns `&mut pg_sys::IndexInfo` from a
   safe fn** (`src/am/ec_ivf/build_parallel.rs:868-871`). This is
   the same anti-pattern B borderline shape the HNSW reference uses
   (`src/am/ec_hnsw/index_info.rs:74-80`). The only caller mutates
   `ii_Concurrent` (line 546). Per view-operations rule, expose a
   typed `set_concurrent(&mut self, bool)` operation instead. Fix
   in both engines as a cross-cut.

3. **Code duplication — `IndexInfoView` and
   `build_index_info_inner`** (`src/am/ec_ivf/build_parallel.rs:839-872`)
   are copy-paste from HNSW. Lift to `src/am/common/index_info.rs`
   (or extend the existing HNSW module to host both engines)
   instead of forking. Phase 2 step 1 ("skeleton") was the right
   moment to do this — please do it now while the call sites are
   shallow.

4. **2× heap-row memory peak / no HWM gate**
   (`src/am/ec_ivf/build_parallel.rs:169-180`). The leader holds
   `worker_tuples: Vec<BuildTuple>` for the full heap, then the
   `for tuple in worker_tuples { state.push(tuple) }` loop only
   shrinks the source as `state.heap_tuples` grows — both Vecs are
   nearly full at the transition. For Phase 3's 100k corpus this
   is on the order of hundreds of MB. Either (a) sort in place and
   move into a `BinaryHeap` / iterator the BuildState consumes, or
   (b) capture peak capacity into `BuildTimingSnapshot` so the
   Phase 3 manifest stops reporting `not_measured`.

5. **Worker `nparticipantsdone` / `scanned_heap_tuples` are written
   but never read** (`src/am/ec_ivf/build_parallel.rs:127-131,
   581-586`). Either consume them as a leader-side cross-check
   (assert `nparticipantsdone == workers_launched &&
   scanned_heap_tuples == state.scanned_tuples`) or delete the
   spinlock-protected struct entirely. Dead synchronization surface
   is technical debt that hides bugs later.

## Test coverage gap — the load-bearing item

`src/tests/ec_ivf.rs::test_ec_ivf_parallel_build_workers_and_counts`
is a single-table smoke test (lines 152-260). It validates
`workers_launched >= 1`, `requested_workers == 2`, `heap_tuples ==
index_tuples == 128`, and basic directory health. It does **not**
validate the Phase 2 step 4 exit criterion: structurally-equivalent
posting/centroid pages between parallel and serial builds at fixed
seed.

Add a pg_test that:
- Builds the same fixture twice (e.g. `parallel_workers = 0` vs
  `parallel_workers = 4`) at fixed seed.
- Asserts byte-equal posting-list pages, directory pages, and
  centroid pages — or at minimum identical page hashes / posting
  digests.
- Asserts byte-equal `pg_relation_size(idx)`.

The 4 in-file unit tests (plan routing × 2, message round-trip × 2)
are useful but only cover encoding format, not the DSM/queue/leader
control path.

Also missing:
- `workers_launched == 0` fallback path test (when PG declines to
  spawn workers).
- Worker error propagation test (synthetic `pgrx::error!` in a
  worker should reach the leader as a build error, not a hang).

## Why these matter under task §"Exit Criteria"

- "Determinism preserved: same-seed builds produce byte-equal or
  structurally-equal index pages across worker counts" — currently
  asserted, not tested.
- "No new `unsafe { ... }` blocks outside the PG callback boundary
  the existing IVF build code already lives in" — satisfied, but
  the `# Safety` doc and view-operations rules apply equally to the
  unsafe surface added inside that boundary.
