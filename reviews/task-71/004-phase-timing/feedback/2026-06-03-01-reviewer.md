# Packet 004 — Phase Timing — APPROVE (instrumentation)

## Verdict

**APPROVE** as instrumentation. This is a useful, narrow
extension of the build-timing surface that turns the seq 17
Amdahl narrative from "heap_ingest vs. everything else" into a
properly-decomposed phase breakdown. No production-path
regressions, no scope creep.

## What this lands

- `ec_ivf_last_build_timing()` gains `train_model_us`,
  `stage_build_plan_us`, `flush_build_plan_us`.
- pg_test helper + `ecaz corpus load` timing row + the
  `ec_ivf_build_timing` loader line all carry the same fields.
- `ecaz dev test ivf-parallel-build-probe` drops + recreates
  the probe timing SQL function on each install so the return
  shape can evolve.
- Single small perf nit: reuses one resolved pq_fastscan
  posting quantizer during serial staging instead of resolving
  per-tuple. Reasonable, low-risk.

## The new evidence is consistent with seq 17

real10k probe:
- w1: build 517.65 ms. heap_ingest=91 ms, train=276 ms,
  stage=143 ms, flush=3 ms.
- w8: build 404.66 ms. heap_ingest=35 ms (2.6× speedup on
  phase), train=258 ms, stage=106 ms, flush=2 ms.

w1 → w8 delta on the parallel phase: 91 → 35 ms = ~2.6×.
w1 → w8 delta on total wall time: 517 → 405 ms = ~1.28×.

The leader-side `train_model` and `stage_build_plan` together
account for ~80% of total wall time at w8. This **directly
confirms** the seq 17 Amdahl reading at finer resolution. There
is no surprise here — the parallel-build path works correctly
and is bounded exactly where Option A allowed it to be.

## Rejected experiment — solid discipline

The retained `artifacts/rejected-rayon-encode/` evidence is
exactly the right call. Adding rayon-parallel posting encode
on top of PG parallel workers produced:

- real10k modest improvement (432.68 ms → 349.29 ms at w8).
- real100k **catastrophic regression**: w1 2.31s → **w8
  9.22s** (4× worse). `stage_build_plan_us` blew up from
  834 ms to 4.25 s; `train_model_us` from 501 ms to 3.28 s.
  Classic oversubscription / phase contention pattern when
  rayon's cores compete with PG's workers.

Retaining the negative result instead of silently reverting is
exactly the discipline the project rules want. The note that
this isn't a viable Task 71 completion path **as tested** is
honest — it doesn't rule out rayon entirely, just this naive
shape.
