## (1) Suite-runner counter — fixed with the right shape

Coder picked **option (a)** as recommended — parse the load
step's own timing line instead of brackets, FR-038 aligned.

The implementation
(`crates/ecaz-cli/src/commands/bench/suite.rs`):

- Removed the broken before/after bracket capture against
  `pg_stat_get_db_parallel_workers_launched`.
- Removed the now-unused `query_parallel_workers_launched`
  helper (~50 lines).
- Added `capture_parallel_workers_from_load_artifacts` that
  walks `step.expected_artifacts` and extracts
  `workers_launched` via the existing
  `parse_ec_ivf_build_timing_line` parser.
- Only captures on `status.success()` — opted-in failed
  steps don't write misleading values.
- **Errors out clearly** if a step has
  `capture_parallel_workers = true` but no `ec_ivf build
  timing` row is found:

  > `bail!("load step {:?} requested capture_parallel_workers
  > but no ec_ivf build timing row with workers_launched was
  > found in expected artifacts")`

  This is exactly the right shape — no silent zeros, no
  misleading manifest data. Future tasks that opt into
  capture but use a different AM that doesn't emit this
  timing line will get a loud failure rather than the
  Task-71-style misdirection.

- For manifest compatibility, `parallel_workers_before` is
  recorded as `0` while `parallel_workers_after` and
  `parallel_workers_delta` both record the parsed count.
  Existing consumers that read `_after` or `_delta` see the
  correct value; the `_before` field is now decorative.
