## Verdict so far: the screen is working — it already produced attributable signal

All numbers below are aggregated from the committed
`pipeline-{variant}-stage-containment.jsonl` (route stage = stage 1

### 1. Route stage == final stage, exactly (Task 120 finding reproduces)

For every variant and nprobe, stage 1 (`topology_route_set`) containment equals
stage 6 (`final_top_k`) containment to the digit. The candidate/rerank/block
stages lose nothing — **all recall loss is at coarse routing**, and route-stage
containment is final recall 1:1. The whole premise of Task 121 holds.

### 2. `boundary_replica_count` 0 -> 1 is a real, strong lever (the Task 120 miss)

| nprobe | baseline | bound1 | delta |
| ---: | ---: | ---: | ---: |
| 8 | 0.7250 | 0.8365 | **+0.1115** |
| 16 | 0.8525 | 0.9235 | +0.0710 |

Biggest gain at **low** nprobe — exactly where routing loss was worst. `bound1`
at nprobe 24 (0.9605) already beats `baseline` at nprobe 32 (0.9310): boundary
replication recovers recall by making routing more precise, i.e. at **lower**
fanout — the opposite of brute-force overfetch. This is precisely the lever
Task 120 left at 0. Cost: index ~2x (`baseline` 81.9 MiB -> `bound1` 160.1 MiB;
per-row total 17504.8 -> 18324.4 B); heap unchanged (7.3 MiB). A real, quantified
Pareto point — carry to Phase 2 and sweep `bound2`/`bound4` for the knee.

### 3. `top_graph_search_list_size` 96 -> 200 is INERT in this sweep — and that is a screen-design bug, not a null result

`tgsl200` is byte-identical to `baseline` at every nprobe (and same 81.9 MiB).
That is expected: the top-graph beam only binds when `nprobe > beam`, and the
sweep tops out at 96 (= baseline beam). With the route set truncated to
nprobe <= 96, widening the beam to 200/400/800 cannot change which leaves are
selected. **As configured, the `tgsl*` variants cannot test the beam lever** —
they will all report "no effect" for the wrong reason.

**Required fix before running tgsl400/tgsl800:** for the `tgsl*` variants, extend
the nprobe sweep past the beam-vs-baseline crossover (e.g. add 128/160/200) so
the wider beam actually selects a larger/better route set. Otherwise drop the
`tgsl*` variants from this screen and test the beam only in a sweep that ranges
beyond 96. Do not conclude "beam-widening doesn't help" from the current data.
