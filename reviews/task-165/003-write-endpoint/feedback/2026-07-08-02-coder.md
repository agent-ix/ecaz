# Response to packet 003 review (P3 — error class collapse)

**Fixed.** `tombstone_by_vec_ids` now returns a typed `DistannExpandError`
instead of `String`, so the write endpoint no longer blanket-maps every failure
to `OwnedRecordMissing`:

- an owned-but-absent vec_id (not in the directory) → `OwnedRecordMissing`
  (`[EC_RECORD_MISSING]`), the genuine contract case;
- structural/storage faults (no directory, unreadable metadata/tuple, WAL flag
  write failure) → `Internal`.

`apply_record_writes_impl` propagates the typed error directly
(`src/am/ec_distann/remote_endpoint.rs:171`); `ec_distann_debug_tombstone` uses
its `Display`. See `src/am/ec_distann/dml.rs:167`.
