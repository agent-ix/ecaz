# Task 165 packet 018 review

No signoff for closing FR-082-AC-5. The drill is a useful VACUUM/tombstone smoke
test, but it does not demonstrate the specific TID-reuse hazard named by AC-5.

## Findings

### P1 - The AC-5 drill probes an untouched row, not a TID-reused vec_id correspondence

FR-082-AC-5 requires that a vec_id's exact-rerank vector resolved through
`heap_tid` remains byte-identical to its build-time vector, and that a concurrent
base-table delete + VACUUM + TID reuse never causes rerank against a different
tuple (`spec/functional/index/distann/FR-082-distann-epoch-lifecycle.md:82`).
The drill records row 1's top-1 result, deletes a mid-range, VACUUMs, reinserts
that same mid-range, and then probes row 1 again
(`crates/ecaz-cli/src/commands/dev/distann_multicluster.rs:960`,
`crates/ecaz-cli/src/commands/dev/distann_multicluster.rs:973`,
`crates/ecaz-cli/src/commands/dev/distann_multicluster.rs:991`,
`crates/ecaz-cli/src/commands/dev/distann_multicluster.rs:1012`).

Row 1 was never deleted, so its heap TID should not be reclaimed or reused. The
test therefore proves that unrelated heap churn did not change an untouched
top-1 result. It does not prove that a stale indexed vec_id cannot follow a
reused TID to a different tuple, nor does it assert byte-identical rerank vectors
for a vec_id whose old heap slot was part of the churn.

### P2 - The implementation still relies on live heap reads for exact rerank

The packet's design rationale says the existing D10/VACUUM behavior is enough to
avoid a separate frozen-vector tier. That may become a defensible single-node
degenerate posture, but the current multi-node read path still resolves heap
ctids at read/materialization time (`src/am/ec_distann/remote_endpoint.rs:293`)
and slices the node record's raw `heap_tid` field directly
(`src/am/ec_distann/remote_endpoint.rs:356`). The spec text for multi-node
deployments says the `heap_tid` resolves an epoch-owned frozen snapshot rather
than a base-table TID exposed to reuse
(`spec/functional/index/distann/FR-082-distann-epoch-lifecycle.md:47`).

If M3 deliberately narrows AC-5 to the single-node degenerate behavior, that
should be documented as a scoped deviation. As written, the packet overclaims
the multi-node frozen-vector requirement.

### P3 - Packet 018 has no artifact manifest

The evidence is a summary log and node logs, but the packet lacks
`artifacts/manifest.md` with exact SHA, command, fixture parameters, and cited
result lines.

## What was done well

- The drill runs real DELETE/VACUUM/reinsert on every node instead of relying on
  a mocked tombstone path.
- It checks for `EC_VECTOR_MISSING` after churn, which is the right class of
  failure to keep watching.
