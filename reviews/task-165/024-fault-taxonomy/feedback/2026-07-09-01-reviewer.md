# Task 165 packet 024 review

Reject the 12/12 NFR-020 verdict. Several drills prove that an injected call
errored, but two of the accepted post-error states are not transactionally safe.

## Findings

### P0 - The mid-delete drill accepts a live row being hidden by an aborted write

`ec_distann_apply_record_writes` flips the tombstone in-place and then injects an
error (`src/am/ec_distann/remote_endpoint.rs:274-285`). The packet observes that
the non-MVCC index-page flag survives transaction abort and treats
`errored && stable_tombstoned && excluded_from_scan` as success. In the drill,
however, the endpoint is invoked directly against a live heap row; the error
aborts the SQL transaction while the heap row remains live. Subsequent ANN scans
silently omit that row. That is neither a correct-complete result nor a durable
delete, and violates NFR-020/SQL transaction semantics.

The GUC documentation still states the opposite—that abort rolls the flag back
(`src/am/ec_distann/options.rs:257-260`). Redesign this as an idempotent,
recoverable write protocol whose visibility is coupled to a committed delete,
or fail the index/epoch and rebuild after an indeterminate outcome. Do not count
the current behavior as a passing fault arm.

### P1 - The mid-insert drill cannot prove rollback after visible backlink writes

`graph_insert_record` appends the node, mutates existing backlinks in place, and
writes a replacement directory before the injected failure; only afterward does
it publish metadata (`src/am/ec_distann/insert.rs:391-450`). The same packet
establishes that WAL-logged index-page mutations are not undone on transaction
abort. A failure can therefore leave an active neighbor pointing to a vec_id
that the active directory cannot resolve, causing `OwnedRecordMissing` during a
later traversal. Concurrent readers can observe the same interval even without
an injected error.

Comparing one pre/post top-10 query does not inspect graph closure or force the
mutated neighbor to expand. Add a pending/idempotent mutation protocol and a
drill that validates every published adjacency resolves in the active directory
after abort/restart, plus concurrent scans through each amended record.

### P1 - The packet does not verify distributed DML routing

The AM's live insert callback still only appends to the local delta buffer
(`src/am/ec_distann/routine.rs:80-98`) and rejects global
`source_identity='include'` inserts (`src/am/ec_distann/dml.rs:290-296`). Vacuum
delete only tombstones the local index, and the write endpoint supports only a
caller-supplied tombstone list. Calling that endpoint directly in a fixture is
not coordinator-to-owner DML routing. Task 165 AC-3 and the packet's
“tombstone/delta DML distributed” claim remain open.

## Validation

The current-head EC_DISTANN test selection passed 110 tests. Those tests confirm
the injected calls and happy paths, but do not assert transactional recovery,
global adjacency closure, or routed distributed DML.
