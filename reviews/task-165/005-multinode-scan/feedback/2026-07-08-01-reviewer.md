# Task 165 packet 005 review

No signoff for real multinode reads. This packet is a useful loopback AM integration check, but the materialization architecture is still loopback-only.

## Findings

### P1 - Remote-hit materialization still depends on a full local coordinator directory

The request says remote responses are materialized by resolving each remote hit from the local directory, and that a real multi-node deployment would ship row data from the owning node instead (`reviews/task-165/005-multinode-scan/request.md:15`). The manifest repeats that both loopback roster entries point at the same instance and the coordinator has the full directory (`reviews/task-165/005-multinode-scan/manifest.md:16`).

The code does exactly that: for any hit with `heap_tid=INVALID`, it performs a local `directory_lookup`, reads the local index record, and decodes the heap TID (`src/am/ec_distann/routine.rs:395`). If the vec_id is absent locally, it errors with "multi-node row materialization is a follow-up" (`src/am/ec_distann/routine.rs:407`). This preserves fail-closed behavior, but it means a real 3-worker scan cannot yet return remote-owned SQL rows. Task 165's 3-worker fixture requirement is therefore not satisfied by this packet.

### P2 - Remote index resolution uses an unqualified relation name

The scan passes `distann_index_relname(index_relation)` into the remote transport (`src/am/ec_distann/routine.rs:378`), and that helper returns only the unqualified relname (`src/am/ec_distann/routine.rs:535`). The remote SQL resolves it with `$1::text::regclass::oid` (`src/am/ec_distann/remote_transport.rs:113`). This works in the loopback scripts because both sessions share the same default schema/search_path, but it is fragile for real nodes where schema/search_path or per-node index names differ.

Use a schema-qualified regclass string or, better, carry the remote node's index identity from the epoch/placement manifest. Add a test where the index is not on the default search path so this does not regress.

### P3 - The measurement manifest is outside the required artifacts location

This packet has `reviews/task-165/005-multinode-scan/manifest.md`, but the workflow requires measurement packet metadata at `artifacts/manifest.md`. The manifest also says `head SHA: this commit` rather than an exact commit hash (`reviews/task-165/005-multinode-scan/manifest.md:3`). Please move/copy the manifest to the artifact directory and pin the exact SHA that produced `artifacts/scan-compare.log`.
