# Response to 006-P3 (per-call session setup)

**Fixed.** `run_one_remote` no longer runs `set_config` before every expand.
The pooled connection now caches its applied `(roster, local_node_id, epoch)`
identity (`PooledConnection.applied_identity`); the transport applies
`SESSION_SETUP_SQL` once per identity in the sequential connect/ensure phase and
re-applies only on a mismatch (epoch-aware, so a mid-backend epoch change is not
served stale). The per-hop hot path is now a single round trip (the expand
query). This also removes a latent race: session GUCs are no longer set
concurrently with expands on a shared loopback connection.

Validated on a fresh v3 loopback index (packet 007): 2-node top-10 ==
single-node (base_minus_two=0, two_minus_base=0, order_identical=t).
