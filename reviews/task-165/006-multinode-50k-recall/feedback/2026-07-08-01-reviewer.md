### P1 - The exit gate evidence is loopback SQL, not the required M3 3-worker bench suite

Task 165 requires a full fault matrix on a 3-worker fixture, epoch swap under concurrent load, and 50k multinode `distinct_recall >= single-node - 0.001` via `ecaz bench suite` (`plan/tasks/165-ec-distann-m3-lifecycle-faults.md:15`, `plan/tasks/165-ec-distann-m3-lifecycle-faults.md:35`). This packet instead runs SQL scripts against monolithic `m1_50k_mono_idx` / `m1_100k_mono_idx` indexes, with both roster nodes pointed at the same `ec_distann_bench` instance (`reviews/task-165/006-multinode-50k-recall/manifest.md:5`, `reviews/task-165/006-multinode-50k-recall/recall-compare.sql:6`).

The result proves a strong loopback property: the 2-node loopback AM path returns the same top-10 ids as the single-node path across 51 queries (`reviews/task-165/006-multinode-50k-recall/artifacts/recall-compare.log:8`, `reviews/task-165/006-multinode-50k-recall/artifacts/recall-compare-100k.log:5`). It does not prove the required 3-worker build/publish/retire lifecycle, transport fault matrix, row shipping/materialization, or `ecaz bench suite` recall output. Please keep this as supporting evidence, not the M3 closeout gate.

### P2 - Reproduction depends on manual extension SQL refresh

The manifest says `ec_distann_bench` predates the M2 endpoints and was refreshed by applying CREATE FUNCTION statements manually from the installed extension SQL (`reviews/task-165/006-multinode-50k-recall/manifest.md:29`). That is not a clean reproduction path for closeout evidence. For gate evidence, use a fresh database created from the built extension, or record the exact SQL patch and command output as packet-local artifacts so another reviewer can reproduce the state.

### P2 - Packet provenance does not meet the review artifact rules

The manifest is at `reviews/task-165/006-multinode-50k-recall/manifest.md`, not `artifacts/manifest.md`, and records `head SHA: this commit` instead of an exact SHA (`reviews/task-165/006-multinode-50k-recall/manifest.md:3`). The workflow requires `artifacts/manifest.md` as the packet-local source of truth with exact head SHA, commands, timestamp, fixture, and key result lines. Please move the manifest under `artifacts/`, pin the commit, and include the exact suite/script command provenance.

### P3 - Remote calls still pay a session-setup query on every owner/hop

`run_one_remote` executes the `set_config` session setup before every expand query (`src/am/ec_distann/remote_transport.rs:217`). In a hop-round scan that is one extra round trip per remote owner per hop. The Task 164 packet already measured loopback transport around 2.8-3.0 ms/query and called this out as an efficiency follow-up; it remains in this exit-gate branch.

Because connections are pooled by target, move stable roster/local-node/epoch setup to connection initialization or cache the last applied target identity per connection. If epoch can change mid-backend, make the cache epoch-aware and invalidate on mismatch/retry.
