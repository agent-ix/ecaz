# Task 165 packet 017 review

No completion signoff. The lock-manager retention gate is a real improvement over
the earlier debug-only in-flight counter, but it does not close the remaining
FR-082 lifecycle claims by itself.

## Findings

### P1 - `publish_epoch` still is not the scan path's active epoch source

`ec_distann_publish_epoch` writes `metadata.active_epoch`
(`src/am/ec_distann/epoch_manifest.rs:74`), but scans still derive the active
epoch from the session GUC (`src/am/ec_distann/roster.rs:77`) and build the
placement directory from that GUC value (`src/am/ec_distann/roster.rs:140`). The
packet's new concurrency drill churns `ec_distann_publish_epoch(..., 1/2)`
(`crates/ecaz-cli/src/commands/dev/distann_multicluster.rs:654`), while every
scan in the same drill explicitly sets `ec_distann.epoch=1`
(`crates/ecaz-cli/src/commands/dev/distann_multicluster.rs:612`).

That means the drill proves metadata writes do not crash concurrent scans; it
does not prove FR-082-AC-1's query-visible epoch swap or the "one scan attempt
executes wholly within one published epoch" rule. The read path still needs to
consume the published manifest/active epoch, with the GUC path demoted to the
documented fallback/override.

### P2 - The live retention gate is useful, but the override can still retire while scans hold locks

The normal retire path now conditionally acquires `AccessExclusiveLock` on the
index (`src/am/ec_distann/epoch_manifest.rs:94`), which correctly conflicts with
scan-held `AccessShareLock` and auto-clears on backend exit. However,
`ec_distann_force_retire_epoch` still uses only the `RowExclusiveLock` path
(`src/am/ec_distann/epoch_manifest.rs:133`), which does not conflict with active
`AccessShareLock` scans.

If force-retire is intentionally allowed to override live locks, the operator
contract should say so explicitly because it is stronger and riskier than
"wedged persisted count override." If it is not intended, force-retire should
also check or report live relation locks before changing lifecycle state.

### P3 - Packet 017 has no artifact manifest

The packet contains `distann-multinode-summary.log` and node logs, but no
`artifacts/manifest.md`. The review workflow asks packet-local evidence to name
the exact head SHA, command, fixture, timestamp, and key cited result lines.

## What was done well

- Using PostgreSQL relation locks for the live gate is a pragmatic auto-clearing
  mechanism and avoids a fragile shared-memory counter.
- The held-cursor drill exercises a real scan-held `AccessShareLock`, not just a
  direct metadata setter.
