# Task 165 packet 019 review

This packet did something valuable: it caught a real recall regression that the
default-top_k identity check missed. The bench GUC fix is good. No signoff,
because the new gate is not actually hard-gated and is not the required suite
closeout evidence.

## Findings

### P1 - A failing suite recall gate does not fail the fixture

The packet artifact contains:

```
suite_recall_gate single=0.5000 multi=0.3700 delta=-0.1300 pass=false
```

but `drive_fixture` only writes `suite_line` to the summary
(`crates/ecaz-cli/src/commands/dev/distann_multicluster.rs:321`,
`crates/ecaz-cli/src/commands/dev/distann_multicluster.rs:528`) and never bails
when it contains `pass=false`, `SKIPPED`, or `INCONCLUSIVE`. The hard failure
checks later cover the old byte-identical recall line, concurrency, retention,
AC-5, fault matrix, recovery, and disjoint shard only
(`crates/ecaz-cli/src/commands/dev/distann_multicluster.rs:539`).

That made the packet's most important finding non-blocking. A regression gate
should return a structured status and fail the fixture unless the caller has
explicitly requested an informational run.

### P1 - This is not the required `ecaz bench suite` closeout matrix

The fixture calls `ecaz bench recall` directly on a 2k-row/50-query copied corpus
(`crates/ecaz-cli/src/commands/dev/distann_multicluster.rs:781`,
`crates/ecaz-cli/src/commands/dev/distann_multicluster.rs:830`). Task 165's
required evidence is 50k multinode recall via `ecaz bench suite` in release
build (`plan/tasks/165-ec-distann-m3-lifecycle-faults.md:33`), and the repository
closeout rule for index/scan/storage behavior requires 10k/50k/100k recall,
latency, and storage evidence via `ecaz bench suite`.

This packet is a good diagnostic gate, not promotion evidence. It has no suite
config, suite manifest, `results.jsonl`, latency rows, storage rows, or
10k/50k/100k staged corpus rows.

### P3 - Packet provenance and artifact hygiene need cleanup

The packet lacks `artifacts/manifest.md`. Also, the current worktree has
uncommitted modifications to the three packet 019 node logs, so the committed
packet evidence and local artifact state do not currently match.
