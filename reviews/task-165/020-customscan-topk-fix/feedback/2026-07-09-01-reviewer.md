# Task 165 packet 020 review

Partial approval for the specific exploration-bar bug. No read-path signoff:
the fix is correct for the unqualified LIMIT shape the suite gate covered, but
several CustomScan correctness blockers remain.

## Findings

### P1 - CustomScan still applies LIMIT before executor quals can filter rows

The fix now explores to `ec_distann.top_k.max(LIMIT)` and truncates hits to
`state.top_k` (`src/am/ec_distann/custom_scan.rs:803`,
`src/am/ec_distann/custom_scan.rs:833`). That fixes the packet 019 top_k=32
under-exploration for simple unqualified top-k queries.

However, the CustomScan stores the original quals on the plan, then gathers and
truncates ANN hits before PostgreSQL's executor applies those quals. There is no
loop that over-fetches until LIMIT rows survive filtering. A query such as
`ORDER BY embedding <#> $q LIMIT 10` with an additional remote-row predicate can
therefore return fewer than 10 qualifying rows or the wrong top-10-after-filter
set even when more qualifying rows exist just beyond the first ANN LIMIT.

### P1 - Remote payload narrowing ignores qual columns

Remote row payload metadata narrows shipped columns to plain target-list Vars
only (`src/am/ec_distann/custom_scan.rs:552`). `store_remote_payload` sets every
unshipped attribute to NULL (`src/am/ec_distann/custom_scan.rs:975`). If a qual
references a column that is not projected, the coordinator evaluates the qual
against NULL for remote rows. That is a correctness bug for common SQL shapes
like selecting only `id` while filtering on another column.

Payload selection must include all attributes needed by target list and quals,
or fall back to shipping the whole row whenever quals are present.

### P2 - Planner eligibility still does not bind the ORDER BY expression to the selected index

The planner hook accepts any relation Var plus `real[]` ORDER BY operand
(`src/am/ec_distann/custom_scan.rs:164`) and then picks the first ec_distann
index on the relation (`src/am/ec_distann/custom_scan.rs:229`). It does not
verify that the Var's attribute/opclass/operator family match the chosen index.
On a table with multiple vector columns or multiple ec_distann indexes, the
distributed CustomScan can execute against the wrong index.

### P3 - Packet 020 has no artifact manifest

The packet lacks `artifacts/manifest.md` with the exact head SHA, command,
fixture, and cited result lines.
