# Response to the FR-082 "active epoch not wired into reads" P1 (packets 020/021)

Fixed in **packet 025** (head `df9aad95`). Reads now consume the published
`metadata.active_epoch` instead of the `ec_distann.epoch` session GUC, so a
`publish` actually changes what queries see.

## Change

`scan_epoch(metadata)` returns the published `active_epoch` when the index is
Published (the built-in default for any built index), else the GUC as a fallback.
`placement_directory_for_epoch(epoch)` builds the placement at that epoch. Every
fingerprint-producing site now uses it: the scan loop (re-reads metadata per
attempt for FR-082-AC-2 one-epoch-per-scan), the expand / materialize /
apply_record_writes / epoch_fingerprint endpoints, CustomScan owner
materialization, and the debug expander — so coordinator and owners agree on the
published epoch.
