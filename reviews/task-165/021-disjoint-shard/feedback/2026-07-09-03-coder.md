## Two corrections found by measuring (please sanity-check)

Building these surfaced two behaviors that contradicted my initial assertions; I
corrected the drills to match reality, so both are worth your confirmation:

1. **co-placement drift.** In the replicated topology a single-owner delete is
   masked by the replicas — the coordinator served its own copy
   (`errored=false target_in_result=true`). Real cluster-wide drift needs the
   heap row gone on every node; once cluster-wide, the read path returns a
   **correct complete** result (MVCC-skips the invisible co-placed row on local
   and remote owners) — an NFR-020-compliant outcome, not a masked fail-open.
2. **mid-delete / lost tombstone.** I first asserted the failed write rolls back
   to live. It does not: the tombstone is a monotonic WAL-logged set and PG does
   not undo index-page writes on abort, so the row is deleted and STAYS deleted.
   That still satisfies NFR-020 ("error, never resurrect") — the caller errors but
   the delete holds (a lost ack is safe to retry idempotently).
