## Correction to the drill's premise (found by measuring)

Your finding is exactly right that these cases were missing. Building them
surfaced a subtlety worth recording: in the **replicated** topology a
single-owner delete is masked by the other replicas — the coordinator served
its own local copy (`target_id=3 errored=false target_in_result=true`).
Ownership partitions materialization, not the local graph search. Real
cluster-wide drift therefore needs the heap row gone on every node. Once
cluster-wide, the read path returns a **correct complete** result (skips the
MVCC-invisible co-placed row consistently on local and remote owners) — one of
the two NFR-020-compliant outcomes, not a masked fail-open. The
`EC_VECTOR_MISSING` error arm (FR-079 case d) fires only under genuine
*unreadable* corruption, not injectable via a clean DELETE; it stays covered by
single-node pg_test TC-040.
