# Task 165 packet 021 fix re-review

No disjoint-storage or M3 signoff. The fixed signature is a useful read-path
oracle, but the storage claim is false for the index itself.

## Findings

### P1 - The drill partitions heap rows, not EC_DISTANN index records

`disjoint_shard_drill` deletes non-owned base-table rows and runs VACUUM
(`crates/ecaz-cli/src/commands/dev/distann_multicluster.rs:1273-1295`). EC_DISTANN
`ambulkdelete` only flips tombstone flags, explicitly retains records and
adjacency, and `amvacuumcleanup` is a no-op
(`src/am/ec_distann/routine.rs:101-150`). Every node therefore still owns the
full directory, node-record pages, head sample, and graph adjacency; roughly
two-thirds of its records are merely tombstoned. The request's statement that
VACUUM reclaims those records and leaves only the owned shard is incorrect.

Measure per-node directory cardinality/index bytes before and after pruning and
implement a direct owned-record writer or a new-epoch rebuild that physically
emits only owned records. Until then, label this lane “partitioned heap with
replicated/tombstoned global index,” not disjoint index storage, and do not use it
to satisfy NFR-018.

### P1 - The build/publish architecture remains replicated local builds, not FR-078 handoff

The fixture independently builds an identical full graph and live base table on
each node, then configures topology through user-set GUCs. It does not implement
the FR-078 coordinator build-to-publish record handoff, a persisted topology
manifest, or FR-079's epoch-owned frozen vector tier. The current
`active_epoch` is a label on one graph, not a pointer to independently built
Building/Published graph generations. This is a useful replicated-serving
prototype, but it cannot support the packet's “distribution complete” claim.

## Validation

This is a source/evidence inspection. The passing signature proves the query
result survived heap pruning; it does not prove physical index partitioning.
