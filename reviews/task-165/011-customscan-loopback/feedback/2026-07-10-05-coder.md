Thanks for the precise re-review of `d4bd980dc`. Two of the three findings are
fixed; the third (the tie-break) turned out to be coupled to the early-exit
soundness and I am reporting that rather than shipping an unsound half-fix.

## P1 raw proven boundary through materialization — FIXED

`run_search_and_build_outputs` now tracks `proven_outputs` while building the
output vector: it counts only outputs whose **raw hit rank** is `< effective`,
computed during the build loop, not `min(effective, outputs.len())` after remote
payload-miss drops. `proven_prefix_len` returns `proven_outputs` (early-exit) so
an in-window dropped payload can no longer shift a beyond-boundary hit into the
counted prefix.

## P2 self-moving cap — FIXED

Added `deepen_cap`, derived once in `ensure_outputs` from the initial bar
(`effective * 64`), and the exec loop tests `state.effective < state.deepen_cap`
instead of recomputing the ceiling each iteration.

## P1 tie-break / stable prefix — REPORTED AS COUPLED, not shipped

I implemented the `(exact_dist, vec_id)` total order at both hit-sort sites
(`scan.rs`, `routine.rs`) as suggested, then reverted it. Making the order total
**exposes a pre-existing early-exit soundness gap** (your Task 164 FR-081-AC-4
finding): with a deterministic total order,
`test_ec_distann_limit_beyond_top_k_deepens_correctly` fails —
`deepened=[1,8,5,2,7,4]` vs `full=[1,8,5,3,7,4]`. The shallow-bar (top_k=2) scan
early-exits and declares a proven prefix that **omits a true top-k member**
(id 3), serving id 2 at rank 4; the deeper re-run then cannot reinsert id 3
because the cursor already passed rank 4. The bare distance sort was masking this
by ordering the id 2 / id 3 tie the same way in both scans.

So the tie-break is correct in isolation but must land **with** the early-exit
lower-bound fix (164-P1), not before it — otherwise it converts a latent
early-exit miss into a visible deepening divergence. I left an explicit note at
both sort sites. The single-node AM and multi-node CustomScan continue to share
the identical bare-distance sort, so their results stay identical (the real-10k
`qual_correctness mismatch=0` is from the proven-boundary fix, not the tie-break).
