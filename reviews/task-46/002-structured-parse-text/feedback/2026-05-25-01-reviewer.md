# Task 46/002 APPROVED on merits with §Validation-threshold note — 2× coverage hit honestly disclosed; operator disposition needed on per-target vs aggregate gate

`2bfcca062` (code) + `17f7e5afd` (request) reviewed.

## Scope — second structured-fuzz target

`parse_text_structured` — explicitly named in Task 46 §Why as the
canonical structural-waste example.

Surface has **7 structural gates** before reaching the parser's
arithmetic: valid UTF-8 → `[…]` brackets → comma-separated
`key=value` header → numeric `dim`/`bits` → canonical defaults
(`bits == 4`, `seed == 42`) → valid hex body → body length equals
`payload_len(dim, bits) - 4`. Raw byte fuzzer almost never passes
all seven; structured target encodes the valid-shape relationship
via `Arbitrary` derive.

## Code — minimal, scope-correct

- `fuzz/Cargo.toml`: registers `fuzz_parse_text_structured` bin
- `fuzz/src/lib.rs`: promotes `DEFAULT_QUANT_BITS` / `DEFAULT_QUANT_SEED`
  to `pub` + re-exports via `bench_api`
- `fuzz/fuzz_targets/parse_text_structured.rs` (new, +85 lines):
  `Arbitrary` produces `(dim ∈ 1..=1024, gamma_bits, code_seed)`;
  formats canonical `[dim=…,bits=…,seed=…,gamma=…]:hex` with exact
  `payload_len(dim, bits) - 4` code bytes; asserts every field
  round-trips (`gamma` within `1e-3 * |gamma|` per `f32::parse`
  precision floor)

**Zero production code change.** Tooling-only.

Slice 002 hits **~2× absolute coverage** — below the 5× threshold.

### Coder framing — intellectually honest

The request explicitly discloses the gap and offers two structural
reasons:

1. **`parse_text` has richer error branches than `unpack_mse`**:
   `unpack_mse` rejects almost every raw input at the first length
   check (one branch); `parse_text` traverses 7 error returns plus
   success arithmetic, so raw bytes can plausibly hit several of
   them without ever satisfying the full success path
2. **cov-per-corp-entry is the more honest metric**: 0.90 → 3.20
   (3.55×) — shows the structural-fuzz win in per-input terms

This is **not** a "within rounding" off-ramp. Coder isn't claiming
2× ≈ 5×; they're transparently reporting that this surface doesn't
hit the 5× threshold and explaining why.
