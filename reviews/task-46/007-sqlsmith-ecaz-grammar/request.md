## What changed

### New crate: `crates/ecaz-sqlgen/`

- `Cargo.toml`: clap + tokio-postgres + ChaCha8Rng. Workspace
  already includes `crates/*` so no top-level Cargo.toml change.
- `src/lib.rs` (~140 LOC): the `Generator` struct with the five
  templates Task 46 §Approach 3 names line-by-line:
  1. `select_order_by_vector` — `SELECT ... ORDER BY <col> <op>
     '<vec>'::vector LIMIT n`, op drawn from
     `{ <->, <#>, <=> }`, dim from production ladder
     `{16,64,128,...,3072}`, k from `{1,5,10,25,50,100}`.
  2. `create_index_and_workload` — `CREATE INDEX ... USING
     {ec_diskann,ec_hnsw,ec_ivf} ({col})` followed by random
     INSERT / SELECT / VACUUM.
  3. `prepared_vector_query` — PREPARE/EXECUTE/DEALLOCATE with a
     bound vector parameter of varying dim.
  4. `partial_or_expression_index` — partial (with
     `WHERE id > threshold`) or expression (`(col::vector)`)
     index over the vector column.
  5. `reindex_interleaved` — CREATE INDEX → REINDEX INDEX
     CONCURRENTLY → vector query in sequence.
- `src/main.rs` (~120 LOC): clap binary with two subcommands:
  - `generate`: emits N statement groups to stdout or `--out PATH`.
    Default seed `42`, count `64`.
  - `execute`: streams the deterministic stream to a live PG18
    cluster via `--dsn` (or `SQLSMITH_DSN` env). Tolerates clean
    SQL ERRORs; counts and surfaces hard failures (`PANIC`,
    `server closed`). `--fail-fast` flag for the CI lane.
- Three unit tests:
  - `deterministic_for_same_seed`
  - `each_template_emits_at_least_one_statement`
  - `statements_terminate_with_semicolon`

### Seed corpus: `fixtures/sqlsmith-ecaz/seed-42-count-32.sql`

- 85 lines (32 statement groups, average ~2.6 statements per group).
- Generated by `./target/release/ecaz-sqlgen generate --seed 42
  --count 32 --out fixtures/sqlsmith-ecaz/seed-42-count-32.sql`.
- Deterministic — re-running with the same args reproduces the
  same file byte-for-byte (verified by `deterministic_for_same_seed`
  unit test + the in-process determinism of `ChaCha8Rng`).

### `Makefile`: `sqlsmith-ecaz` target

- Wraps `cargo run --release -p ecaz-sqlgen -- execute
  --dsn $(SQLSMITH_DSN) --seed $(SQLSMITH_ECAZ_SEED) --count
  $(SQLSMITH_ECAZ_COUNT)`.
- Errors out if `SQLSMITH_DSN` is unset.
- Defaults: seed=42, count=256.

### `.github/workflows/sqlsmith-ecaz-nightly.yml`

- Cron: `37 4 * * *` (nightly 04:37 UTC).
- Steps:
  1. Install PG18 via apt, start the systemd unit.
  2. Create `runner` superuser + `ecaz_sqlsmith` database.
  3. Build the ecaz extension (release, features=pg18).
  4. Create base table `ecaz_sqlgen_t (id, embedding vector(128))`.
  5. Run `make sqlsmith-ecaz` against the cluster.
  6. Upload `fixtures/sqlsmith-ecaz/` as run artifact.
- 120-minute timeout for the full generate→execute cycle.

## Reviewer focus

- The generator is small (~140 LOC of templates + ~120 LOC of CLI)
  and intentionally so: Task 46 §Approach 3 lists exactly five
  templates; the crate implements exactly those five. No
  speculation, no untested patterns.
- `ChaCha8Rng` seeded from a fixed u64 is the deterministic
  source — `deterministic_for_same_seed` unit test confirms
  byte-for-byte reproducibility, which is what makes a committed
  seed corpus useful.
- The `execute` path is honest about disposition:
  - Clean SQL ERROR → counted, not failed (workload is supposed
    to hit constraint and partial-index validation errors).
  - PANIC / "server closed" → counted as `hard_failures`; non-zero
    exit when any are observed.
- `make sqlsmith-ecaz` errors out cleanly when `SQLSMITH_DSN` is
  unset, matching the existing `make sqlsmith-pg18` lane's
  ergonomics.
- The nightly workflow sets up PG, the ecaz extension, and a
  base table before invocation — the lane is self-contained, not
  dependent on a long-lived test cluster.
