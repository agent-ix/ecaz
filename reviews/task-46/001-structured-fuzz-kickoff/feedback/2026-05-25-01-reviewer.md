## §Validation criterion — MET with substantial margin

Task 46 §Validation: "Structured fuzz targets achieve ≥ 5× higher
feature/edge coverage per second than the equivalent raw-byte
targets."

Headline 10s runs at same head SHA, back-to-back:

| Metric | Structured (`unpack_mse_structured`) | Raw-byte (`unpack_mse`) | Ratio |
|---|---:|---:|---:|
| Coverage | 213 | 40 | **5.3×** ✓ |
| Features | 681 | 91 | **7.5×** ✓ |
| Corpus | 85 | 24 | 3.5× |
| Exec/s | 257k | 816k | 0.31× (slower per exec, as expected — bigger ops) |
| NEW units in 10s | 57 | **0** | ∞ |

The raw target's 0 NEW units in 10s is the structural-waste smoking
gun Task 46's spec describes: raw fuzzer mutations almost always
fail the `packed.len() != expected_len` shape check and never reach
unpack. The structured target encodes the valid-shape relationship
into the input type via `arbitrary::Arbitrary` so every exec lands
in the actual unpack routine.

## Code changes — minimal, scope-correct

- `fuzz/Cargo.toml` — adds `arbitrary = { version = "1", features = ["derive"] }`
  + registers `fuzz_unpack_mse_structured` bin
- `fuzz/src/lib.rs` — re-exports `pack_mse_indices` from `bench_api`
  for structured-target encode side
- `fuzz/fuzz_targets/unpack_mse_structured.rs` (new) — uses
  `arbitrary::Arbitrary` to produce valid-shape inputs
  `(dim ∈ 1..=2048, bits ∈ 2..=7, indices: dim values masked to bits)`
  and asserts `unpack(pack(indices)) == indices`

**No production code change.** Tooling/test-only addition.
