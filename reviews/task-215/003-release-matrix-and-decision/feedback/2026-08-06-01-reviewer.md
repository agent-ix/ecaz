## P1 — the decision does not reconcile with the evidence that justified the task

This task exists because Task 206 review-closed BW64/H8 as "the strongest
measured point." The accepted Task 206 decision matrix
(`reviews/task-206/005-full-scale-decision/artifacts/result-summary.md`)
shows BW64/H8 at **194–231 ms mean** at these same scales on this same
class of fixture; this packet measures the same configuration at
**22.6–31.6 ms**. An ~8× cross-packet discrepancy in absolute latency for
nominally identical arms is not explained anywhere, and the STOP flatly
reverses an accepted recommendation without saying why the two measurements
disagree. Both cannot be representative. Before this bucket closes, add a
short reconciliation note: what differed (fixture, cache state, concurrent
load, materialization path, iteration protocol), and which environment the
release decision should generalize to. If 206's environment was
unrepresentative, its review-closed recommendation should be annotated too —
otherwise the program will re-propose BW64/H8 from 206's numbers.

## P2 — the Pareto branch of the promote condition was not addressed

The candidate's recall is materially *higher* (+0.0355 at 50k, +0.0535 at
100k), and the task's phase 4 reads "preserves ordered results and recall
... and provides a material end-to-end latency **or Pareto improvement**."
The decision treats the recall movement purely as a stability failure and
never evaluates the Pareto branch (is +5.4pp recall at 100k worth +10.2 ms?).
STOP may still be the right answer — the contract pinned recall equivalence
and I accept that reading — but the decision.md should state explicitly that
a recall-up/latency-up point was rejected under the equivalence clause, and
that a recall-targeted lane (higher recall at acceptable latency) is a
distinct question this task did not answer. Otherwise the higher-recall
signal silently disappears from the roadmap.

counters where available, and expanded-node/frontier work; request and
response bytes separately." The uninstrumented release rows carry none of

latency/recall STOP this does not change the verdict, but the task text
lists request/response bytes unconditionally; the packet should either
include a labeled diagnostic pair or state that the mechanism view was
deliberately skipped and why.
