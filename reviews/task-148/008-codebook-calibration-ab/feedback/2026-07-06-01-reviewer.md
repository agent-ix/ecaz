# Review: Task 148 — TQ estimator bias corrections (closeout across packets 001–008)

## Verdict

**Science: APPROVE as a source-grounded negative.** Both corrections (length
renorm, codebook calibration) are honestly measured negatives with full
10/50/100k A/B tracing to `results.jsonl`; the reverts of the failed levers are
clean and the default hot-path scorer is byte-unchanged.

**Merge: CHANGES-NEEDED.** The branch tip is **not landable as-is** — it ships
an on-disk IVF format bump (v9→v10) plus ~1,000 lines of default-off calibration
machinery for a feature that failed promotion, and the layout-stability test was
not updated (the `size_of_assertions` test target does not compile). Resolve the
strip-vs-keep decision below before merge.

## What's sound

- **Revert hygiene — clean.** `git diff 9bc66bcab 2de14b389` over all four
  renorm-touched files is empty; `git diff a3bcb13d0 da7ede88a -- ec_ivf/quantizer.rs`
  (gamma-less sidecar) is empty. `git grep -iE 'renorm'` at tip returns nothing.
  The failed levers leave no scaffolding in the shipped scorer; quantizer gamma
  invariants (`quantizer.rs:968/1279`) match baseline.
- **Calibration core math — correct, correctly scoped.** The affine
  per-coordinate reparameterization (`prod.rs:485/518/551`) reconstructs `<q,x>`
  up to quantization, with degenerate/non-finite scale guarded to identity.
  Gated to `storage_format == TurboQuant && turboquant_profile == TqPlus`
  (`scan.rs:1067`, tightened by `dcd9874cc`); coarse postings kept in RaBitQ
  (`a18c8c063`). No risk to `Standard` / non-TQ paths — the default scorer is
  untouched (`c49fc3e31` is purely additive).
- **Evidence — full matrix, honest negatives.** Renorm (pkt 002): +0.62pp recall
  @100k but 5–6× latency regression (100k n40 1.85→11.80 ms). Calibration
  (pkt 008): +1.25pp @50k / +2.19pp @100k pure-TQ recall but fails the neutral
  latency gate (100k n32 +44%); stage2@25 recall unchanged. 1m skipped is
  defensible (100k already failed the gate).

## Merge blockers

1. **On-disk format bump for a failed, default-off feature.** `365704672` /
   `79e1f31ef` grew `EC_IVF_METADATA_BYTES` 92→100 and bumped
   `EC_IVF_INDEX_FORMAT_VERSION` 9→10 (`page.rs:77-85,114`), adding a new
   `EC_IVF_TQ_CALIBRATION_*` on-disk tuple format. Merging this to main makes
   every IVF index write v10 metadata (unreadable by v9/main binaries) to carry
   calibration state that is off by default and measured net-negative. Per the
   repo's on-disk-format-invariant hardening, a format bump must be a deliberate,
   justified change with a backward-compat story — not a side effect of a shelved
   experiment.
2. **Layout-stability test not updated — branch test suite doesn't build.**
   `tests/size_of_assertions.rs` still asserts `EC_IVF_INDEX_FORMAT_VERSION == 9`
   and `EC_IVF_METADATA_BYTES == 92`, so `cargo check --tests` fails
   (`error[E0080]`). This is the layout-stability guard doing its job: the format
   grew without the assertion being re-blessed.
3. **Task file stale.** `plan/tasks/148-...md` still reads `Status: proposed,
   Owner: unassigned` — should reflect the measured-negative closeout and the
   retained-vs-stripped machinery decision.

## Recommended resolution (needs an operator call)

- **Strip** (preferred if the calibration surface has no near-term promotion
  path): revert packets 004–008, returning the on-disk format to v9 and the
  scorer to baseline. Cleanest main; no format churn for a failed feature.
- **Keep as a gated research profile:** then the v9→v10 format change must be
  consciously blessed — document the backward-compat behavior for v9 readers,
  update `size_of_assertions` to the new v10 layout (100 bytes + the calibration
  offsets), and record the rationale in an ADR / the task file. Only then does
  the branch build and land honestly.

The measurement conclusion (both corrections rejected on evidence) stands either
way; this is purely about not shipping experimental on-disk format surface to
main by default.
