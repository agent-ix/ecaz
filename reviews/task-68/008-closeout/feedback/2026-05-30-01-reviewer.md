## Recall floor — note 2

100k recall@10 = **0.8525** at nprobe=16 on 200 queries.

The packet cites the number but does not cite a pre-Task-68
comparator. The Task 68 plan's exit criteria require:

> SPIRE recall@10 within 0.5 pp of baseline on whatever fixtures
> the Phase-1 packet pins as the comparators.

Two things support that this is fine:

1. **No code path in the Task 68 slices changes scoring semantics.**
   The zero-replica fast path uses the same
   `build_boundary_leaf_assignment_placements_with_identity` helper
   with identical inputs (only the *route* changes from "compute
   primary via boundary scan" to "look up primary from
   `assignment_indexes`", and the centroid plan that produces
   `assignment_indexes` is unchanged). The top-graph distance cache
   is byte-equivalent to the direct closure (packet 006 unit test).
   So by code review, recall is preserved by construction.

2. **The determinism check on leaf assignments** in the closeout
   would catch any silent routing drift — those hashes matched.

But the closeout *should* still cite the pre-Task-68 SPIRE 100k
recall@10 at the same nprobe=16 to close the loop explicitly.
Looking at the artifact set, I don't see a citation to an older
recall packet. If a pre-Task-68 SPIRE 100k recall number exists
(e.g. from Task 30 phase 13d/13e or an earlier characterization),
add a one-line "pre-Task-68 baseline X.XXXX vs closeout 0.8525,
delta = …" to `closeout-summary.md`. If no historical comparator
exists at this fixture + nprobe combination, say so explicitly:
"recall@10=0.8525 at nprobe=16 is recorded as the post-Task-68
baseline; no pre-Task-68 same-config comparator is on file, so the
0.5 pp gate is satisfied by the byte-equivalence-by-construction
argument above."

Neither closeout note is a blocker — they're narrative hygiene.
