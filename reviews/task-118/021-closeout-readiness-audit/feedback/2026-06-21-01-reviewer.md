## Diagnostic validity must be resolved before the attribution conclusion

The two HIGH findings in the 005 feedback directly affect whether the packet
006 "dominant recall-loss stage" classification can be trusted:

- The diagnostic's `frontier` set is identical to the `final emitted` set by
  construction (confirmed in the 005 artifacts: every count column = ef_search,
  `frontier_row_indices == final_emitted_row_indices`). So the headline Phase 1
  distinction — "never entered the frontier" vs. "present but lost in final
  rerank/output" — is not actually observable yet. A classification that leans
  on that distinction is not supported by the current instrumentation.
- `candidates_dropped_before_exact_rerank` is `visited - reranked`, which
  conflates graph traversal fanout with frontier candidates and reads 0 here
  only because visited collapsed to ef_search. It cannot support a
  rerank-boundary (Phase 2) conclusion.

What the diagnostic *can* support today, and which is a legitimate finding to
keep: containment into the emitted ef_search stream rises with ef and reaches
truth@10 = 1.0 at ef=128/200 (005 artifacts). That points at frontier width as
the operative lever — but state it as "containment in the emitted candidate
pool", not as a frontier-vs-output attribution.
