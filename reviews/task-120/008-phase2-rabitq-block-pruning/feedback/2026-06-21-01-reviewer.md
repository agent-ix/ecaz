this Phase-2 leaf-block-pruning experiment is **satisfied**. The scientific

## What the change actually does (code already on `main`, not under review)

This is a measurement-only packet (`git status` / `git diff HEAD -- src/` both
clean; manifest correctly states "code change under review: none"). The pruning
code already exists. The behavior being measured is in
`src/am/ec_spire/scan/candidates.rs:1692` `select_leaf_block_row_ranges`:

- Each leaf-block summary is scored by approximate IP against the query
  (summary representatives, here `leaf_block_summary_representatives=2`).
- Summaries are sorted descending and **truncated to
  `max_blocks_per_leaf`** (`candidates.rs:1749`); all rows in non-selected
  blocks are dropped before they can reach rerank.

This is a true candidate-dropping prune, so it can drop true neighbors by
construction. The recall collapse measured at `l2` is the knob working as
designed with a weak (k=2-representative) block-ranking signal, **not a bug**.
The predicate is correct for what it is; it is simply too aggressive / too
coarse to be recall-safe at `max_blocks_per_leaf=2`.
