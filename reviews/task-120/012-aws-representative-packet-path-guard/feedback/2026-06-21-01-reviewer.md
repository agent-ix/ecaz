# Review: Task 120 AWS Representative Packet Path Guard

**Verdict: LGTM** (with one minor pre-existing note, non-blocking).

## Summary

The change broadens the artifact-dir path guard in the two SPIRE AWS
representative-pass scripts from `reviews/task-30/*/artifacts` to
`reviews/task-*/*/artifacts`, so Task 120 (and other appropriately-scoped
SPIRE work) can write packet-local artifacts in its own bucket instead of being
forced into the Task 30 bucket. This is correct, narrow, and well-targeted
harness enablement. It touches no quantizer/index/scan/rerank/storage behavior,
so the 10/50/100k benchmark closeout gate does not apply (confirmed — see
below). The packet is small (4 files, 24K) and well-provenanced.

## Code verification (accept/reject behavior)

I read both guards in full, not just the diff.

1. `scripts/spire-aws/run-representative-performance-pass.sh:96-102` — the
   `--artifact-dir` case now accepts `reviews/task-*/*/artifacts` and its
   `$repo_root`-prefixed form, and still falls through to `die` for anything
   else. Shape is preserved: it still requires the
   `reviews/task-<id>/<packet>/artifacts` three-segment structure, so genuinely
   misplaced paths (e.g. `tmp/...`, `reviews/foo`, a bare `reviews/task-120`)
   are still rejected. The relaxation is exactly "allow any task bucket," not
   "disable the guard."

2. `scripts/spire-aws/preflight-representative-performance.sh:55-65` — same
   shape broadening, **plus** it retains the explicit legacy-default rejection
   at lines 63-65:
   `reviews/task-30/957-spire-aws-verification/artifacts` is still hard-`die`'d.
   This backs the request's "legacy Task 30 default packet remains explicitly
   rejected" claim. I confirmed `infra/spire-aws/Makefile:20` sets
   `ARTIFACT_DIR ?= .../reviews/task-30/957-spire-aws-verification/artifacts`,
   so the preflight rejection is precisely what forces an operator to pass an
   explicit, non-default packet dir — that protective intent survives the
   broadening intact.

So the new accept/reject matrix is sound:
- accept: `reviews/task-120/012-.../artifacts`, any other real task bucket;
- reject: the Makefile legacy default packet (preflight), and any non-packet
  shape (both scripts).

## Minor note (non-blocking, pre-existing)

The legacy-default rejection lives **only** in the preflight, not in the
run-script's own case statement. The run script accepts the legacy-default path
on shape alone (`run-representative-performance-pass.sh:96-102`) and relies on
the preflight (invoked via `make ... preflight-representative-performance`,
line 158) to reject it. Under `--skip-preflight` (line 63-65) or
`--reserve-artifact-dir` (which sets `run_preflight=0`, line 79-82) the
run script would not re-reject the Makefile legacy default. This is **not
introduced by this diff** — the legacy-default guard was already preflight-only
before this change — and it is low-risk for a research harness. Optional
hardening for a follow-up: mirror the explicit legacy-default `die` into the
run-script case block so `--skip-preflight`/`--reserve-artifact-dir` paths can't
silently target the Makefile default. I would not block on this.

I also note `task-*` matches non-numeric/empty ids (e.g. `task-`), but that is
not a realistic misuse vector and matches the repo's existing convention of
treating `reviews/task-*` as the canonical bucket glob; no change requested.

this is not required, but a one-line "rejects legacy default + non-packet path"
demonstration would have fully closed the accept/reject matrix. Optional.
