## Honestly-disclosed limitation (not blocking)

Stages 4/5/6 (`local_candidate_frontier`, `exact_source_rerank_frontier`,
`final_top_k`) all use the same containment predicate —
`predicted_id_set.contains(truth_id)` (`spire_pipeline.rs:2731-2733`,
`2762-2764`, `2789-2791`) — so their `contained_truth_count` values are
identical; only the per-row `missing_reason` differs
(`candidate_or_later_cap` vs `rerank_or_final_topk_cap` vs
`not_returned_in_topk`). This is a final-hit lower bound, correctly labeled with
`containment_basis = "final_hits_lower_bound_until_target_candidate_rank_snapshot"`
and called out in both `request.md` and `manifest.md`. It means candidate-budget
drops cannot yet be split from rerank/final-top-k drops. This is acceptable for a
diagnostic checkpoint but is a real gap against Phase 1's intent (separating
"local candidate frontier" containment from "exact/source rerank frontier"
containment). It must be closed before any Phase 2/3 policy decision rests on
candidate-vs-rerank attribution.
