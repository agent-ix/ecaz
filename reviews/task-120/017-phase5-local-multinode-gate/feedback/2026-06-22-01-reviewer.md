## Required follow-ups / caveats

1. **Scope caveat — the route-overfetch / candidate-budget lever was NOT
   exercised on the distributed path.** The only varied knob is `nprobe`
   (64/96); the `rowcap25k` step did not bind because nprobe96 selected only
   19,200 PIDs, well under the 25k cap (`manifest.md:178-179`,
   `summary.md:61-64`, confirmed: rowcap and default nprobe96 rows are
   counter-identical at `selected_pid_sum=remote_pid_sum=19200`). So this gate
   proves *the distributed path runs and holds recall*, but it does **not**
   prove the Phase 3/4 budget/overfetch lever behaves on the distributed path —
   one of the things 015 conceptually left open. This is acceptable for a
   *gate* (the gate's job is "distributed path works locally before AWS spend"),
   but the AWS matrix, when approved, must include a route count high enough
   that rowcap actually binds, or the rowcap lever remains unproven distributed.
   State this explicitly in the AWS request when it comes.

2. **NDCG not emitted.** `ecaz bench spire-pipeline` did not emit NDCG@10
   (`manifest.md:183`), which the task's Required Metrics lists "where
   available" (`task:200`). 015 *did* report NDCG@10 from its AWS recall step
   (`015/request.md:31-35`). Not a gate blocker, but the AWS 1M matrix should
   restore NDCG so the distributed product-claim evidence is complete.

3. **`requires_remote_heap_resolution` handoff caveat is correctly bounded.**
   The smoke handoff summary still reports `requires_remote_heap_resolution`
   for full arbitrary-row materialization
   (`smoke-customscan-read.log:23`), but the production-read suite path proves
   the compact remote-heap-candidate path with `id` projection
   (`final_heap_fetch_status=remote_ready`, `status=ready`). The packet is
   honest about this (`summary.md:67-71`); it is a known Phase-5 boundary, not
   a regression. Full-row materialization remains owed for any workload that
   projects columns beyond `id`.
