# Review: SPIRE Pipeline Artifact Templates (Task 120 / packet 006)

## Verdict: LGTM (benchmark plumbing; AC1 measurement still owed, correctly stated)

This is a correct, narrow bug fix to the suite runner's `${artifact_dir}`
template expansion for `SpirePipeline` steps. The fix is complete, the
regression test is meaningful, and the request honestly scopes the change as
plumbing that does not itself close any Task 120 acceptance criterion.

## What the change does (verified)

Commit `8225571c2` (`crates/ecaz-cli/src/commands/bench/suite.rs:1168-1177`)
extends `apply_artifact_dir_templates` so the `SuiteStep::SpirePipeline` arm now
rewrites `${artifact_dir}` for every path-typed field, not just `log_output`.

## Correctness findings

1. **Completeness — all path fields now covered.** `SpirePipelineStep`
   (`suite.rs:398-486`) has exactly nine `Option<PathBuf>` / `PathBuf` fields:
   `truth_corpus_file`, `truth_cache_file`, `leaf_block_rank_output`,
   `target_block_rank_output`, `target_candidate_rank_output`,
   `miss_attribution_output`, `log_output`, `funnel_output`,
   `stage_containment_output`. The diff rewrites all nine. Before this fix only
   `log_output` was rewritten, so the other eight would have been handed to the
   `ecaz bench spire-pipeline` invocation with a literal `${artifact_dir}/...`
   path — i.e. truth corpus/cache and every diagnostic JSONL (the Phase-1
   containment outputs this whole task depends on) would land in a bogus
   directory. This is a real, load-bearing fix, not cosmetic.

2. **The fields are genuinely wired to CLI args.** `expand_spire_pipeline`
   (`suite.rs:2867,2877,3094-3099,3114,3152-3155`) emits `--truth-corpus-file`,
   `--truth-cache-file`, `--target-candidate-rank-output`, `--funnel-output`,
   `--stage-containment-output`, etc. from these exact fields, so rewriting them
   is necessary for the produced artifacts to be discoverable.

3. **`expected_artifacts` stays consistent.** The SpirePipeline arm
   (`suite.rs:2580-2590`) reports the seven *produced* outputs and correctly
   omits `truth_corpus_file` / `truth_cache_file` (those are inputs/caches, not
   artifacts). The new test asserts that exact seven-element vector. Good
   separation; no over- or under-counting.

4. **Test is real, not a tautology.** `artifact_dir_templates_rewrite_spire_pipeline_paths`
   (`suite.rs:3857-3968`) constructs a config with `artifact_dir =
   "artifacts/current"`, runs `apply_artifact_dir_templates`, then asserts (a)
   `truth_corpus_file`/`truth_cache_file` are rewritten, (b) the full
   `expected_artifacts` list is rewritten, and (c) the *expanded CLI args* carry
   the rewritten paths for `--target-candidate-rank-output` and
   `--stage-containment-output`. The end-to-end expand assertion is what makes
   this a regression guard rather than a no-op.
