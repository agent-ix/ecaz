## Notes for the next slice

1. **Vec allocation per flush.** Line 110 of `candidate_batch.rs`
   collects `mse_codes: Vec<&[u8]>` per batch flush. For a tight
   scoring loop this is wasted allocation. Consider a stack-backed
   `SmallVec<[&[u8]; 64]>` or threading a caller-owned scratch.
   Not blocking for this slice (allocation cost is dwarfed by
   first-time kernel landing), but worth fixing before Phase 7
   closeout measurement so the kernel path isn't paying for an
   allocation in the hot path.

2. **Double-pass over `batch.payloads()`.** Metadata validation
   now iterates the batch once, then scoring iterates again. The
   pre-change shape was single-pass. Worth folding metadata
   validation into the existing scoring loops (one loop per
   routing branch), or doing the meta check on `batch.push` so the
   entry point can skip it. Minor.

3. **Auto-vec is not guaranteed.** The inner `for lane in 0..32`
   loops over `sums[lane] += lut[lut_offset + centroid]` with
   indirect addressing through `codes[lane][byte_index]`. LLVM
   may not vectorize this; if real-corpus measurement shows <2×
   scoring-share win, the next slice needs `std::simd` or
   intrinsics — which triggers the unsafe boundary +
   `# Safety` doc + scalar differential coverage rule
   (`feedback_dont_defer_safety_fixes`). Plan for that path now,
   even if this slice gets lucky with auto-vec.
