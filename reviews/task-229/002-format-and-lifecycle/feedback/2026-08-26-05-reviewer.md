## Item 2 — the X8 finding is real, and I verified it independently

I checked the three sites the log names, at the reviewed source commit
`56a1b37fc`, and the claim holds. Each bypasses the canonical decoder and
hand-rolls a version-2-only gate:

- `generation_read.rs:1228` — `if fingerprint[..2] != [2, 0]` → "physical epoch
  fingerprint is not canonical v2"
- `handoff.rs:1279` — `epoch_fingerprint[0] != 2 || epoch_fingerprint[1] != 0`
  → `EC_EPOCH_FINGERPRINT_VERSION: unsupported epoch fingerprint version`
- `traversal_replica.rs:208` — `self.epoch_fingerprint[..2] != 2_u16.to_le_bytes()`
  → "EC_REPLICA_IDENTITY: epoch fingerprint is not canonical version 2"

Meanwhile the canonical path is already correct:
`DistannEpochFingerprint::decode` and `from_versioned_manifest_digest`
(`manifest_v2.rs:618-664`) both gate on
`matches!(version, DISTANN_EPOCH_MANIFEST_VERSION | DISTANN_EPOCH_MANIFEST_COVER_VERSION)`,
so V2 and V3 are both accepted there. The three sites above are the only ones
that disagree with it.

Two details worth recording that the log does not state:

- **The length gates are fine.** `DISTANN_EPOCH_FINGERPRINT_BYTES` is unchanged
  between V2 and V3 — only the two-byte version prefix differs — so
  `generation_read.rs`'s `[u8; 34]` conversion and `handoff.rs`'s `len() != 34`
  check do not need to move. Only the version comparisons do.
- **It is latent, not live.** At `56a1b37fc` these sites are unreachable for a
  V3 fingerprint because sealing still emits V1 receipts and covered manifest
  construction fails closed, which is why checkpoint 3's tests pass without
  touching them. That is exactly what makes it a checkpoint-4 blocker: the first
  checkpoint that can publish a V3 epoch is the one where read, handoff, and
  replica identity start rejecting it.

**Amending my seq-04 authorization:** checkpoint 4 remains authorized, with the
added requirement that these three sites route through
`DistannEpochFingerprint::decode` (or an equivalent canonical dual-version
check) before any covered epoch becomes publishable. A hand-rolled version
comparison sitting next to a correct canonical decoder is the shape that
produces exactly this class of bug, so prefer deleting the hand-rolled checks
over widening them to `[2,0] | [3,0]`.
