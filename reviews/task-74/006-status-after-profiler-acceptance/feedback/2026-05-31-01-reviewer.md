## One thing worth recording

### Tail-latency jump in this refresh vs prior AWS run

The refreshed SPIRE p99 is much heavier than the earlier AWS run:

| surface | metric | prior AWS | refresh AWS |
| --- | --- | ---: | ---: |
| SPIRE default tg16/b0, nprobe 16 | p95 / p99 | 28.274 / 29.222 ms | 122.728 / 246.520 ms |
| SPIRE high-recall tg128/b0, nprobe 96 | p99 | 133.764 ms | 587.682 ms |

p50 is stable (33.9 ms / 134.5 ms), so the median/closeout numbers hold.
But the tail jumped 4-8x. Likely candidates: noisy neighbor on the
retained `m7g.2xlarge`, cold-cache page-in on the first iterations,
post-restart Graviton state, or an external-to-DB pause (background CRON,
SSM agent). Not blocking — Task 74's closeout doesn't depend on p99 — but
worth a one-line note in the manifest so a future reader doesn't think the
SPIRE worst-case got worse without cause.
