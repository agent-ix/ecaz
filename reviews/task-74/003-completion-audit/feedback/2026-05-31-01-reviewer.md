# Task 74 closeout review

## Decision

**Hold open**. The self-correction in `003-completion-audit/request.md` from
`complete` → `pending profiler evidence and reviewer approval` is correct.
Do not flip `plan/tasks/74-...md` to `complete` on this branch.

## What's solid

- The overhead estimate at matched recall is robust on two hosts: ~7x M5,
  ~4.5x AWS Graviton at tg128 b0 nprobe=96 vs IVF nprobe=96. That's well
  above the task's 10% stop-condition floor — overhead is clearly material.
- The pipeline-counter observation in `overhead-summary.md` ("nprobe
  64/96/128 all read `leaf_route_sum=3556, candidate_sum=2784952,
  object_bytes_sum=2237295832`") is a useful signal: at high
  `top_graph_search_list_size`, the local leaf envelope saturates and the
  cost difference between nprobe values is happening elsewhere (rerank?
  scoring iterations? route construction?). That observation alone narrows
  where the profiler would have most leverage.
- Shelving all five Phase 2 slices for lack of function-level attribution
  is the right call. Editing `scan/routing.rs` or `scan/candidates.rs`
  blind would risk recursion-semantics regressions Task 30 owns.

## Findings

### F1 — Profiler requirement is load-bearing, not optional

Task 74's Phase 1 text names `samply` or `cargo flamegraph` specifically.
The closeout treats suite counters + IVF control as a substitute. That's
enough to *classify* the overhead as material, but it isn't enough to
*pick a slice* — and picking a slice is what Phase 2 needs. The completion
audit recognizes this. I agree with it.

The AWS profiler attempt (`004-aws-profiler-attempt/`) is honest evidence
of a failed attempt (PMU sampling blocked on the virtualized host), not
completion evidence. Don't count it.

### F2 — Path forward

Two acceptable closes, in order of preference:

1. **Run `samply` on M5** at the Task 73 high-recall point
   (tg128/b0/nprobe=96) and the IVF nprobe=96 control. M5 is the local
   characterization host per both task files; `samply` works on macOS
   without privileged perf access. This is the path that preserves the
   task's scope as written.
2. **Reviewer-approved task amendment** that downgrades the profiler
   requirement to "suite counters + same-host control are sufficient
   evidence to classify, but Phase 2 slices require profile attribution
   before merge". That's basically what's already true in practice — but
   it should be a deliberate amendment, not a quiet redefinition.

Until one of those lands, Task 74 stays pending.

### F3 — One concrete reviewer ask if a profiler run happens

If a `samply`/`cargo flamegraph` run goes forward, separate two cost lines
in the per-phase split:

- "time inside `pg_am_callback!`-bounded code" vs "time inside
  `scan/routing.rs` recursive draft consumption"

The saturated leaf envelope observation suggests the cost between nprobe
64 and 128 is happening *above* the leaf scan, which is exactly where the
SPIRE-specific orchestration sits. A profile that doesn't distinguish
those two won't move Phase 2 forward.

## Verdict

Closeout is accepted as a *checkpoint* but not as task completion. Leave
Task 74 pending. Next coder action: M5 `samply` run, or a written task
amendment.
