### Dispatch + ISA fallback

`score_grouped_pq_block32` (mod.rs:87-108) dispatches via
`current_isa()` and routes:

- `Avx2` → `avx2::score_block32_avx2`
- `Sve2 | Sve` → `sve::score_block32_sve`
- `Neon` → `neon::score_block32_neon`
- `Scalar` → `scalar::score_block32_scalar`

All three SIMD stubs delegate to `scalar::score_block32_scalar` and
return `Isa::Scalar` — matches ADR-076 fallback contract and the lut32
Phase 2 pattern. ✓ When Phase 3/4/5 ship real kernels, those stubs
return their true dispatched ISA without changing the trait surface.

## Minor observations (non-blocking)

### O1 — `score_grouped_pq_batch` is `#[cfg(test)]`

The test-only batch wrapper is fine for Phase 2 — Phase 6's
`score_grouped_pq_batch_for(surface, ...)` in `candidate_batch.rs` will
be the production entry point with timing and counter recording. Just
flagging so the test-only attribute gets lifted intentionally (or kept
test-only with a sibling production helper) when Phase 6 lands.

### O2 — Block-width `try_into` panic on test-fixture mismatch

`mod.rs:69-71` uses `try_into().expect("slice length is exactly one
block")` — that's appropriate (the surrounding `while block_start +
BLOCK_WIDTH <= codes.len()` guarantees the length). No action needed,
just noting it stays sound.

### O3 — `Isa::Sve2` mapped to the SVE stub

The dispatch routes both `Sve2` and `Sve` to `sve::score_block32_sve`.
That's correct for now (stub returns `Isa::Scalar`). When Phase 4 lands
a real SVE2 kernel, the function should return the actual dispatched
ISA (`Isa::Sve2` on Graviton 4), not collapse `Sve2`/`Sve` to a single
return value. Re-check the per-host counter row attribution in Phase 4.

### O4 — Test ISA assertion

`grouped_pq_block32_matches_scalar_reference_bits_across_shapes`
asserts `isa == Isa::Scalar`. Correct today since all SIMD stubs return
`Isa::Scalar`. After Phase 3, that assertion should be loosened (or
replicated under an ISA-aware harness) to allow real ISA returns on
Graviton 4 / AVX2 hosts. Worth flagging on the Phase 3 packet so the
test doesn't silently regress to "always scalar" by being a tautology
under real ISA.
