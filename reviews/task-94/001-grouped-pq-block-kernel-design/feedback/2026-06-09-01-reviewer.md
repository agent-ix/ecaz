## Non-blocking notes

### N1 — SVE2 inner-loop gather under predicate

The SVE2 pseudocode loops one group at a time and gathers
`lut_f32[group*16 + idx]` under predicate per group. That is correct and
VL-agnostic, but FAISS-style PQ4-FastScan typically expresses the inner
shuffle via TBL against a packed 16-entry byte LUT, with the f32 LUT
materialized on the way out. The packet's f32-gather approach is fine
for the first SVE2 landing; if Graviton 4 measurements show gather
stalls dominating, a TBL-based repack is a follow-up packet, parity
re-anchored on the same scalar reference. No design change required
here.

### N2 — `f32::to_bits()` parity scope

Parity is asserted between the scalar block kernel and
`grouped_pq_score_f32`. That is the right anchor. Make sure the test
fixtures use the same sum order — the scalar block kernel loops
candidates outer / groups inner exactly like `grouped_pq_score_f32`'s
`(0..group_count).map(...).sum()`. Phase 2 should add an explicit fixture
with non-trivial LUT values (no zeros, no powers of two) to catch any
candidate-major accumulation reordering that compiles down to the same
sum on benign inputs.

### N3 — Counter row for ISA fallback at full block

Restating for the record: a full 32-candidate block scored on the scalar
ISA fallback should record a kernel row with `isa=scalar` (matching the
lut32 fallback semantics from Task 92 Packet 008), not a scalar tail
row. The packet already says this; reviewer agreement noted.
