## Blocker

### B5. The preregistered semantic gate demands seven correctness rows; the mandated build emits nine

`request.md:141-142` and the same rule in `manifest.md` state:

> Each isolated semantic step must emit exactly seven
> `physical_materialization_correctness` rows and every row must say
> `pass=true`.

Under the attribution-feature extension that this packet *requires*, each
semantic step emits **nine** such rows. Seven is the count for a build with the
attribution hooks absent — which the packet forbids.

The core loop in `run_materialization_correctness` iterates seven scenarios
(`distann_multicluster.rs:6195-6249`: `fewer_than_window`, `exactly_one_window`,
`more_than_window`, `reject_first_window`, `reject_multiple_windows`,
`null_payload`, `toasted_projection_qual`). The function then branches:

- **Without attribution hooks** it returns early at `:6272-6277`, emitting
  `physical_materialization_feature_isolation … semantic_scenarios=7`. Seven
  correctness rows. This is where the number in `request.md` comes from.
- **With attribution hooks** it continues and emits two more
  `physical_materialization_correctness` rows — `scenario=mixed_local_remote`
  (`:6316-6318`) and `scenario=post_first_batch_remote_failure`
  (`:6392-6395`). Nine.

`has_attribution_hooks` is `to_regprocedure('ec_distann_stage_scoring_reset()')
IS NOT NULL AND to_regprocedure('ec_distann_materialization_work_snapshot()')
IS NOT NULL` (`:6005-6013`), and
`ec_distann_materialization_work_snapshot` is
`#[cfg(feature = "distann-head-attribution-benchmark")]` (`src/lib.rs:1938-1941`).
So the probe is exactly "is this an attribution build".

The semantic steps cannot avoid being one. Both set
`"distann_stage_counters": true` and `"physical_benchmark": true`; the candidate
step sets `"owner_fast_real_array_send": true`, whose GUC, whose SQL
substitution and whose `owner_fast_real_array_values` counter are all
feature-gated; and the latency child bails unless it sees
`54 * expected_counter_groups` `[distann-materialization-work]` rows
(`distann_multicluster.rs:8447-8460`), of which there are zero without the
feature.

Not a code reading — two real attribution-build runs, both nine rows per step:


Both sets are the seven core scenarios plus `mixed_local_remote` and
`post_first_batch_remote_failure`. Log:
`artifacts/reviewer-seq03-correctness-row-count.log`.

Why this blocks rather than being a nit: the gate has exactly two outcomes and
neither is acceptable. Either the semantic suite fails a correct run and Task 224

meant "the seven core scenarios" — which is a post-hoc amendment to a
