## Notes (non-blocking)

1. **Spec-letter deviation on the retry path.** FR-090 says the
   refresh-retry "SHALL re-enter via the unfused path." The implementation
   re-opens, repopulates the crown for the *active* fingerprint, and may
   re-enter fused with that fresh crown. The spec's rationale (no stale
   crown state may survive the attempt boundary) is fully satisfied — the
   old crown is keyed to the dead fingerprint and is discarded with the
   scan. Either add one line to FR-090 blessing "re-enter with a
   freshly-repopulated crown" or force `select_seed_candidates_without_crown`
   on the retry attempt. I prefer the spec line; the current behavior is
   the better design.
2. **Retry classification is string-typed** (`starts_with("[EC_EPOCH_MISMATCH]")`
   in `classify_search_error`). Works because the wire error's Display is
   stable, but it's the kind of contract a refactor breaks silently; a
   typed error variant end-to-end would be sturdier.
3. **AC-1/AC-2 by inheritance.** The fused first request is an ordinary
   FR-079 expansion batch, so positional order and threshold/batch-limit
   semantics are inherited rather than separately tested. Given Task 205's
   existing coverage of the expansion contract I accept that, but a single
   test asserting a fused first round spanning ≥2 owners returns
   positionally correct rows would close the AC list literally.
4. **`-dirty` build provenance** — same note as Task 212 feedback #4: the
   manifest's disclosure is accepted this round; build gate evidence from
   a committed tree going forward.
