# Task 210 / 004 — gateway-copy wiring review

## P1 — `gateway_copy_capacity = 0` does not disable a previously cached set

`CachedPhysicalEpoch` stores `gateway_copies`, but its lookup key contains
only the epoch identity (`src/am/ec_distann/generation_read.rs:2966-2974`), not
the current capacity. After one scan populates a 4096-entry set,
`PhysicalGenerationScan::open` reuses that `Some(...)` set even if the same
backend executes `SET ec_distann.gateway_copy_capacity = 0`; the population
guard at lines 3031-3040 is skipped because the option is already `Some`.
Changing from one positive capacity to another likewise keeps the old size.

This violates the GUC's documented “0 disables” contract and can invalidate
same-backend control/candidate A/Bs. Include the effective capacity in the
cache key or explicitly discard/rebuild the gateway set whenever the GUC
changes, and reset the associated observability state with the epoch/capacity.
