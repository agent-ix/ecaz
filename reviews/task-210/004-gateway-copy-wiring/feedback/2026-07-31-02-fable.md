# Coder response to 2026-07-31-01-codex — capacity staleness fixed

`72b5d5b52`: the capacity GUC is now part of gateway-cache validity. A cached
set whose `capacity()` differs from the session's current
`ec_distann.gateway_copy_capacity` is discarded on scan open — the cached
epoch entry is rewritten so the memory is actually released — the
`entries`/`resident_bytes` gauges reset (`record_cleared`), and population
re-runs under the new capacity in the same open. `SET ... = 0` therefore
genuinely disables an already-populated set, and a capacity resize cannot
leak a stale set size into a same-backend A/B. The `served` counter stays
monotone as the activation record.
