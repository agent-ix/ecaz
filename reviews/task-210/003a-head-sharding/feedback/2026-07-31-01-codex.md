# Task 210 / 003a — P2 head-sharding review

## P1 — P2a is still opt-in, so the shipped default remains unsharded

`ECDISTANN_SHARD_HEAD_STORAGE_GUC` and
`ECDISTANN_SHARDED_HEAD_SEARCH_GUC` are both registered with `false` defaults
(`src/am/ec_distann/options.rs:390-404`). The build path passes
`options::shard_head_storage()` into `persist_head_sample`, and the read path
only fans out when `sharded_head_search` is true or a membership-only head was
already built. Consequently a normal default `CREATE INDEX` still persists
all landmark vectors on the coordinator and uses the coordinator-local head;
the P2 candidate evidence is an arm with explicit flags, not the shipped
configuration required by Task 210's Goal and Benchmark Gate.

Please make the multi-owner sharded shape the production default (or make the
default build/read path equivalent without requiring session GUCs), then rerun
the 10k/50k/100k final default-config gate. Until then P2a and the task cannot
be accepted as delivered.

## P1 — replica serving is unreachable because ownership validation runs first

`RetainedGenerationScan::head_search` begins with
`self.validate_request(query, members)` (`src/am/ec_distann/generation_read.rs:1242`).
That calls `validate_ownership`, so a replica that receives a foreign shard
fails before the subsequent `replica_head_vectors(members)` branch at line
1295 can inspect its imported copy. The new replica table therefore cannot
serve any non-owner shard even after population; the first call is rejected as
`EC_PLACEMENT`.

Split query/dimension validation from owner validation and apply the latter
only to the owner-vector fallback. Add a test or A/B that routes a shard to a
non-owner replica and proves `replica_scans`/head serving actually occurs.

## P1 — the population marker does not attest replica coverage

`populate_head_replicas_impl` skips every shard whose owner is the local
coordinator when `owner.conninfo` is absent (`src/am/ec_distann/generation_read.rs:2020-2024`),
but still writes one epoch-level `replica_count` marker afterward. The routing
check only tests `replica_count > 0` (`head_replicas_populated` at lines
3370-3384), so it can route a coordinator-owned shard to a replica that was
never imported. The same marker also does not record which shard/replica pairs
were populated, nor whether its count matches the current
`head_replica_count` GUC.

This makes a successful population call capable of turning a valid owner path
into a deterministic `EC_PLACEMENT`/missing-copy failure for some queries.
Export the local coordinator shard through the local path, record/validate
complete `(shard, replica)` coverage for the requested count, and only enable
replica routing when that attestation matches the current epoch and count.
