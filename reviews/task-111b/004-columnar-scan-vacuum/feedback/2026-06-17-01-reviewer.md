## Verdict

Strong slice — this makes the columnar format readable and vacuum-safe, and it
addressed the packet-003 notes head-on (shared writer/reader length derivation,

## Verified correct

- **Read path with read-back safety.** `IvfColumnarFrozenListRef::decode`
  validates the assembled byte length equals `header.total_column_bytes` and runs
  `validate_offsets`, so a placement/length error fails loud at decode rather than
  silently mis-scoring. The raw-page valid-length derivation
  (`columnar_frozen_list_raw_page_lengths`) is shared by writer, reader, and tests
  — exactly the "don't let writer/reader drift" point from packet-003 note #2, and
  it handles the partial last page.
- **Page-validity fix (packet-003 note #4).** The 8-byte guard before the special
  area resolves the live-build abort when special space starts exactly at
  `pd_lower`, while still leaving too little room for normal tuple insertion to
  reuse a column page. Good catch and a sound workaround — and it confirms these
  pages round-trip through the normal page path.
- **Deleted semantics + vacuum.** Scan skips `is_deleted(index)` postings.
  `bulkdelete_columnar_frozen_list` marks a posting deleted only when all its heap
  TIDs are dead, rewrites the logical bytes via
  `rewrite_columnar_frozen_list_logical_bytes` (fixed-size bitmap → size
  preserving), and keeps directory live/dead counts correct alongside row/dense
  rewrites.
- **Mixed scan.** Row delta tuples in the same list range continue to scan
  normally; the new `IvfPostingEntryRef::ColumnarHeader` is dispatched cleanly.
- **End-to-end coverage.** `test_ec_ivf_columnar_frozen_lists_scan_insert_vacuum`
  exercises build scan, mixed inserted-row scan, vacuum deletion from the
  columnar bitmap, directory counts, and post-vacuum scan — the round-trip that
  would catch any placement/length error.

## Notes (forward-looking, non-blocking)

1. **Add an assembly/copy-bytes counter for the columnar copy path.** This slice
   copies all logical bytes into scratch to feed the existing scorer (correct for
   111b). To make 111c's zero-copy win measurable, instrument the per-scan copy
   bytes here the same way packet 006 did for the packed path — then the 111b
   benchmark shows "parity-with-A + copy cost X" and 111c shows X → ~0.
2. **Dedicated columnar counter.** Columnar postings are currently charged to the
   dense posting counters. Fine for correctness, but a distinct counter (or a
   `columnar` label) would let the benchmark separate columnar / dense / row
   contributions cleanly.
3. **Vacuum rewrites all raw pages** from the modified logical bytes, though only
   the bitmap region changed. Correct and size-preserving; if vacuum cost ever
   matters under churn, rewriting only the bitmap-bearing page(s) is a later
   optimization (Task 114 territory).
4. **Recall parity (AC#3/#4)** is exercised for controlled fixtures here; the
   111b benchmark slice should still assert identical candidates vs the legacy
   path across the TQ + RaBitQ{1,2,4,8} matrix and report storage/page-reads net
   of the separator-page + padding overhead.

This completes the readable+vacuum-safe columnar foundation. With placement
validated (005) and the round-trip green, 111b is in good shape for the benchmark
slice and then 111c. Leaving the request open.
