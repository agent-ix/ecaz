## Verdict

LGTM. Clean, well-validated header slice for the columnar format. Correctly
scoped — reserves the durable tag/version and the deterministic column-offset
contract without switching any scan/build behavior. Not blocking.

## Verified correct

- **Versioned, self-describing header.** New tag `0x29`, version 1, zeroed
  reserved flags; distinct from the dense (`0x25`/`0x28`) and the abandoned
  111a packed (`0x26`/`0x27`) tags. Existing tuple tags untouched, so old
  indexes stay readable (AC#2 groundwork).
- **Offsets are derived, not trusted.** `new()` validates `posting_count > 0`,
  payload bytes > 0, `total_heap_tids >= posting_count`, and the block range,
  then derives all column offsets via `checked_columnar_frozen_list_offsets`
  (checked arithmetic). `decode()` re-derives the expected offsets in
  `validate()` and compares — so a tampered/drifted header is rejected rather
  than mis-read. Good defensive posture, consistent with the existing dense
  codec.
- **Decode rejects** wrong tag/version, nonzero reserved flags, inverted/invalid
  column block ranges, zero counts/widths, and inconsistent heap-TID totals — as
  the request claims and the tests cover.

## Notes (non-blocking)

1. **u32 offset headroom.** Offsets/total span are u32. Per-list columns are
   bounded by `rows/nlists` postings (≈15k/list at 1M/64), so even TQ-sized
   payloads keep a list well under 4 GiB — fine — and `checked_*` guards
   overflow regardless. Worth a one-line note in the writer slice confirming the
   per-list span invariant, so nobody later assumes u32 covers a whole-index
   span.
2. **Tag retirement.** Per the 111b task AC#6 / Task 42: when the columnar format
   lands, the abandoned packed tags `0x26`/`0x27` should be retired or
   quarantined. Track that in the format-version doc alongside `0x29`.

This is the right first slice — the durable contract is locked down and
validated before the page write path. Leaving the request open.
