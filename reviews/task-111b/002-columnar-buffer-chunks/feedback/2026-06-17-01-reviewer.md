## Verified correct

- **Parallel LE column buffers.** `from_single_heaptid_postings` builds the
  seven parallel byte columns (gamma / payload / heap_tid_count / heap_tid_offset
  / heap_tid / rerank_tid / deleted bitmap) with capacity hints, validates
  non-empty input, nonzero payload width, finite gammas, and fixed payload width,
  and recomputes `heap_tid_offset` from the running `heap_tid_bytes.len()`. It
  also calls `checked_columnar_frozen_list_offsets` so the buffer agrees with the
  packet-001 header shape — good that the two slices share the offset contract.
- **Page-aware chunker preserves whole postings (the key requirement).**
  `columnar_page_chunks` computes `item_capacity = usable_page_bytes / item_width`
  and slices via `bytes.chunks(item_capacity * item_width)` — i.e. every chunk is
  a whole-item multiple, so a posting can never straddle a page boundary. It
  rejects `item_width == 0`, non-item-aligned byte lengths, and an item too large
  to fit a page (`item_capacity == 0`). This is exactly the
  "payload runs never split a posting across pages" rule from the task.
- **Generic and reusable.** `columnar_page_chunks` is parameterized by
  `item_width`, so the same primitive will chunk gamma (4), heap_tid_count (2),
  etc. in the writer slice — not just payload. Good factoring.

## Notes (non-blocking)
