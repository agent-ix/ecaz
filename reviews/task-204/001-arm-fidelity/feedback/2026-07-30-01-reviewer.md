## Open item 1 (Phase 3) — the cross-scale growth ratio is still not emitted

Phase 3 requires "the cross-scale growth ratio the invariant needs", and NFR-021
Verification requires "The suite computes the cross-scale growth ratio per node
and fails the run on breach."

What is emitted is `max_single_node_growth_reference=100k_div_10k` — a literal
string label naming which ratio *would* be computed, with no computed value and
no gate. There is no growth row in `results.jsonl`.

The cost of this is visible one packet over: Task 205 `003-ab` had to hand-compute
the ratio into `artifacts/nfr-021-growth.md`, a derived markdown sidecar. That is
precisely the log-only/sidecar pattern Task 204 exists to end, reproduced inside
the first packet that consumed the new emitter.

Two things are needed, and they are separable:

1. a `physical_benchmark_storage_growth` row (or equivalent) computed by the
   suite across the scales present in the run;
2. a `--fail-on-growth-breach` style gate, per NFR-021.

Note that this cannot be demonstrated by a single-scale run. Whatever packet
closes Phase 3 needs at least a 10k+100k pair.

Before building the gate, please read my Task 205 `003-ab` feedback: the NFR-021
threshold as currently written cannot be applied to a fixed-roster fixture. Wiring
a hard `<= 2.0` failure into every distann gate run would halt the program. The
spec question should be settled first.

## Open item 2 (Phase 4) — "absence fails the run" is not enforced

`cluster_index_space_amplification` is emitted unconditionally inside
`run_physical_benchmarks` (`distann_multicluster.rs:5342-5345`), and there is a
`bail!` on a non-positive raw-vector denominator. That is good, and it is most of
the practical benefit.

But Phase 4 asks for the stronger property: "its absence fails the run rather
than being silently omitted." Nothing at the suite level asserts that a
`physical_benchmark_storage_ratio` row exists per scale in `results.jsonl` — a
future step type, an early `return`, or a skipped arm would omit it silently and
the run would still exit 0. Either add the post-run assertion in
`suite.rs`, or record in the task that unconditional emission is the accepted
interpretation of Phase 4 and close it.
