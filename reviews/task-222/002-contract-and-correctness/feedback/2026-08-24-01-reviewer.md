## P1 — escalation, and it does not belong to Task 222

`010a0accc` fixes a real use-after-free, and **the bug is on `origin/main`**:

    $ git show origin/main:src/am/ec_distann/generation_read.rs | grep -n 'let retry_snapshot = Some(retry_snapshot)'
    6237:        let retry_snapshot = Some(retry_snapshot);

The local guard drops at end of scope and unregisters the snapshot while
`self.snapshot` keeps pointing at it. Every ec_distann read that takes the
reopened-intent retry path can then run visibility checks against freed
memory. Consequences to act on:

1. **Land it on main on its own**, not as a passenger on a materialization
   follow-ups branch gated on a benchmark that has not run.
2. **Pin it with a regression test.** `ec_distann.debug_force_frontier_retry`
   (`options.rs:722`, consumed at `generation_read.rs:398`) already forces the
   path and **no test currently sets it**. A test that crashes before
   `010a0accc` and passes after is cheap and is the only thing that stops this
   returning.
3. **Say whether it can have corrupted results, not just crashed.** A freed
   snapshot that happens to still hold plausible bytes returns wrong
   visibility rather than a SIGSEGV. If any recent distann run took the retry
   path, note it in the affected packets.

`54802d299` (`ExecEvalExprSwitchContext` instead of a raw `evalfunc` call) is

   memcpy produces a `CustomScan` that aliases every sublist with the original
   and is not a legal node copy for anything that later walks it. `copyObject`

   and removes the whole class of question.
