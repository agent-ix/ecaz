## Equivalent-mutant verification (lines 42:28 `>` → `==` / `>=`)

Source line 42: `if relation_name.len() > max_identifier_bytes`.

Triage argument:
- `pg_identifier_limit_bytes()` returns `Ok(63)` in careful build
  (`#[cfg(not(any(feature = "pg17", feature = "pg18")))]` arm).
- `relation_name` format: `ec_spire_store_{index_relid}_{local_store_id}`
  = 14 + 1 + d1 + 1 + d2 bytes where d1, d2 are decimal digit
  counts of u32 values (1-10 each).
- Maximum length: 14 + 1 + 10 + 1 + 10 = **36 bytes**.
- 36 < 63 → original `>` guard never fires for any test input.

Mutant analysis:
- `> → ==`: `len() == 63` is also never true for length ≤ 36.
  Same observable behavior as original (never errors). **Equivalent ✓**
- `> → >=`: `len() >= 63` requires length ≥ 63, never reached.
  Same observable behavior. **Equivalent ✓**
- `> → <` (killed): `len() < 63` is ALWAYS true for length ≤ 36
  → always errors → rejects every valid name → round-trip fails
  → KILLED, consistent with the verification log.

The reachability argument is sound and the math checks out.
