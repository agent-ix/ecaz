## Key fixes verified

**Fix 1: Boundary-assertion strengthening.**
Triage cites `bound.is_finite()` on the equal-to-floor case for
the `< → <=` mutants. The mutated `score_at` returns
`estimate = 0.0` on the floor boundary (finite, so original
`estimate.is_finite()` would pass). The new assertion checks
`bound.is_finite()`, where the mutant returns `f32::INFINITY` →
fails.

**This is a useful diagnostic pattern:** `is_finite()` is a
weak boundary check because both 0.0 and the intended valid
value pass it. For floor/ceiling boundary tests, assert against
the intended *failure mode* (infinity, NaN, specific value)
rather than the survival predicate.

**Fix 2: `RABITQ_QUANT_RANGE = 4.0` literal refactor.**
`quantize_level`/`dequant_level` originally had `2.0 * c` with
`c == RABITQ_QUANT_CLIP == 2.0`. Result is 4.0. Mutant `* → +`:
`2.0 + 2.0 = 4.0`. **Equivalent.**

Refactor: introduce `const RABITQ_QUANT_RANGE: f32 = 4.0`; use
the const directly. No binop to mutate. **Structural retirement
of equivalent mutant.** Same pattern as 015 dead-branch removal,
016 `1<<0` literal, 047 disjoint-flag literal.

**Fix 3: Timeout retirement via boundary helpers.**
The 2 timeouts at former 1127/1132 were `< → <=` on the floor
checks. Triage explicitly cites "the same boundary-assertion
strengthening that closes the missed `< → <=` mutants" — i.e.,
the timeout mutants are killed by the same `bound.is_finite()`
asserts that catch the floor-boundary class.

This is the same approach as 017's loop-test rewrite: the
timeouts came from a search-loop helper; rewriting tests to
assert against fixed expected edges directly eliminated the
loop and thus the timeout class.
