## Architecture verification

### `pg_sys` fake surface

The fake `pg_sys` module exports the types and functions that the
production guard files (`src/storage/*_guard.rs`) reference:

- Buffer/BlockNumber/LOCKMODE/Oid/Page/Snapshot type aliases
- Lock-mode constants (`AccessShareLock`, `BUFFER_LOCK_UNLOCK`,
  etc.)
- Opaque struct types (`LWLock`, `SnapshotData`, `ScanData`,
  `RelationData`, `TupleTableSlot`, `SPITupleTable`,
  `TupleDescData`)
- 15 `AtomicUsize` call counters (line 120-134)

### Counter-based RAII verification

Each `pg_sys::*` function the guards call increments a specific
counter:
```rust
pub unsafe fn LWLockAcquire(_lock: *mut LWLock, _mode: LWLockMode) {
    LWLOCK_ACQUIRE_CALLS.fetch_add(1, Ordering::SeqCst);
}
```

Tests then:
1. Call `reset_counters()`.
2. Take the production guard (which acquires the FFI).
3. Drop the guard at end of scope.
4. Assert exact counter values (e.g., `LWLOCK_ACQUIRE_CALLS=1`,
   `LWLOCK_RELEASE_CALLS=1`).

This is **stronger than line coverage**: it proves the RAII
contract (FFI called exactly once on drop) rather than just
exercising the drop code. Per packet 014's lesson — coverage
without assertion is decorative; this packet adds the assertion.

### `#[path]` source reuse

Lines 798-820 import 7 production guard files via `#[path]` —
not copied. Any production-side change is automatically visible
to the careful tests. **No drift risk** between careful and
production.

### Test serialization

`static TEST_LOCK: Mutex<()> = Mutex::new(());` serializes
counter-using tests. Necessary because the counters are
process-global; parallel tests would race. Each test starts
with `let _serial = TEST_LOCK.lock().unwrap(); reset_counters();`.

## Findings

### 1. The counter pattern is reusable for future RAII verifications

15 counters is enough for the 7 current guards (buffer, lock,
relation, snapshot, scan, slot, spi) plus their multiple FFI
endpoints. The pattern scales: any future RAII wrapper just
adds a counter for each FFI function its Drop touches.

### 2. (cross-reference) `reset_buffer_registry()` added in 035

Line 156: `reset_counters()` also calls `reset_buffer_registry()`
— that hook was added in packet 035 to clean the backing-page
emulator state between tests. Backwards-compatible addition; the
035 review confirms.

### 3. The fake is narrow on purpose

The fake doesn't simulate Postgres semantics — it just tracks
calls. That's the right scope for RAII verification: drop should
call `index_close` once, regardless of what `index_close`
actually does on a real backend. Whether `index_close` does the
right thing on a real backend is a separate test surface (live
pgrx integration).

### 4. Stable struct addresses for FFI pointers

`RelationData::rd_att: *mut TupleDescData` — the guard tests
pass real pointers (e.g., stack-allocated `pg_sys::RelationData`)
to the guard constructor. Since the fake `pg_sys` types are
opaque structs with no methods, no UB is introduced — the
guards just hold and return the pointer, then call the matching
release FFI on drop. No real memory is dereferenced.

## Disposition

**Code-level verified.** 582 lines of fake `pg_sys` + 15 atomic
counters + `#[path]` source reuse is the right architecture for
RAII contract verification without a live Postgres backend.

Highest-impact pre-cascade harness packet. Unlocks 7 guard
files' coverage from 0 → 82-100% as documented.
