### 1. (IMPORTANT) Second tooling bug; check if prior packets are affected

This is the second `cargo-mutants` verification-helper bug found
during the cascade:

- **049:** `apply_body` searched forward for `{`, mutating the
  wrong function for one-line implicit-return bodies.
- **052:** `BODY_REPLACE_RE` used `\S+`, silently skipping any
  `<impl Trait for Type>::method` mutation due to spaces inside
  `<...>`.

The coder's claim: "previous packets (047-051) didn't surface
this because the affected files had no trait-impl methods
directly in the source file (or their impl bodies were on
inherent methods, not on `impl Trait for Type`)."

**Required verification:** before declaring the cascade closed,
the next packet should spot-check by re-running the fixed regex
against the enumeration files from 046/047/048/049/050/051. If
any prior file had `<impl Trait for Type>::method` mutations
that the buggy regex skipped, those mutants need verification.

Concretely, a one-shot grep over each prior packet's
`*-mutants-enumerated.txt` for `^<impl ` would surface any
affected mutations in seconds. If the grep returns empty for all
prior files, the claim is verified and no re-verification needed.
If it returns hits, those packets need a quick re-verification
sweep.

Not blocking 052's acceptance — but the verification sweep
should land before any closeout audit.
