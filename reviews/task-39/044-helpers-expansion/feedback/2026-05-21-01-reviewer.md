### `read_stream_*` emulator (lines 89-118)

```rust
pub unsafe fn read_stream_begin_relation(...) -> *mut ReadStream {
    Box::into_raw(Box::new(ReadStream))
}

pub unsafe fn read_stream_next_buffer(
    _stream: *mut ReadStream,
    _per_buffer_data: *mut *mut std::ffi::c_void,
) -> Buffer {
    BUFFER_REGISTRY.with(|r| {
        let mut reg = r.borrow_mut();
        match reg.read_stream_queue.pop_front() {
            Some((rd_id, block)) => reg.pin_buffer(rd_id, block),
            None => InvalidBuffer,
        }
    })
}

pub unsafe fn read_stream_end(stream: *mut ReadStream) {
    if !stream.is_null() {
        drop(unsafe { Box::from_raw(stream) });
    }
}
```

The queue-based approach lets tests enqueue specific
(rd_id, block) sequences. `read_stream_next_buffer` pops from
the queue and pins the buffer (returning a real `Buffer`
handle). When the queue is empty, returns `InvalidBuffer` →
production-side loop terminates cleanly.

`read_stream_end` drops the leaked `Box<ReadStream>` from
`read_stream_begin_relation`. RAII semantics correct.

## Findings

### 1. ReadStream API matches PG18 contract

Production `prefetch_relation_blocks_with_read_stream` uses:
- `read_stream_begin_relation` to start
- `read_stream_next_buffer` in a loop until `InvalidBuffer`
- `read_stream_end` for cleanup

The fake exactly mirrors this contract. Production code can
compile and run against the fake without modification.

### 2. Queue-driven emulator is the right pattern for prefetch

Real prefetch reads blocks in heuristically-determined order;
testing this directly is brittle (the order changes). Queue-
driven simulation lets tests prescribe the order, which is
deterministic.

The downside: tests have to populate the queue per scenario,
which is a manual setup step. Acceptable for the relation_store
test surface; not great for general prefetch testing if it
expands.

### 3. RAII drop is correct

`read_stream_end` drops via `Box::from_raw` — matches the
`Box::into_raw` in `read_stream_begin_relation`. No leak.
