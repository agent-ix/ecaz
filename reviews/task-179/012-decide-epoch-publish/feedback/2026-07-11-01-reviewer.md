# Task 179 packet 012 — decide_epoch_publish (first outside review)

**Status: CHANGES REQUIRED — two P1s.** The T3 validation core is
genuinely strong (`DistannBuildCandidateV1::validate()` is a complete
digest-chain + cross-component recompute over stored bytes; the decision
FK on `candidate_digest` makes the recomputed digest an implicit CAS;
parent==active is taken FOR UPDATE under retained control SRE, honoring
the packet-003 abort invariant; exact replay returns the stored digest
and conflicting manifests are rejected; the `one_recovery_active` partial
unique index + slot check correctly make a Pending/Activated decision
block begin-build and a second decide). But the decision surface ships
with a lifecycle-bricking state hole and an incomplete privilege model.

## P1

- **P1-1 — decide↔abort state decoupling permanently wedges the index;
  the 'Decided' registration state exists everywhere except reality.**
  `ec_distann_decide_epoch_publish` (`build_coordinator.rs:1666-1858`)
  never reads `ec_distann_build_registration`: it does not require state
  `Ready` and never transitions the registration to `Decided` — a state
  declared in the bootstrap CHECK (`bootstrap.sql:437`), the gate mask
  (`build_gate.rs:73`), and the slot check (`build_coordinator.rs:542`)
  but **set nowhere**. Meanwhile `ec_distann_abort_epoch_build`
  (`:2115-2123`) accepts state `Ready` and never consults
  `ec_distann_publish_decision` (its own doc comment claims otherwise).
  Two reachable poisoned sequences: **decide → abort** physically
  destroys the generation under a durable Pending decision (violating
  FR-082:580-581), and **abort → decide** persists a Pending decision
  over an Aborted build with dropped storage (abort leaves the candidate
  row intact). Either way recovery can never complete (participant
  publish fails `EC_EPOCH_STATE`), the Pending row permanently occupies
  the `one_recovery_active` partial index **and** the build slot, there
  is no decision-abort endpoint, and the spec forbids inventing one — the
  logical index is bricked for its lifetime. Note this also gives the
  open seq-04 Pending-wedge P1 a second entry route. Fix: T3 locks the
  registration row, requires `Ready`, and CASes `Ready → 'Decided'` in
  the decision-insert transaction; abort additionally rejects when any
  Pending/Activated decision exists. Add both negatives as pg_tests
  asserting state unchanged.
- **P1-2 — seven coordinator endpoints missing SECURITY DEFINER + pinned
  search_path + REVOKE (FR-082:230-235).** The
  `distann_internal_privileges` finalize block (`lib.rs:513-635`) ends at
  `ec_distann_apply_epoch_retire`; not covered:
  `decide_epoch_publish`, `recover_epoch_publish`, `build_epoch`,
  `abort_epoch_build`, `epoch_build_status`, `generation_topology`,
  `epoch_topology`. They ship invoker-rights with default PUBLIC
  EXECUTE: unprivileged callers fail only *accidentally* on catalog ACLs
  (with misleading `EC_PUBLISH_DIGEST` errors instead of permission
  denied) **after** taking `ShareRowExclusiveLock` on the control index
  (unauthenticated lock-contention side effect, contra "before catalog,
  secret, lock, or RPC side effects it SHALL authorize"); and the
  intended granted-operator model is broken (DEFINER for begin, denied
  for everything after). All packet tests run as superuser, so nothing
  catches this. Mechanical fix: extend the finalize block for all seven.

## P2

- **P2-1** — No negative or crash-window coverage on the decision path:
  no-candidate, conflicting-manifest replay, parent≠active, second
  decide while Pending, decide-after-abort — none tested; and there is no
  fault-GUC point between participant publish and pointer swap, so
  FR-082-AC-9/CON-4 crash boundaries are untested. Additionally the only
  end-to-end pipeline evidence runs build→decide→recover in **one
  transaction**, which FR-082:281-283 forbids (decide SHALL commit before
  any recover) — and nothing in recover guards against consuming an
  uncommitted same-transaction decision.
- **P2-2** — The spec recovery locking protocol (FR-082:239-249: source
  ShareLock, then control SRE, then exact registration revalidation) is
  not implemented — decide takes only the control SRE.

## P3

- `EC_PUBLISH_DIGEST` overloaded for SPI lookup failures, NULL columns,
  and the decision INSERT (a `one_recovery_active` unique violation
  surfaces as a digest error); "no build candidate" should be
  `EC_EPOCH_STATE`/`EC_PUBLISH_INCOMPLETE`; `EC_PUBLISH_PENDING` never
  used.
- FR-078:798-800 SHALL: T3 verifies the Ready generation via
  `ec_distann_generation_topology` before persisting the decision — not
  called.
- Single-flight uses the control SRE relation lock instead of the
  spec's transaction-scoped advisory lock keyed by logical-index UUID
  (FR-082:615-618); serialized today, but the scan-triggered-T4a slice
  needs the non-blocking advisory acquire — plan the switch now.
