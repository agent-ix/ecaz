## New findings

- **P2-1 — `ambuild` unconditionally touches the PUBLIC-revoked Task 179
  catalogs as the calling role, breaking non-owner `CREATE INDEX` on the
  legacy lane.** `ambuild.rs` (~:195) calls
  `generation_store::reset_control_index_for_rebuild` on **every** build,
  before the `distributed_control` branch. That runs
  `generation_relations_for_index` + `delete_index_catalog_rows`
  (`generation_catalog.rs:297-418`) via SPI as the session user — AM
  callbacks have no SECURITY DEFINER context — and `bootstrap.sql`
  revokes ALL on all seven catalogs from PUBLIC with no compensating
  grant. Any role other than the extension owner now gets `permission
  denied for table ec_distann_generation` when creating a plain legacy
  ec_distann index on their own table: a regression versus
  pre-checkpoint behavior and FR-075's user-facing AM surface (NFR-014
  restricts internal endpoints, not index creation). The packet's 147/0
  runs as superuser, so the tests cannot see it. Fix: gate the reset on
  the rebuild actually being control-related (block-0 metadata is
  v5-control, or reloptions request `distributed_control`), or route the
  cleanup through a SECURITY DEFINER helper. Add a role-switch pgrx test
  (SET ROLE non-owner → legacy CREATE INDEX succeeds; internal endpoints
  are denied) — the current privilege test only introspects ACL rows and
  never exercises an unprivileged role.
- **P3-1** — The drop event trigger fires for **every** index dropped
  database-wide (any AM, temp, even the cascaded `_ecdz_dir_*` indexes)
  and pays one seven-table count + six DELETEs each time; a
  `DROP SCHEMA ... CASCADE` with N indexes pays ~7N statements. Add a
  cheap EXISTS probe (or `_ecdz_dir_%` name skip) in the plpgsql before
  PERFORMing the Rust cleanup.
- **P3-2** — No `DROP EXTENSION ecaz` test with a live control index +
  unpublished generation. The sql_drop trigger, its function, and the
  catalogs it deletes from are all dropped by the same command; the
  ec_spire trigger sets precedent that this is safe, but nothing proves
  it for the new trigger. One loopback test closes it.
- **P3-3** — Tablespace fidelity: `tablespace_clause`
  (`generation_store.rs:166-176`) emits nothing for `InvalidOid`, so
  generation heaps inherit the session's `default_tablespace` GUC (not
  pinned by `SET search_path`) and can land in a different tablespace
  than their control index. Pin `default_tablespace = ''` on the definer
  writers or always emit an explicit clause.
- **P3-4** — Under REPEATABLE READ, a begin replay after a concurrent
  committed begin misses the catalog row in its old snapshot and dies on
  the deterministic-name collision check
  (`EC_GENERATION_MISSING: ... exists without matching catalog identity`)
  instead of returning replay progress. Fail-closed, not corrupting —
  document READ COMMITTED as required isolation for handoff endpoints or
  read the catalog with a fresh snapshot.
- **P3-5** — `ec_distann_abort_epoch_handoff`'s publish-decision check is
  race-free only if checkpoint 005's publish path takes the same
  ShareRowExclusive control-index lock before inserting into
  `ec_distann_publish_decision`. Record that invariant now (comment at
  the abort site + task-file note) so 005 cannot miss it.
- **P3-6** — Row-tier `NOT NULL` at this commit is copied from live
  `attnotnull`, which the frozen descriptor does not bind — two
  participants with byte-equal descriptors could build shells with
  divergent NULL enforcement. Noted that HEAD (`17bb92b27`) already
  drops the NOT NULL propagation (captured columns physically nullable),
  which resolves this — confirm that removal was deliberate and keep it.
