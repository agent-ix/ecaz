# Packet 025 — multi-owner physical handoff (outside review)

**Status: CHANGES REQUIRED — two P1s.** The transport binding for the
packet-005 router ack-callback seam is functionally correct (retry
preserves byte-identical unacked batches, verified; secrets resolved
only after identity freeze; per-participant Ready receipts decoded
independently in roster order; abort replays the immutable binding
snapshot including removed owners), but two systemic P1s land here.

- **P1-1 (systemic) — the FR-078:573-579 EC_TRANSACTION_ISOLATION
  runtime check exists nowhere** (zero hits for the code /
  XactIsoLevel / IsolationUsesXactSnapshot in src/). Remote dispatch was
  the task-file gate for this SHALL, and this packet crosses it. A
  coordinator/endpoint under Repeatable Read reads stale
  generation/journal state and mis-replays begin/stage/seal and the T4
  windows. Add a helper (IsolationUsesXactSnapshot → EC_TRANSACTION_
  ISOLATION) at the top of every handoff and FR-082 lifecycle endpoint,
  before lock/catalog/RPC side effects. (This was my 006-seq-07 N-3;
  now ~10 more endpoints ship without it.)
- **P1-2 — Resolved conninfo (incl. any password=) leaks into error
  messages**: remote_transport.rs:57 ("could not parse participant
  conninfo {conninfo:?}"), and the pre-existing M2 paths at :601-611
  and :812-826. The request claims secrets never enter logs. Report
  only the secret name / owner ordinal; connect errors carry {error}
  only.
- **P2 — Transport is neither interrupt-safe nor time-bounded**: every
  RPC is block_on on a current-thread runtime with no
  CHECK_FOR_INTERRUPTS, no connect timeout, no remote statement_timeout,

  cross-instance wait cycle invisible to PostgreSQL's deadlock detector.
  Set connect_timeout + per-call tokio timeout and re-check interrupts
