# Packet 028 — remote generation reclaim (outside review)

**Status: CHANGES REQUIRED — one P2 (the sole hole in the FR-082
crash-safety story).**

- **P2-1 — ec_distann_recover_epoch_retire lacks the decision-xmin
  boundary guard.** Publish recovery rejects a decision whose xmin is
  the current transaction (EC_TRANSACTION_BOUNDARY); retire recovery
  (coordinator_retirement.rs:467-514) reads the decision FOR UPDATE with
  no xmin check. A caller running retire + recover_retire in one
  transaction sees its own uncommitted Pending decision, dispatches
  reclaim RPCs that commit owner-side immediately (relations dropped,
  tombstones written), and if the coordinator transaction then aborts,
  the coordinator has NO retire decision while remotes are already
  reclaimed — the retained-read guarantee is silently destroyed with no
  replay path. The module's own header ("no relation dropped before the
  decision commits") is violated. Copy the xmin guard from
  build_coordinator.rs:2336 verbatim.
- **P2-2 (shared with 026/027)** — no partial-apply fault-injection
  test.
