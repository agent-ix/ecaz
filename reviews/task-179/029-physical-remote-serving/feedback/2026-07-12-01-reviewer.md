# Packet 029 — physical remote serving (outside review)

**Status: CHANGES REQUIRED — one P1.** The distributed read is correct
in identity/ownership/wire discipline (see VERIFIED GOOD), but the
authorization boundary and two design regressions need fixing.

- **P1-1 — The physical read endpoints are effectively PUBLIC.**
  lib.rs:694-716 REVOKEs the SQL wrappers, but the pgrx impl functions
  ec_distann_expand_physical_nodes /
  ec_distann_materialize_physical_row_payloads appear in no privilege
  block → default PUBLIC EXECUTE, so any role bypasses the wrapper and
  reads any retained generation's rows/graph directly. The wrappers
  themselves also lack SECURITY DEFINER / search_path pin (unlike every
  sibling). And the legacy caller-selected-send-function endpoint
  ec_distann_materialize_row_payloads(oid,…,text[],text[]) is still
  PUBLIC and executes any identifier-shaped schema.func the caller
  names. Add all impls + the legacy endpoint to the DEFINER/search_path/
  REVOKE block. (Same root cause as packet 020 P2-2 — this is the
  privilege-gap pattern from packet 012 P1-2 recurring on new endpoints;
  the missing unprivileged-caller test is why it keeps slipping.)
- **P2-1 — Remote frozen-row missing payload silently drops a top-k
  hit** (generation_read.rs:964-966, custom_scan.rs:1077-1092) while the
  local path hard-errors (EC_GENERATION_MISSING). In an immutable
  Published generation a missing row is corruption; the
  tuple_payload_missing escape hatch was for the mutable legacy path.
  Treat it as an error on the physical path per FR-079's no-silent-miss.
- **P2-2 — Physical fan-out is serial (Σ RTT), regressing FR-081**: the
  expander and materializer loop owners sequentially with one block_on
  each; the M2 logical path already uses join_all. This will show up
  directly in the multi-owner latency evidence. Batch through a
  join_all variant (physical endpoints need no session GUCs, so it's
  easier than M2).
- **P2-3 — No EC_UNSUPPORTED_PROJECTION guard** (FR-078:557-559):
  system-column projections/quals over remote-owned rows are NULLed
  rather than rejected. Add a planner/begin-time rejection + test.

P3: expect() on route.conninfo in scan code should be a classified
error, not a panic path.

VERIFIED GOOD: fingerprint-addressed serving (never pointer-addressed),
state IN (Published,Retired), canonical [2,0] version check, descriptor/
roster identity revalidated on open; per-request ownership validation
(→ EC_PLACEMENT/55000) with position-carrying reassembly; no CTIDs on
the wire; attnum-only projection with 32-byte schema-fingerprint triple
check; resolve→pin→revalidate token dance; complete-response-before-
iterator; exemplary error-code discipline (seven SQLSTATEs, only
40001/EpochMismatch retriable, round-trip unit-tested); correct
connection-pool keying.
