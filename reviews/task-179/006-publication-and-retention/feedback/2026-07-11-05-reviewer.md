## 1. build_gate.rs (28b99f151) — CHANGES REQUIRED

### P1 — Durable gate bypassed by any cached plan: enforcement is plan-time only

`build_gate.rs:255-269`. DML gating happens exclusively in the planner hook.
While the coordinator backend lives, its session ShareLock blocks DML anyway —
the hook's entire marginal value is the durable window after the coordinator
dies. In that window nothing forces replanning: a prepared statement with a
generic plan, a PL/pgSQL cached plan, or an FK ri_triggers cached SPI plan
created before the registration row committed executes via
`AcquireExecutorLocks`/`CheckCachedPlan` without re-entering the planner
(registration-row commits generate no relcache invalidation on the source).
`PREPARE ins AS INSERT INTO src ...` before begin-build, `EXECUTE ins` after
the coordinator dies → writes through the gate, defeating exactly the
FR-082:244-246 window. Fix: enforce at ExecutorStart over
`plannedstmt->resultRelations`/`permInfos` (also covers FK-trigger cached
plans). Logical-replication apply workers (`ExecSimpleRelationInsert`) are a
smaller residual gap worth a doc note.

### P2s — database-wide regressions beyond distann

- **P2-1** (`build_gate.rs:158-172`, generation_catalog.rs:25): the planner
  hook unconditionally resolves the helper via `extension_relation_name`,
  which uses `get_extension_oid(..., missing_ok=false)`. After
  `DROP EXTENSION ecaz`, every DML in any backend with the .so loaded fails
  until restart; under shared_preload_libraries, DML breaks in every database
  lacking the extension. Treat extension-absent as mask 0 (`missing_ok=true`,
  return 0 on InvalidOid) — distinct from registration-row-absent.
- **P2-2** (`build_gate.rs:271-283` + callers :286-411): the utility hook
  takes AccessShareLock on the named relation, then standard_ProcessUtility
  escalates to AccessExclusiveLock. Two concurrent DROP/ALTER/TRUNCATE of the
  *same* table (any table) now lock-upgrade deadlock where stock PostgreSQL
  queues. Use the operation's target lockmode in the hook lookup, or resolve
  at NoLock — the OID+UUID+IndexGetRelation revalidation inside the mask
  already bounds stale-resolution damage.
- **P2-3** (`build_gate.rs:286-305, 337-347, 386-400`): fail-open bypass set —
  `DROP SCHEMA CASCADE` / `DROP OWNED BY` / `DROP EXTENSION CASCADE` remove
  the gated source/control via dependency traversal without hitting gate_drop;
  `REINDEX SCHEMA/DATABASE` destructively rebuilds the control (new UUID →
  registration row silently inert via the :117-119 skip arm);
  `TRUNCATE other CASCADE` truncates the source without it appearing in
  `stmt.relations`. Gate at least REINDEX SCHEMA/DATABASE and DROP SCHEMA
  CASCADE with the whole-registry check already used for bare CLUSTER/VACUUM.
- **P2-4** (`build_gate.rs:132-156, 57-97`): every planned DML statement on
  every table performs uncached catalog lookups + an SPI regprocedure cast +
  OidFunctionCall + an inner SPI registry scan. Cache the helper OID (with
  invalidation) and add a cheap "any live registration?" fast path. Per repo
  rule this hook sits on the DML path of every benchmarked lane — needs an A/B
  latency data point before closeout.

### P3s

- P3-1: no supported gate-clearing surface at this commit; tests model release
  with raw `UPDATE ... SET state='Published'` — the real release path is
  untested. State this explicitly in the packet.
- P3-2: REPEATABLE READ sessions snapshotted before begin-build commit read

  snapshot.
- P3-3: the UUID/heap-parent mismatch skip arms (:117-124) are correct

  reserved, or restore the guard.
- **P3** (:60-65): `predecessor_abandon_error` splits on the first `": "` and

- **P3** (:131-135): corruption of a *persisted* candidate's receipt set

## 3. participant_lifecycle.rs (4aed07da2) — approve with follow-ups

Verified sound: no forbidden transition reachable (Rust guard + SQL CAS
predicate double-check on every transition); single-transaction atomicity
including the tombstone+drop+delete reclaim (with a genuine rollback drill in
the tests); all three replay paths return stored bytes, never recompute;
SECURITY DEFINER + pinned search_path + PUBLIC revoke on all four endpoints;
clean pgrx error discipline (no backend unwraps).

- **P2-1** (:797-804): the "digest chain" guard is vacuous — both sides of
  both comparisons recompute from the same in-memory struct
  (`abandoned_binding_set_bytes()` *is* `abandoned_bindings.encode()`), so
  `EC_PUBLISH_DIGEST: abandoned-binding set digest mismatch` can never fire.
  It falsely reads as an independent check. Compare wire-captured segment
  bytes against the recomputation, or delete it.
- **P2-2**: zero negative tests for forbidden transitions — publish from
  Building, retire-mark on Ready, reclaim on Published, unknown build id,
  non-advancing epoch, non-v4 build id are all guarded in code and all
  untested. Single-participant fixture also leaves the out-of-roster-ordinal
  paths unexercised. FR-082 explicitly requires these to fail with
  `EC_EPOCH_STATE` and leave state unchanged; add the matrix.
- **P3**: reclaim replay lookup takes `.next()` without a multi-row assertion
  (:549-601), unlike status which errors on overlap; publish-ack durability is
  delegated to the transport committing — the coordinator slice must treat
  only committed statement success as the ack (record in packet);
  coordinator-side abandonment CAS/decide/recover does not exist yet — FR-082
  must not be claimed complete on this evidence; DES-009 is absent from this
  branch's tree (traceability); minor misordered error for never-published

## 4. scan_registry.rs (ebaa8ebdb → 474382e93) — accept foundation with conditions

The three fix commits each closed a real, distinct bug class (cross-backend
token theft/PID reuse; partial-mutation + tombstone capacity exhaustion;
operation-reference released before heavyweight-lock release). The final
structure — owner generations, validate-before-mutate, reference-outlives-lock
— is coherent and spec-conformant on the paths that exist. Verified: fail-closed
capacity (`EC_EPOCH_PIN_CAPACITY`, reap-before-decision); LWLock never held
across heavyweight acquire/SPI; dropped-UUID fence recycling requires
zero tokens + zero refs; a queued waiter always holds a reference so locktags
cannot recycle under it; panics unwind through the lock guard.

Conditions before any slice consumes this module:

- **P2-1**: no abort/error release path for scan tokens — a live pooled
  backend that ERRORs between register and release wedges retirement with
  `EC_RETENTION_ACTIVE` until backend exit. FR-082 requires release on error/
  cancellation/rescan/EndCustomScan. `FenceOperationReference` has RAII +
  xact callbacks; tokens have a raw register/release pair and only
  before_shmem_exit cleanup. Add a `ScanTokenGuard` RAII type **in this
  module** so no caller can hold a token without it.
- **P2-2**: the retirement observation API is missing and the maintained
  counter is per-UUID, not per-fingerprint. FR-082 requires rejecting unless
  the *target fingerprint's* count is zero; `TokenSlot` stores the fingerprint
  but nothing exposes a fingerprint-scoped count. Add it here — this is
  exactly the seam the retirement slice would otherwise improvise on
  (wrongly, by blocking on unrelated fingerprints).
- **P2-3**: the real shared-memory path has zero executed coverage — the
  preloaded pg_test is `#[ignore]`, all ~20 unit tests run the Vec-backed
  TestRegistry with a stubbed liveness predicate. Never executed:
  shmem_request/startup hooks, tranche acquisition, generation bump,
  before_shmem_exit, `with_scan_registration_fence`, and all of
  `acquire_retirement_fence_xact` (subxact reparenting, abort release). Stand
  up a `shared_preload_libraries='ecaz'` integration lane and drive the fence
  through subxact commit/abort before Task 179 closeout.
- **P2-4** (:1568-1574): `mem::forget` on unconfirmed LockRelease silently
  leaks the operation reference for the backend's lifetime (before_shmem_exit
  releases tokens only), permanently consuming fence capacity. Fail-safe
  direction is right; add a WARNING and a diagnosable slot mark.
- **P3s**: PID+proc-slot reuse window inherent in the spec's liveness
  definition (note only); lock-manager anomalies mapped to
  `CorruptSharedState` (wrong category, :1553-1566); narrow longjmp leak
  window in `acquire_retirement_fence_xact` (:1651-1668); single exclusive
  LWLock + O(capacity) reap scan on every failing registration will need
  attention if scan-start rates matter. The session-lock + one-shot xact
  callback emulation of "transaction exclusive lock" preserves the spec's
  intent (exclusion survives through decision commit) — add one comment line
  in spec or code acknowledging the deviation.
