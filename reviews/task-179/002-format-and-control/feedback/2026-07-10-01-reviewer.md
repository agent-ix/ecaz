# Task 179 packet 002 — format-and-control checkpoint review

**Status: CHANGES REQUIRED — one P1.** The frozen wire formats themselves
are in excellent shape: decode safety is genuinely solid across all eight
new codecs, domain separation is real, spec parity was verified
field-by-field, and the v4/v5 boundary is airtight **on the AM-callback
surface**. The hole is the non-AM SQL surface: the pre-existing FR-082
epoch-lifecycle functions mutate control metadata unguarded and permanently
brick a v5 control index (P1-1). That plus two operational P2s
(autovacuum, reloption toggling) need code + tests before this checkpoint
is accepted. The format-freeze P2s (unpinned scoring constants, mutable
validity bounds) should land before the formats are declared immutable —
they are cheap now and expensive after.

Review basis: three parallel deep passes at HEAD `86515967e` (detached
read-only worktree) — (a) wire/format code line-by-line
(`canonical_wire.rs`, `manifest_v2.rs`, `generation_descriptor.rs`,
`handoff_wire.rs`, `row_schema.rs`, `quantizer.rs`, `placement.rs`,
`page.rs`/`tuple.rs`), with `cargo test --test on_disk_fixtures distann`
(12/12) and the touched-module unit tests (45/45) re-run independently;
(b) v4/v5 boundary walk across every AM callback and every `pg_extern`
touching index state; (c) artifact verification (all cited counts match
the logs verbatim; both head SHAs real; no banned cruft). Placement-hash
golden vectors were additionally recomputed clean-room from the spec text
alone and match spec, impl, and test.

## P1

- **P1-1 — Ungated epoch-lifecycle SQL functions write v4-era mutations
  into a v5 control index and permanently brick it.**
  `src/am/ec_distann/epoch_manifest.rs:73` (`ec_distann_publish_epoch`),
  `:93` (`ec_distann_retire_epoch`), `:132` (`ec_distann_force_retire_epoch`),
  `:171` (`ec_distann_debug_set_in_flight`) all go through
  `with_metadata_mut` (`epoch_manifest.rs:41`) with **no
  `is_distributed_control()` check**. On a v5 control index,
  `ec_distann_publish_epoch(ctrl_idx, 1)` succeeds and writes
  `epoch_state=PUBLISHED, active_epoch=1`; the strict v5 decoder
  (`page.rs:374-395`) then rejects its own metadata on every subsequent
  read. Every AM callback — `aminsert`, `ambeginscan`, `ambulkdelete`,
  `collect_distann_hits` — thereafter errors with "metadata read failed"
  instead of the clean fail-closed codes; the index is bricked until
  DROP/REINDEX, and because `ambulkdelete` errors on the metadata read,
  **autovacuum of the parent table fails forever** (bloat + wraparound
  hazard). `retire`/`force_retire` (RETIRED where v5 requires BUILDING)
  and `debug_set_in_flight(_, n>0)` brick it the same way, and the latter
  two don't even need the lock gate. This is the worst variant of "can v4
  code paths write into a v5 index" because `publish_epoch` is exactly the
  function the distributed-control workflow will eventually target. Fix:
  gate `with_metadata_mut` (or each caller) with `is_distributed_control()`
  → a classified `EC_DISTANN_CONTROL_*` ereport until Task 179's real
  publication path defines control-index state transitions; add a pgrx
  test that `ec_distann_publish_epoch` on a control index fails cleanly
  and the index remains readable afterward.

## P2

- **P2-1 — Fail-closed `ambulkdelete` makes VACUUM/autovacuum of the source
  table permanently fail** (`routine.rs:115-121`). Heap DML that never
  touches `aminsert` (DELETE, HOT-miss UPDATE) creates dead tuples;
  autovacuum then calls `ambulkdelete`, which raises
  `EC_GENERATION_MISSING`, failing the whole VACUUM every cycle forever. A
  control index indexes zero rows — there is nothing to fail closed about
  in maintenance. Return the no-op stats (`ec_distann_noop_vacuum_stats`
  already handles v5 with `node_count=0`) for control indexes; keep the
  error for user-initiated `aminsert`.
- **P2-2 — `ALTER INDEX ... SET (distributed_control = ...)` is accepted
  and silently flips semantics at the next REINDEX**
  (`options.rs:364-371`). Runtime behavior correctly keys off the metadata
  version, not the reloption, so there is no immediate flip — but
  v4 + `SET true` + REINDEX silently converts a serving graph index into
  an empty control index, and v5 + `SET false` + REINDEX destroys the
  logical UUID and materializes a local graph under the same relation.
  Related: a plain REINDEX of a v5 control index mints a **new** UUID
  (`new_logical_index_uuid()` per build), silently changing the logical
  identity that registrations/generations reference. Either reject the
  ALTER, or make REINDEX-is-identity-destroying a durable normative
  statement (spec + comment + test); today it is undefined behavior by
  omission.
- **P2-3 — Scoring-relevant constants are not pinned by the frozen codec
  artifact.** `RABITQ_DEFAULT_QUANT_CLIP: f32 = 2.0`
  (`src/quant/rabitq.rs:79`) is baked into restoration via
  `cached_seeded_srht_bits` (the cache is even keyed by `quant_clip_bits`,
  `rabitq.rs:309-314` — proving it is scoring state), yet the RaBitQ
  artifact v1 encodes only `{dimensions, seed, bits}`. Same class: TQ
  restoration depends on everything inside
  `ProdQuantizer::new(dim, bits, seed)`, and decode/validate call live
  `effective_transform_dim`/`mse_code_len`/`code_len_for`
  (`manifest_v2.rs:221-243`, `generation_descriptor.rs:324-359`). Anyone
  changing the clip constant, the SRHT derivation, or the transform-dim
  rounding silently changes the meaning of already-frozen artifact-v1
  bytes with no version bump and no failing test. Fix while the format is
  still cheap to change: encode `quant_clip` (bit pattern) in the RaBitQ
  variant, or add freeze assertions + "bump DISTANN_CODEC_ARTIFACT_VERSION
  if changed" comments at those constants, plus a golden score-vector test
  (fixed inputs → pinned expected code bytes/scores) so derivation drift
  fails CI.
- **P2-4 — Frozen-wire validity domain is coupled to mutable reloption
  tuning bounds.** `DistannBuildOptions::encode`
  (`generation_descriptor.rs:523-537`) and the manifest degree check
  (`manifest_v2.rs:301-306`) validate against `ECDISTANN_MIN/MAX_*` from
  `mod.rs:89-115`, and decode re-validates via encode
  (`generation_descriptor.rs:559`, `manifest_v2.rs:334`). Tightening any
  reloption bound retroactively makes previously frozen manifests
  undecodable; widening admits bytes into "v1" that old binaries reject —
  both without a version bump. Snapshot the wire-validity bounds as frozen
  format-module constants (or const-assert equality next to a freeze
  comment).
- **P2-5 — Duplicated/weaker identity validation.**
  `DistannBuildSpec::validate` (`generation_descriptor.rs:591-599`)
  re-implements parent-fingerprint validation with hardcoded length 34 and
  literal version 2 instead of calling `DistannEpochFingerprint::decode`
  (as `manifest_v2.rs:46-51` does) — one path will drift on a version
  bump. And `build_id` is accepted as any non-zero 16 bytes in build spec,
  manifest, receipt, and handoff batch, while FR-076 pins it as RFC 4122
  and roster UUIDs *are* checked with `is_rfc4122_v4_uuid`. Validate
  `build_id` with the same predicate everywhere (the coordinator already
  generates it v4).

## P3

- **P3-1** — FR-079/FR-083 remote/debug endpoints return empty success (or
  a fingerprint) for a control index instead of failing closed:
  `ec_distann_list_directory` returns 0 rows, `epoch_fingerprint_impl`
  computes a fingerprint attesting `scan_epoch(BUILDING, active_epoch=0)`,
  `ec_distann_fold_delta_into_graph` returns 0, `debug_tombstone` no-ops.
  None can corrupt (delta head/directory are INVALID), but a coordinator
  mistakenly targeting a control index gets silent empties rather than
  `EC_GENERATION_MISSING`. Add the gate for symmetry.
- **P3-2** — Dead/latent branch in `ambuildempty` (`ambuild.rs:236-250`):
  `require_permanent_control` always errors first, so the
  `initialize_metadata_page(control_metadata(...))` branch is unreachable;
  if it ever became reachable it would mint a *different* UUID in the init
  fork than the main fork. Replace with an unconditional error or a
  comment so the trap can't be armed later.
- **P3-3** — pgrx coverage gaps vs the claims: no TEMP-table rejection test
  (only UNLOGGED), no lifecycle-function-on-control-index test (would have
  caught P1-1), no `ALTER INDEX SET distributed_control` test, no CREATE
  INDEX CONCURRENTLY test (validate phase fails via `aminsert` mid-flight
  leaving an INVALID index — acceptable fail-closed, but untested and
  undocumented), no VACUUM/`ambulkdelete` test.
- **P3-4** — Row-schema dropped attributes are non-canonical
  (`row_schema.rs:76-93`): a `dropped=true` attribute may carry arbitrary
  name/type/typmod/collation/generated bytes; force them to empty/`-1`/`0`
  for a frozen canonical form. Related float canonicality: `-0.0` is
  accepted for `closure_epsilon` (two digest-distinct encodings of
  PartialEq-equal structs); reject via `.to_bits()` or document.
- **P3-5** — Snapshot semantic validation is shallow (`manifest_v2.rs:76-89`):
  no `xmin_full <= xmax_full`, no xip-range checks. Harmless for
  digest-identity use; cheap fail-closed hardening.
- **P3-6** — `DISTANN_PHYSICAL_INDEX_FORMAT_VERSION = 5`
  (`generation_descriptor.rs:23`) duplicates
  `page::INDEX_FORMAT_V5_DISTANN_CONTROL` with no tie — do what the
  amendment did for the placement-hash version and alias it. Also reserve
  graph-record version 9 in FR-076 as never-assignable (physical
  `record_version = 9` byte-collides with the legacy `(0x09, 0x00)`
  prefix).
- **P3-7** — Ready receipt freezes two forced-equal u64s
  (`owned_record_count == row_count` required by validate,
  `manifest_v2.rs:364-369`); if intentional future divergence, say so in
  FR-082, otherwise drop one pre-freeze. And manifest `codec_parameters`
  vs descriptor `codec_artifact` are only digest-bound, never plaintext
  cross-checked — the participant validation path that holds both should
  assert seed/kind/stride equality (flag for the next wiring slice).
- **P3-8** — `looks_like_raw_conninfo` (`generation_descriptor.rs:82-101`)
  is a best-effort blocklist (misses `requiressl=`, percent-encoded URIs);
  fine as defense-in-depth, must not be treated as the secret-material
  boundary (FR-078 correctly puts that on registration).
- **P3-9** — `aminsert`/`ambulkdelete` now read+decode block-0 metadata on
  every call to gate control mode — added (buffer-cached, small) cost on
  the legacy hot path; consider a relcache-scoped cache later.
- **P3-10** — Packet/manifest hygiene: the snapshot/build-spec/handoff-batch
  fixture `.hex` bytes changed between `04c1ce70b` and `57a45cca1` (u32→u64
  XID fix) — the manifest should state explicitly that the freeze point is
  `57a45cca1`'s bytes. Three of the four logs don't echo their command

## Verified GOOD (decision-grade)

- **Decode safety:** every variable count/length across all eight codecs is
  preflighted before allocation (snapshot xip/subxip, roster ≤4096,
  GroupedPQ shapes with `count*4 <= remaining`, handoff neighbor lists,
  batch entry section, manifest receipts); `CanonicalDecoder::take` uses
  checked offset arithmetic; version is read first everywhere; trailing
  bytes are rejected at every nesting level; 8 MiB caps on decode and
  encode; no panic path on hostile input found.
- **Canonical soundness:** strictly-ascending xip/subxip and batch vec_ids,
  zero adjacency padding enforced both directions, NULL-bitmap padding
  bits must be zero, booleans restricted to 0/1, unknown flag bits
  rejected, GroupedPQ signs exactly ±1.0, codebooks finite, seeded codecs
  must zero trained-shape fields, `code_stride` must equal the derived
  stride. Domain separation is real: distinct versioned NUL-terminated
  ASCII prefixes for all seven digested record types; fingerprint is
  `u16_le(2) || SHA-256` as specified; the owner-stream digest is
  length-framed and order-enforced.
- **Spec parity:** field-by-field verified — 21-field manifest, 31-byte
  codec-parameters, 30-byte build-options wrapping the exact 26-byte
  FR-078 body, 303-byte receipt, u64 FullTransactionId snapshot, FR-076
  20-byte graph header with the 6-byte `u32_le||u16_le` ItemPointer, and
  the placement hash (independently recomputed golden vectors).
- **Quantizer restoration:** `ProdQuantizer::new(dim, bits, seed)` takes no
  corpus data, so TQ/RaBitQ restoration is deterministic from the
  artifact; GroupedPQ carries complete trained state; the dim-1536 parity
  test asserts bit-equal codes and prepared scores across all three
  codecs. Remaining exposure is P2-3, not the round-trip.
- **v4/v5 AM boundary:** version dispatched at the byte level on every
  read; v5 requires a valid non-zero RFC4122-v4 UUID and zero/INVALID for
  all fifteen graph/lifecycle fields; v4 must have `flags==0`; the v4
  encoder is byte-stable (97-byte golden + regression test); every AM
  read/DML path gates with classified ereports (no panics);
  `pg_sys::pg_strong_random` UUID with checked return, forced
  version/variant bits, written once under generic WAL inside the build.
- **Tests/fixtures:** the fixture decoders are genuinely independent (raw
  offset walker with literal expected bytes, not the production codec);
  byte-swap/unknown-version rejection exercised for all 12 distann
  fixtures; all 15 `.hex` fixtures referenced; compile-time size/offset
  assertions; upgrade matrix names all 14 writable distann formats.
- **Artifacts:** all cited counts (139/0/1 unit; 65+13+2 integration;
  clippy exit 0; 3/3 pgrx) match the logs verbatim; head SHAs are real
  commits; timestamps internally consistent; packet is 5 files, no banned
  cruft.
