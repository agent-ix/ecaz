# Task 179 packet 013 — recover_epoch_publish / T4a (first outside review)

**Status: CHANGES REQUIRED — one P2 blocking (plus the cross-packet
privilege P1 and the packet-012 P1-1 state hole, both of which this
endpoint inherits).**

Verified good: publish → verify-ack → CAS swap → Applied → Published is
one atomic local transaction, so for the single-node case "all durable
acks before the swap commits" holds degenerately with no torn window;
participant publish replay is exactly-once idempotent, so coordinator
crash pre-commit re-drives safely; no rollback path after activation
exists; `has_predecessor` fails closed rather than faking T4b;
Pending→Applied direct is spec-sanctioned for the no-predecessor case;
session-lock release is correctly deferred to a post-commit callback
with subxact reparenting and is a harmless no-op in a fresh recovery
backend.

## P2

- **P2-1 — T4a does not recompute the candidate digest chain.**
  FR-082:266-270 requires T3 **and every T4 recovery transaction** to
  recompute and verify the canonical candidate digest chain over stored
  bytes before consuming them. `ec_distann_recover_epoch_publish`
  (`build_coordinator.rs:1883-1928`) reads epoch/fingerprint/manifest
  bytes straight off the decision row — no `load_build_candidate`, no
  `validate()`, no coordinator-side manifest-digest recompute (only the
  participant checks it), and the idempotent-replay arm (`:1954-1957`)
  returns the stored fingerprint with zero verification. Call
  `load_build_candidate(...)?.validate()` (or minimally recompute
  manifest digest + fingerprint binding) before the publish call and
  before the replay return.
- **P2-2** — Shared with packet 012: the FR-082:239-249 recovery locking
  protocol (source ShareLock → control SRE → exact registration
  revalidation) is not implemented; recover touches the registration
  only to blind-UPDATE it to Published. And the recover negatives
  (no-decision, different active build, has_predecessor fail-closed,
  mismatched participant ack) are all untested — see packet 012 P2-1 for
  the shared coverage finding, including that the only pipeline evidence
  runs decide+recover in one transaction, which FR-082:281-283 forbids.
