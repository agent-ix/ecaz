## New findings

- **NEW-P2-A — retirement-fence lock identity is ambiguous, and it is the
  crux of the P1-3 design.** FR-082 says scans register "under that logical
  index's retirement fence" (per-index) while retirement "SHALL acquire the
  **fingerprint's** exclusive retirement fence" (per-fingerprint); the task
  file §7 says "per-index retire fence". If these are two different locks,
  the exact race the fence exists to close reopens: a scan reads the active
  pointer (F_old); swap + retire(F_old) runs; a per-fingerprint fence does
  not exclude the scan's per-index registration; retire observes zero in
  flight, reclaims; the scan then registers F_old and addresses reclaimed
  storage. The atomic read-pointer-and-register step only linearizes
  against retirement if fence acquisition is **one lock**, and per-index is
  the only workable identity, since registration cannot know the
  fingerprint before reading the pointer under the fence. Also unstated:
  registration must reject a fingerprint that already has a committed
  retire decision. Fix FR-082 (and align the task file wording) before
  checkpoint 005.
- **P3-1 — terminology leftovers from the P2-8 sweep:** FR-075:54 and
  FR-075-AC-5 "a physical generation is Published" (means epoch);
  FR-079:96 "multi-node generation"; spec.md:48 and :165 still say
  "fingerprint-pinned" after FR-079's pinned→selected rename.
- **P3-2 — "authoritative coordinator" (FR-082:255, 276) is used but never
  defined.** The load-bearing topology assumption — all scans that can
  address a generation originate on the single coordinator instance holding
  that logical index's active pointer and registry — is only implicit
  (FR-075 CustomScan-only + FR-082-CON-1). A second privileged instance
  invoking FR-079 endpoints by fingerprint would be invisible to the
  registry. State the single-coordinator-per-logical-index assumption
  explicitly.
- **P3-3 — fence-edge behavior unstated:** whether the fence is released on
  `EC_RETENTION_ACTIVE` rejection, and whether a scan arriving during a
  held fence blocks briefly or errors.
- **P3-4 — NFR-014 item 5's endpoint enumeration** does not explicitly name
  `ec_distann_control_identity` or `ec_distann_list_unpublished_generations`.
  The identity trust-root endpoint in particular deserves explicit listing.
- **P3-5 — audit-script scope:** it does not guard AC→TC mapping
  completeness — the exact defect class of the seq-01 trace asymmetries,
  which were fixed by hand and are now unguarded. Worth extending;
  `require_pattern` checks are fixed-string presence tests.
