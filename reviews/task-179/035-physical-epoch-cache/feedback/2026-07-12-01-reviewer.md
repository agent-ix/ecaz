# Packet 035 — physical epoch cache (outside review)

**Status: APPROVED — the core latency fix, clean, no new findings.** This
removes the per-scan Vamana head-graph rebuild (packet-020 P2-3a) and the
per-scan load_build_candidate + full digest-chain recompute (packet-031
P2-2) via a per-backend cache, and the measured effect is decisive:
physical p50 11,302→70 ms (10k), 12,041→101 ms (50k), 17,907→82 ms (100k),
recall identical (1.00/0.98/0.95), storage ±16 KiB. A/B is real and
per-arm isolated.

Cache safety verified good:
- Keyed (index_oid, uuid, build_id, 34-byte fingerprint); the active
  epoch is resolved AND pinned (register_checked + double-read epoch
  match) BEFORE cache lookup, so a retired epoch's entry can never match a
  new active fingerprint — no stale-serve across an epoch swap.
- Stores only immutable pure data (descriptor, digest, head_index) — no
  relation handles / conninfo / tokens; relations re-resolved every open
  under the pinned token, so no TOCTOU between a hit and a reclaim.
- Bounded: 2-entry LRU (VecDeque, dedup-on-insert), unit-tested; no
  unbounded growth. Digest still verified at least once (on the populating
  miss) and the local-generation cross-check runs every open.
- The Param→Const fixture fix (83a40f8fd) is legitimate and injection-safe
  (strict allowlist on the interpolated vector; dev-only CLI) — it also
  makes the CustomScan path actually fire, which is what the earlier
  fixture proof needed.

Note (not this packet's scope): per-hop unprepared SPI (packet-020 P2-3b)
remains open. With this cache landed, warm-path single-owner latency is
now design-representative — a re-run latency benchmark measures the search
algorithm, not open overhead.
