## New P2 findings (post-closeout hardening; none reopen the task)

These did not exist in the closeout reconciliation and should get a named
follow-up packet (or land as the first slice of Task 167):

- **P2-1 (safety) `scan_registry.rs:1814-1825`** —
  `remove_xact_fence_reference` holds `XACT_FENCE_REFERENCES.borrow_mut()`
  across `pg_sys::LockRelease` and `drop_after_confirmed_lock_release`, whose
  drop path takes the registry LWLock (`LWLockAcquire` can ereport). A longjmp
  there leaks the `RefMut` and permanently poisons the thread-local: every
  later fence acquire/release in that backend panics on borrow. This is the
  packet-040 bug class; the sibling `remove_tracked_scan_token` (:1585-1601)
  already does it correctly (remove inside the borrow, release outside).
  Spot-checked at source. Trivial fix.
- **P2-2 (safety/UX) `remote_transport.rs:120-123`** — the 5 ms cancellation
  poll checks `InterruptPending && QueryCancelPending` only.
  `pg_terminate_backend`/fast shutdown set `ProcDiePending`, so terminate
  requests stall until RPC completion or the client deadline
  (`remote_statement_timeout_ms + 5s`). Add `ProcDiePending` to the predicate.
- **P2-3 (portability) `remote_transport.rs:101-118`** — `dlsym(NULL, …)`
  resolves globals only on glibc; on macOS it returns NULL and the packet-051
  prompt-cancellation poll is silently inert (degrades to timeouts) on the M5
  lane. Also resolves twice per 5 ms tick and reads a `volatile sig_atomic_t`
  non-volatilely. Cache in a `OnceLock` and/or read the pgrx-bound
  `InterruptPending`/`QueryCancelPending` directly.
- **P2-4 (resource) `custom_scan.rs:633-641` / :1367-1375** — the CustomScan
  exec state (Rust-allocator Vecs: outputs, query, payloads,
  `PhysicalGenerationScan`) is only `drop_in_place`d in `end_custom_scan`,
  which PostgreSQL does not call on transaction abort. Every mid-scan ERROR
  (statement timeout, epoch mismatch, remote failure — all NFR-020 drills)
  leaks the Rust heap in a long-lived backend. Shared-memory tokens are
  correctly released by xact callbacks; only the malloc'd side leaks. Fix:
  `MemoryContextCallback` on the per-query context running `drop_in_place`
  (and drop the nonstandard manual `pfree(state)`).
- **P2-5 (perf, legacy lane) `remote_endpoint.rs:397-402`** —
  `resolve_owned_rows` rebuilds the entire vec_id→TID directory from disk on
  every legacy-lane materialize RPC (O(N) buffer reads per call; ~100k-entry
  reconstruction to resolve a handful of ctids), while the expand endpoint on
  the same path already uses `cached_index_entry`. Spot-checked at source.
  Same defect class packet 048 measured at 283→2613 ms. Not exercised by the
  accepted physical benchmarks (physical path unaffected), but a live
  endpoint; fix or explicitly waive for the deprecated legacy multi-node lane.
- **P2-6 (perf, physical path)** — three concrete, compounding per-RPC costs
  on owners: (a) `generation_read.rs:826/866/913` rebuilds
  `RetainedGenerationScan` per RPC — control-index open, SPI catalog lookup,
  descriptor decode + SHA-256 verify, 3 relation opens, GroupedPq LUT rebuild
  — every hop round on every owner (the coordinator got a 2-entry epoch
  cache in packet 035; the owner endpoint got none); (b) no prepared-statement
  reuse on pooled connections (`remote_transport.rs:220-283`) — per-call
  parse/plan including `$1::text::regclass` catalog resolution; (c) default
  `BW=4` (`mod.rs:245`) makes per-owner RPCs carry 1-2 vec_ids, so overhead ≈
  rounds × per-RPC fixed cost. These three are the code-level substance of the
  accepted ~14-16× product finding. The BW/H shape A/B (e.g. BW=16, H=25 at
  fixed BW×H) is config-only and runnable with the existing 045-style suite —
  cheapest possible next measurement, plausibly the largest single win.
- **P2-7 (perf, build path) `handoff.rs:513-570`** — `insert_prepared_entries`
  runs one `Spi::connect_mut` + statement parse per entry in the stage ingest
  loop (thousands per 8 MiB batch). Batch via multi-row VALUES or
  `unnest($1::bigint[], $2::bytea[], $3::tid[])`.
- **P2-8 (design)** — the four string-typed state machines (registration,
  decision, generation, disposition) have no single transition authority:
  legality lives only in `WHERE state='…'` clauses across ≥8 SPI sites in
  build_coordinator.rs/generation_catalog.rs. Combined with
  `build_coordinator.rs` at 3,841 lines (579/499/410/292-line endpoint
  functions), this is exactly where Task 167 and BatANN will add transitions.
  Extract typed state enums + one transition helper and split the coordinator
  along its T1/T2/T3/T4a/T4b/cancel phase boundaries before more work stacks
  on top.
- **P2-9 (test debt)** — the shmem scan-token registry has no cross-backend
  concurrency test (`ec_distann_registry_concurrency.rs` exercises the SQL
  node-descriptor registry, not FR-082 shared memory; the preloaded-lane test
  is permanently `#[ignore]`d), and `src/tests/ec_distann_basic.rs` is a
  9,161-line flat file with 84 pg_tests. Split by lifecycle area; add one real
  two-backend registry contention test on a preloaded instance.
- **P2-10 (evidence)** — NFR-018's `control_index_bytes` column and
  heap-vs-TOAST split exist in fixture code but are absent from the committed
  031/032 topology artifacts (grep: zero hits). One-line disposition needed:
