  EXECUTE.** `ec_distann_expand_nodes(oid,…)` (remote_endpoint.rs:166)
  has only its `(regclass,…)` wrapper revoked, not the oid-signature impl
  the coordinator actually calls; `ec_distann_materialize_rows(oid,…)`
  (remote_endpoint.rs:317) is in no REVOKE/DEFINER block at all. Both are

  privilege-gap pattern (packet-029 P1 / packet-012 P1-2) this commit
  otherwise closed, recurring on the endpoints I did not enumerate

  not another round of naming endpoints.
- **P1-2 (spec over-claim) — FR-082-AC-17's orphan remedy is
  unimplementable under the current schema.** The new FR-082:361-366 +
  AC-17 assert that a Published-but-never-active generation named by a
  Cancelled decision "may be reclaimed only through an explicit audited
  force-retire path tied to that cancelled decision" — but no such path
  exists, and `ec_distann_retire_decision` requires
  `covering_successor_decision_state = 'Applied'` (NOT NULL + CHECK + FK
  to an Applied successor, bootstrap.sql:764-773/821-823/895-897). A
  Cancelled decision can never be an Applied covering successor, so that
  reclaim is structurally foreclosed today. The request lists this as
  "explicitly still open," which is the honest posture — but AC-17 states
  the remedy as a passing acceptance criterion. It is SAFE (the orphan is
  non-routable; future builds proceed; no logical-index brick) but leaks
  unreclaimable participant storage with no working reclaim. Either
  downgrade AC-17 to a stated TODO or land the cancelled-decision reclaim
  path (which needs the covering-successor constraint relaxed — this is
  packet-006 seq-07 N-2 becoming concrete).

## P2 findings

- **P2-1 — `ec_distann_apply_record_writes` (remote_endpoint.rs:228) is a
  mutating FR-083 write endpoint with no require_read_committed guard.**
  Under Repeatable Read it applies tombstone writes against a
  snapshot-stale placement/roster. Narrower exposure than the coordinator
  endpoints (it reads the epoch from the metadata page, not an MVCC
  catalog snapshot), but it is the same mutating-endpoint class the "every
  mutating endpoint" rule covers. Add the guard.
- **P2-2 (carried from packet-017) — recover_epoch_publish still never
  revalidates the registration and its terminal UPDATEs assert no
  rows-affected.** Decided→Published (:2936) and decision
  Pending→Applied/Activated (:2838/:2886) carry state predicates but only
  the active-pointer swap checks rows-affected. A 0-row silent no-op is
  still possible. The new Cancelled guard (read under the shared lock)
  prevents a Cancelled decision slipping past, so the state machine is not
  newly widened, but the robustness gap is not fully closed — assert
  rows-affected on all three.
- **P2-3 (carried from packet-024) — abandon replay caller check still
  missing.** The +1 line here is only the isolation guard; the replay
  branch (coordinator_abandonment.rs:188-200) still compares only
  successor_build_id/ordinal/reason, not audit.caller_name == session_user
  (FR-082:382-388). Still open.
