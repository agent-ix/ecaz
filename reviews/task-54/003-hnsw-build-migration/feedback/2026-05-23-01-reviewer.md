`grep -n 'unsafe {' src/storage/wal.rs` shows 13 blocks, all of which
wrap PG-extern boundaries that are irreducible per module:

```
74:  unsafe { pg_sys::GenericXLogStart(relation) };
112: unsafe { /* page setup */ };
131: unsafe { pg_sys::GenericXLogFinish(self.state) };
151: unsafe { /* page write */ };
202: unsafe { pg_sys::GenericXLogAbort(self.state) };
219: unsafe { pg_sys::PageInit(self.page, ..., special_size) };
234: unsafe { /* PageAddItemExtended */ };
289: unsafe { GenericXLogTxn::start(relation) };
304: unsafe { Self::start(handle.as_ptr()) };
```

These are precisely the PG-ABI boundaries the wrappers exist to
encapsulate. They cannot be self-narrowed further within `wal.rs` —
they ARE the irreducible boundary. **The slice 001 plan's ≤ 3 target
was set against the pre-wrapper baseline (5) and a -2 minimum; the
slice 002 wrappers necessarily added 8 internal unsafes to absorb the
ABI surface, so the new floor is ~13.**

### Required: decide direction BEFORE slice 005 closeout

Three paths, pick one:

1. **Re-baseline wal.rs target with structural-ceiling rationale**
   (recommended, matches Task 50/448 precedent). Slice 004 or 005
   adds a `§"wal.rs ceiling"` subsection documenting that the 9
   PG-extern boundaries (`GenericXLogStart/Finish/Abort`, `PageInit`,
   `PageAddItemExtended`, `start`, etc.) are the irreducible unsafe
   surface for the WAL/page primitive layer; new target ≤ 13 with
   the recognition that wrapper-internal blocks are the intended
   category. Cite Task 50/448 §"Structural-ceiling documentation"
   as precedent (same disposition for source.rs's SIMD intrinsic
   blocks and the FromDatum boundary).

2. **Restructure wrappers** to share PG-extern blocks (e.g., one
   private `unsafe fn pg_page_init` wraps `PageInit` and is called
   from all wrapper methods). Reduces block count by deduplicating
   the unsafe boundary at the cost of a layer of indirection.
   Realistically saves 2-3 blocks at best — won't reach ≤ 3.

3. **Drop the ≤ 3 target as part of slice 005 closeout**, citing the
   §Migration Targets table in `plan/tasks/54-*.md` (which gives the
   wal.rs floor as `-2 to -4` — a range, not an absolute) rather
   than the slice 001 plan's `≤ 3` restating. The task spec is
   looser than the plan; the plan can re-state.

**Per `feedback_no_premature_task_close`, slice 005 cannot close on
partial targets without explicit structural-ceiling rationale.** Pick
option 1 or 3 before the closeout commit.
