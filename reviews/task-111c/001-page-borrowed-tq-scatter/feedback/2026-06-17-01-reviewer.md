# Feedback: Task 111c Packet 001 — Page-Borrowed TQ Columnar Scoring

**Reviewer:** Claude (Opus 4.8)
**Date:** 2026-06-17
**Checkpoint reviewed:** `11b145d2d`

## Verdict

Strong start to 111c, and — importantly — it achieves **genuine payload
zero-copy**, not a relocated copy. I traced the data path and confirmed the
payload bytes are never materialized into a batch-owned buffer. The mechanism
(pinned-page set + bounds-checked borrowed slices + the already-ref-based
`CandidateBatch`) is memory-safe and correct. Two gaps to close: a score
equivalence test, and the benchmark that proves the win against the right
baseline. Not blocking.

## Verified — it is true zero-copy (the key question)

The 111b path copied a full logical slab; I checked whether this slice merely
moves that copy into the batch, and it does not:

- `IvfColumnarFrozenListPinnedPages` holds `Vec<LockedBufferGuard>` — the whole
  list's raw pages pinned **as a set** for the struct's lifetime.
- `single_page_slice` returns `&[u8]` borrowed from a page's special area, with
  the borrow lifetime tied to `&self`, so refs can't outlive the pinned pages.
- `CandidatePayload<'a>` stores the payload as a borrowed `&[u8]` (`code`), and
  `CandidateBatch.payloads: Vec<CandidatePayload<'a>>` holds **refs, not byte
  copies**; the block kernel consumes `&[&[u8]]` blocks and transposes directly
  from them.

So payload bytes flow page-cache → SIMD transpose with no intermediate copy;
only gammas (4 B) and heap TIDs (6 B) are copied into scratch, as intended. The
`Columnar Logical Bytes Copied` counter dropping to ~0 on this path will reflect
a real floor, not a hidden batch copy.

## Memory safety — sound

`single_page_slice` validates the (offset,len) maps to a single page via
`columnar_single_page_range`, checks `special_size >= page_offset + len`, rejects
a null special pointer, and only then forms the slice — bounds-checked and
lifetime-tied. The whole-posting-per-page format invariant (and the shared
`page_lengths` derivation) guarantees a payload never crosses a page, so the
single-page validation should always pass for well-formed data and fail loud on
corruption. The borrow is released when `PinnedPages` drops (pages unpinned).

## Gaps to close

1. **No score-equivalence test (111c AC#2 "bit-identical").** The focused test
   covers `columnar_single_page_range` only. Add a test that runs the same
   fixture with `ec_ivf.columnar_page_scatter = on` vs `off` and asserts
   identical output rows + scores. The GUC fallback makes this a clean A/B; it's
   the guard that the scatter path can't silently diverge from the 111b copy
   path. Worth a PG18 fixture across a multi-page list.
2. **Benchmark must prove the win vs the right baseline.** When the 111c
   benchmark lands, it needs to show, in one suite: `Columnar Logical Bytes
   Copied` → ~0 **and** latency that **beats dense-a** (per the 008 feedback —
   111b columnar trailed dense-a, so the bar is dense-a, not just "parity with
   A"), columnar-scatter vs dense-a vs row in the same run.

## Carry-forward from 008 (still applies)

This slice is scan-only — it does not change storage, so columnar still reads
more posting pages than compact dense (the 008 storage-density finding). The
zero-copy scan win must overcome those extra page reads. Please pursue the 008
storage-density items (elide always-INVALID cold columns, reduce per-column
padding, drop the separator page) alongside the 111c kernel fan-out, or
columnar-scatter may win on copy and lose on I/O vs dense.
