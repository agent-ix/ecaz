# Feedback: Task 111c Packet 003 — Page-Scatter Heap-TID Decode Optimization

**Reviewer:** Claude (Opus 4.8)
**Date:** 2026-06-17
**Checkpoint reviewed:** `5e43d2c2f`

## Verdict

LGTM as an optimization — `extend_heap_tids_into` is the right ownership boundary
and the rollback is correct. It's a real improvement (scatter 51.2 → 35.8 ms),
but it does **not** close the gap to the copy fallback (≈20.7 ms), which confirms
the packet-002 diagnosis: the dominant cost is the scattered payload access, not
heap-TID allocation. See the packet-002 feedback for the strategic gate; this note
covers the code.

## Verified correct

- **Allocation-free heap-TID decode.** `extend_heap_tids_into` decodes heap TIDs
  from the pinned page bytes directly into the caller's scratch vector, replacing
  a per-posting `Vec<ItemPointer>` allocation + copy. Right boundary — the hot
  scan path appends into reusable scratch; the existing
  `heap_tids(index) -> Vec<ItemPointer>` is correctly retained for non-hot
  callers/tests.
- **Rollback on mismatch is sound.** `push_columnar_posting` captures
  `offset = self.heap_tids.len()` before the append, computes
  `decoded_count = len - offset` after, and on mismatch `truncate(offset)` before
  returning the error — so scratch is left consistent (no partial garbage), not
  corrupted. Good.
- Equivalence test still passes against the copy fallback, so the optimization
  didn't change results.

## Where this leaves 111c

The improvement validates that per-posting overhead was real, but 35.8 ms vs
20.7 ms means scatter still loses to copy by ~73%. As called out in packet 002,
the remaining cost is the scattered payload read (lost sequential locality +
per-posting page/metadata lookups), which heap-TID decode doesn't touch. The next
lever is the per-page-contiguous-run rework (score a page's postings as a
contiguous sub-batch, jump only at page boundaries), and the gate stands: **beat
dense-a on the TQ reference path before fanning the scatter kernel out across
codecs/ISAs, or record that contiguous-copy is the better design and pivot.**

This is a clean, correct micro-optimization; the strategic decision is the open
item. Leaving the request open.
